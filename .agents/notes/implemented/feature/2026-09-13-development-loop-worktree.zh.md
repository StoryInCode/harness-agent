# Agent Note: 任务块 worktree 的寿命长于单次角色运行

Status: implemented

[English](2026-09-13-development-loop-worktree.md) | 中文

## 问题

Test Writer 的文件必须保留给 Implementer 和后续转移检查。子级运行结束或其服务卸载不能证明检出可被丢弃。干净的分离 HEAD 可包含主线没有的提交，而忽略文件可包含证据或秘密。

## 决策

[Worktree 服务](../../../../packages/dev-loop/worktree/README.zh.md)为每个任务块保留一份进程本地分配。Git 从固定提交创建分离检出；既有链接隔离被借用而非嵌套。发布分配前，规范文件系统身份和 Git 清单必须一致。并发兼容请求共享所有者的尝试，而等待调用方的取消不取消另一调用方的命令。

分配所有权属于任务块，而不是单个角色。服务 dispose（资源释放）中止并等待活跃命令，但保留物理目录树。显式退役仅移除已创建、干净、未改变的目录树，不强制执行。借用目录树、改变的 HEAD，以及已跟踪、未跟踪或忽略的工作保留。失败命令报告保留或不确定的残留，而不是尝试广泛清理。

命令截止时间发起取消。所有者请求终止，并等待受管范围静止，不以计时器替代它。取消后的成功进程退出不能发布分配。

## 考虑过的替代方案

每个执行者一个分支会违反项目仅主线工作流；分离检出无需新分支引用即可提供独立文件和索引。角色完成时自动移除会破坏交接。将干净状态视为转移证据会丢失分离提交或忽略文件。重启后自动接管缺少安全退役所需的保留基点和所有权证据。

受委派的 Research 检查了 [Git worktree 手册](https://git-scm.com/docs/git-worktree)，包括分离创建、移除、目录身份和 NUL 分隔的 porcelain 输出。Git 拥有检出创建和注册；未复制外部代码。此分配服务不替换既有 [worktree 本地钩子安装器决策](../process/2026-07-27-worktree-local-lefthook.zh.md)，后者拥有独立的安装职责。

## 影响

分配在角色改变后仍然存在，但其映射不持久化。已占用而未记录的路径需要显式恢复。转移证明和删除已转移的脏目录树需要独立协议；分配不会从测试成功推断这些事实。子级会话工作区选择属于 subagent 创建请求，而不是父级元数据变更。目录分配不是文件系统安全边界。

[冻结行为套件](../../../../packages/dev-loop/worktree/tests/worktree.spec.ts)使用私有 Git 仓库和真实本地服务验证独立索引、固定基点、保留交接文件、借用、保守退役和 Loader 释放。[补充用例](../../../../packages/dev-loop/worktree/tests/coverage.spec.ts)覆盖格式错误的外部观察、provider 失败、取消和改变的所有权证据，不以 mock 替换业务服务。
