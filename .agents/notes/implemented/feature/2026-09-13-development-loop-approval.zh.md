# Agent Note: 针对当前源码的显式开发循环决定

Status: implemented

[English](2026-09-13-development-loop-approval.md) | 中文

## 问题

规格摘要可能省略人类授权工作所需的细节。自由文本反馈不是明确无歧义的决定，文件也可能在人类考虑期间改变。将任务块标记为 pending 必须区分显式接受、问题、修订和过期观察。

## 决策

[批准工具](../../../../packages/dev-loop/approval/README.zh.md)使用既有用户问答服务展示完整当前规格，将缺失教学警告追加到源码，而不是替代源码。它要求一个精确选择和独立的可选反馈。只有 Accept 才尝试生命周期的 todo-to-pending 比较并设置；Question 和 Change 保持状态不变。

Consumer 要求调用 Agent，并将该确切对象提供给强制在线根所有权的用户问答服务。文件系统版本包围源码读取，并在接受前再次检查。目录验证提供配置的语法并确认请求身份。这些检查检测观察到的修订变化；不会创建跨文件系统状态和生命周期内存的原子事务。

每次调用组合调用方取消与插件生命周期。Dispose（资源释放）关闭准入、中止活跃操作，并等待其结算。工具仅在接受的转换结算后返回规范 JSON 结果；其渲染器不读取服务，也不重复人类提示。

这是任务规划决定，不是权限授予。[权限批准决策](2026-07-06-approval-seam.zh.md)仍是操作权限、沙箱提权及其审计事件的权威。限定范围的活跃记录搜索未发现被取代的开发循环决策；该权限记录仍独立有用且保持不变。

## 考虑过的替代方案

**从反馈推断接受。** 拒绝，因为问题和修订指令可能包含肯定语言，却未选择 Accept。独立选择与反馈字段保留该区分。

**展示缓存摘要。** 拒绝，因为摘要不能确立人类考虑的是哪份完整源码。当前源码和版本观察揭示交互期间的变化。

**使用权限批准服务。** 对此任务规划交互拒绝该方案：允许／拒绝权限结果不能表达 Question、Change 和独立反馈。工具不使用通用问题授予特权操作权限。

**在此存储持久化批准授权。** 延后给循环持久化和完成策略所有者。本地 pending 状态不是绑定修订、可跨重启或后续源码编辑保留的授权。

## 影响

行为测试通过真实服务执行显式选择、格式错误答案、调用方拒绝、源码变化、生命周期冲突、取消和释放。缺失文件回归区分发现后消失与任务块初始不存在。文件系统版本检查和生命周期比较并设置保护不同观察；两者不能相互替代。

工具不对每个直接生命周期调用者强制策略，不持久化批准授权，不分派执行者，也不挂载用户界面。组合循环必须提供这些所有者。后续文件编辑和进程重启需要独立的修订绑定与协调恢复规则；成功的本地批准不证明这些规则存在。
