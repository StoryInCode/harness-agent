# Agent Note: 持久化角色委派记录观察到的证据

Status: implemented

[English](2026-09-13-development-loop-roles.md) | 中文

## 问题

专业工作需要跨连续运行保留文件和可归属报告。仅有子级结果不能证明清理完成、历史已持久化或其主张经过独立验证。模型提供执行策略还会让任务选择本应属于 Host 的权限。

## 决策

[Roles](../../../../packages/dev-loop/roles/README.zh.md) 将 Host 服务与作用域 Brain 工具 Consumer 组合。Host 配置为 Research、Test Writer、Implementer 和 Utility 选择 provider、persona 及继承工具过滤器。模型只提供有界任务。Provider 兼容性检查拒绝不支持的能力。Research 要求非空显式允许列表，可通过可选拒绝列表扣除；其他角色要求显式允许和／或拒绝列表。此要求使选择显式化，但不证明获准工具为只读。

Roles 捕获确切的在线发起者，并在 Queue 准入前保存意图。准入后的分派取得保留的 worktree，通过公共 subagent 请求提供其目录。实际返回的租约直接交给 Queue，由 Queue 拥有结果观察和 dispose（资源释放）。Roles 记录实际子级身份及可选头部预设，绝不猜测组合，并在返回前持久化终态观察。报告保持为 `reported` 证据，而非父级直接检查。

清理分类遵循可观察的所有权。`SubagentRuntime.start` 拒绝且未返回租约时，清理保持 `unproven`，即使内部清理可能已经成功。对于已返回的租约，即使结果拒绝，成功等待 `QueueTicket.cancel` 也能证明清理完成。取消拒绝使清理保持 `unproven`。不确定的清理始终产生 `failed`；Roles 只保留公共运行时和 Queue 可观察的失败，不保留隐藏的启动释放细节。

完整值字节限制分别作用于任务、持久化终态记录和渲染后的工具内容。溢出绝不会静默截断成功报告或返回部分历史。必需终态元数据无法容纳或持久化失败时，请求记录保持未解决，操作拒绝。持久化意图不宣称子级正在运行，重启也不会自动重试它。

## 考虑过的替代方案

**让 Queue 启动专业执行者。** Queue 的回调已允许 Consumer 选择 provider 和分配，无需重复准入或清理。将这些选择移入 Queue 会合并独立拥有的策略与调度。

**在每个角色结束后退役 worktree。** 子级结束不能证明转移完成，也不意味着其他角色的输入可被丢弃。任务块独立于每次运行保留其分配。

**将 persona 或目录视为隔离。** 指令不强制执行权限，工作目录也不限制文件系统访问。Provider 应用继承工具过滤，部署则拥有获准能力的安全性。

**从错误类推断清理。** 启动拒绝可能隐藏清理信息，结果拒绝也可能与成功释放同时发生。只有返回的租约和 Queue 的已等待取消才能支持这种区分。

## 影响

该服务保留归属和未解决意图，无需维护第二份历史缓存或另一套子级生命周期控制器。它不提供崩溃协调恢复、转移、自动退役、独立证据验证或 Research 策略验收。存储失败和不确定清理需要检查，而不是自动重试。该服务没有可与权威记录比较的独立维护观察，因此不需要运行时 invariant 配套入口。

## 验证

[历史覆盖率补充报告](../../../../packages/dev-loop/roles/tests/COVERAGE-ADDITIONS.md)记录了对应所列源码哈希的 47 个通过用例，以及失败的严格逐文件覆盖率检查。它明确指出实际 provider 的清理失败集成尚未验证。这些冻结测量不代表当前源码验收。本记录不声称任何新的测试、快照或覆盖率结果。

## 相关决策与取代范围

限定范围的取代审查将 [Queue 决策](2026-09-13-development-loop-queue.zh.md)和 [Worktree 决策](2026-09-13-development-loop-worktree.zh.md)保留为独立的活跃记录。Queue 仍拥有直到清理完成的容量；Worktree 仍拥有分配和保守退役。Roles 使用两项决策，但不替换它们的理由、替代方案或验证。两份记录都未被取代、合并、移动或归档。
