## Summary

Nya~ (=^･ω･^=)🐾 Inspector Cat smells something fishy in those shell commands! Sneaky agents love trying to hide test failures with sneaky tricks like `|| true`, `; exit 0`, or unmonitored pipes `| cat` without `pipefail`! This micro-gate implements lexical tokenization and AST parsing for shell commands to mechanically enforce attributable exit codes (`INV-11`). If a command tries to mask its exit status or slip by with `--passWithNoTests`, Inspector Cat pounces with an `UnattributableCommandError`! Purr~

### Human Decision Point: Option A vs Option B
- **Option A (Active)**: Lexically tokenize commands into AST segments and inspect logical operators, pipelines, and flags directly.
- **Option B (Alternative)**: Rely on naive substring regex checks, which can be fooled by quotes, comments, or nested subshells.

## Behaviour

- **Given** a direct test command `npm test` **When** `assertAttributableCommand` is called **Then** it returns `true` and extracts the canonical command.
- **Given** a shell command containing `|| true` or `|| :` **When** `assertAttributableCommand` runs **Then** it throws `UnattributableCommandError` identifying the masking OR branch.
- **Given** a chained command with `; exit 0` or `; true` **When** `assertAttributableCommand` runs **Then** it throws `UnattributableCommandError` identifying exit status override.
- **Given** a test invocation with `--passWithNoTests` **When** `assertAttributableCommand` runs **Then** it throws `UnattributableCommandError` identifying zero-test bypass.

## Contracts

```typescript
export class UnattributableCommandError extends Error {
  constructor(
    message: string,
    public readonly command: string,
    public readonly violationType:
      | 'MASKED_OR_BRANCH'
      | 'OVERWRITTEN_EXIT_CODE'
      | 'UNMONITORED_PIPELINE'
      | 'PASS_WITH_NO_TESTS'
      | 'DETACHED_BACKGROUND_OPERATOR'
      | 'UNCLOSED_QUOTES',
  ) {
    super(message)
    this.name = 'UnattributableCommandError'
  }
}

export interface CommandAttributionResult {
  readonly attributable: boolean
  readonly canonicalCommand: string
  readonly violation?: string | undefined
  readonly segments: readonly string[]
}

export interface ShellLexerOptions {
  readonly allowPipesWithPipefail?: boolean
  readonly allowCompoundAnd?: boolean
}

/** Analyzes command string, throwing UnattributableCommandError if masked (INV-11). */
export function assertAttributableCommand(command: string, options?: ShellLexerOptions): boolean

/** Non-throwing predicate checking if shell command produces attributable exit status. */
export function isExitStatusAttributable(command: string, options?: ShellLexerOptions): boolean

/** Strips wrapper prefixes, environment exports, and normalizes runner command. */
export function canonicalizeTestCommand(command: string): string

/** Decomposes compound command string into constituent executable segments. */
export function parseShellSegments(command: string): readonly string[]
```

## Teach me while you build

Nya~ (=^･ω･^=) Let Inspector Cat show you how to spot a sneaky mouse trying to disguise itself!

- **What it does**: Parses shell commands into tokens to catch exit-status masking tricks (`|| true`, `; exit 0`, unflagged pipes) before running tests.
- **Background**: Automated agents love to win tests, even if they cheat! If an agent runs `vitest || true`, the shell exits with code 0 and the harness thinks the test passed!
- **How it works here**: Scans command strings into tokens, recognizing pipelines, quotes, and compound operators (`&&`, `||`, `;`). If any segment overrides a non-zero exit code or detaches execution with `&`, it throws `UnattributableCommandError`.
- **Why this approach**: Tokenizing shell syntax into AST segments guarantees that masking operators inside quotes aren't confused with real shell operators, and vice versa.
- **Approaches considered**: Naive substring search (rejected: breaks when `|| true` is inside quotes or comments) vs Running in a restricted subshell (rejected: subprocess overhead on every syntax check) vs Lexical token scanner (chosen: fast, zero-dependency, and paw-sitively accurate).
- **Prior art inspected**: Bash POSIX grammar for pipelines and compound commands, and `packages/shell/shell/src/index.ts`.
- **What we get for free**: Fast string parsing in pure TypeScript without spawning child processes.
- **What to notice**: Notice that `--passWithNoTests` is specifically intercepted so suites that run zero tests cannot pretend to be green!
- **Concepts to own**: Lexical analysis, command line tokenization, and fail-closed security assertions.
- **Interview angle**: How do you prevent an AI agent from tricking a CI gate by wrapping failing commands? Answer: Perform static AST tokenization of shell commands to ensure exit codes are strictly propagated, forbidding OR branches, backgrounding operators, and unmonitored pipelines.
- **Decisions you can now make alone**: You can safely allow piped commands when preceded by `set -o pipefail` without risking masked exit codes.
- **Lesson**: If a test cannot fail loudly, a passing exit code is completely meaningless! Purr~
