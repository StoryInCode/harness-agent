## Summary

Implements the concrete `VerificationService` class extending `VerificationStore` and mounts it on the Cordis Host Plane. Injects `['storageDomain', 'shell', 'subprocess', 'fs']`. Implements the full lifecycle: opens the typed verification domain on `[Service.init]()`, recovers monotonic event sequence numbers, registers domain release disposers, executes independent RED and GREEN gates, handles workspace edit marking, evaluates command attributability, and enforces periodic ledger retention pruning.

### Human Decision Point: Option A vs Option B
- **Option A (Active)**: Implement an authoritative Host Plane Service Provider (`VerificationService`) injecting `storageDomain`, `shell`, `subprocess`, and `fs`, orchestrating the full lifecycle with domain cleanup disposers on `ctx.effect`.
- **Option B (Alternative)**: Implement verification as ad-hoc utility functions invoked directly inside worker sessions, resulting in split storage locks, unmanaged database handles, and uncoordinated state across sessions.

## Behaviour

- **Given** Cordis host container startup **When** `VerificationService` initializes **Then** `storageDomain` opens the typed domain spec and recovers event sequence state.
- **Given** a verified command execution **When** `recordEvent` runs **Then** an immutable record is committed to `events`, in-memory state is updated, and `verification/event-recorded` fires.
- **Given** an agent turn stop **When** `getStatus` runs **Then** synchronous state lookup returns fresh, stale, or unverified status with zero disk latency.
- **Given** host shutdown **When** the service disposes **Then** all pending operations finish and domain handles close cleanly via `ctx.effect`.

## Harness fit

This is a `Service Provider` primitive owned by `@deepseek-ai/dsh-verification-service`. It is the central host service implementing `VerificationStore` on the Host Plane (PRESET-RULE 6). It consolidates the discrete capabilities (storage domain, attributable shell parser, hasher, red/green gates, pruner) into an authoritative, long-lived host service shared by all worker sessions.

```typescript
import { Context, Service } from '@deepseek-ai/cordis'
import z from '@deepseek-ai/schemastery'
import {
  VerificationStore,
  type VerificationEvent,
  type WorkspaceVerificationStatus,
  type PinnedSuiteManifest,
  type RedGateVerificationRequest,
  type RedGateVerificationResult,
  type GreenGateVerificationRequest,
  type GreenGateVerificationResult,
} from '@deepseek-ai/dsh-verification'

export interface VerificationConfig {
  maxEventsPerSessionRoot: number
  maxEventAgeDays: number
  maxOutputSummaryChars: number
}

export const VerificationConfig: z<VerificationConfig> = z.object({
  maxEventsPerSessionRoot: z.number().default(100),
  maxEventAgeDays: z.number().default(30),
  maxOutputSummaryChars: z.number().default(2000),
})

export class VerificationService extends VerificationStore {
  static inject = ['storageDomain', 'shell', 'subprocess', 'fs'] as const

  constructor(ctx: Context, config: VerificationConfig)
  protected [Service.init](): Promise<void>
  recordEvent(event: Omit<VerificationEvent, 'id' | 'createdAt'>): Promise<VerificationEvent>
  getStatus(sessionId: string, cwd: string): Promise<WorkspaceVerificationStatus>
  markWorkspaceEdited(sessionId: string, root: string, paths: readonly string[]): Promise<void>
  isExitStatusAttributable(command: string): boolean
  evaluateRedGate(request: RedGateVerificationRequest): Promise<RedGateVerificationResult>
  evaluateGreenGate(request: GreenGateVerificationRequest): Promise<GreenGateVerificationResult>
  getPinnedManifest(cardId: string): Promise<PinnedSuiteManifest | undefined>
}
```

## Teach me while you build

Tutturu~ ♪ Mayuri here! Let's weave all the verification threads into a lovely, reliable blanket for our workers!

- **What it does**: Binds the whole verification family together into one friendly, dependable Host service so developers and workers always have a single source of truth!
- **Background**: Verification isn't just one script—it's a symphony of storage tables, shell parsers, subprocess runners, and anti-cheat guards. If each agent tried to run these on its own, they'd clash over file locks and leave behind orphan handles.
- **How it works here**: Mounted on the Cordis Host Plane, `VerificationService` inherits from `VerificationStore`. In `[Service.init]()`, it opens the storage domain, hydrates event counters, and registers an async disposer in `ctx.effect()` that gracefully flushes records and closes handles.
- **Why this approach**: Centralizing coordination in a single Host Service Provider guarantees monotonic event sequencing, atomic state tracking, and clean lifecycle teardown adhering to `docs/defensive-patterns.md`.
- **Approaches considered**: Per-session decentralized verifiers (rejected: risk of SQLite lock contention and split-brain state) vs Singleton host service (chosen: guaranteed consistency, zero latency in-memory status checks, and safe shared storage).
- **Prior art inspected**: Cordis Service injection and disposal patterns in `packages/dev-loop/claims/src/index.ts`.
- **What we get for free**: Cordis dependency injection (`static inject`) ensuring `storageDomain`, `shell`, `subprocess`, and `fs` are ready before initialization.
- **What to notice**: `getStatus()` reads from an in-memory cache updated during `recordEvent()` and `markWorkspaceEdited()`, allowing high-frequency turn-stop checks with zero disk I/O!
- **Concepts to own**: Host Plane Service Provider pattern: long-lived infrastructural services stay bound to the application container, shielding worker fibers from lifecycle management.
- **Interview angle**: Why separate service definition interfaces from concrete service providers in an extensible plugin architecture? Answer: It allows multiple implementations (e.g. in-memory test fakes vs production SQLite stores) while keeping consumer code decoupled.
- **Decisions you can now make alone**: You can add event listeners or telemetry reporters to `verification/event-recorded` without modifying core gate execution logic.
- **Lesson**: When everyone shares a clean, well-cared-for home service, nobody has to worry about cleaning up database handles alone! Tutturu~ ♪
