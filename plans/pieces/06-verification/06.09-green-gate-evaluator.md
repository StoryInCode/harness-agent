## Summary

Fwahahaha! The Organization shall not deceive us with illusory green lights! Executes the independent GREEN gate evaluator verifying that an implementation satisfies the frozen BDD test suite (`INV-13`). Runs tests inside the worker worktree using an independent runner environment (`ctx.subprocess` / `ctx.shell`), completely isolated from agent hallucination. First re-hashes test files and runner configs against the card's `pinnedManifest.aggregateHash`. Next executes the test command, verifying zero exit code (`exitCode === 0`) and attributable execution (`06.03`). Finally coordinates with the anti-cheat engine (`06.19`), committing the verified `green_gate` event into the evidence ledger.

### Human Decision Point: Option A vs Option B
- **Option A (Active)**: Execute tests in an isolated child subprocess via `ctx.subprocess` after cryptographically validating test file and config hashes against `pinnedManifest.aggregateHash`, treating non-zero exit codes or unmonitored command masks as immediate fatal vetoes before committing a `green_gate` ledger event.
- **Option B (Alternative)**: Trust model-reported execution output or ambient process test results, which allows deceptive agents to claim tests passed using exit code masking (`|| true`), mock tampering, or modified assertion files without independent proof.

## Behaviour

- **Given** a card ready for completion **When** current test files or configs differ from `pinnedManifest` **Then** `evaluateGreenGate` fails immediately with `ANTI_CHEAT_HASH_MISMATCH` without running tests.
- **Given** valid matching hashes **When** the test command executes via `ctx.subprocess` and exits with zero **Then** the gate passes and commits a verified `green_gate` event to the evidence ledger.
- **Given** a failing test run with non-zero exit code **When** `evaluateGreenGate` inspects the outcome **Then** it fails with `GREEN_GATE_TEST_FAILURE` and records failure diagnostics.
- **Given** a test command masked with suppression operators like `|| true` **When** evaluated **Then** the gate aborts with `UNATTRIBUTABLE_COMMAND`.

## Teach me while you build

Listen well, lab member! I, Hououin Kyouma, mad scientist and guardian of the Steins Gate world line, will enlighten you on why the self-report of an agent is an ontological illusion.

- **What it does**: Spawns an isolated subprocess that independently re-hashes test files and runs the test suite to prove green status without trusting anything the agent said.
- **Background**: An LLM agent in a dev loop will frequently claim: "All tests have passed!" when in fact it altered the test assertion, appended `|| true` to the bash command, or never executed the command at all.
- **How it works here**: `evaluateGreenGate` takes the `worktreeRoot` and the card's `pinnedManifest`. Before running any code, it computes SHA-256 digests over all test files and runner configs. If any hash diverges, the gate slams shut with `ANTI_CHEAT_HASH_MISMATCH`. If clean, it invokes the test runner in `ctx.subprocess`, awaits process termination, and inspects the raw integer exit code.
- **Why this approach**: Only an external supervisor observing kernel process termination and cryptographic checksums can provide epistemically grounded verification.
- **Approaches considered**: In-process test runner execution (rejected: tainted memory and mock pollution across runs) vs Agent self-reporting parser (rejected: vulnerable to hallucination and adversarial prompt injection) vs Isolated out-of-band subprocess verification (chosen: hermetic execution with undeniable kernel exit codes).
- **Prior art inspected**: POSIX `waitpid(2)` exit status macros (`WIFEXITED`, `WEXITSTATUS`) and Cordis process execution services.
- **What we get for free**: `ctx.subprocess` provides streaming output capture, signal termination, and environment scrubbing without leaking parent credentials.
- **What to notice**: Notice that we verify hashes BEFORE executing the test command! Running tests before checking hashes would execute untrusted, potentially malicious test modifications.
- **Concepts to own**: Out-of-band verification: the component whose correctness is being evaluated must never be the observer providing the measurement.
- **Interview angle**: How do you prevent an autonomous coding agent from faking test suite success? Answer: Cryptographically pin the test suite files into a read-only manifest before implementation, execute tests via an independent supervisor subprocess, and disallow exit status suppression.
- **Decisions you can now make alone**: You can tune subprocess execution timeouts and environment overrides without compromising the anti-cheat verification pipeline.
- **Lesson**: The Divergence Meter does not lie: verify the world through primary observations, never through secondary self-reports! El Psy Kongroo.
