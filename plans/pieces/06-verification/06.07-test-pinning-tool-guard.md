# 06.07 — Monotonic Implementer Test Pinning Tool Guard (INV-13)

**Set:** 06-verification · **Queue:** 7 · **Depends on:** `06.01`, `06.05`
**Status:** todo
**Harness primitive:** event/hook plugin · **Package:** `@deepseek-ai/dsh-guard-test-pinning`

## Summary

Registers an agent-scoped monotonic tool guard on `ctx.tools.guard()` executing inside `ToolRuntime.stagePreExecuteAndGuards` (`packages/core/tools/src/index.ts:1476-1488`). Synchronously inspects file mutation tools (`writeText`, `editText`, `patch`, etc.) proposed during implementer turns. Resolves target paths and cross-references them against the card's cryptographically pinned test files and runner configs (`INV-13`). Returns an immutable denial reason string that aborts execution immediately before dispatch, ensuring implementers can only modify production code.

## Behaviour

- **Given** an implementer session **When** `@deepseek-ai/dsh-guard-test-pinning` mounts **Then** `ctx.tools.guard()` registers on the agent context layer.
- **Given** an implementer proposing `writeText` targeting `src/feature.ts` **When** the guard evaluates **Then** it returns `undefined` and tool execution proceeds normally.
- **Given** an implementer proposing `writeText` or `editText` targeting `tests/auth.spec.ts` **When** the guard evaluates **Then** it returns a denial reason string citing `INV-13` and the pinned hash.
- **Given** a denial string returned from the guard **When** `stagePreExecuteAndGuards` executes **Then** it short-circuits with `isError: true` and the tool body is never dispatched.
- **Given** an implementer attempting to modify `vitest.config.ts` or `tsconfig.json` **When** the guard evaluates **Then** it rejects the tool call as configuration tampering.
- **Given** a BDD test writer session **When** active **Then** the implementer guard is absent from its scoped layer, permitting test creation.

## Harness fit

This is an `event/hook plugin` primitive owned by `@deepseek-ai/dsh-guard-test-pinning`. It hooks the agent-scoped `ctx.tools.guard()` rather than the host-global `tools/pre-execute` waterfall. Quoting `packages/core/tools/src/index.ts:1476-1488`, `this.guardReason(exec)` runs after user approvals and returns a monotonic rejection string: once denied, no downstream listener or approval prompt can override it, mechanically locking pinned tests (`INV-13`).
