# 06.02 — Verification Storage Domain and Retention Pruner

**Set:** 06-verification · **Queue:** 2 · **Depends on:** `06.01`
**Status:** todo
**Harness primitive:** Service Provider · **Package:** `@deepseek-ai/dsh-verification-store`

## Summary

Implements the verification evidence persistence domain using `ctx.storageDomain` across `events`, `state`, and `manifests` tables, enforcing schema validation via Zod and `VERIFICATION_DOMAIN_VERSION = 1`. Provides zero-latency synchronous in-memory reads and sequential write-chain durability, eliminating bespoke SQLite database boilerplate. Integrates automatic evidence retention pruning, capping records per `(sessionId, root)` at 100, deleting records older than 30 days, and clamping output summaries to 2,000 characters.

## Behaviour

- **Given** a Cordis context with `storageDomain` **When** `openVerificationDomain` is called **Then** tables `events`, `state`, and `manifests` open with schema validation.
- **Given** an incompatible stored version on disk **When** opening the domain **Then** it rejects immediately with `DomainError('version-mismatch')`.
- **Given** a new verification record **When** `eventsTable.put()` runs **Then** medium durability occurs before in-memory state mutation and `domain/changed` emits.
- **Given** more than 100 events recorded for a session root **When** `pruneLedger` runs **Then** events beyond the newest 100 are deleted from durable storage.
- **Given** verification events older than 30 days **When** `pruneLedger` runs **Then** expired records are removed from the domain table.
- **Given** an output summary exceeding 2,000 characters **When** prepared for insertion **Then** it is clamped to 2,000 characters with a truncation marker.
- **Given** an open domain handle **When** the Cordis context disposes **Then** `domain.close()` runs via registered `ctx.effect` disposer.

## Harness fit

This is a `Service Provider` primitive owned by `@deepseek-ai/dsh-verification-store`. It fulfills Plan 09 (§2.2 Option (a)), reusing `ctx.storageDomain` (`packages/storage/storage-domain/src/index.ts:1-50`) instead of maintaining a bespoke SQLite database. Backed by the configured repository backend (`packages/storage/storage-sqlite`), it provides synchronous in-memory `get()` lookups for turn-stopping gates while guaranteeing sequential write-chain durability without SQLite transaction contention.

## Contracts

```typescript
import { z } from 'zod'
import { defineDomain, domainTable, type KvTable, type DomainHandle } from '@deepseek-ai/dsh-storage-domain'
import type { VerificationEvent, VerificationState, PinnedSuiteManifest } from '@deepseek-ai/dsh-verification'

export const VERIFICATION_DOMAIN_VERSION = 1

export const verificationEventSchema = z.object({
  id: z.number(),
  createdAt: z.string(),
  sessionId: z.string(),
  cwd: z.string(),
  root: z.string(),
  command: z.string(),
  canonicalCommand: z.string(),
  kind: z.enum(['test', 'typecheck', 'lint', 'build', 'format', 'red_gate', 'green_gate']),
  scope: z.enum(['workspace', 'package', 'file', 'ad_hoc']),
  status: z.enum(['passed', 'failed', 'error']),
  exitCode: z.number(),
  outputSummary: z.string(),
  metadata: z.record(z.unknown()).optional(),
})

export const verificationStateSchema = z.object({
  sessionId: z.string(),
  root: z.string(),
  lastEventId: z.number().optional(),
  lastEditAt: z.string().optional(),
  changedPaths: z.array(z.string()),
})

export const pinnedSuiteManifestSchema = z.object({
  cardId: z.string(),
  baseCommit: z.string(),
  pinnedAt: z.string(),
  aggregateHash: z.string(),
  files: z.record(z.string()),
  testRunnerConfigs: z.record(z.string()),
})

export const verificationDomainSpec = defineDomain({
  name: 'verification',
  version: VERIFICATION_DOMAIN_VERSION,
  tables: {
    events: domainTable<string, VerificationEvent>(verificationEventSchema as any),
    state: domainTable<string, VerificationState>(verificationStateSchema as any),
    manifests: domainTable<string, PinnedSuiteManifest>(pinnedSuiteManifestSchema as any),
  },
})

export interface VerificationStoreConfig {
  maxEventsPerSessionRoot: number
  maxEventAgeDays: number
  maxOutputSummaryChars: number
}

export interface VerificationDomainHandles {
  readonly domain: DomainHandle
  readonly events: KvTable<string, VerificationEvent>
  readonly state: KvTable<string, VerificationState>
  readonly manifests: KvTable<string, PinnedSuiteManifest>
}

export function clampOutputSummary(summary: string, maxChars = 2000): string
export function pruneLedger(handles: VerificationDomainHandles, config: VerificationStoreConfig): Promise<number>
export function openVerificationDomain(ctx: Context): Promise<VerificationDomainHandles>
```
