# 06.08 — Physical Filesystem Read-Only Permissions Synchronizer

**Set:** 06-verification · **Queue:** 8 · **Depends on:** `06.01`, `06.05`
**Status:** todo
**Harness primitive:** workflow capability · **Package:** `@deepseek-ai/dsh-verification-permissions`

## Summary

Applies kernel-level filesystem write protections (`chmod 0o444` to test files and `chmod 0o555` to parent test directories) to cryptographically pinned test suites and runner configs within the worker's Git worktree. Provides defense-in-depth against direct subprocess writes, shell redirects (`> tests/unit.spec.ts`), sed/awk mutations, and non-tool filesystem edits during implementer turns. Restores permissions on session teardown or when transferring custody back to authorized test writer roles.

## Behaviour

- **Given** a pinned test suite manifest **When** `lockFilesystemPermissions` runs **Then** target files receive `0o444` read-only mode and parent directories receive `0o555`.
- **Given** pinned test files with `0o444` mode **When** a shell command attempts direct redirection (`cat > tests/spec.ts`) **Then** the kernel rejects the write with `EACCES (Permission denied)`.
- **Given** locked filesystem paths **When** `unlockFilesystemPermissions` is called **Then** files restore `0o644` writable mode and directories restore `0o755`.
- **Given** a Windows environment **When** locking permissions **Then** files are marked read-only via Windows filesystem attribute APIs (`fs.chmod` or `attrib +r`).
- **Given** a failure midway through permission locking **When** an error occurs **Then** any previously modified paths roll back to their original permission snapshots.

## Harness fit

This is a `workflow capability` primitive owned by `@deepseek-ai/dsh-verification-permissions`. While `06.07` intercepts model tool calls, autonomous agents with shell or terminal access could theoretically bypass tool guards using shell commands (`cat > tests/...`). Physical permission locking provides mechanical kernel-level defense-in-depth, strictly enforcing read-only status on disk.

## Contracts

```typescript
import type { PinnedSuiteManifest } from '@deepseek-ai/dsh-verification'

export interface FilePermissionEntry {
  readonly path: string
  readonly originalMode: number
  readonly isDirectory: boolean
}

export interface FilePermissionSnapshot {
  readonly worktreeRoot: string
  readonly cardId: string
  readonly lockedAt: string
  readonly entries: readonly FilePermissionEntry[]
}

/** Applies read-only permissions (0o444 / 0o555) to all files and configs in manifest. */
export function lockFilesystemPermissions(
  worktreeRoot: string,
  manifest: PinnedSuiteManifest,
): Promise<FilePermissionSnapshot>

/** Restores original permission bits recorded in the snapshot. */
export function unlockFilesystemPermissions(
  snapshot: FilePermissionSnapshot,
): Promise<void>

/** Verifies that all files in manifest currently hold read-only permission bits. */
export function verifyPermissionsLocked(
  worktreeRoot: string,
  manifest: PinnedSuiteManifest,
): Promise<boolean>
```
