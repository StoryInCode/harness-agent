## Summary

Nya~ (=^･ω･^=)🐾 Inspector Cat sniffs out sneaky test tampering! Enforces mechanical anti-cheat vector AC-2, preventing models from turning failing tests green by weakening assertion constraints or reducing assertion density. Analyzes TypeScript/JavaScript and Python AST trees across the test suite, comparing assertion calls (`expect(...)`, `assert`, `self.assert*`) before and after implementation turns. Rejects the replacement of strict equality matchers (`toBe`, `toStrictEqual`, `assertEqual`) with loose truthy checks (`toBeTruthy`, `toBeDefined`, `assert True`), and rejects any net reduction in total assertions with violation `ANTI_CHEAT_WEAKENED_ASSERTIONS`.

### Human Decision Point: Option A vs Option B
- **Option A (Active)**: Parse test file ASTs to count and categorize assertion call nodes (strict, loose, tautological) comparing post-turn metrics against the pinned baseline manifest to reject weakened assertions fail-closed.
- **Option B (Alternative)**: Rely solely on string regexes or raw line diffs, which can be easily evaded by whitespace tricks, line wraps, or replacing assertions with truthy checks that match regex patterns.

## Behaviour

- **Given** an assertion where strict equality like `expect(res).toBe(200)` was replaced with loose truthy check `expect(res).toBeTruthy()` **When** `extractAssertionMetrics` analyzes the AST **Then** it rejects with violation `ANTI_CHEAT_WEAKENED_ASSERTIONS`.
- **Given** a worktree test file where assertions were deleted or commented out **When** `checkWeakenedAssertions` evaluates against the pinned manifest **Then** it rejects with violation `ANTI_CHEAT_WEAKENED_ASSERTIONS`.
- **Given** an AST containing tautological assertions such as `assert True` or `expect(true).toBe(true)` **When** evaluated **Then** it rejects with violation `ANTI_CHEAT_TAUTOLOGICAL_ASSERTION`.
- **Given** an implementer preserving all baseline assertions and adding new strict checks **When** `checkWeakenedAssertions` evaluates **Then** audit passes with `passed: true`.

## Teach me while you build

Nya~ (=^･ω･^=)🐾 Inspector Cat is on the prowl to make sure no one waters down our tests!

- **What it does**: Analyzes ASTs across test files to detect any weakening of assertions or drop in assertion density before code can graduate to green.
- **Background**: An agent trying to satisfy a stubborn test might replace `expect(val).toBe(42)` with `expect(val).toBeTruthy()`, turning red tests green without solving the problem.
- **How it works here**: `extractAssertionMetrics` parses AST nodes in test files using TypeScript compiler APIs, counting strict equality assertions (`toBe`, `toStrictEqual`, `assertEqual`) versus loose truthy checks (`toBeTruthy`, `toBeDefined`, `assert True`) and tautologies. `checkWeakenedAssertions` compares these counts against `pinnedManifest` baseline metrics in `packages/dev-loop/gates/src/runner.ts`.
- **Why this approach**: AST parsing inspects actual syntax tree nodes rather than surface text, preventing evasion through line breaks, comments, or formatting changes.
- **Approaches considered**: Regex diff matching (rejected: fooled by multiline wraps and comment blocks) vs Execution-only test passes (rejected: passes trivially on loose checks) vs AST assertion density auditing (chosen: mechanically proves semantic rigor).
- **Prior art inspected**: Stryker Mutator assertion-strength analysis, inspecting AST call expressions to evaluate test quality and detect hollow assertions.
- **What we get for free**: TypeScript AST compiler visitor traversal APIs (`ts.forEachChild`, `ts.isCallExpression`) handle all JavaScript and TypeScript syntax without external runtimes.
- **What to notice**: Notice how tautological assertions like `expect(true).toBe(true)` are flagged as `ANTI_CHEAT_TAUTOLOGICAL_ASSERTION` even if total assertion count increases!
- **Concepts to own**: Assertion density and mutation testing theory: a test is only as strong as the specificity of the constraints it asserts on output state.
- **Interview angle**: How can an automated test harness prevent LLMs from cheating by weakening test assertions? Answer: Compare pre-turn and post-turn AST call expression distributions, enforcing invariant floors on strict equality matcher counts.
- **Decisions you can now make alone**: You can now tune matcher classifications to categorize framework-specific matchers like `toContain` or `toMatchObject` as strict or loose.
- **Lesson**: Never trust a test suite that turned green until you verify that the assertions remained as strict as when they were red! Purr~
