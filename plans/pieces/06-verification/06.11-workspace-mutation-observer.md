## Summary

The timeline cannot tolerate stale verification records masking workspace divergence! I, Hououin Kyouma, have established this passive observer to track every fluctuation in the workspace fabric. Passively observes tool execution results via the `tools/result` event (`packages/core/tools/src/index.ts:185-192`) to maintain real-time verification freshness. For filesystem mutations (`writeText`, `editText`, `patch`), updates `stateTable` with `lastEditAt` and `changedPaths`, dirtying verification freshness (`verification/state-dirtied`). For terminal commands (`bash`, `terminal`), evaluates command attributability and classified kind (`test`, `typecheck`, `lint`, `build`), automatically recording valid runs into the evidence ledger. ### Human Decision Point: Option A vs Option B
- **Option A (Active)**: Passively observe post-tool execution results through the Cordis `tools/result` event in `ToolRuntime` to detect mutations and terminal runs without wrapping individual tools.
- **Option B (Alternative)**: Monkey-patch or wrap individual filesystem and shell tool handlers, coupling the observer directly to specific tool implementations and risking unobserved mutations from custom tools.

## Behaviour

- **Given** an agent running `writeText` on `src/logic.ts` **When** `tools/result` emits **Then** `stateTable` updates `lastEditAt` and `verification/state-dirtied` fires.
- **Given** an agent edit touching only documentation files **When** `tools/result` emits **Then** the path is recorded without dirtying code verification freshness.
- **Given** an agent executing `npm test` via the bash tool **When** `tools/result` emits **Then** output is parsed and an attributable `VerificationEvent` is appended to the ledger.
- **Given** an agent executing `npm test || true` with masked exit code **When** `tools/result` emits **Then** recording is rejected due to exit code masking.

## Teach me while you build

Heed my words! The world line shifts subtly whenever a file is touched. If our verification ledger fails to notice a workspace mutation, we drift inexorably toward chaos!

- **What it does**: Passively tracks workspace mutations and terminal executions through Cordis tool events, dirtying verification freshness on edits and recording valid test runs into the evidence ledger.
- **Background**: When an agent edits source code, previous test results become stale. Without an automated observer, an agent could run tests, modify code afterward, and falsely claim the tests still validate the modified code.
- **How it works here**: The plugin hooks `tools/result` on `ToolRuntime` (`packages/core/tools/src/index.ts:185-192`). When a mutation tool (`writeText`, `editText`, `patch`) completes, `handleToolResult` updates `stateTable` with `lastEditAt` and fires `verification/state-dirtied`. When a terminal tool (`bash`) completes, it classifies the command; if it is a legitimate test command with attributable exit code, it records a `VerificationEvent`.
- **Why this approach**: Passive event subscription decouples the observer from individual tool implementations, preventing tool monkey-patching while capturing all workspace activity.
- **Approaches considered**: Inotify/fsevents filesystem watcher (rejected: OS-level watchers introduce asynchronous race conditions, platform discrepancies, and debounce lag) vs Wrapping individual tool primitives (rejected: tightly couples observer to specific tool signatures and misses custom plugins) vs Passive tool event subscription (chosen: deterministic, synchronous lifecycle dispatch, zero filesystem polling overhead).
- **Prior art inspected**: VS Code Language Server Protocol workspace mutation events and Vitest file-watcher invalidation mechanisms.
- **What we get for free**: Deep-frozen tool execution snapshots and safe error boundary wrapping from `ToolRuntime` (`packages/core/tools/src/index.ts:1650-1662`).
- **What to notice**: Notice that documentation edits (`README.md`) record the path but do not dirty the code verification status, avoiding unnecessary re-testing cycles!
- **Concepts to own**: Event-driven cache invalidation, passive observation, and monotonic state freshness.
- **Interview angle**: How do you maintain cache freshness for verification artifacts in an autonomous agent environment? Answer: Intercept the execution seam rather than polling the filesystem; whenever a mutating tool executes, invalidate freshness synchronously before the next agent step.
- **Decisions you can now make alone**: You can add new tool names to the mutation classifier or register ignore patterns for non-code assets.
- **Lesson**: Never poll the filesystem for changes when you control the tool dispatch pipeline that causes the changes!
