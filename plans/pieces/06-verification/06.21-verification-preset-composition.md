## Summary

Composes the verification subsystem into the DeepSeek Harness runtime environment across the Host Plane and Agent Plane. Configures the host bundle via `packages/bundle/base/cordis.patch.yml` routing `verification: sqlite` to the shared backend and mounting `VerificationService` (`06.20`). Mounts agent plugins into worker preset configurations without isolate realms, installing the monotonic test pinning guard (`06.07`) and turn-stopping verification interceptor (`06.10`) inside worker sessions.

### Human Decision Point: Option A vs Option B
- **Option A (Active)**: Mount the host verification service singleton on the Host Plane in `cordis.patch.yml` and register agent-scoped tool guards in worker presets without isolate realms, letting workers resolve host services while strictly enforcing test invariants.
- **Option B (Alternative)**: Mount the verification service inside worker presets under isolate realms or hardcode guards in the agent loop, causing service resolution failures and preventing workers from accessing shared host databases.

## Behaviour

- **Given** the base host bundle **When** launched with `packages/bundle/base/cordis.patch.yml` **Then** `storageDomain` configures the verification route and `VerificationService` registers on the host container.
- **Given** a worker subagent spawning in `dev-loop-worker` preset **When** initialized **Then** `guard-test-pinning` and `verification-stop` mount in the agent's scoped context without isolate realms.
- **Given** an implementer attempting to mutate pinned tests **When** running inside the worker preset **Then** the pinning guard synchronously vetoes the tool call.
- **Given** an orchestrator or test writer preset **When** spawning **Then** `guard-test-pinning` is not mounted, permitting test creation.

## Harness fit

This is a `patch layer` primitive owned by `@deepseek-ai/dsh-verification-presets`. It adheres to Harness plane separation rules (`plans/REVIEW-contracts.md`). The host service provider mounts in `packages/bundle/base/cordis.patch.yml` on the Host Plane, while scoped plugins mount in worker presets on the Agent Plane without isolate realms, ensuring worker sessions resolve host services while remaining constrained by scoped guards.

## Teach me while you build

Tutturu~ ♪ Mayuri is back to make sure all the lovely dresses fit just right without any uncomfortable seams!

- **What it does**: Weaves our verification service into the host patch layer and pins the guardian tools onto worker presets so everyone can work safely and happily!
- **Background**: Cordis separates the world into the Host Plane (shared process singletons like storage and subprocesses) and the Agent Plane (per-session tools, personas, and prompts). If you mix them up, services leak or subagents get locked out from their parent's tools.
- **How it works here**: In `packages/bundle/base/cordis.patch.yml`, we mount `VerificationService` on the root container with its SQLite domain route. In worker presets, we add `guard-test-pinning` and `verification-stop` as tool and hook rows without `isolate` realms, so they protect workers while still reaching the host `ctx.verification`!
- **Why this approach**: Keeps heavy singletons on the Host Plane where they belong, while allowing per-session agents to inherit tool guards without breaking Cordis service resolution.
- **Approaches considered**: Embedding verification services inside agent presets (rejected: violates preset rules and leaks global services), putting presets in isolate realms (rejected: cuts off access to host services like `ctx.kanban`), and clean patch-layer plus preset separation (chosen: standard Cordis architecture).
- **Prior art inspected**: Cordis patch layer conventions and preset mounting rules in `packages/preset/agent-presets/src/mount.ts`.
- **What we get for free**: Automated preset validation from `mountPreset` that prevents leaked services or inactive rows from booting.
- **What to notice**: Scoped tool guards do not provide a `Service`, so they need no `isolate` realm and seamlessly protect tool execution.
- **Concepts to own**: Plane separation in Cordis: host composition holds infrastructure singletons, while presets configure agent-facing tools and prompts.
- **Interview angle**: How do you enforce security guards on agent sessions in a plugin architecture without duplicating service singletons? Answer: Mount the singleton service on the host plane, and register lightweight guard hooks on the agent-scoped session context.
- **Decisions you can now make alone**: You can tune protected path globs or verification stop attempt limits in worker preset configs without touching host infrastructure.
- **Lesson**: When everyone has the right place at the workbench, our code stays safe and our tests never get bumped! Tutturu~ ♪
