This micro-gate establishes the abstract `VerificationStore` service extending `@deepseek-ai/cordis.Service` and binds `ctx.verification` to the Cordis container. El Psy Kongroo.

### Human Decision Point: Option A vs Option B
- **Option A (Active)**: Define an abstract `VerificationStore` service on the Cordis host plane with branded nominal IDs and typed event streams, decoupling gate consumers from storage engines.
- **Option B (Alternative)**: Couple gate evaluation directly to concrete SQLite tables and subprocess execution, making verification logic unpluggable and difficult to mock during isolated unit testing.

## Behaviour

- **Given** the Cordis root container **When** `@deepseek-ai/dsh-verification` is loaded **Then** `ctx.verification` resolves as an instance of `VerificationStore`.
- **Given** a positive integer **When** `asVerificationEventId` is invoked **Then** it returns a branded `VerificationEventId`.
- **Given** a non-integer or negative number **When** `asVerificationEventId` is invoked **Then** it throws a descriptive `TypeError`.
- **Given** an active `VerificationStore` **When** verification events or gate executions complete **Then** typed events (`verification/event-recorded`, `verification/red-gate`, `verification/green-gate`) dispatch on the Cordis event bus.

## Harness fit

This is a `Service Definition` primitive owned by `@deepseek-ai/dsh-verification`. It declares the abstract `VerificationStore` interface and merges `interface Context { verification: VerificationStore }` into Cordis (`packages/core/tools/src/index.ts:129-140`). Isolating domain contracts from concrete storage and execution engines allows downstream modules to bind to pure interfaces without coupling to storage engines or subprocess runners.

## Contracts

```typescript
export type VerificationEventId = number & { readonly __brand: unique symbol }
export type VerificationKind = 'test' | 'typecheck' | 'lint' | 'build' | 'format' | 'red_gate' | 'green_gate'
export type VerificationScope = 'workspace' | 'package' | 'file' | 'ad_hoc'
export type VerificationStatus = 'passed' | 'failed' | 'error'

export interface VerificationEvent {
  readonly id: VerificationEventId
  readonly createdAt: string
  readonly sessionId: string
  readonly cwd: string
  readonly root: string
  readonly command: string
  readonly canonicalCommand: string
  readonly kind: VerificationKind
  readonly scope: VerificationScope
  readonly status: VerificationStatus
  readonly exitCode: number
  readonly outputSummary: string
  readonly metadata?: Readonly<Record<string, unknown>> | undefined
}

export interface VerificationState {
  readonly sessionId: string
  readonly root: string
  readonly lastEventId?: VerificationEventId | undefined
  readonly lastEditAt?: string | undefined
  readonly changedPaths: readonly string[]
}

export interface WorkspaceVerificationStatus {
  readonly status: 'passed' | 'failed' | 'stale' | 'unverified'
  readonly latestEvent?: VerificationEvent | undefined
  readonly unverifiedChanges: readonly string[]
}

export interface PinnedSuiteManifest {
  readonly cardId: string
  readonly baseCommit: string
  readonly pinnedAt: string
  readonly aggregateHash: string
  readonly files: Readonly<Record<string, string>>
  readonly testRunnerConfigs: Readonly<Record<string, string>>
}

export type RedGateFailureClassification =
  | 'EXPECTED_ASSERTION_FAILURE'
  | 'EXPECTED_MISSING_SYMBOL'
  | 'EXPECTED_NOT_IMPLEMENTED'
  | 'SETUP_SYNTAX_ERROR'
  | 'SETUP_IMPORT_ERROR'
  | 'SETUP_HARNESS_ERROR'
  | 'SETUP_ZERO_TESTS'
  | 'UNEXPECTED_PASS'

export interface RedGateVerificationRequest {
  readonly cardId: string
  readonly worktreeRoot: string
  readonly baseCommit: string
  readonly testCommand: string
  readonly testGlobs: readonly string[]
  readonly configGlobs?: readonly string[] | undefined
  readonly signal?: AbortSignal | undefined
}

export interface RedGateVerificationResult {
  readonly passed: boolean
  readonly classification: RedGateFailureClassification
  readonly exitCode: number
  readonly outputSummary: string
  readonly manifest?: PinnedSuiteManifest | undefined
  readonly eventId?: VerificationEventId | undefined
  readonly failureReason?: string | undefined
}

export interface GreenGateVerificationRequest {
  readonly cardId: string
  readonly worktreeRoot: string
  readonly testCommand: string
  readonly pinnedManifest: PinnedSuiteManifest
  readonly signal?: AbortSignal | undefined
}

export interface GreenGateVerificationResult {
  readonly passed: boolean
  readonly exitCode: number
  readonly hashMatch: boolean
  readonly outputSummary: string
  readonly eventId?: VerificationEventId | undefined
  readonly antiCheatViolations: readonly string[]
}

export abstract class VerificationStore extends Service {
  constructor(ctx: Context) { super(ctx, 'verification') }
  abstract recordEvent(event: Omit<VerificationEvent, 'id' | 'createdAt'>): Promise<VerificationEvent>
  abstract getStatus(sessionId: string, cwd: string): Promise<WorkspaceVerificationStatus>
  abstract markWorkspaceEdited(sessionId: string, root: string, paths: readonly string[]): Promise<void>
  abstract isExitStatusAttributable(command: string): boolean
  abstract evaluateRedGate(request: RedGateVerificationRequest): Promise<RedGateVerificationResult>
  abstract evaluateGreenGate(request: GreenGateVerificationRequest): Promise<GreenGateVerificationResult>
  abstract getPinnedManifest(cardId: string): Promise<PinnedSuiteManifest | undefined>
}

declare module '@deepseek-ai/cordis' {
  interface Context { verification: VerificationStore }
  interface Events {
    'verification/event-recorded'(event: VerificationEvent): void
    'verification/red-gate'(result: RedGateVerificationResult): void
    'verification/green-gate'(result: GreenGateVerificationResult): void
    'verification/state-dirtied'(state: VerificationState): void
  }
}
```

## Teach me while you build

Listen well, my assistant! The divergence meter cannot move toward Steins Gate if we build on unstable ground!

- **What it does**: Defines the abstract `VerificationStore` service class and core domain contracts for attributable verification events and four-gate execution.
- **Background**: Verification in autonomous agent loops requires evidence-bound proof. Without strongly typed domain contracts, disparate workers corrupt the timeline with unverifiable status claims.
- **How it works here**: Declares `VerificationStore` extending Cordis `Service` in `@deepseek-ai/dsh-verification`. Downstream providers implement storage and gate execution while consumers rely purely on `ctx.verification`.
- **Why this approach**: Separating the service contract from the storage engine prevents vendor lock-in and allows mock implementations during isolated test execution.
- **Approaches considered**: Monolithic concrete class with embedded SQLite (rejected: impossible to unit test without disk I/O) vs Ad-hoc callback hooks (rejected: lacks type safety and lifecycle guarantees) vs Abstract Cordis Service (chosen: idiomatic harness architecture).
- **Prior art inspected**: Cordis `Service` architecture in `packages/core/tools/src/index.ts` and `packages/dev-loop/gates/src/index.ts`.
- **What we get for free**: Cordis manages singleton service registration, inversion of control, and type-safe event broadcasting across plugins.
- **What to notice**: Notice how `VerificationEventId` uses a nominal branding pattern to prevent raw number confusion with test run IDs or exit codes.
- **Concepts to own**: Interface segregation and nominal typing in TypeScript using unique symbol branding.
- **Interview angle**: Why declare abstract service interfaces in a separate package from their SQLite storage provider? Answer: It decouples interface contracts from database drivers, enabling parallel development, clean testing, and adherence to hexagonal architecture.
- **Decisions you can now make alone**: You can now define new gate result classifications or event payloads without altering underlying storage schemas.
- **Lesson**: An immutable domain contract is the first defense against chaotic entropy. El Psy Kongroo!
