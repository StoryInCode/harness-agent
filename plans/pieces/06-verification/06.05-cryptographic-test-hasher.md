# 06.05 — Cryptographic Test Suite Pinning and Manifest Generator (INV-13)

**Set:** 06-verification · **Queue:** 5 · **Depends on:** `06.01`
**Status:** todo
**Harness primitive:** workflow capability · **Package:** `@deepseek-ai/dsh-verification-hasher`

## Summary

Generates deterministic cryptographic manifests (`PinnedSuiteManifest`) freezing test suites and runner configurations into immutable SHA-256 digests (`INV-13`). Normalizes line endings (`\r\n` -> `\n`) and file paths before hashing to eliminate cross-platform variances across Windows, macOS, and Linux. Covers all test files and critical test runner configurations (`vitest.config.*`, `jest.config.*`, `tsconfig.json`, `pytest.ini`, `package.json` test scripts), producing an aggregate hash that serves as the cryptographic anchor for the implementer tool guard (`06.07`) and GREEN gate verification (`06.09`).

## Behaviour

- **Given** a worktree path and glob patterns **When** `pinTestSuite` runs **Then** SHA-256 digests are computed for all matching test files and runner configs.
- **Given** files containing CRLF line endings **When** hashed **Then** line endings are normalized to LF before digest calculation, ensuring deterministic results across operating systems.
- **Given** a set of relative file paths and SHA-256 hashes **When** `computeAggregateSuiteHash` runs **Then** paths are sorted lexicographically to produce an unforgeable aggregate digest.
- **Given** an existing `PinnedSuiteManifest` and current worktree files **When** `verifySuiteIntegrity` runs **Then** it reports `hashMatch: true` if unchanged, or an exact diff of modified, deleted, or added files.
- **Given** a single whitespace edit in `vitest.config.ts` **When** `verifySuiteIntegrity` runs **Then** it detects the discrepancy and flags configuration tampering.

## Harness fit

This is a `workflow capability` primitive owned by `@deepseek-ai/dsh-verification-hasher`. It implements the cryptographic hashing layer demanded by `INV-13` (`Spec §6.5`). By isolating deterministic hash computation into a dedicated utility, it provides an unforgeable, mathematical integrity anchor shared by the RED gate generator, the implementer tool guard, the anti-cheat engine, and the GREEN gate evaluator.

## Contracts

```typescript
import type { PinnedSuiteManifest } from '@deepseek-ai/dsh-verification'

export interface PinTestSuiteOptions {
  readonly cardId: string
  readonly worktreeRoot: string
  readonly baseCommit: string
  readonly testGlobs: readonly string[]
  readonly configGlobs?: readonly string[] | undefined
}

export interface HashIntegrityDiff {
  readonly modifiedFiles: readonly string[]
  readonly addedFiles: readonly string[]
  readonly deletedFiles: readonly string[]
  readonly modifiedConfigs: readonly string[]
}

export interface HashIntegrityResult {
  readonly hashMatch: boolean
  readonly currentAggregateHash: string
  readonly expectedAggregateHash: string
  readonly diff: HashIntegrityDiff
}

/** Computes SHA-256 hash of UTF-8 content with CRLF line ending normalization. */
export function computeContentHash(content: string | Buffer): string

/** Computes canonical aggregate SHA-256 hash over sorted relative paths and file digests. */
export function computeAggregateSuiteHash(
  files: Readonly<Record<string, string>>,
  configs: Readonly<Record<string, string>>,
): string

/** Scans worktree, hashes test files and runner configs, returning an immutable manifest. */
export function pinTestSuite(options: PinTestSuiteOptions): Promise<PinnedSuiteManifest>

/** Compares existing pinned manifest against current worktree state on disk. */
export function verifySuiteIntegrity(
  manifest: PinnedSuiteManifest,
  worktreeRoot: string,
): Promise<HashIntegrityResult>
```
