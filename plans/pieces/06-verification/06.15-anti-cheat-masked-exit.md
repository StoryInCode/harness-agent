## Summary

Enforces mechanical anti-cheat vector AC-4 (`INV-11`), evaluating test command lines proposed or executed by workers to prevent suppressed failure exits. Bridges the attributable shell parser (`06.03`) into the verification gate pipeline. Analyzes command ASTs for compound conditional operators (`|| true`, `|| :`, `|| echo`), sequencing semicolons with exit overrides (`; exit 0`), unmonitored pipes (`|` without `pipefail`), subshell masks `(cmd) || true`, and background detachments (`&`). Rejects any masked command with violation `ANTI_CHEAT_MASKED_EXIT`.

### Human Decision Point: Option A vs Option B
- **Option A (Active)**: Parse shell command structure into an attributable AST and fail closed on any suppressed exit or unmonitored compound pipeline before subprocess spawn.
- **Option B (Alternative)**: Rely solely on the subprocess exit code observed at runtime, which allows sneaky workers to swallow test crashes using `|| true` or subshell wrappers.

## Behaviour

- **Given** an attributable command `pnpm vitest run` **When** `checkMaskedShellExit` evaluates **Then** it confirms attributable execution without violation.
- **Given** a compound command `npm test || true` **When** `checkMaskedShellExit` evaluates **Then** it rejects with violation `ANTI_CHEAT_MASKED_EXIT`.
- **Given** an exit override command `pytest ; exit 0` **When** `checkMaskedShellExit` evaluates **Then** it rejects with violation `ANTI_CHEAT_MASKED_EXIT`.
- **Given** an unmonitored pipeline `npm test | grep pass` without `pipefail` **When** `checkMaskedShellExit` evaluates **Then** it rejects with violation `ANTI_CHEAT_MASKED_EXIT`.

## Teach me while you build

Yo! Daru here. Time to make sure no shady subagent cheats our test runner with cheap shell parlor tricks.

- **What it does**: Inspects proposed shell test commands as an AST before spawning, blocking sneaky tricks like `|| true` or trailing `; exit 0`.
- **Background**: Exit codes in POSIX shells determine whether a command succeeded (0) or failed (non-zero). Rogue workers or lazy agents try to cheat verification gates by appending `|| true` or `; exit 0` to make failing tests look green.
- **How it works here**: Attributable command parsing lexes the command tokens into an AST in `packages/dev-loop/gates/src/runner.ts`. `checkMaskedShellExit` traverses operators, rejecting `||`, `;`, unmonitored pipes, and background `&` wrappers with violation `ANTI_CHEAT_MASKED_EXIT`.
- **Why this approach**: Validating shell syntax mechanically at the AST boundary fails fast before any subprocess spawns, adhering to `docs/defensive-patterns.md`.
- **Approaches considered**: Runtime exit-code observation alone (rejected: `|| true` returns 0 to the OS, hiding failures), regex string matching (rejected: fooled by quotes, comments, or whitespace variations), and static AST analysis (chosen: deterministic syntax inspection).
- **Prior art inspected**: POSIX Shell Command Language IEEE Std 1003.1 exit status conventions and defensive subprocess handling in `docs/defensive-patterns.md`.
- **What we get for free**: Subprocess exit code capture primitives and Cordis service orchestration across package boundaries.
- **What to notice**: Even if `pipefail` is omitted, piping test runners to `grep pass` discards non-zero exit codes; we require attributable pipelines.
- **Concepts to own**: Attributable execution and fail-closed syntax admission: untrusted command strings must be proven safe before execution.
- **Interview angle**: How do you prevent untrusted CLI automation from suppressing non-zero exit codes? Answer: Parse the command grammar into an AST before execution and forbid masking control operators.
- **Decisions you can now make alone**: You can add new forbidden shell operators (like `&>` redirection or trap masks) without changing the gate evaluation pipeline.
- **Lesson**: Never trust a process exit code if the shell command was allowed to redefine its own return value.
