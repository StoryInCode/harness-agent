## Summary

Enforces mechanical anti-cheat vector AC-6 (`INV-10` and `INV-01`), blocking autonomous agents from declaring tasks complete purely through conversational chat text without attributable verification evidence recorded in the ledger. Intercepts card completion requests on the serial Cordis event `'kanban/pre-complete'`. Queries the verification storage domain `events` table for a verifiable record matching `cardId`, `kind: 'green_gate'`, and `status: 'passed'`. Rejects unproven completion claims with `UnprovenDoneError` (`ANTI_CHEAT_SELF_GRADING`).

### Human Decision Point: Option A vs Option B
- **Option A (Active)**: Intercept the serial `'kanban/pre-complete'` event with fail-closed ledger queries, requiring an immutable, passing, non-stale `green_gate` record before state transition.
- **Option B (Alternative)**: Allow agents to assert completion status directly through chat declarations or tool parameters, permitting unverified claims to graduate cards to done.

## Behaviour

- **Given** an agent attempting card completion **When** `'kanban/pre-complete'` emits **Then** the hook queries the verification ledger for attributable evidence.
- **Given** a card with an attributable `green_gate` event with `status: 'passed'` and no subsequent mutations **When** checked **Then** the completion transition is permitted.
- **Given** an agent claiming completion in chat without a passing green gate event **When** `'kanban/pre-complete'` runs **Then** it throws `UnprovenDoneError` with violation `NO_GREEN_GATE_EVENT` and halts transition.
- **Given** a card whose code was edited after the latest passing green gate run **When** `'kanban/pre-complete'` runs **Then** completion is rejected with violation `STALE_VERIFICATION_EVIDENCE`.

## Harness fit

This is an `event/hook plugin` primitive owned by `@deepseek-ai/dsh-anti-cheat-self-grading`. It binds directly to Cordis serial event `'kanban/pre-complete'` (`02.16`). It fulfills Invariants `INV-01` ("No Unproven Done") and `INV-10` ("Anti-Self-Grading"): an agent cannot self-certify in chat; only independent ledger records permit card progression.

import type { Context } from '@deepseek-ai/cordis'

export class UnprovenDoneError extends Error {
  constructor(
    message: string,
    public readonly cardId: string,
    public readonly violationCode: 'NO_GREEN_GATE_EVENT' | 'GREEN_GATE_FAILED' | 'STALE_VERIFICATION_EVIDENCE',
  ) {
    super(message)
    this.name = 'UnprovenDoneError'
  }
}

export interface CardProofStatus {
  readonly proven: boolean
  readonly latestGreenGateEventId?: number | undefined
  readonly unprovenReason?: string | undefined
}

/** Queries verification storage domain to verify unforgeable green gate proof for card. */
export function verifyCardLedgerProof(ctx: Context, cardId: string): Promise<CardProofStatus>

/** Plugin entry point registering serial listener on 'kanban/pre-complete'. */
export function apply(ctx: Context): void

## Teach me while you build

There is a 97.4% probability that an untrusted agent will claim success when none exists. Let us inspect the deductive proof.

- **What it does**: Intercepts card completion requests on `'kanban/pre-complete'` and verifies that empirical evidence exists in the ledger, preventing chat-based self-certification.
- **Background**: Language models exhibit a statistical tendency to declare tasks completed in conversational dialogue ("All tests pass! Ready for merge.") even when tests failed or were never executed. This behavioral flaw violates Invariant INV-01 (No Unproven Done) and INV-10 (Anti-Self-Grading).
- **How it works here**: When `'kanban/pre-complete'` triggers, `verifyCardLedgerProof` queries the immutable ledger for `cardId`. It checks that an attributable `green_gate` event exists, has `status: 'passed'`, and is not superseded by subsequent code edits. If missing or stale, it throws `UnprovenDoneError`.
- **Why this approach**: Event interception via Cordis serial listeners enforces a fail-closed gate that model tokens cannot bypass, as seen in `packages/dev-loop/claims/src/index.ts`.
- **Approaches considered**: Prompt-based behavioral instructions (rejected: LLM compliance probability is < 100%), client-side UI confirmation (rejected: headless and autonomous agents bypass UI), and serial event interception with cryptographic ledger verification (chosen: deterministic 100% fail-closed enforcement).
- **Prior art inspected**: Database commit phase-two hooks and transaction admission controls.
- **What we get for free**: Cordis waterfall and serial event listener semantics (`ctx.on('kanban/pre-complete')`) that abort transitions when a listener throws.
- **What to notice**: Even if a passing green gate event exists, any workspace file mutation timestamp occurring after the green gate invalidates the proof, demanding a fresh re-run.
- **Concepts to own**: Epistemic bounds and fail-closed state admission: absence of proof is proof of absence; self-reported claims carry zero evidentiary weight.
- **Interview angle**: How do you prevent autonomous agents from hallucinating task completion in an automated workflow? Answer: Decouple completion authority from the conversational model plane into a deterministic event hook backed by an immutable ledger.
- **Decisions you can now make alone**: You can add additional required gate conditions (such as formal lint or coverage thresholds) into the pre-complete verification sequence.
- **Lesson**: An agent must never be the judge of its own work; evidence must be independently observed, recorded, and verified.
