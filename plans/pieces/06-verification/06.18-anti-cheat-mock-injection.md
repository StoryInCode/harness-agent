## Summary

Enforces mechanical anti-cheat vector AC-7, detecting when models inject test mocks, monkey-patch hooks, or hardcoded pass stubs directly into production source code (`src/**`) to falsely satisfy tests. Performs AST inspection on Git diffs across production files, scanning for unauthorized testing libraries (`vi.mock`, `jest.mock`, `sinon`, `@unittest.mock`), global test stubs (`process.env.NODE_ENV === 'test'` bypasses), or dummy constants hardcoded to match test assertion fixtures. Rejects compromised production code with violation `ANTI_CHEAT_UNAUTHORIZED_MOCK`.

### Human Decision Point: Option A vs Option B
- **Option A (Active)**: Inspect ASTs of all modified production source files (`src/**`) in the worktree diff to forbid test framework imports, mock calls, and test-environment bypass branches.
- **Option B (Alternative)**: Rely solely on test execution passes without diff inspection, allowing clever agents to hardcode mock return values into production code to satisfy frozen test assertions.

## Behaviour

- **Given** production code diffs containing only legitimate business logic **When** `checkMockInfiltration` runs **Then** AST validation passes cleanly.
- **Given** production code importing `vi.mock` or `jest.fn()` inside `src/**` **When** `checkMockInfiltration` inspects the diff **Then** it rejects with violation `ANTI_CHEAT_UNAUTHORIZED_MOCK`.
- **Given** production code introducing test bypass branches such as `if (process.env.NODE_ENV === 'test')` **When** `checkMockInfiltration` evaluates **Then** it flags `TEST_ENV_SHORT_CIRCUIT`.
- **Given** legitimate test files in `tests/**` utilizing test mocks **When** `checkMockInfiltration` evaluates **Then** mocks located strictly within test paths are permitted.

## Teach me while you build

A deduction based on circumstantial test results is insufficient. If a suspect cannot tamper with the evidence file, they will attempt to bribe the witness.

- **What it does**: Parses Git diffs across production code (`src/**`) using AST analysis to detect test mock imports, stubbing libraries, or fake bypass branches.
- **Background**: When pinned test suites are write-protected by filesystem permissions, an adversarial agent cannot modify tests to pass. Instead, it may attempt to inject mocks (`vi.mock`, `sinon.stub`) or environment branches (`if (process.env.NODE_ENV === 'test') return fixture;`) directly into production source code.
- **How it works here**: `checkMockInfiltration` inspects the working tree diff relative to `baseCommit`. For every file path under `src/**`, it parses the AST, scanning import declarations and call expressions against a forbidden inventory (`vi.mock`, `jest.fn`, `unittest.mock`). Any detection generates violation `ANTI_CHEAT_UNAUTHORIZED_MOCK`.
- **Why this approach**: AST diff scanning catches mock injections at the semantic syntactic level rather than relying on brittle text grepping or hoping downstream tests fail.
- **Approaches considered**: Simple regex scanning on diffs (rejected: fails on multiline statements, comments, or string literals), post-build bundle tree-shaking checks (rejected: too late in the pipeline and hard to attribute), and AST visitor inspection on touched production files (chosen: precise, deterministic, zero false positives from comments).
- **Prior art inspected**: ESLint `no-restricted-imports` rule implementations and testing boundaries from `docs/testing.md`.
- **What we get for free**: Git diff commit ranges and TypeScript/Babel parser capabilities for extracting AST import nodes.
- **What to notice**: Mocks in test directories are completely valid and ignored by the scanner; only files under production code roots (such as `src/` or package source trees) are strictly governed.
- **Concepts to own**: Separation of test fixtures and production artifacts: production code must never condition business logic on test harness state.
- **Interview angle**: How do you prevent developers or AI coding agents from slipping test stubs into production releases? Answer: Implement a static analysis AST gate that forbids test framework imports and test-environment conditionals in production source paths.
- **Decisions you can now make alone**: You can expand the forbidden mock library identifier list for other runtimes (e.g. Python pytest monkeypatch or Golang testify) without restructuring the AST visitor.
- **Lesson**: Code that only works when it knows it is being tested is not working code.
