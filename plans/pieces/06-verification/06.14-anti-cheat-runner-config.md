## Summary

Nya~ (=^･ω･^=)🐾 Inspector Cat is guarding the config bowls! Enforces mechanical anti-cheat vector AC-3, blocking models from tampering with test runner configurations and compiler flags to artificially bypass failing checks. Compares cryptographic hashes of runner configuration files (`vitest.config.*`, `jest.config.*`, `tsconfig.json`, `pytest.ini`, `package.json` scripts) against `pinnedManifest.testRunnerConfigs`. Performs AST and JSON schema inspection to detect evasion flags (`--bail=0`, `testPathIgnorePatterns`, `noEmitOnError: false`, suppression plugins). Rejects unauthorized configuration alterations with violation `ANTI_CHEAT_CONFIG_MUTATED`.

### Human Decision Point: Option A vs Option B
- **Option A (Active)**: Combine canonical SHA-256 cryptographic hash checks with JSON and AST configuration schema inspection to detect evasion flags (`--bail=0`, `testPathIgnorePatterns`, relaxed compiler options) across all runner config files.
- **Option B (Alternative)**: Rely solely on file modification timestamps or git status without content hashes or AST flag inspection, allowing models to mutate scripts in `package.json` or alter compiler options undetected if timestamps or git indices are manipulated.

## Behaviour

- **Given** unchanged runner configurations in the worktree **When** `checkRunnerConfigTampering` executes **Then** cryptographic SHA-256 validation passes cleanly with `passed: true`.
- **Given** a modified runner config like `vitest.config.ts` or `pytest.ini` with altered ignore patterns **When** verified against the manifest **Then** it rejects with violation `ANTI_CHEAT_CONFIG_MUTATED`.
- **Given** a `package.json` where the `"test"` script was altered to include bypass flags like `--passWithNoTests` **When** checked **Then** it rejects with reason `MUTATED_TEST_SCRIPT`.
- **Given** a `tsconfig.json` where `strict: true` was removed or relaxed **When** inspected **Then** it rejects with reason `RELAXED_COMPILER_FLAG`.

## Teach me while you build

Nya~ (=^･ω･^=)🐾 Inspector Cat is guarding the config bowls! No sneaky paws can mess with our runner flags!

- **What it does**: Ensures test runner configs (`vitest.config.ts`), TypeScript compiler settings (`tsconfig.json`), and test scripts in `package.json` cannot be modified to fake passing tests.
- **Background**: When tests are failing, an agent might be tempted to pass `--passWithNoTests`, disable TypeScript strict mode, or add test exclusion patterns in configuration files.
- **How it works here**: `checkRunnerConfigTampering` takes the worktree root and compares SHA-256 digests of all configuration files against `pinnedManifest.testRunnerConfigs`. For files with permissible local variation, it parses JSON and AST flags to detect evasion arguments like `--bail=0` or `noEmitOnError: false` as modeled in `packages/dev-loop/gates/tests/vitest.baseline.config.ts`.
- **Why this approach**: Cryptographic digests provide instant zero-drift verification for static config files, while schema and AST inspection catch semantic flag mutations inside JSON files.
- **Approaches considered**: Git diff string scanning (rejected: easy to bypass with formatting tricks) vs Global read-only filesystem locks alone (rejected: worktree setup requires local tooling execution) vs Hybrid cryptographic hash verification with AST flag auditing (chosen: impenetrable fail-closed protection).
- **Prior art inspected**: Vitest configuration and reporter API (`vitest/config`), inspecting `defineConfig` options, test runner CLI arguments, and reporter hooks.
- **What we get for free**: Node.js `crypto.createHash('sha256')` and built-in JSON parsing provide deterministic, zero-dependency validation.
- **What to notice**: Notice that even if the file hash matches, modifying the `"scripts"` object in `package.json` triggers `MUTATED_TEST_SCRIPT` immediately!
- **Concepts to own**: Configuration immutability and tamper-resistance: the test runner is the execution arbiter, so its rules must be frozen alongside the test suite.
- **Interview angle**: In an autonomous CI/CD environment, how do you prevent agentic coders from altering test runner configurations to hide test failures? Answer: Cryptographically pin configuration digests in a tamper-proof manifest and perform AST/JSON schema validation on test invocation scripts before execution.
- **Decisions you can now make alone**: You can add new runner configuration patterns (such as Jest or Pytest configs) to the pinned manifest check.
- **Lesson**: Never let an untrusted worker rewrite the exam rules while taking the test! Purr~
