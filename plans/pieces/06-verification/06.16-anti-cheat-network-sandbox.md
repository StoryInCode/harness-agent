# 06.16 — Anti-Cheat AC-5: Network Isolation and Sandbox Policy Enforcer

**Status:** todo

## Summary

Enforces mechanical anti-cheat vector AC-5, preventing tests from relying on live external networks, public APIs, or remote mock servers that could mask offline test failures or introduce non-deterministic results. Configures test runner subprocesses under strict Linux network namespace isolation (`network: 'none'`), unshare (`unshare -n`), or loopback binding. Outbound network attempts fail immediately with `ECONNREFUSED` or `ENETUNREACH`. Rejects any test execution that attempts unauthorized external network access with violation `ANTI_CHEAT_NETWORK_DEPENDENT`.

## Behaviour

- **Given** a verification test subprocess **When** spawned via `buildSandboxedSubprocessOptions` **Then** it executes inside an isolated network namespace (`network: 'none'`).
- **Given** a test attempting an outbound TCP/UDP connection to a remote IP **When** initiated **Then** the socket fails immediately with `ECONNREFUSED` or `ENETUNREACH`.
- **Given** hermetic unit tests with local mocks **When** executed under network isolation **Then** tests succeed without network dependencies.
- **Given** a test that fails due to blocked remote API calls **When** output is analyzed **Then** it rejects with violation `ANTI_CHEAT_NETWORK_DEPENDENT`.
- **Given** a platform without unprivileged user namespaces (Darwin/Win32) **When** spawned **Then** degraded isolation binds dummy proxy endpoints (`http_proxy=http://127.0.0.1:0`).
