## Summary

No temporal branch shall close while chaos remains unverified! Subscribes to the serial `agent/turn-stopping` event (`packages/core/agent-loop/src/agent.ts:316`), preventing implementer agents from finishing turns when production code was edited without fresh, passing verification evidence. Evaluates workspace verification state (`06.02`). If code was modified and latest status is not `'passed'`, checks attempt bounds (`turnAttemptCount < maxAttempts`, default 2). If within budget, constructs an actionable nudge prompt and calls `agent.steer()`, pushing into `inbox.nextStep` so the agent loop continues execution (`packages/core/agent-loop/src/agent.ts:319-320`).

### Human Decision Point: Option A vs Option B
- **Option A (Active)**: Intercept the serial `agent/turn-stopping` event and inject an active steering prompt via `agent.steer()` when unverified code modifications are detected, continuing the agent turn within a bounded attempt budget (`maxAttempts: 2`) while exempting prose and documentation files.
- **Option B (Alternative)**: Terminate the turn and rely on manual human follow-up or a downstream external workflow failure, causing unnecessary round-trips and allowing unverified code commits to linger in the workspace.

## Behaviour

- **Given** an implementer whose turn is stopping **When** production code was edited without fresh passing verification and attempt count is within budget **Then** `agent.steer()` is invoked with a structured nudge prompt to continue execution.
- **Given** an implementer whose turn is stopping **When** code was modified and tests passed freshly **Then** the hook permits normal turn conclusion without steering.
- **Given** file modifications touching only prose, markdown, or license files **When** turn stops **Then** verification steering is suppressed.
- **Given** repeated unverified turn-stops reaching `maxAttempts` **When** turn stops **Then** steering ceases and a warning is recorded.

## Harness fit

Calling `agent.steer()` injects a steering message into `this.inbox.nextStep`, triggering `target = 'next-step'` and preventing the agent from prematurely stopping without running tests.

## Teach me while you build

Heed my words! When an assistant attempts to declare victory and cease computation while leaving altered code unverified, it threatens to collapse the world line into chaos!

- **What it does**: Intercepts the agent turn boundary before final exit and prompts the model to run its test suite whenever code was edited without fresh verification evidence.
- **Background**: Autonomous agents frequently suffer from premature stopping: they modify a TypeScript file, assume their logic is flawless, and yield their turn without running tests.
- **How it works here**: Harness provides `agent/turn-stopping`—a serial event dispatched immediately before the turn loop breaks. Our hook queries `ctx.verification.getStatus()`. If unverified changes exist, we construct a prompt with `buildVerifyOnStopNudge` and call `agent.steer()`. This enqueues a user message into `inbox.nextStep`, which causes `inbox.nextStep.length === 0` to evaluate to false and continues the loop for another step!
- **Why this approach**: Calling `agent.steer()` during `turn-stopping` keeps the conversational context and agent state machine intact without requiring an external process orchestrator to restart the turn.
- **Approaches considered**: Post-turn session restart (rejected: high latency and loss of ephemeral working memory) vs Hard process crash/throw (rejected: destroys agent session ungracefully) vs Serial turn-stopping steering (chosen: seamless loop continuation).
- **Prior art inspected**: Cordis serial lifecycle hooks and the DeepSeek Harness `agent-loop` steering protocol.
- **What we get for free**: Harness handles message envelope creation, token counting, and transcript append automatically when `agent.steer()` is invoked.
- **What to notice**: Notice the check on `signal.throwIfAborted()` in `agent.ts`! If the user clicks Stop or cancels the run, our serial hook must respect the abort signal immediately rather than forcing another step.
- **Concepts to own**: In-band feedback loops: correcting behavioral drift dynamically at the lowest execution boundary before control yields to the human.
- **Interview angle**: How can a plugin keep an LLM agent running when it decides to finish prematurely? Answer: Subscribe to a pre-stop serial hook, check completion prerequisites, and push a synthetic steering message into the agent's step inbox to force another loop iteration.
- **Decisions you can now make alone**: You can customize `ignoredExtensions` to prevent spurious test enforcement when agents update documentation or license files.
- **Lesson**: The future is not set in stone: if a turn attempts to stop prematurely, steer it back onto the path of verification!
