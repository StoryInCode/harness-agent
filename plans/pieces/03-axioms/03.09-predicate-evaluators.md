## Summary

Deterministic evaluation engine executing the 9 declarative predicate check types defined in Spec §2.5: filesystem predicates (`path_exists`, `path_absent`, `forbidden_directory`, `forbidden_file_pattern`), content predicates (`grep_absent`, `required_symbol`, `required_reference`, `max_lines`), and import predicates (`forbidden_import` AST inspection). Returns typed `CheckResult` objects recording execution time, pass/fail state, and diagnostic error output. Replaces subjective agent claims with objective ground truth.

## Behaviour

- **Given** a `path_exists` check for `src/index.ts` **When** the file exists on disk **Then** it returns `passed: true` with execution timing.
- **Given** a `grep_absent` check for `eval\(` **When** matching text exists in `src/calc.ts` **Then** it returns `passed: false` with the matching line content.
- **Given** a `forbidden_import` check targeting `lodash` **When** an ES import or `require('lodash')` exists in parsed AST **Then** it fails with the import AST node detail.
- **Given** a `max_lines` check with limit 160 on a 170-line file **When** evaluated **Then** it returns `passed: false` reporting actual line count.
- **Given** an unsupported predicate type **When** evaluated **Then** it returns `passed: false` with unsupported check error.

## Harness fit

This component is a `Service Provider` mounted on the host plane (`ctx.predicateEvaluator`), utilizing `ctx.fs` (`packages/fs/fs/src/index.ts:24-52`) and TypeScript AST inspection for import and content verification.

## Contracts

```typescript
import { Context, Service } from '@deepseek-ai/cordis'
import type { PredicateCheck } from '@deepseek-ai/dsh-axiom'

export interface CheckResult {
  readonly check: PredicateCheck
  readonly passed: boolean
  readonly exitCode?: number | null
  readonly stdout?: string
  readonly stderr?: string
  readonly message?: string
  readonly executionTimeMs: number
}

declare module '@deepseek-ai/cordis' {
  interface Context {
    predicateEvaluator: PredicateEvaluator
  }
}

export abstract class PredicateEvaluator extends Service {
  constructor(ctx: Context) {
    super(ctx, 'predicateEvaluator', true)
  }
  abstract evaluatePredicate(check: PredicateCheck, targetDir: string, signal?: AbortSignal): Promise<CheckResult>
  abstract evaluateBatch(checks: readonly PredicateCheck[], targetDir: string, signal?: AbortSignal): Promise<readonly CheckResult[]>
}
```

## Teach me while you build

- **Background**: Declarative predicates are check specifications (like "file must exist" or "symbol must not appear") described as data rather than arbitrary code, making them safe, portable, and fast to execute.
- **How it works here**: `ctx.predicateEvaluator.evaluatePredicate(check, targetDir)` switches on `check.type`. For filesystem checks (`path_exists`, `forbidden_file_pattern`), it queries `ctx.fs`. For content checks (`grep_absent`), it scans file lines. For `forbidden_import`, it parses the TypeScript AST to inspect `import` and `require` declarations. It returns a `CheckResult` with timing and pass/fail state. Open `packages/axiom/predicates/src/index.ts`.
- **Why this approach**: 9 declarative predicate evaluators. The simplest alternative is running arbitrary bash scripts for every check, but bash scripts are slow to fork, platform-dependent, and prone to shell injection or exit-code masking.
- **What we get for free**: Native TypeScript AST parsing and `ctx.fs` file access run in-process without process-spawning overhead.
- **What to notice**: Every check execution records `executionTimeMs`, allowing the sweeper to detect slow checks or timeouts.
- **Lesson**: Express structural invariants as declarative data predicates rather than shell scripts for speed, safety, and cross-platform consistency.
