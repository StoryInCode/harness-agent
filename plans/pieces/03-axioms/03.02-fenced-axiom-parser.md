## Summary

Extracts and validates ```` ```axiom ```` fenced YAML blocks embedded within colocated `AGENTS.md` files while preserving surrounding markdown as model-binding prose guidance. It enforces the crucial architectural boundary separating machine-verifiable predicate checks from prose instructions, guaranteeing that human guidance is never dropped or mistakenly evaluated as code. It normalizes relative target paths relative to the directory containing the enclosing `AGENTS.md`, and gracefully reports malformed blocks without aborting document ingestion.

## Behaviour

- **Given** an `AGENTS.md` containing prose and a valid ```` ```axiom ```` YAML block **When** parsed **Then** it produces a `CheckableAxiom` record with extracted checks and retains the full prose content.
- **Given** an `AGENTS.md` containing only prose sections **When** parsed **Then** it returns zero checkable axioms and leaves the entire prose content intact.
- **Given** a check with relative path `src/jwt.ts` inside `packages/auth/AGENTS.md` **When** normalized **Then** the check target path is resolved to `packages/auth/src/jwt.ts`.
- **Given** a fenced axiom block with malformed YAML syntax **When** parsed **Then** it records a structured diagnostic warning naming file and line, skips the broken check, and preserves prose.
- **Given** multiple fenced axiom blocks across a single file **When** parsed **Then** each block is validated, assigned its branded `AxiomId`, and returned in the checkable list.

## Teach me while you build

- **Background**: Fenced code blocks in markdown (```` ```axiom ````) allow embedding structured machine-readable YAML directly inside human-readable documentation without breaking markdown renderers.
- **How it works here**: When `ctx.axiomParser.parseAxiomBlocks(filePath, content)` runs, it scans for ````` ```axiom ```` blocks. It parses the block YAML, extracts predicate checks (e.g. `path_exists`, `grep_absent`), and resolves relative target paths relative to the directory containing `AGENTS.md`. Surrounding text is preserved as `proseContent`. Open `packages/axiom/parser/src/index.ts`.
- **Why this approach**: Fenced blocks inside `AGENTS.md`. The simplest alternative was dedicated `.yaml` rule files, but separate files force humans and models to read two different files to understand rules and their rationale.
- **What we get for free**: YAML parser handles structured predicate schemas, while `ctx.fs` handles path normalization.
- **What to notice**: Malformed YAML blocks emit structured warnings instead of throwing, ensuring a typo in one check doesn't disable all documentation.
- **Lesson**: Embed machine-executable assertions inside prose documentation so developers see the rules while machines enforce them.
