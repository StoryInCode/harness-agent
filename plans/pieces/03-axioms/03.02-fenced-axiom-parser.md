## Summary

Extracts and validates ```` ```axiom ```` fenced YAML blocks embedded within colocated `AGENTS.md` files while preserving surrounding markdown as model-binding prose guidance. It enforces the crucial architectural boundary separating machine-verifiable predicate checks from prose instructions, guaranteeing that human guidance is never dropped or mistakenly evaluated as code. It normalizes relative target paths relative to the directory containing the enclosing `AGENTS.md`, and gracefully reports malformed blocks without aborting document ingestion.

### Human Decision Point: Option A vs Option B
- **Option A (Active)**: Parse embedded ```` ```axiom ```` fenced YAML blocks directly from `AGENTS.md` using a resilient markdown scanner while preserving full prose for model context.
- **Option B (Alternative)**: Store machine-verifiable rules in standalone `.yaml` files, which separates rules from human prose guidance and increases file clutter.

## Behaviour

- **Given** an `AGENTS.md` containing prose and a valid ```` ```axiom ```` YAML block **When** parsed **Then** it produces a `CheckableAxiom` record with extracted checks and retains the full prose content.
- **Given** an `AGENTS.md` containing only prose sections **When** parsed **Then** it returns zero checkable axioms and leaves the entire prose content intact.
- **Given** a check with relative path `src/index.ts` inside `packages/fs/fs/README.md` **When** normalized **Then** the check target path is resolved to `packages/fs/fs/src/index.ts`.
- **Given** a fenced axiom block with malformed YAML syntax **When** parsed **Then** it records a structured diagnostic warning naming file and line, skips the broken check, and preserves prose.

## Harness fit

## Teach me while you build

Nya~ (=^･ω･^=)🐾 Inspector Cat is sniffing out the tastiest YAML fish treats hiding inside crunchy markdown biscuits!

- **What it does**: Scans `AGENTS.md` files to extract fenced ```` ```axiom ```` YAML blocks into typed `CheckableAxiom` objects while preserving the surrounding markdown prose unharmed for the model.
- **Background**: In markdown documentation, humans read paragraphs while automated runners need structured constraints. Fenced code blocks allow embedding structured YAML predicates directly inside documentation.
- **How it works here**: The parser scans line by line. When it spots an opening ```` ```axiom ```` fence, it collects lines until the matching closing fence and parses the body as YAML. Relative target paths inside checks are anchored to the directory of the containing `AGENTS.md`. Surrounding text is joined into `proseContent`.
- **Why this approach**: Colocating machine checks with human documentation ensures instructions and their automated enforcement never drift apart into separate files.
- **Approaches considered**: Standalone `.yaml` rule files (rejected: splits human documentation from machine checks) vs Full remark AST compiler (rejected: heavyweight dependency tree for a simple fenced block scan) vs Fence-aware line scanner with embedded YAML parser (chosen: lightweight, zero-loss prose retention).
- **Prior art inspected**: CommonMark fenced code block specification and `packages/dev-loop/directory/src/parse.ts`.
- **What we get for free**: Standard YAML parser parses predicate schemas, while `ctx.fs` handles path normalization across operating systems.
- **What to notice**: Notice that malformed YAML blocks emit diagnostic warnings rather than throwing fatal exceptions, keeping valid prose intact even if someone misplaces a colon.
- **Concepts to own**: Prose-code demarcation: separating structured machine-executable schemas from unstructured context in a single source of record.
- **Interview angle**: How do you extract structured configuration embedded within unstructured Markdown files without losing commentary? Answer: Stream the document through a fence-aware scanner, partition into block tokens, parse fences into schema-validated ASTs, and preserve intermediate spans as prose.
- **Decisions you can now make alone**: You can add new predicate types (like `max_lines` or `forbidden_import`) to the YAML schema without disturbing prose handling.
- **Lesson**: Keep your instructions and their automated checks sleeping in the exact same bed, so nobody ever wanders off and gets lost! Nya~
