# 03.03 — Task Axiom Storage Domain and Lifecycle Store

**Set:** 03-axioms · **Queue:** 3 · **Depends on:** 03.01
**Status:** todo
**Harness primitive:** Service Provider · **Package:** `@deepseek-ai/dsh-axiom-store`

## Summary

Manages persistence and state transitions for card-level task axiom documents (`TaskAxiomDocument`) via `ctx.storageDomain`. Consumes the typed `task_axioms` domain (version 1) over table `documents`, providing zero disk latency synchronous in-memory reads during completion gates and sequential write chain durability. Enforces the 6-state lifecycle (`PROPOSED`, `ACTIVE`, `SATISFIED`, `VIOLATED`, `BLOCKED`, `SUPERSEDED`) with Zod schema validation, failing fast on schema version mismatches. Supersedes bespoke `~/.hermes/task-axioms/` file persistence.

## Behaviour

- **Given** a valid `TaskAxiomDocument` **When** `saveTaskAxioms` is called **Then** the record commits to `ctx.storageDomain` atomically and updates the in-memory cache.
- **Given** an existing card row ID **When** `getTaskAxioms` is called **Then** it returns the document synchronously from memory without disk I/O.
- **Given** an uninitialized card row ID **When** `getTaskAxioms` is called **Then** it returns `undefined`.
- **Given** an active task axiom **When** status updates to `SATISFIED` **Then** the transition commits and `axioms/task-updated` fires.
- **Given** an incompatible storage schema version on startup **When** opening the domain **Then** it throws `DomainError('version-mismatch')`.

## Harness fit

This component is a `Service Provider` mounted on the host plane consuming `ctx.storageDomain` (`packages/storage/storage-domain`), eliminating bespoke filesystem persistence and lock contention (`plans/03-axiom-subsystem.md:81-99`).

## Contracts

```typescript
import { Context, Service } from '@deepseek-ai/cordis'
import { z } from 'zod'
import { defineDomain, domainTable } from '@deepseek-ai/dsh-storage-domain'
import type { TaskAxiomDocument, TaskAxiomId, TaskAxiomStatus } from '@deepseek-ai/dsh-axiom'

export const TASK_AXIOMS_DOMAIN_VERSION = 1

export const taskAxiomDocumentSchema = z.object({
  task: z.string(),
  row: z.string(),
  goal: z.string(),
  created: z.string(),
  governing: z.array(z.string()),
  axioms: z.array(z.record(z.unknown())),
  proofs: z.array(z.record(z.unknown())),
  unresolved: z.array(z.string()),
  nextAction: z.string(),
})

export const taskAxiomsDomainSpec = defineDomain({
  name: 'task_axioms',
  version: TASK_AXIOMS_DOMAIN_VERSION,
  tables: {
    documents: domainTable<string, TaskAxiomDocument>(taskAxiomDocumentSchema as any),
  },
})

declare module '@deepseek-ai/cordis' {
  interface Context {
    taskAxiomStore: TaskAxiomStore
  }
}

export abstract class TaskAxiomStore extends Service {
  constructor(ctx: Context) {
    super(ctx, 'taskAxiomStore', true)
  }
  abstract get(rowId: string): Promise<TaskAxiomDocument | undefined>
  abstract save(doc: TaskAxiomDocument): Promise<void>
  abstract updateStatus(rowId: string, axiomId: TaskAxiomId, status: TaskAxiomStatus, blocker?: string): Promise<void>
}
```

## Teach me while you build

- **Background**: Storage domains (`ctx.storageDomain`) provide structured key-value/table persistence backed by SQLite with in-memory caching for low-latency reads.
- **How it works here**: `taskAxiomsDomainSpec` defines the `task_axioms` domain with table `documents`. When `save(doc)` is called, it validates the object against `taskAxiomDocumentSchema` (Zod), persists it sequentially, and caches it in memory. `get(rowId)` reads synchronously from the cache. Open `packages/axiom/store/src/index.ts`.
- **Why this approach**: Managed storage domain. The simplest alternative was ad-hoc JSON files on disk (`~/.hermes/task-axioms/`), but loose JSON files suffer from concurrent write corruption, lack schema migration checks, and introduce disk I/O latency.
- **What we get for free**: `dsh-storage-domain` provides atomic writes, automatic serialization, and monotonic version checks.
- **What to notice**: Fast failure: if the stored version does not match `TASK_AXIOMS_DOMAIN_VERSION`, initialization immediately throws `DomainError('version-mismatch')`.
- **Lesson**: Store operational task metadata in a validated storage domain rather than scattered ad-hoc filesystem files.
