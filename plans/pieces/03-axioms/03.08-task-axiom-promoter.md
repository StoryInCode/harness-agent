## Summary

Promotes verified card-level task axioms to permanent colocated repository axioms in target `AGENTS.md` files (`promoteToColocatedAxiom`). It appends approved assertions into the target package's `AGENTS.md` under formatted ```` ```axiom ```` blocks, assigns a canonical `AxiomId`, updates the card record in `ctx.storageDomain` with `promotedTo: canonicalId`, and emits `axioms/promoted` on the host bus. It prevents premature promotion of unverified or active axioms.

## Behaviour

- **Given** a satisfied task axiom on a card When promoted to `packages/auth/AGENTS.md` with ID `SIC-AUTH-005` **Then** the formatted fenced block is appended to the file.
- **Given** an unverified or active task axiom When promotion is attempted **Then** it rejects promotion and throws `CANNOT_PROMOTE_UNSATISFIED_AXIOM`.
- **Given** a target `AGENTS.md` file that does not yet exist **When** promotion executes **Then** it initializes the file with standard headers and appends the block.
- **Given** a successful promotion **When** writing finishes **Then** `axioms/promoted` is broadcast on the host bus and the card document updates in domain store.

## Harness fit

This component is a `workflow capability` mounted on the host plane (`ctx.axiomPromoter`), using `ctx.fs` (`packages/fs/fs/src/index.ts:24-52`) for safe markdown file mutations and `ctx.taskAxiomStore` for card state synchronization.

## Teach me while you build

- **Background**: Rule promotion is converting an ephemeral, card-specific task constraint (proven during execution) into a permanent, repository-wide axiom in an `AGENTS.md` file.
- **How it works here**: When `promoteToColocatedAxiom(rowId, taskAxiomId, targetPath, canonicalId)` is called, it verifies the task axiom is in `SATISFIED` status. It then formats a ```` ```axiom ```` YAML block and appends it to the target `AGENTS.md` using `ctx.fs`. Finally, it marks `promotedTo: canonicalId` in `ctx.storageDomain` and emits `axioms/promoted`. Open `packages/axiom/promoter/src/index.ts`.
- **Why this approach**: Append-only markdown promotion with domain sync. The simplest alternative is manually copying and pasting rules into docs, but manual promotion leads to forgotten rules and untracked provenance.
- **What we get for free**: Reuses `ctx.fs` for file reads and writes and `ctx.taskAxiomStore` for card state synchronization.
- **What to notice**: Attempting to promote an axiom that is not `SATISFIED` throws `CANNOT_PROMOTE_UNSATISFIED_AXIOM`, preventing unproven rules from becoming permanent policy.
- **Lesson**: Automate the promotion of verified task-level learnings into permanent codebase rules, but gate promotion behind objective proof.
