## Summary

Promotes verified card-level task axioms to permanent colocated repository axioms in target `AGENTS.md` files (`promoteToColocatedAxiom`). It appends approved assertions into the target package's `AGENTS.md` under formatted ```` ```axiom ```` blocks, assigns a canonical `AxiomId`, updates the card record in `ctx.storageDomain` with `promotedTo: canonicalId`, and emits `axioms/promoted` on the host bus. It prevents premature promotion of unverified or active axioms.

### Human Decision Point: Option A vs Option B
- **Option A (Active)**: Automated markdown append writer gated on verified task status, appending formatted ```` ```axiom ```` blocks to target `AGENTS.md` and updating storage records with canonical IDs.
- **Option B (Alternative)**: Manual copy-paste or unbounded prose promotion without status verification, which risks committing unverified task assertions as permanent codebase rules.

## Behaviour

- **Given** a satisfied task axiom on a card **When** promoted to `packages/web/AGENTS.md` with ID `SIC-AUTH-005` **Then** the formatted fenced block is appended to the file.
- **Given** an unverified or active task axiom **When** promotion is attempted **Then** it rejects promotion and throws `CANNOT_PROMOTE_UNSATISFIED_AXIOM`.
- **Given** a target `AGENTS.md` file that does not yet exist **When** promotion executes **Then** it initializes the file with standard headers and appends the block.
- **Given** a successful promotion **When** writing finishes **Then** `axioms/promoted` is broadcast on the host bus and the card document updates in domain store.

## Harness fit

This component is a `workflow capability` mounted on the host plane (`ctx.axiomPromoter`), using `ctx.fs` (`packages/fs/fs/src/index.ts:24-52`) for safe markdown file mutations and `ctx.taskAxiomStore` for card state synchronization.

## Teach me while you build

Yo! Don't let an LLM trick you into promoting half-baked junk into repo root rules! Real hackers verify disk state before writing anything permanent.

- **What it does**: Takes verified task axioms from finished cards, formats them into valid ```` ```axiom ```` markdown blocks, and appends them to target `AGENTS.md` files while syncing storage.
- **Background**: Temporary rules in a card are like scratchpad RAM. Once proven in combat, promoting them commits them to repo disk so all future agents respect the invariant.
- **How it works here**: Call `promoteToColocatedAxiom(rowId, taskAxiomId, targetPath, canonicalId)`. It checks if the task axiom status is `SATISFIED`. If not, it throws `CANNOT_PROMOTE_UNSATISFIED_AXIOM`. Otherwise, it serializes YAML under ```` ```axiom ````, appends it via `ctx.fs`, updates `ctx.storageDomain`, and fires `axioms/promoted`.
- **Why this approach**: Option A locks promotion behind a hard status check and direct filesystem append. It eliminates human copy-paste errors and keeps storage records synced with disk reality.
- **Approaches considered**: Manual operator documentation updates (rejected: lazy and error-prone) vs Unchecked agent self-promotion (rejected: agents promote unverified hallucinated rules) vs Status-gated automated promoter with storage sync (chosen).
- **Prior art inspected**: Git patch application workflows where only reviewed commits can merge to mainline branches.
- **What we get for free**: `ctx.fs` (`packages/fs/fs/src/index.ts`) handles safe filesystem operations and directory creation.
- **What to notice**: If the target `AGENTS.md` doesn't exist yet, the promoter initializes standard instruction headers before appending the block.
- **Concepts to own**: Append-only audit logs; atomic state promotion; invariant persistence; idempotent file serialization.
- **Interview angle**: How do you prevent agents from polluting permanent repository rules with transient task hacks? Answer: Gate rule promotion behind strict status verification and serialize only verified axioms through a single controlled write path.
- **Decisions you can now make alone**: You can add automated promotion triggers to your CI pipeline when release cards pass all verification gates.
- **Lesson**: If an invariant isn't proven to green on disk, it never touches `AGENTS.md`. End of story.
