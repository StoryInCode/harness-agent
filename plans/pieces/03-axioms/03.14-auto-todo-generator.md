# 03.14 — Automated Auto-Todo Generator on Sweep Failure

**Set:** 03-axioms · **Queue:** 14 · **Depends on:** 03.01, 03.11, 02.01
**Lead Developer:** 🌸 Mayuri (Gentle Seamstress)
**Status:** todo
**Harness primitive:** workflow capability · **Package:** `@deepseek-ai/dsh-axiom-auto-todo`

## Summary

Tutturu~ 🌸 Mayuri is here to help when things don't go as planned! When a verification sweep finds an unhappy axiom, we shouldn't just crash or make scary red error alerts. Instead, Mayuri sews a neat, gentle failure brief with all the command outputs and error snippets, and leaves a helpful comment on the kanban card! That way, our developer friends know exactly what needs fixing without getting overwhelmed!

### Human Decision Point: Option A vs Option B
- **Option A (Active)**: Format failure details into an out-of-band markdown brief file and emit an informative `[AXIOM_SWEEPER_AUTO_TODO]` comment on the kanban card, leaving the sweeper daemon running.
- **Option B (Alternative)**: Throw a fatal error inside the sweeper service on the first failed check, crashing background monitoring and requiring manual log inspection to triage errors.

## Behaviour

- **Given** a verification sweep with failing axioms **When** the auto-todo generator runs **Then** it writes a structured markdown document detailing failed checks, stderr snippets, and exit codes.
- **Given** an active kanban card and failing sweep **When** the generator finishes formatting **Then** it posts an `[AXIOM_SWEEPER_AUTO_TODO]` comment referencing the generated brief.
- **Given** a sweep with 100% satisfied axioms **When** evaluated by the generator **Then** zero auto-todo documents or kanban comments are created.
- **Given** a failed sweep running without kanban service available **When** generating the auto-todo **Then** it writes the markdown brief cleanly without throwing errors.

## Harness fit

This component is a `workflow capability` mounted on the host plane (`ctx.autoTodoGenerator`), consuming `ctx.fs` for file creation and optional `ctx.kanban` for card commentary.

## Teach me while you build

When a stitch breaks, Mayuri doesn't throw away the whole dress! We make a gentle pattern note so we can fix it together!

- **What it does**: Translates complex sweeper verification failures into gentle, structured markdown remediation briefs and posts helpful kanban card comments.
- **Background**: When background sweepers detect broken invariants, workers and human operators need immediate failure context without digging through raw logs.
- **How it works here**: When verification finds unsatisfied axioms, `generateAutoTodo` renders a structured brief with failure snippets and writes it using `ctx.fs` (`packages/fs/fs/src/index.ts`). If `ctx.kanban` is present, it posts an `[AXIOM_SWEEPER_AUTO_TODO]` comment referencing the brief.
- **Why this approach**: Option A separates failure notification into an out-of-band artifact and gentle card comment. Crashing the sweeper daemon would halt background monitoring entirely.
- **Approaches considered**: Crashing the daemon on failure (rejected: stops ongoing background monitoring) vs Spamming full command logs directly into chat (rejected: overwhelms operator context) vs Generating an out-of-band markdown brief with concise card pointer (chosen: clean, actionable triage).
- **Prior art inspected**: GitHub Actions job summaries and GitLab CI artifact reports.
- **What we get for free**: Cordis optional service resolution lets `ctx.kanban` be leveraged if available while safely degrading when running standalone.
- **What to notice**: If all axioms pass, the generator immediately returns `null` without writing files or creating comments.
- **Concepts to own**: Actionable defect reports: turning automated assertion failures into ready-to-execute worker work orders.
- **Interview angle**: How should background verification failures be surfaced to autonomous worker agents? Answer: Produce structured failure briefs with command snippets and link them directly on the parent task card, enabling worker agents to self-triage without manual human intervention.
- **Decisions you can now make alone**: You can customize the auto-todo markdown template or output directory via `AutoTodoGeneratorConfig`.
- **Lesson**: Clear, gentle failure cards save everyone from frustration and keep the development loop running smoothly.
