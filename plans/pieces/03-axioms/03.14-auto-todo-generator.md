# 03.14 — Automated Auto-Todo Generator on Sweep Failure

**Set:** 03-axioms · **Queue:** 14 · **Depends on:** 03.01, 03.11, 02.01
**Status:** todo
**Harness primitive:** workflow capability · **Package:** `@deepseek-ai/dsh-axiom-auto-todo`

## Summary

Generates structured auto-todo request markdown documents and kanban card commentary when verification sweeps detect unsatisfied, violated, or blocked axioms. Writes formatted briefs to `~/.hermes/auto-todos/<task_id>-unsatisfied-todo.md` detailing failed check commands, output snippets, and missing proofs. Emits an `[AXIOM_SWEEPER_AUTO_TODO]` comment on the kanban card via `ctx.kanban.addComment()`, alerting operators and orchestrators without halting background processing.

## Behaviour

- **Given** a verification sweep with failing axioms **When** auto-todo generator runs **Then** it writes a markdown document to `~/.hermes/auto-todos/<task_id>-unsatisfied-todo.md`.
- **Given** failing check outputs **When** the auto-todo is rendered **Then** exit codes, error snippets, and failing file paths are embedded in code blocks.
- **Given** an active kanban card **When** a sweep fails **Then** it posts an `[AXIOM_SWEEPER_AUTO_TODO]` comment referencing the generated file.
- **Given** a sweep with 100% satisfied axioms **When** evaluated **Then** zero auto-todo documents or comments are created.

## Harness fit

This component is a `workflow capability` mounted on the host plane (`ctx.autoTodoGenerator`), consuming `ctx.fs` for file creation and optional `ctx.kanban` for card commentary.

## Teach me while you build

- **Background**: An auto-todo is a machine-generated work order produced when a verification sweep fails, giving the next worker agent exact failure context without manual triage.
- **How it works here**: When `ctx.axiomVerifier` discovers unsatisfied axioms during a sweep, it calls `ctx.autoTodoGenerator.generateAutoTodo(summary, cardTitle)`. The generator parses failed checks, extracts exit codes and stderr snippets, renders a structured markdown brief, and saves it to `~/.hermes/auto-todos/<task_id>-unsatisfied-todo.md` using `ctx.fs`. If `ctx.kanban` is present, it posts an `[AXIOM_SWEEPER_AUTO_TODO]` comment referencing the brief. Open `packages/axiom/auto-todo/src/index.ts`.
- **Why this approach**: Out-of-band markdown documents coupled with card commentary. The simplest alternative is throwing an error that aborts the sweeper daemon, but that halts background monitoring rather than queueing remediation for worker agents.
- **What we get for free**: Cordis optional service injection allows `ctx.kanban` to be utilized when present while gracefully skipping comment emission when running in standalone mode.
- **What to notice**: Sweeps with 100% satisfied axioms exit immediately and return `null`, creating zero filesystem noise.
- **Lesson**: Turn background verification failures into actionable, persistent artifacts rather than burying them in transient daemon logs.
