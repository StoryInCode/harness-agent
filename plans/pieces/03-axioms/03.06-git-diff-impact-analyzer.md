## Summary

Analyzes unified git diff patches to map modified, added, or deleted files in a worktree to their governing colocated `AGENTS.md` hierarchy and machine-checkable constraints. It parses diff headers, extracts changed file paths, resolves directory containment chains, and collects all governing `CheckableAxiom` records. This ensures that verification sweeps and merge checks evaluate exactly the constraints applicable to the changeset without sweeping unaffected subsystems.

### Human Decision Point: Option A vs Option B
- **Option A (Active)**: Parse unified git diff text in-memory and map touched paths to governing `AGENTS.md` hierarchies without spawning external git subprocesses.
- **Option B (Alternative)**: Spawn external shell subprocesses (`git status`, `git diff`) on every evaluation, introducing subprocess overhead and failing on in-memory or staged patch buffers.

## Behaviour

- **Given** a unified git diff modifying `packages/fs/fs/src/index.ts` **When** analyzed **Then** it identifies affected instruction files and their checkable axioms.
- **Given** a diff touching files across multiple packages **When** analyzed **Then** all unique governing instruction files are returned with union deduplication.
- **Given** an empty diff or a diff touching only untracked scratch files **When** analyzed **Then** it returns an empty affected list without throwing.
- **Given** deleted files in the diff **When** analyzed **Then** their parent directory containment chains are resolved to check applicable absence invariants.

## Harness fit

This component is a `Service Provider` mounted on the host plane (`ctx.diffImpactAnalyzer`) providing pure diff text parsing and filesystem containment mapping via `ctx.fs`.

## Contracts

```typescript
import { Context, Service } from '@deepseek-ai/cordis'
import type { CheckableAxiom } from '@deepseek-ai/dsh-axiom'

export interface DiffImpactResult {
  readonly touchedPaths: readonly string[]
  readonly affectedInstructionFiles: readonly string[]
  readonly checkableAxioms: readonly CheckableAxiom[]
}

declare module '@deepseek-ai/cordis' {
  interface Context {
    diffImpactAnalyzer: GitDiffImpactAnalyzer
  }
}

export abstract class GitDiffImpactAnalyzer extends Service {
  constructor(ctx: Context) {
    super(ctx, 'diffImpactAnalyzer', true)
  }
  abstract analyzeDiffImpact(repoRoot: string, diffText?: string): Promise<DiffImpactResult>
  abstract extractTouchedPaths(diffText: string): readonly string[]
}
```

## Teach me while you build

Daru here! Why waste CPU cycles running test suites on untouched packages like a n00b? Smart hackers inspect the raw git diff first.

- **What it does**: Parses unified git diff patches to extract modified, added, and deleted file paths, mapping them directly to their governing `AGENTS.md` hierarchy and checkable axioms.
- **Background**: Incremental verification means running checks only on what actually changed. In a massive monorepo, running every rule across every package on every commit is painfully slow.
- **How it works here**: When `analyzeDiffImpact(repoRoot, diffText)` runs, it scans unified diff headers (`diff --git a/... b/...`). It extracts the touched paths, resolves their directory containment chains up to repo root, and retrieves only the `CheckableAxiom` records governing those specific paths via `03.02`.
- **Why this approach**: Pure in-memory diff parsing is lightning fast and works equally well on staged patches, unstaged changes, and in-memory diff streams without needing subprocess spawns.
- **Approaches considered**: Spawning `git diff` / `git status` shell subprocesses (rejected: process spawn overhead and fails on detached patch buffers) vs Full repo sweep on every edit (rejected: O(N) repository traversal wastes seconds on trivial edits) vs Pure in-memory unified diff parser (chosen: zero subprocess overhead, deterministic, instant).
- **Prior art inspected**: Unified diff format specification and git worktree isolation in `packages/dev-loop/worktree/src/index.ts`.
- **What we get for free**: Standard unified diff grammar (`--- a/`, `+++ b/`) gives us file states (add, edit, delete) directly from patch headers.
- **What to notice**: Even if a file is deleted, we still resolve its parent directory chain so negative invariants (like `path_absent`) are properly evaluated!
- **Concepts to own**: Impact analysis: computing the minimal subset of validation rules required to verify a delta.
- **Interview angle**: How do you implement fast incremental verification in large codebases? Answer: Parse the unified diff to extract modified file paths, map paths to their enclosing directory governance scopes, and evaluate only the axioms bound to those scopes.
- **Decisions you can now make alone**: You can extend header regexes to support git rename and copy metadata without changing downstream axiom evaluation.
- **Lesson**: Don't sweep the whole hard drive when you can read the diff header in 2 milliseconds. Keep your verification loops tight and fast.
