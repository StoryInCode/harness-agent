## Summary

Analyzes unified git diff patches to map modified, added, or deleted files in a worktree to their governing colocated `AGENTS.md` hierarchy and machine-checkable constraints. It parses diff headers, extracts changed file paths, resolves directory containment chains, and collects all governing `CheckableAxiom` records. This ensures that verification sweeps and merge checks evaluate exactly the constraints applicable to the changeset without sweeping unaffected subsystems.

## Behaviour

- **Given** a unified git diff modifying `packages/auth/src/jwt.ts` **When** analyzed **Then** it identifies affected instruction files (`packages/auth/AGENTS.md`, root `AGENTS.md`) and their checkable axioms.
- **Given** a diff touching files across multiple packages **When** analyzed **Then** all unique governing `AGENTS.md` files are returned with union deduplication.
- **Given** an empty diff or a diff touching only untracked scratch files **When** analyzed **Then** it returns an empty affected list without throwing.
- **Given** deleted files in the diff **When** analyzed **Then** their parent directory containment chains are resolved to check applicable file absence invariants.

## Harness fit

This component is a `Service Provider` mounted on the host plane (`ctx.diffImpactAnalyzer`) providing pure diff text parsing and filesystem containment mapping via `ctx.fs`.

```typescript
import { Context, Service } from '@deepseek-ai/cordis'
import type { CheckableAxiom } from '@deepseek-ai/dsh-axiom'

export interface DiffImpactResult {
  readonly touchedPaths: readonly string[]
  readonly affectedInstructionFiles: readonly string[]
  readonly checkableAxioms: readonly CheckableAxiom[]
}

declare module '@deepseek-ai/cordis' {
  interface Context {
    diffImpactAnalyzer: GitDiffImpactAnalyzer
  }

export abstract class GitDiffImpactAnalyzer extends Service {
  constructor(ctx: Context) {
    super(ctx, 'diffImpactAnalyzer', true)
  }
  abstract analyzeDiffImpact(repoRoot: string, diffText?: string): Promise<DiffImpactResult>
  abstract extractTouchedPaths(diffText: string): readonly string[]
}
```

## Teach me while you build

- **Background**: Incremental verification means verifying only what changed. Instead of running every check in the repository on every edit, a diff analyzer inspects git diffs to run only the checks governing modified files.
- **How it works here**: `analyzeDiffImpact(repoRoot, diffText)` parses unified git diff headers (`diff --git a/... b/...`), extracts touched paths (including deleted paths), and maps them to ancestor directories containing `AGENTS.md`. It extracts the governing `CheckableAxiom` records via `03.02`. Open `packages/axiom/diff-analyzer/src/index.ts`.
- **Why this approach**: Pure text diff parsing and directory containment. The simplest alternative is running `git status` via shell subprocesses, but pure diff text parsing works on staged diffs, patch files, and in-memory diffs without shell overhead.
- **What we get for free**: `ctx.fs` allows checking existence of ancestor `AGENTS.md` files across the worktree.
- **What to notice**: For deleted files, the analyzer inspects the parent directory containment chain to verify absence invariants (e.g. `path_absent`).
- **Lesson**: Scope verification sweeps to the exact changeset by extracting affected directory scopes from git diff headers.
