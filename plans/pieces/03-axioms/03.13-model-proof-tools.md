## Summary

Registers the model-facing proof tool catalog (`attach_proof` and `verify_task_axioms`) on `ctx.tools` on the agent plane for worker sessions (`hermes-worker`). `attach_proof` appends structured, cryptographically typed evidence records with branded `ProofId` to active task axioms. `verify_task_axioms` triggers on-demand deterministic sweeps and reports granular check outcomes directly to the model. Surfaced strictly to worker sessions; hidden from orchestrator Brain sessions.

## Behaviour

- **Given** an active task axiom When a worker calls `attach_proof` with test evidence **Then** a branded `ProofId` is assigned, recorded on the card, and persisted.
- **Given** an active worker session When invoking `verify_task_axioms` **Then** it triggers `ctx.axiomVerifier.verifyTask` and returns structured summary counts.
- **Given** an invalid task axiom ID When calling `attach_proof` **Then** it throws an error rejecting the attachment.
- **Given** a Brain orchestrator session When inspecting tools **Then** `attach_proof` and `verify_task_axioms` are not present in the tool catalog.

## Teach me while you build

- **Background**: Model-facing tools give LLM agents a structured, typed interface to interact with the environment, replacing fragile freeform text parsing with JSON Schema validation.
- **How it works here**: When loaded in a `hermes-worker` preset, `attachProofTool` and `verifyTaskAxiomsTool` register into `ctx.tools`. A worker agent calls `attach_proof` with parameters like `task_id`, `axiom_id`, and test output. The handler validates branded IDs, appends a `ProofRecord` via `ctx.storageDomain`, and returns a confirmation payload with a unique `ProofId`. When calling `verify_task_axioms`, it triggers `ctx.axiomVerifier.verifyTask` and formats summary counts. Open `packages/axiom/tool-axiom/src/index.ts`.
- **Why this approach**: Explicit tool schemas via `defineTool`. The simplest alternative is parsing markdown comments from agent text responses, but unstructured text parsing cannot enforce strict typing or guarantee deterministic state updates.
- **What we get for free**: Harness `defineTool` validates schema types, handles argument parsing, and formats tool error responses automatically before our handler executes.
- **What to notice**: Tools are registered strictly in `hermes-worker` sessions via preset configuration; `hermes-brain` sessions never see these tools, preventing orchestrator agents from fabricating worker proofs.
- **Lesson**: Protect system invariants by exposing narrow, strongly typed tools to specific agent roles rather than sharing all capabilities across all agents.
