## Summary

When worker agents execute tasks, they cannot simply claim that an invariant holds; probability of defect approaches certainty when assertions lack cryptographic and empirical grounding. We register the model-facing proof tool catalog (`attach_proof` and `verify_task_axioms`) on `ctx.tools` on the agent plane for worker sessions (`dev-loop-worker`). `attach_proof` appends structured, cryptographically typed evidence records with branded `ProofId` to active task axioms. `verify_task_axioms` triggers on-demand deterministic sweeps and reports granular check outcomes directly to the model. Surfaced strictly to worker sessions; hidden from orchestrator Brain sessions.

### Human Decision Point: Option A vs Option B
- **Option A (Active)**: Expose structured `attach_proof` and `verify_task_axioms` tools via `defineTool` on the agent plane for worker sessions, enforcing branded proof records and on-demand verification sweeps.
- **Option B (Alternative)**: Parse proof submissions out of freeform LLM chat text responses using regex patterns, risking hallucinated proof IDs and unvalidated evidence structures.

## Behaviour

- **Given** an active task axiom **When** a worker calls `attach_proof` with test evidence **Then** a branded `ProofId` is assigned, recorded on the card, and persisted.
- **Given** an active worker session **When** invoking `verify_task_axioms` **Then** it triggers `ctx.axiomVerifier.verifyTask` and returns structured summary counts.
- **Given** an invalid task axiom ID **When** calling `attach_proof` **Then** it throws an error rejecting the attachment.
- **Given** a Brain orchestrator session **When** inspecting tools **Then** `attach_proof` and `verify_task_axioms` are not present in the tool catalog.

## Teach me while you build

The suspect presented an assertion. We examine the forensic evidence and demand cryptographic proof.

- **What it does**: Exposes `attach_proof` and `verify_task_axioms` tools to worker agents, allowing them to record verifiable proof artifacts and query verification status deterministically.
- **Background**: Autonomous worker agents frequently assert success without presenting empirical evidence. Transforming vague claims into structured, verifiable records eliminates epistemic ambiguity.
- **How it works here**: Implemented via `defineTool` in `packages/core/tools/src/schema.ts`. When loaded into the worker preset, tools attach to `ctx.tools`. A worker calls `attach_proof` with target axiom, evidence category, and test artifact; the handler validates IDs, persists a `ProofRecord`, and returns a unique `ProofId`. Calling `verify_task_axioms` executes on-demand sweeps through the verifier service.
- **Why this approach**: Option A binds proof ingestion to typed JSON schemas and branded identifiers. Unstructured chat claims cannot be falsified or audited automatically.
- **Approaches considered**: Unstructured chat transcript scraping (rejected: high error rate and no schema enforcement) vs Ambient filesystem scraping (rejected: cannot attribute intent or link artifacts to specific axioms) vs Explicit typed tool RPC (chosen: fail-closed validation and deterministic attribution).
- **Prior art inspected**: Model Context Protocol (MCP) tool schemas and JSON-RPC 2.0 structured tool invocation conventions.
- **What we get for free**: Harness `defineTool` provides parameter validation, JSON Schema inference, timeout guards, and error formatting before handlers run.
- **What to notice**: Brain orchestrator presets omit these tools; only worker subagent sessions receive proof-attachment capabilities, ensuring segregation of duties.
- **Concepts to own**: Epistemic auditability: ensuring every state assertion is tied to a reproducible artifact and immutable identifier.
- **Interview angle**: How do you prevent LLM agents from hallucinating task completion? Answer: Expose structured proof tools that require deterministic artifacts (test results, diffs, log hashes) before allowing lifecycle state advancement.
- **Decisions you can now make alone**: You can introduce new proof artifact categories (e.g. static analysis reports, coverage metrics) by extending `AttachProofParams`.
- **Lesson**: If an outcome cannot be independently proven with durable evidence, the probability of correctness is zero.
