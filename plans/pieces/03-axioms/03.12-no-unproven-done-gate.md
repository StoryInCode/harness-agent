## Summary

Subscribes to the Cordis serial event hook `'kanban/pre-complete'` to enforce Invariant `INV-01` / `M-009` (No Unproven Done). Awaited sequentially before committing card status transitions to `done`. If any task axiom is unproven, unmet, or violated, or if any governing colocated `AGENTS.md` checkable axiom fails, throws `UnprovenDoneError` and emits `axioms/unproven-done-blocked`, aborting the completion transition atomically before database state changes. Decouples cleanly from Kanban storage by communicating strictly via Cordis serial events.

### Human Decision Point: Option A vs Option B
- **Option A (Active)**: Decoupled event-driven serial hook on `'kanban/pre-complete'` that queries `ctx.axiomVerifier.assertTaskProven` and vetoes status transitions by throwing `UnprovenDoneError`.
- **Option B (Alternative)**: Hardcoding axiom verification queries directly inside the Kanban storage layer, tightly coupling kanban persistence to the axiom subsystem and breaking modularity.

## Behaviour

- **Given** a task with unmet or unproven task axioms **When** `'kanban/pre-complete'` evaluates **Then** the hook throws `UnprovenDoneError` and halts transition to `done`.
- **Given** a task with all task axioms `SATISFIED` and all governing colocated checks passing **When** `'kanban/pre-complete'` evaluates **Then** the hook resolves cleanly.
- **Given** a card lacking a `TaskAxiomDocument` **When** `'kanban/pre-complete'` evaluates **Then** it throws `UnprovenDoneError` with missing document reason.
- **Given** an unproven completion attempt **When** rejected **Then** `axioms/unproven-done-blocked` event is emitted with unproven axiom IDs.

## Contracts

```typescript
import type { Context } from '@deepseek-ai/cordis'
import type { TaskAxiomId } from '@deepseek-ai/dsh-axiom'
import type { TaskRecord, SubtaskCardRecord } from '@deepseek-ai/dsh-kanban'

export class UnprovenDoneError extends Error {
  constructor(
    public readonly taskId: string,
    public readonly unprovenAxioms: readonly TaskAxiomId[],
    public readonly reason: string,
  ) {
    super(`INV-01 Violation: Task "${taskId}" cannot transition to done: ${reason}`)
    this.name = 'UnprovenDoneError'
  }
}

declare module '@deepseek-ai/cordis' {
  interface Events {
    'axioms/unproven-done-blocked': (event: {
      taskId: string
      unprovenAxioms: readonly TaskAxiomId[]
      reason: string
    }) => void
  }
}

export function registerAxiomCompletionGate(ctx: Context): () => void {
  return ctx.on('kanban/pre-complete', async (entity: TaskRecord | SubtaskCardRecord) => {
    // Validates that all task axioms are SATISFIED and governing colocated checks pass
  })
}
```

## Teach me while you build

Listen well! Invariant `INV-01` — 'No Unproven Done' — is the absolute law that prevents our timeline from descending into operational chaos! Without empirical proof, no task shall ever cross into the realm of `done`!

- **What it does**: Intercepts the `'kanban/pre-complete'` serial event hook, calling `assertTaskProven` to verify every task axiom and governing check before allowing a card to reach `done`.
- **Background**: "No Unproven Done" (`INV-01` / `M-009`) is the ultimate guardian of state integrity. If an entity can reach terminal status on good intentions alone, entropy wins and unverified code ships to production.
- **How it works here**: When an operator or agent calls complete on a card, `registerAxiomCompletionGate` listens on `'kanban/pre-complete'`. It delegates to `ctx.axiomVerifier.assertTaskProven(entity.id)`. If any axiom is unproven, unmet, or missing, it immediately throws `UnprovenDoneError` and emits `axioms/unproven-done-blocked`, aborting the database transaction.
- **Why this approach**: Option A uses Cordis serial event hooks. This ensures zero database coupling between the Kanban storage domain and the Axiom verification engine while retaining absolute veto power.
- **Approaches considered**: Direct SQL transaction triggers inside Kanban store (rejected: corrupts modularity and forces circular schema dependencies) vs Post-completion asynchronous auditor (rejected: allows invalid `done` state to be committed and observed) vs Pre-complete serial event interceptor (chosen).
- **Prior art inspected**: Git pre-commit and pre-receive hooks where script exit codes deterministically abort repository transitions before ref updates commit.
- **What we get for free**: Cordis waterfall serial events await all registered handlers; throwing an error in any listener automatically aborts the pipeline.
- **What to notice**: Even if all individual axiom checks pass, missing the `TaskAxiomDocument` itself triggers rejection, preventing sneaky agents from bypassing verification by defining zero axioms.
- **Concepts to own**: Serial event interception; fail-closed state machines; invariant enforcement (`INV-01`); transactional abort semantics.
- **Interview angle**: How do you enforce strict business invariants across independent subsystem plugins without circular dependencies? Answer: Use serial lifecycle event hooks where domain modules publish transition events that external validator plugins can intercept and veto by throwing errors.
- **Decisions you can now make alone**: You can add additional pre-complete verification hooks (such as security audit scans or licensing checks) without touching core Kanban code.
- **Lesson**: Never let a status transition commit before all governing invariants have been verified on the wire. El Psy Kongroo!
