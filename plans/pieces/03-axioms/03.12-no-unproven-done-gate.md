# 03.12 — No Unproven Done Completion Gate Hook

**Set:** 03-axioms · **Queue:** 12 · **Depends on:** 03.01, 03.11, 02.01, 02.16
**Status:** todo
**Harness primitive:** event/hook plugin · **Package:** `@deepseek-ai/dsh-axiom-completion-gate`

## Summary

Subscribes to the Cordis serial event hook `'kanban/pre-complete'` to enforce Invariant `INV-01` / `M-009` (No Unproven Done). Awaited sequentially before committing card status transitions to `done`. If any task axiom is unproven, unmet, or violated, or if any governing colocated `AGENTS.md` checkable axiom fails, throws `UnprovenDoneError` and emits `axioms/unproven-done-blocked`, aborting the completion transition atomically before database state changes. Decouples cleanly from Kanban storage by communicating strictly via Cordis serial events.

## Behaviour

- **Given** a task with unmet or unproven task axioms **When** `'kanban/pre-complete'` evaluates **Then** the hook throws `UnprovenDoneError` and halts transition to `done`.
- **Given** a task with all task axioms `SATISFIED` and all governing colocated checks passing **When** `'kanban/pre-complete'` evaluates **Then** the hook resolves cleanly.
- **Given** a card lacking a `TaskAxiomDocument` **When** `'kanban/pre-complete'` evaluates **Then** it throws `UnprovenDoneError` with missing document reason.
- **Given** an unproven completion attempt **When** rejected **Then** `axioms/unproven-done-blocked` event is emitted with unproven axiom IDs.

export class UnprovenDoneError extends Error {
  constructor(
    public readonly taskId: string,
    public readonly unprovenAxioms: readonly TaskAxiomId[],
    public readonly reason: string,
  ) {
    super(`INV-01 Violation: Task "${taskId}" cannot transition to done: ${reason}`)
    this.name = 'UnprovenDoneError'
  }
}

  interface Events {
    'axioms/unproven-done-blocked': (event: {
      taskId: string
      unprovenAxioms: readonly TaskAxiomId[]
      reason: string
    }) => void
  }
}

export function registerAxiomCompletionGate(ctx: Context): () => void {
  return ctx.on('kanban/pre-complete', async (entity: TaskRecord | SubtaskCardRecord) => {
    // Validates that all task axioms are SATISFIED and governing colocated checks pass
  })
}

## Teach me while you build

- **Background**: "No Unproven Done" (`INV-01`) is the core axiom of the system: a task cannot transition to `done` unless every governing axiom and acceptance criterion has verifiable proof.
- **How it works here**: The plugin registers a listener on the Cordis serial hook `kanban/pre-complete`. When a card attempts to complete, the hook calls `ctx.axiomVerifier.assertTaskProven(entity.id)`. If any task axiom is unproven, unmet, or violated, it throws `UnprovenDoneError` and emits `axioms/unproven-done-blocked`, causing the lifecycle transaction to abort. Open `packages/axiom/completion-gate/src/index.ts`.
- **Why this approach**: Event-driven serial pre-complete interceptor. The simplest alternative is embedding axiom checks directly inside the Kanban store, but that would create tight coupling between Kanban persistence and Axiom verification.
- **What we get for free**: Cordis `ctx.on('kanban/pre-complete')` serial execution ensures the gate runs before status commits, without Kanban knowing about Axioms.
- **What to notice**: Missing `TaskAxiomDocument` also causes rejection, guaranteeing cards cannot bypass verification by skipping axiom definition.
- **Lesson**: Enforce system invariants through decoupled serial event hooks that can veto state transitions without polluting core domain models.
