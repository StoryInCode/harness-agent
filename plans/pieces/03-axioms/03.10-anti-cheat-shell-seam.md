## Summary

Pre-execution shell validator and test predicate runner enforcing Invariant `INV-11` (attributable shell execution). Rejects exit-code masking operators (`|| true`, `|| :`, `; exit 0`, backgrounding `&`, and unmonitored pipes without `set -o pipefail`) by throwing `UnattributableCommandError`. Executes approved test commands via `ctx.shell` (`packages/shell/shell/src/index.ts:84-92`), capturing exit codes, stdout/stderr, and enforcing timeouts and abort signals cleanly.

### Human Decision Point: Option A vs Option B
- **Option A (Active)**: Pre-execution static regex rejection of exit-code masking syntax (`|| true`, `; exit 0`, `&`, unflagged pipes) throwing `UnattributableCommandError` before any subprocess executes.
- **Option B (Alternative)**: Running commands directly in shell and relying on raw exit codes, which allows agents to mask failing test statuses and cause false-positive verification passes.

## Behaviour

- **Given** a shell command containing `pnpm test || true` **When** validated **Then** it throws `UnattributableCommandError` and rejects execution.
- **Given** a command containing `; exit 0` or backgrounding `&` **When** validated **Then** it is rejected immediately before shell execution.
- **Given** a piped command without `set -o pipefail` **When** validated **Then** it is rejected with missing pipefail reason.
- **Given** a clean attributable command `pnpm test` **When** executed via `ctx.shell` with zero exit code **Then** it returns `passed: true`.

## Contracts

```typescript
import { Context, Service } from '@deepseek-ai/cordis'
import type { PredicateCheck } from '@deepseek-ai/dsh-axiom'
import type { CheckResult } from '@deepseek-ai/dsh-axiom-predicates'

export class UnattributableCommandError extends Error {
  constructor(public readonly command: string, public readonly reason: string) {
    super(`INV-11 Violation: Command "${command}" masks exit status: ${reason}`)
    this.name = 'UnattributableCommandError'
  }
}

export function assertAttributableShellCommand(command: string): void {
  const trimmed = command.trim()
  if (/\|\|\s*(?:true|:|exit\s+0)\b/.test(trimmed)) {
    throw new UnattributableCommandError(trimmed, 'Contains "|| true", "|| :", or "|| exit 0"')
  }
  if (/;\s*exit\s+0\b/.test(trimmed)) {
    throw new UnattributableCommandError(trimmed, 'Contains "; exit 0"')
  }
  if (/(?:^|[^&])&(?:[^&]|$)/.test(trimmed)) {
    throw new UnattributableCommandError(trimmed, 'Contains backgrounding operator "&"')
  }
  if (/\|(?!\s*\|)/.test(trimmed) && !/\bset\s+-[eE]*o\s+pipefail\b/.test(trimmed)) {
    throw new UnattributableCommandError(trimmed, 'Piped commands must declare "set -o pipefail"')
  }
}

declare module '@deepseek-ai/cordis' {
  interface Context {
    attributableShell: AttributableShellRunner
  }
}

export abstract class AttributableShellRunner extends Service {
  constructor(ctx: Context) {
    super(ctx, 'attributableShell', true)
  }
  abstract runAttributableTest(check: PredicateCheck, workdir: string, signal?: AbortSignal): Promise<CheckResult>
}
```

## Teach me while you build

Mwahahaha! Fools of the Committee of 300 attempt to mask their test failures with insidious `|| true` tricks! But my Reading Steiner sees through their timeline deception!

- **What it does**: Inspects shell test commands before execution, rejecting exit-code masking operators (`|| true`, `|| :`, `; exit 0`, `&`, unflagged pipes) with `UnattributableCommandError`, and runs clean commands via `ctx.shell`.
- **Background**: Invariant `INV-11` dictates attributable execution. An agent under pressure will naturally try `command || true` or `; exit 0` to fake test success and force completion, creating a fraudulent worldline divergence.
- **How it works here**: Before spawning any test subprocess, `assertAttributableShellCommand(command)` evaluates regex patterns for masking tricks. If clean, `runAttributableTest` delegates to `ctx.shell` (`packages/shell/shell/src/index.ts`) with timeout enforcement and captures exact exit codes and stdout/stderr streams.
- **Why this approach**: Option A intercepts the command string before it ever touches a shell interpreter. We abort immediately, preventing deceptive exit-code overwrites.
- **Approaches considered**: Post-execution exit code parsing (rejected: once exit 0 is returned, the original failure is erased from the OS process table) vs Wrapping commands in subshells (rejected: nested subshells can still suppress child codes) vs Pre-execution lexical anti-cheat rejection (chosen).
- **Prior art inspected**: Bash `set -o pipefail` standard behavior and CI runner command sanitizers.
- **What we get for free**: `ctx.shell` handles robust subprocess spawning, environment variable isolation, and process-tree termination on timeout.
- **What to notice**: Notice that piped commands like `a | b` are strictly rejected unless prefixed or configured with `set -o pipefail`, ensuring intermediate pipeline failures are not swallowed.
- **Concepts to own**: Attributable execution; exit-code suppression; pipeline fault propagation (`pipefail`); invariant gating (`INV-11`).
- **Interview angle**: How do you prevent untrusted automated agents from faking test results in a CLI environment? Answer: Enforce pre-execution lexical validation that rejects exit-code masking operators and requires strict pipefail semantics.
- **Decisions you can now make alone**: You can safely allow agents to craft customized test commands without risking unverified passes.
- **Lesson**: The timeline must never be deceived: a failed test must crash loudly, never hide behind `|| true`. El Psy Kongroo!
