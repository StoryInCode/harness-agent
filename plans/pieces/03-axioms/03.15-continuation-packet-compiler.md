## Summary

Listen up. When a worker crashes or gets killed mid-flight, dumping the whole thousand-turn transcript back into its context window is garbage engineering—it blows the token budget and confuses the LLM. `ContinuationCompiler` does crash recovery hydration: it pulls the active task from `ctx.storageDomain`, strips out all the completed junk, and compiles a lean `ContinuationPacket` with just the unsatisfied axioms, blockers, and next action. Clean restart in milliseconds, no bloated history.

### Human Decision Point: Option A vs Option B
- **Option A (Active)**: Compile an ephemeral `ContinuationPacket` projecting only unsatisfied axioms, active blockers, and immediate next actions from the storage domain.
- **Option B (Alternative)**: Replay the entire multi-turn transcript and completed card history into the restarted worker session, bloating LLM context and inducing hallucinations.

## Behaviour

- **Given** a card with 3 satisfied and 1 unsatisfied axiom **When** `compileContinuation` runs **Then** the packet contains only the single unsatisfied axiom.
- **Given** an unsatisfied axiom with a recorded blocker **When** compiled **Then** the blocker string and previous check failures are summarized in the packet.
- **Given** an active worker restart **When** injected **Then** the continuation packet provides immediate next action context.
- **Given** a card where all axioms are satisfied **When** compiled **Then** it returns an empty unsatisfied list and marks next action as completion.

## Contracts

```typescript
import { Context, Service } from '@deepseek-ai/cordis'
import type { TaskAxiomId, TaskAxiomStatus } from '@deepseek-ai/dsh-axiom'

export interface ContinuationPacket {
  readonly taskId: string
  readonly compiledAt: string
  readonly unsatisfiedAxioms: readonly {
    readonly id: TaskAxiomId
    readonly statement: string
    readonly status: TaskAxiomStatus
    readonly blocker: string
  }[]
  readonly nextAction: string
}

declare module '@deepseek-ai/cordis' {
  interface Context {
    continuationCompiler: ContinuationCompiler
  }
}

export abstract class ContinuationCompiler extends Service {
  constructor(ctx: Context) {
    super(ctx, 'continuationCompiler', true)
  }
  abstract compileContinuation(taskId: string): Promise<ContinuationPacket>
}
```

## Teach me while you build

Real hackers don't drag a gigabyte of log baggage into a fresh shell. You take the delta and run.

- **What it does**: Compiles a lean, ephemeral resumption packet containing only active blockers, unsatisfied axioms, and next actions so restarted worker subagents hit the ground running.
- **Background**: Replaying thousands of tokens of chat history and obsolete failures after an agent crash is amateur hour. Agents need crash recovery hydration with minimal delta state.
- **How it works here**: When a worker session spins up or recovers, `compileContinuation` queries the task state in `ctx.storageDomain`. It discards all satisfied axioms, correlates remaining unsatisfied items with failed verification results from `ctx.axiomVerifier`, and bundles them into an ephemeral `ContinuationPacket` (`packages/session/session-projection/src/index.ts`).
- **Why this approach**: Option A builds an ephemeral delta projection. Replaying full conversational transcripts explodes context windows and causes LLMs to repeat past hallucinated mistakes.
- **Approaches considered**: Full transcript history replay (rejected: massive context bloat and token waste) vs Disk cache file dump (rejected: risks stale cache drift and desync) vs Pure in-memory delta projection from storage domain (chosen: zero bloat, guaranteed fresh).
- **Prior art inspected**: Erlang OTP supervisor crash recovery state reconstitution and Git rebase todo list generation.
- **What we get for free**: Harness `SessionProjectionRegistry` patterns and typed access to `ctx.storageDomain` domain entities.
- **What to notice**: Notice that the packet is completely ephemeral and never written back to disk, making desync impossible!
- **Concepts to own**: State delta projection: deriving a minimal, task-focused slice of state from durable logs for execution efficiency.
- **Interview angle**: How do you handle subagent crash recovery and session continuation without overflowing token context limits? Answer: Use an ephemeral session projection that strips historical progress and projects only unsatisfied constraints, current blockers, and immediate next steps.
- **Decisions you can now make alone**: You can add extra contextual diagnostic fields to `ContinuationPacket` without altering underlying database schema.
- **Lesson**: Keep your continuation packets lean and your state monotonic. Never feed an agent garbage history it already completed.
