## Summary

Resolves applicable governing instruction chains and machine-checkable axioms for candidate directories and file paths before any files are touched or modified. Reuses `dsh-agent-instructions` algorithms to walk upward to project root markers, discover colocated `AGENTS.md` files in broad-to-specific containment order, deduplicate symlink siblings, enforce byte budgeting, and extract checkable axioms via `03.02`. Bridges the planning-time visibility gap, enabling models to deliberate on normative constraints during card decomposition.

## Behaviour

- **Given** candidate path `packages/auth/src/jwt.ts` **When** resolving the candidate chain **Then** it discovers `AGENTS.md` (root), `packages/AGENTS.md`, and `packages/auth/AGENTS.md` in strict broad-to-specific order.
- **Given** multiple candidate paths spanning disjoint subtrees **When** resolving **Then** it aggregates directory containment chains, deduplicates shared root files, and returns a unified instruction set.
- **Given** candidate instruction files exceeding `maxBytes` (e.g. 65536) **When** rendering **Then** broader ancestor files are dropped before truncating specific descendant files.
- **Given** instruction files containing fenced axiom blocks **When** processed **Then** extracted `CheckableAxiom[]` are returned alongside rendered instruction text.
- **Given** a non-existent candidate path **When** resolved **Then** it walks upward to the nearest existing directory without throwing.

## Teach me while you build

- **Background**: Scope resolution walks up the directory tree from a target file to the repository root to collect all configuration or instruction files that govern that path.
- **How it works here**: When called with candidate paths (e.g. `['packages/auth/src/jwt.ts']`), `resolveCandidateChain` walks upward to root markers, discovering `AGENTS.md` files in order: root `AGENTS.md` -> `packages/AGENTS.md` -> `packages/auth/AGENTS.md`. It parses each file via `03.02`, collects checkable axioms, renders the combined instructions, and trims older broad files if exceeding `maxBytes`. Open `packages/axiom/candidate-resolver/src/index.ts`.
- **Why this approach**: Upward containment walk. The simplest alternative is loading every `AGENTS.md` in the repo or only the closest one, but loading all files blows token budgets while loading only the closest ignores repository-wide policies.
- **What we get for free**: Reuses `dsh-agent-instructions` utilities for directory traversal, root marker detection, and deduplication.
- **What to notice**: Byte budgeting drops ancestor (broader) files first before truncating specific descendant files, preserving the most relevant local rules.
- **Lesson**: In hierarchical configuration systems, resolve from root to leaf and budget tokens by discarding generic ancestor rules before specific local rules.
