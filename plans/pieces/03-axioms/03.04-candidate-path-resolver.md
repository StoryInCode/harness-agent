## Summary

Resolves applicable governing instruction chains and machine-checkable axioms for candidate directories and file paths before any files are touched or modified. Reuses `dsh-agent-instructions` algorithms to walk upward to project root markers, discover colocated `AGENTS.md` files in broad-to-specific containment order, deduplicate symlink siblings, enforce byte budgeting, and extract checkable axioms via `03.02`. Bridges the planning-time visibility gap, enabling models to deliberate on normative constraints during card decomposition.

### Human Decision Point: Option A vs Option B
- **Option A (Active)**: Walk upward from candidate paths to project root markers, composing a broad-to-specific instruction chain with byte-budgeted ancestor dropping.
- **Option B (Alternative)**: Eagerly load all repository instruction files or restrict resolution to the single closest file, either blowing context limits or missing governing root policies.

## Behaviour

- **Given** candidate path `packages/fs/fs/src/index.ts` **When** resolving the candidate chain **Then** it discovers root `AGENTS.md`, `packages/AGENTS.md`, and package-level instructions in strict broad-to-specific order.
- **Given** multiple candidate paths spanning disjoint subtrees **When** resolving **Then** it aggregates directory containment chains, deduplicates shared root files, and returns a unified instruction set.
- **Given** candidate instruction files exceeding `maxBytes` **When** rendering **Then** broader ancestor files are dropped before truncating specific descendant files.
- **Given** instruction files containing fenced axiom blocks **When** processed **Then** extracted checkable axioms are returned alongside rendered instruction text.

## Teach me while you build

A detective does not begin an investigation without knowing the local jurisdiction. Every crime scene is governed by concentric circles of authority.

- **What it does**: Resolves the exact chain of governing instruction files and machine-checkable axioms for any candidate file or directory path before modifications begin.
- **Background**: In a monorepo, code is subject to both global repository policies and localized package constraints. To plan accurately, agents must observe the exact hierarchy of governing rules.
- **How it works here**: Given a candidate path like `packages/fs/fs/src/index.ts`, `resolveCandidateChain` walks upward until it detects project root markers (`package.json`, `.git`). It collects all intervening `AGENTS.md` files from root to leaf, parses checkable axioms using `03.02`, and renders the instruction text respecting byte limits.
- **Why this approach**: Broad-to-specific containment order ensures specific package policies override or refine general repository axioms without losing foundational invariants.
- **Approaches considered**: Global repository dump (rejected: overwhelms token context with irrelevant subtree rules) vs Nearest-neighbor file only (rejected: completely ignores root governance and repository invariants) vs Upward containment walk with precedence budgeting (chosen: extracts only relevant jurisdictions and respects byte limits).
- **Prior art inspected**: Context assembly in `packages/context/agent-instructions/src/files.ts` and CommonMark hierarchical document nesting.
- **What we get for free**: Leverages existing `dsh-agent-instructions` utilities for root detection, ancestor directory resolution, and file deduplication.
- **What to notice**: Notice the byte budgeting eviction policy: when instruction text exceeds `maxBytes`, broader ancestor files are dropped before truncating specific leaf files.
- **Concepts to own**: Lexical scoping for repository policies: child directory policies inherit and specialize parent directory rules.
- **Interview angle**: How do you efficiently assemble relevant hierarchical context in large repositories without blowing model context windows? Answer: Traverse upward along the ancestor directory tree to root markers, collect instruction files, order from broad to specific, and evict broader ancestors first if byte budgets are exceeded.
- **Decisions you can now make alone**: You can configure custom root markers or instruction filename candidates for candidate resolution.
- **Lesson**: Scope determines truth. Always resolve the exact governing jurisdictional hierarchy before taking action.
