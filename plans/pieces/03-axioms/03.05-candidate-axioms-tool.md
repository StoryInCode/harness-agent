## Summary

Registers the `resolve_candidate_axioms` tool on `ctx.tools` on the agent plane for planner and orchestrator sessions (`hermes-brain`). It allows the model to explicitly inspect governing prose instructions and machine-checkable constraints for candidate directory and file paths prior to drafting task DoD contracts or modifying code. It solves the planning-time visibility gap cleanly via preset composition without modifying core `agent-instructions` or inventing ad-hoc event hooks.

## Behaviour

- **Given** an orchestrator Brain session **When** calling `resolve_candidate_axioms` with `paths: ['packages/auth']` **Then** it returns rendered instructions, applicable file paths, and checkable constraints.
- **Given** candidate paths spanning multiple subtrees **When** the tool executes **Then** it aggregates constraints across all target paths with shared ancestors deduplicated.
- **Given** an agent preset lacking this tool **When** model tool definitions are assembled **Then** `resolve_candidate_axioms` is absent from available tool schemas.
- **Given** an aborted agent turn **When** the tool is resolving **Then** execution terminates immediately respecting `exec.signal`.

## Teach me while you build

- **Background**: The planning-time visibility gap occurs when an agent plans changes without knowing the constraints of the directories it plans to edit, leading to rejected plans during implementation.
- **How it works here**: `resolve_candidate_axioms` is registered on `ctx.tools` in `hermes-brain`. When the planner enters a planning turn, it calls the tool with planned file paths. The tool delegates to `ctx.candidateResolver.resolveCandidateChain()`, returning formatted instructions and checkable axioms to the model. Open `packages/axiom/candidate-tool/src/index.ts`.
- **Why this approach**: Model-facing query tool. The simplest alternative is automatically injecting all instruction chains into the system prompt, but auto-injecting every potential rule wastes tokens on files the agent might never touch.
- **What we get for free**: Harness `defineTool` validates the input `paths` array and binds `exec.signal` for cancellation.
- **What to notice**: Mounted strictly in `hermes-brain` on the agent plane; worker presets do not receive this tool, keeping worker prompts lean.
- **Lesson**: Give planning agents query tools to inspect domain constraints on demand instead of overloading their initial system prompts.
