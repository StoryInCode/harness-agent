## Summary

Configures host bundle patch layers (`packages/bundle/base/cordis.patch.yml`) and agent plane preset compositions (`presets/hermes-brain/agent.cordis.yml` and `presets/hermes-worker/agent.cordis.yml`) in strict accordance with `PRESET-RULES.md`. Mounts host services (`AxiomRegistry`, `ctx.storageDomain` route `task_axioms: sqlite`, `AxiomVerifier`) on the Host Plane. Composes `tool-candidate-axioms` into `hermes-brain` and `tool-axiom` into `hermes-worker` on the Agent Plane with zero isolate realms, ensuring agents see governing constraints declaratively without custom orchestration code.

## Behaviour

- **Given** the host container boot **When** the base patch layer is applied **Then** `AxiomRegistry` and `AxiomVerifier` mount on the host plane with sqlite domain routing.
- **Given** a `hermes-brain` session boot **When** presets load **Then** `resolve_candidate_axioms` tool is available in `ctx.tools`.
- **Given** a `hermes-worker` session boot **When** presets load **Then** `attach_proof` and `verify_task_axioms` tools are available in `ctx.tools`.
- **Given** a `hermes-brain` session **When** inspecting tools **Then** worker proof tools (`attach_proof`) are completely inaccessible.
- **Given** an HMR reload **When** preset plugins are reloaded **Then** registrations dispose cleanly without leaking Cordis effect listeners.

## Harness fit

This component is a `patch layer` and agent-preset composition conforming to `PRESET-RULES.md:4, 6, 8` separating host plane singleton services from agent plane tool registrations.

## Contracts

```yaml
'@deepseek-ai/dsh-storage-domain':
  routes:
    task_axioms: sqlite

  maxBytes: 65536
  maxSourceBytes: 1048576

  defaultTimeoutMs: 30000
  autoTodosDir: '~/.hermes/auto-todos'

- id: tool-candidate-axioms
  name: '@deepseek-ai/dsh-tool-candidate-axioms'
  inject: ['tools', 'axioms']

  name: '@deepseek-ai/dsh-tool-axiom'

  config:
    autoVerifyOnProof: false
```

## Teach me while you build

- **Background**: Cordis strictly distinguishes between the host plane (long-running daemon services, storage providers) and the agent plane (ephemeral session contexts, model-facing tools). Presets are declarative YAML manifests configuring which plugins run in each plane.
- **How it works here**: The host patch layer `packages/bundle/base/cordis.patch.yml` mounts host services (`AxiomRegistry`, `AxiomVerifier`) and storage routes (`task_axioms: sqlite`). Presets define agent tools: `presets/hermes-brain/agent.cordis.yml` injects `tool-candidate-axioms` for orchestration, while `presets/hermes-worker/agent.cordis.yml` injects `tool-axiom` for workers. Open `packages/bundle/base/cordis.patch.yml`.
- **Why this approach**: Declarative YAML preset composition conforming to `PRESET-RULES.md`. The simplest alternative is registering tools dynamically via imperative TypeScript logic inside session startup, but declarative YAML enforces auditable boundaries and allows clean hot-reloading (HMR).
- **What we get for free**: Cordis schema-validates YAML configs on boot, resolves dependency injection graphs, and tracks disposable registration lifecycles automatically.
- **What to notice**: Agent plane tools declare `inject: ['tools', 'axioms']` without isolate realms, letting them bind cleanly to host plane services while remaining scoped to specific presets.
- **Lesson**: Use declarative preset composition to enforce role-based tool boundaries rather than maintaining complex procedural setup scripts.
