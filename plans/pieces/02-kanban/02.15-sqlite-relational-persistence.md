## Summary

Implements the authoritative relational storage engine for `KanbanStore` using Node.js `node:sqlite`. Reuses verified Plan 01 Option (b) architectural decisions: SQLite WAL mode, `PRAGMA busy_timeout = 120000`, `PRAGMA user_version` monotonic schema validation with newer-version refusal, and `BEGIN IMMEDIATE` cross-table transactions. Persists workspace-scoped tables (`tasks`, `subtask_cards`, `task_trash_audit`), enforcing foreign keys and ACID concurrency across independent agent processes.
Where this supersedes earlier plans: Replaces 38-column 6-table schema from Plan 01 (§4, §5) with workspace-scoped schema supporting 3 states, `tasks.md` references, and quarantined trash.

## Behaviour

- **Given** a new database file **When** initialized **Then** tables are created under WAL mode and `PRAGMA user_version = 1` is stamped last.
- **Given** an existing database with `user_version > KANBAN_SQLITE_SCHEMA_VERSION` **When** opened **Then** initialization refuses to proceed and throws typed `version-mismatch`.
- **Given** competing read and write operations **When** a write transaction begins **Then** `BEGIN IMMEDIATE` acquires exclusive writer locks waiting up to 120,000ms before timeout.
- **Given** a task moved to trash **When** the transaction executes **Then** the task and its cards are removed from active tables and logged into `task_trash_audit` atomically.
- **Given** service unloading during process termination or HMR **When** disposed **Then** `PRAGMA wal_checkpoint(PASSIVE)` flushes changes and handles close cleanly.

## Teach me while you build

- **Background**: SQLite is an embedded relational database. WAL (Write-Ahead Logging) mode allows concurrent readers to read without blocking writers, while writers serialize via `BEGIN IMMEDIATE` to prevent busy deadlocks.
- **How it works here**: `SqliteKanbanStore` extends `KanbanStore` and mounts on `ctx.kanban`. On boot, it checks `PRAGMA user_version`. If matching `KANBAN_SQLITE_SCHEMA_VERSION`, it proceeds; if higher, it refuses with `version-mismatch`. Write transactions run inside `writeTxn(() => { ... })` using `BEGIN IMMEDIATE`. Open `packages/kanban/sqlite/src/index.ts`.
- **Why this approach**: Bespoke SQLite provider with strict WAL pragmas. The simplest alternative is an ORM (like Prisma or TypeORM), but ORMs add heavy dependencies and obscure the low-level pragmas (`busy_timeout`, `WAL`, `user_version`) needed for agent process safety.
- **What we get for free**: Node.js `node:sqlite` provides native SQLite bindings without external native C++ compilation steps.
- **What to notice**: `PRAGMA busy_timeout = 120000` gives concurrent agents 2 minutes to acquire locks before throwing timeout errors.
- **Lesson**: For local embedded databases across multiple agent processes, explicit WAL mode and generous busy timeouts eliminate 99% of file lock errors.
