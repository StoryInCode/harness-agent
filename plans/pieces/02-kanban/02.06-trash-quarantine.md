# 02.06 — Overridden Task Trash and Read-Never Store

**Set:** 02-kanban · **Queue:** 6 · **Depends on:** 02.01
**Status:** todo
**Harness primitive:** Service Provider · **Package:** `@deepseek-ai/dsh-kanban-trash`

## Summary

Quarantines superseded or overridden tasks into an isolated storage partition and enforces a strict read-never guarantee across active LLM contexts. Overridden tasks are immediately evicted from active task tables and board queries to prevent stale text from contaminating prompts. Retains minimal audit metadata (task ID, workspace ID, title, override reason, timestamp, document hash) in a separate audit partition while completely dropping working prompt text and implementation notes from agent memory.
Where this supersedes earlier plans: Replaces in-place transition to `archived` status within active board queries from Plan 01 (§4.2) with strict trash quarantine and read-never guarantee.

Overridden or superseded work goes to trash quarantine and is never read again by active LLM contexts to prevent prompt contamination. In contrast, completed work moves to `<set>/done/` per META AXIOM: finished pieces represent built, verified assets that remain fully readable evidence feeding reuse extraction passes and downstream dependency resolution. Trash means discarded; `done/` means built.

## Behaviour

- **Given** an active task overridden by a user update **When** `moveToTrash` executes **Then** the task and its subtask cards are removed from active tables and archived to the isolated trash partition.
- **Given** tasks residing in the trash partition **When** active board queries or model tools query tasks **Then** trashed tasks are completely excluded and never returned.
- **Given** prompt assembly for the Brain or Worker **When** constructing context **Then** the trash partition is never read, preventing stale prompt contamination.
- **Given** an overridden task **When** audit records are requested **Then** only minimal audit fields (ID, title, timestamp, reason, hash) are returned without prompt bodies.
- **Given** a trashed task ID **When** an active card transition is attempted on it **Then** the operation is rejected with `TASK_IS_TRASHED`.

## Harness fit

This component is a `Service Provider` mounted on the host plane (`ctx.kanbanTrash`) extending `@deepseek-ai/cordis.Service`. It isolates quarantined records and enforces access boundaries between active runtime queries and historical audit logs.

  readonly taskId: TaskId
  readonly workspaceId: WorkspaceId
  readonly title: string

  readonly trashedAt: number

export interface KanbanTrashService {
  moveToTrash(taskId: TaskId, reason: string): Promise<TrashAuditRecord>
  isTrashed(taskId: TaskId): Promise<boolean>
  listTrashAudit(workspaceId: WorkspaceId): Promise<readonly TrashAuditRecord[]>
}

declare module '@deepseek-ai/cordis' {
  interface Context {
    kanbanTrash: KanbanTrashService
  }
}

## Teach me while you build

- **Background**: Prompt contamination occurs when obsolete, superseded, or contradictory instructions remain in an LLM's context window, causing the model to follow outdated specifications.
- **How it works here**: When an operator overrides a task, `ctx.kanbanTrash.moveToTrash(taskId, reason)` removes the task and its subtasks from active tables in a single transaction and writes a minimal audit row (`TrashAuditRecord`) to an isolated partition. Active board queries and prompt assemblers never read this partition. Open `packages/kanban/trash/src/index.ts`.
- **Why this approach**: Read-never quarantine. The simplest alternative is setting `status = 'archived'` in the active table, but soft-deleted rows in active tables are easily leaked into prompts by forgotten query filters.
- **What we get for free**: Transaction atomicity in the storage provider guarantees a task is completely moved or completely kept.
- **What to notice**: The trash record retains metadata (hash, reason, timestamp) for auditability while dropping prompt slices and implementation notes entirely.
- **Lesson**: To keep an LLM from hallucinating on stale instructions, physically isolate dead records into a separate storage partition that active query paths cannot touch.
