# 02.13 — Workspace Task Dropdown and Filtered Card View UI Extension

**Set:** 02-kanban · **Queue:** 13 · **Depends on:** 02.01, 02.07
**Status:** todo
**Harness primitive:** client UI extension · **Package:** `@deepseek-ai/dsh-kanban-ui`

## Summary

Provides the browser client UI extension for the kanban board surface. It renders a workspace-scoped task dropdown listing tasks for the current workspace only. Selecting a task displays strictly that task's decomposed subtask cards distributed across 3 columns (`Todo`, `Pending`, `Done`), guaranteeing cards from different tasks are never mixed in one view. It provides staged indicators, user Accept triggers, per-task automode toggles, and direct links to card discussion.
Where this supersedes earlier plans: Replaces global multi-task board views and generic card presenters from Plan 02 (§1, §5.4) with workspace-filtered task dropdown and isolated subtask board.

## Behaviour

- **Given** a user viewing the kanban board in workspace W **When** the task dropdown opens **Then** only tasks belonging to workspace W are presented.
- **Given** a task selected from the dropdown **When** the board renders **Then** strictly that task's subtask cards appear across Todo, Pending, and Done columns.
- **Given** a subtask card marked `staged: true` in the Todo column **When** rendered **Then** a visible "Staged — Ready to Accept" badge and an active Accept button are displayed.
- **Given** clicking the Accept button on a staged card **When** invoked **Then** `kanbanAccept.acceptCard(cardId)` is triggered and the card moves to Pending.
- **Given** clicking the Discuss button on a card **When** invoked **Then** the card discussion drawer opens with the card's `tasks.md` content.
- **Given** the per-task automode switch on the selected task **When** toggled **Then** `kanbanAutomode` updates and the UI updates the automode indicator immediately.

## Teach me while you build

- **Background**: A client UI extension is a frontend view component registered into the shell application layout that subscribes to backend host events and state projections.
- **How it works here**: `KanbanBoardView` renders in the client layout. It receives `currentWorkspaceTitle` and `availableTasks` for the current workspace. Selecting a task filters the view so only subtask cards for `selectedTaskId` are partitioned into `Todo`, `Pending`, and `Done` columns. Clicking Accept invokes `onAcceptCard(cardId)`. Open `packages/client/src/extensions/kanban/KanbanBoardView.tsx`.
- **Why this approach**: Task-scoped 3-column view with workspace dropdown. The simplest alternative was a single massive board displaying every card in the project, but mixing cards from multiple tasks creates visual clutter and confuses subtask hierarchy.
- **What we get for free**: Host plane RPC subscriptions update React view state automatically when cards transition or staging changes.
- **What to notice**: Cards in `Todo` with `staged: true` render a distinct highlighted badge and an actionable Accept button.
- **Lesson**: Structure UI views around task hierarchies so users focus on one decomposed objective at a time.
