# 02.02 — Kiro-Style tasks.md Document Format and Parser

## Summary

Provides the document parser and serializer for Kiro-style `tasks.md` documents attached to each task and subtask card. It parses YAML frontmatter, objective prose, prompt specifications, implementation notes, and structured GFM checklist items (`- [ ]`, `- [/]`, `- [x]`). It enables deterministic two-way synchronization between disk markdown and kanban state without destroying manual user commentary or formatting.
Where this supersedes earlier plans: Replaces unstructured markdown body and unparsed DoD fields from Plan 01 (§4.1) with Kiro-style `tasks.md` structured documents and AST parser.

## Behaviour

- **Given** a valid `tasks.md` document **When** the parser executes **Then** it produces a structured AST containing frontmatter, main objective, subtask checklist items, and implementation notes.
- **Given** an AST with a subtask checklist item marked `- [x]` **When** serialized to disk **Then** the exact markdown checkbox is updated while preserving adjacent commentary and whitespace.
- **Given** a document missing the mandatory `## Subtasks` section **When** parsed **Then** validation rejects the file with typed `INVALID_TASKS_MD_SCHEMA`.
- **Given** a checklist item with subtask notes **When** the parser processes it **Then** subtask title, verification criteria, and execution prompt details are extracted cleanly.
- **Given** an updated card note from a worker **When** appended **Then** the note is serialized idempotently into the `## Implementation Notes` block.

## Harness fit

This component is a `Service Provider` mounted on the host plane (`ctx.tasksParser`) extending `@deepseek-ai/cordis.Service`. It uses `ctx.fs` (`packages/fs/fs/src/index.ts:24-52`) for safe atomic file reads and writes, avoiding raw Node process forks.

## Contracts

```typescript
import { Context, Service } from '@deepseek-ai/cordis'
import type { TaskStatus } from '@deepseek-ai/dsh-kanban'

export interface SubtaskChecklistItem {
  readonly id: string
  readonly title: string
  readonly status: TaskStatus
  readonly promptDetail?: string
  readonly verificationCriteria?: string
}

export interface TasksMdAst {
  readonly title: string
  readonly description: string
  readonly subtasks: readonly SubtaskChecklistItem[]
  readonly notes: readonly string[]
  readonly rawFrontmatter?: Record<string, unknown>
}

export interface TasksParserService {
  parse(markdown: string): TasksMdAst
  serialize(ast: TasksMdAst): string
  readDocument(filePath: string): Promise<TasksMdAst>
  writeDocument(filePath: string, ast: TasksMdAst): Promise<void>
  updateSubtask(filePath: string, subtaskId: string, status: TaskStatus): Promise<void>
}

declare module '@deepseek-ai/cordis' {
  interface Context {
    tasksParser: TasksParserService
  }
}
```

## Teach me while you build

- **Background**: An AST (Abstract Syntax Tree) is a tree representation of a document's syntax structure. Rather than using fragile regular expressions across an entire markdown document, an AST parser breaks markdown into tokens (headings, lists, code blocks), allowing targeted updates while keeping formatting intact.
- **How it works here**: When callers invoke `ctx.tasksParser.readDocument(filePath)`, it uses `ctx.fs` to read the file, parses frontmatter and markdown sections, and extracts subtasks into a `TasksMdAst`. When modifying a checkbox, `updateSubtask` updates the AST node and serializes it back to disk without wiping developer comments. Open `packages/kanban/tasks-parser/src/index.ts`.
- **Why this approach**: Bidirectional synchronization between markdown files and structured state. The simplest alternative is regex search-and-replace, which fails when users add multi-line comments, code blocks, or nested lists around checklists.
- **What we get for free**: `ctx.fs` provides atomic file read/write operations and error handling.
- **What to notice**: Look at how `serialize()` preserves raw non-task sections and frontmatter untouched.
- **Lesson**: Human-editable text documents acting as state stores must use lossless AST transformations, not naive destructive rewriting.
