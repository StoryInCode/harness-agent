## Summary

Nya~ (=^･ω･^=)🐾 Provides the document parser and serializer for Kiro-style `tasks.md` documents attached to each task and subtask card. It parses YAML frontmatter, objective prose, prompt specifications, implementation notes, and structured GFM checklist items (`- [ ]`, `- [/]`, `- [x]`). It enables deterministic two-way synchronization between disk markdown and kanban state without destroying manual user commentary or formatting. Where this supersedes earlier plans: Replaces unstructured markdown body and unparsed DoD fields from Plan 01 (§4.1) with Kiro-style `tasks.md` structured documents and AST parser.

### Human Decision Point: Option A vs Option B
- **Option A (Active)**: Parse and serialize `tasks.md` via a structured AST that models frontmatter, headings, checklists, and notes losslessly, preserving surrounding developer comments and whitespace.
- **Option B (Alternative)**: Rely on unstructured markdown strings and destructive regex replacements, risking corruption of user commentary, nested code blocks, and formatting on sync.

## Behaviour

- **Given** a valid `tasks.md` document **When** the parser executes **Then** it produces a structured AST containing frontmatter, main objective, subtask checklist items, and implementation notes.
- **Given** an AST with a subtask checklist item marked `- [x]` **When** serialized to disk **Then** the exact markdown checkbox is updated while preserving adjacent commentary and whitespace.
- **Given** a document missing the mandatory `## Subtasks` section **When** parsed **Then** validation rejects the file with typed `INVALID_TASKS_MD_SCHEMA`.
- **Given** a checklist item with subtask notes **When** the parser processes it **Then** subtask title, verification criteria, and execution prompt details are extracted cleanly.

## Harness fit

This component is a `Service Provider` mounted on the host plane (`ctx.tasksParser`) extending `@deepseek-ai/cordis.Service`. It uses `ctx.fs` (`packages/fs/fs/src/index.ts:44-52`) for safe atomic file reads and writes, avoiding raw Node process forks.

## Contracts

```typescript
import { Context, Service } from '@deepseek-ai/cordis'
import type { TaskStatus } from '@deepseek-ai/dsh-kanban'

export interface SubtaskChecklistItem {
  readonly id: string
  readonly title: string
  readonly status: TaskStatus
  readonly promptDetail?: string
  readonly verificationCriteria?: string
}

export interface TasksMdAst {
  readonly title: string
  readonly description: string
  readonly subtasks: readonly SubtaskChecklistItem[]
  readonly notes: readonly string[]
  readonly rawFrontmatter?: Record<string, unknown>
}

export interface TasksParserService {
  parse(markdown: string): TasksMdAst
  serialize(ast: TasksMdAst): string
  readDocument(filePath: string): Promise<TasksMdAst>
  writeDocument(filePath: string, ast: TasksMdAst): Promise<void>
  updateSubtask(filePath: string, subtaskId: string, status: TaskStatus): Promise<void>
}

declare module '@deepseek-ai/cordis' {
  interface Context {
    tasksParser: TasksParserService
  }
}
```

## Teach me while you build

Nya~ Let's learn how to inspect task markdown documents without scratching up the neat notes! (=^･ω･^=)🐾

- **What it does**: Parses and serializes Kiro-style `tasks.md` documents, extracting frontmatter, checklists, and implementation notes into a structured AST without losing human edits.
- **Background**: Markdown is plain text formatted with CommonMark conventions. Without an AST, modifying a single checkbox with naive string replacements can corrupt user comments, code fences, or nested notes.
- **How it works here**: When callers invoke `ctx.tasksParser.readDocument(filePath)`, it uses `ctx.fs` to read the file, parses sections and checklists into `TasksMdAst`, and allows `updateSubtask` to update `- [ ]` marks to `- [x]` losslessly.
- **Why this approach**: Option A builds a dedicated lossless AST. It protects human commentary and formatting while allowing agents to update checklist items programmatically.
- **Approaches considered**: Naive regex search-and-replace (rejected: fragile and corrupts multi-line comments) vs Heavyweight unified/remark dependency tree (rejected: excessive node_modules weight) vs Focused lightweight section/checklist AST (chosen).
- **Prior art inspected**: `packages/dev-loop/directory/src/parse.ts` for fence-aware parsing and GitHub Flavored Markdown Task List items specification.
- **What we get for free**: `ctx.fs` provides atomic file read/write operations and error containment.
- **What to notice**: Look at how `serialize()` preserves non-task sections and surrounding whitespace without stripping raw formatting.
- **Concepts to own**: Abstract Syntax Tree (AST); Round-trip lossless serialization; Idempotent file updates.
- **Interview angle**: How do you safely update a structured section in a human-editable markdown file without destroying unformatted user comments? Answer: Parse the document into an AST that treats unmanaged blocks as raw text tokens, mutating only targeted nodes during serialization.
- **Decisions you can now make alone**: You can safely add custom metadata fields or checklist markers (`- [/]` for in-progress) without breaking existing serializer logic.
- **Lesson**: Human-editable files acting as system state must always use lossless AST transformations, never destructive overwrites.
