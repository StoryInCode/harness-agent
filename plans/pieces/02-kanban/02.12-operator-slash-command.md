## Summary

Yo! Daru here. When you want to manage your kanban cards from the terminal, you need direct, deterministic controls, not a chatty LLM guessing what you meant. We register the `/kanban` slash command directly on `ctx.commands`. It gives the human operator immediate power to launch card discussions (`/kanban <card-id>`), accept staged cards (`/kanban accept <id>`), toggle per-task automode (`/kanban automode <id> on|off`), stage cards (`/kanban stage <id>`), trash aborted tasks (`/kanban trash <id>`), and list workspace tasks (`/kanban list`).

### Human Decision Point: Option A vs Option B
- **Option A (Active)**: Dedicated `/kanban` slash command routing deterministically to host services (`discuss`, `accept`, `automode`, `stage`, `trash`, `list`) outside the LLM loop.
- **Option B (Alternative)**: Rely on natural language chat prompts to trigger kanban actions, which wastes model tokens and risks probabilistic misinterpretation.

## Behaviour

- **Given** input `/kanban c_401` **When** invoked **Then** it delegates to `kanbanDiscussion.openDiscussion("c_401")` opening an interactive discussion.
- **Given** input `/kanban accept c_401` **When** invoked **Then** it delegates to `kanbanAccept.acceptCard("c_401")` transitioning the card to `pending`.
- **Given** input `/kanban automode t_100 on` **When** invoked **Then** it delegates to `kanbanAutomode.enableAutomode("t_100")` confirming per-task opt-in.
- **Given** an unrecognised subcommand or malformed arguments **When** invoked **Then** it prints syntax help and usage examples without raising an unhandled exception.

## Teach me while you build

No fluff, just raw system commands. An operator needs direct levers to pull, not a chatbot playing 20 questions.

- **What it does**: Registers the `/kanban` slash command with subcommands for discussing, accepting, automoding, staging, trashing, and listing cards.
- **Background**: Slash commands execute on the host process before and outside the LLM reasoning cycle, giving the operator direct determinism.
- **How it works here**: The host plugin registers `/kanban` into `ctx.commands`. When invoked, `parseKanbanInput` tokenizes the line. Actions route directly to injected Cordis services (`ctx.kanbanAccept`, `ctx.kanbanDiscussion`, `ctx.kanbanAutomode`, etc.), returning formatted terminal output.
- **Why this approach**: Dedicated deterministic slash command surface. Fast, zero token cost, and impossible for an LLM to hallucinate or ignore.
- **Approaches considered**: Conversational agent prompts (rejected: burns tokens and risks hallucinations) vs Separate OS shell CLI binary (rejected: cannot access live in-memory Cordis session state) vs Host-registered slash command (chosen: instant execution within active harness session).
- **Prior art inspected**: Discord slash command dispatchers and Slack app slash command routers.
- **What we get for free**: Harness `ctx.commands.register()` handles prefix recognition, help command formatting, and CLI event piping.
- **What to notice**: Arguments are parsed with fail-safe syntax error handling; malformed subcommands print usage summaries rather than crashing the session.
- **Concepts to own**: Host command dispatch: routing deterministic operator commands through host services without invoking the model loop.
- **Interview angle**: Why separate operator commands from conversational agent tools? Answer: Operator commands require deterministic, synchronous, zero-token execution and direct host control, whereas agent tools are designed for probabilistic model reasoning.
- **Decisions you can now make alone**: You can easily add new `/kanban` subcommands by adding actions to `ParsedKanbanCommand` and handling them in `handleKanbanCommand`.
- **Lesson**: Don't use an LLM for operations that should be deterministic CLI commands.
