# 02.11 — Card Discussion Coordinator by ID

**Status:** todo

## Summary

Coordinates interactive discussion sessions about a specific card by identifier before any implementation go-ahead is granted. Invoked via `/kanban <card-id>` or the UI Discuss action, it loads the card's `tasks.md`, prompt slice, and verification criteria into an interactive turn loop with the Brain. It allows the user to query assumptions, clarify scope, or adjust specifications prior to staging or acceptance.
Where this supersedes earlier plans: Replaces asynchronous append-only task comments from Plan 01 (§5.1) with interactive card-focused discussion turns prior to execution.

## Behaviour

- **Given** an existing card ID **When** `/kanban <card-id>` is invoked **Then** a discussion session opens loading the card's prompt slice and `tasks.md` into the Brain's focus.
- **Given** an active card discussion **When** the user asks questions or provides adjustments **Then** the Brain replies with context-specific clarifications without initiating execution.
- **Given** user-agreed changes during discussion **When** confirmed **Then** the card's prompt details and `tasks.md` are updated on disk via `tasksParser`.
- **Given** a non-existent card ID **When** discussion is invoked **Then** the session refuses to start and returns `CARD_NOT_FOUND`.
- **Given** an active discussion **When** the user issues go-ahead **Then** the discussion concludes and the card is marked ready for staging.

## Harness fit

This component is a `Service Provider` mounted on the host plane (`ctx.kanbanDiscussion`) extending `@deepseek-ai/cordis.Service`. It bridges the interactive slash command runtime with the agent conversation loop.

## Contracts

```typescript
import { Context, Service } from '@deepseek-ai/cordis'
import type { CardId, SubtaskCardRecord } from '@deepseek-ai/dsh-kanban'

export interface DiscussionMessage {
  readonly sender: 'user' | 'brain'
  readonly text: string
  readonly timestamp: number
}

export interface CardDiscussionSession {
  readonly cardId: CardId
  readonly card: SubtaskCardRecord
  readonly messages: readonly DiscussionMessage[]
  readonly isOpen: boolean
}

export interface KanbanDiscussionService {
  openDiscussion(cardId: CardId): Promise<CardDiscussionSession>
  sendMessage(cardId: CardId, message: string): Promise<DiscussionMessage>
  closeDiscussion(cardId: CardId): Promise<void>
  getActiveSession(cardId: CardId): CardDiscussionSession | undefined
}

declare module '@deepseek-ai/cordis' {
  interface Context {
    kanbanDiscussion: KanbanDiscussionService
  }
}
```

## Teach me while you build

- **Background**: An interactive discussion session scopes an LLM conversation turn loop to a specific topic or card rather than the global project, allowing clarification before work starts.
- **How it works here**: When `/kanban <card-id>` is invoked, `openDiscussion(cardId)` retrieves the card from `ctx.kanban`, loads its prompt slice and `tasks.md`, and creates a `CardDiscussionSession`. Messages sent via `sendMessage()` converse with the Brain. If the user clarifies requirements, `tasksParser` updates the file on disk. Open `packages/kanban/discussion/src/index.ts`.
- **Why this approach**: Pre-execution discussion turn. The simplest alternative is appending comment strings asynchronously to an issue, but comments lack conversational interaction and don't update the active prompt slice.
- **What we get for free**: Reuses `ctx.tasksParser` for serializing agreed updates back to disk markdown.
- **What to notice**: The session never transitions the card to `pending` or triggers worker execution; it only refines the specification.
- **Lesson**: Clarify and amend specifications interactively in a bounded discussion turn before releasing them to workers.
