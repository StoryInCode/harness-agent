# 02.16 — Pre-Complete Serial Hook and Verification Gate Hook

**Set:** 02-kanban · **Queue:** 16 · **Depends on:** 02.01, 02.04, 02.05
**Status:** todo
**Harness primitive:** event/hook plugin · **Package:** `@deepseek-ai/dsh-kanban-gates`

## Summary

Implements the serial verification interceptor registered on the `kanban/pre-complete` Cordis event hook. Awaited before committing status transitions to `done` for both subtask cards and originating parent tasks. It enforces that subtask execution cannot be marked `done` without passing implementation tests and checking off `tasks.md` checklist items. For parent tasks, it validates that 100% of child subtasks are verified and `done` before parent completion commits.
Where this supersedes earlier plans: Replaces the axiom-only pre-complete hook from Plan 01 (§5.2) with dual subtask roll-up and test gate verification hook.

## Behaviour

- **Given** a subtask card with failing unit tests **When** `completeSubtask` triggers `kanban/pre-complete` **Then** the hook throws `VerificationGateError` and the card remains in `pending`.
- **Given** a subtask card with passing tests and completed checklist **When** `kanban/pre-complete` evaluates **Then** the hook resolves cleanly allowing status commit to `done`.
- **Given** a parent task roll-up evaluation **When** `kanban/pre-complete` evaluates the parent **Then** it confirms all subtask cards are in `done` before allowing the parent to transition to `done`.
- **Given** a parent task where any subtask is incomplete **When** pre-complete runs **Then** the transition aborts with `ROLLUP_PREREQUISITES_UNMET`.
- **Given** an unhandled hook rejection **When** caught by the lifecycle controller **Then** transaction rolls back and no database state is corrupted.

  })

## Teach me while you build

- **Background**: A serial hook is an event listener that executes asynchronously in sequence (`ctx.serial()`). If any listener throws an error, execution stops immediately, preventing subsequent actions from running.
- **How it works here**: When a subtask card or task attempts to transition to `done`, the lifecycle manager emits `ctx.serial('kanban/pre-complete', entity)`. The gate listener verifies that subtask tests pass and checklist items are checked. For parent tasks, it verifies 100% of child subtasks are done. If verification fails, it throws `VerificationGateError`. Open `packages/kanban/gates/src/index.ts`.
- **Why this approach**: Event-driven serial hook. The simplest alternative is hard-coding test checks inside the lifecycle service, but using a serial hook decouples test/axiom verification logic from storage and lifecycle code.
- **What we get for free**: Cordis `ctx.on` and `ctx.serial` provide deterministic execution ordering and error propagation.
- **What to notice**: When `VerificationGateError` is thrown, the calling database transaction aborts, ensuring the entity remains in `pending`.
- **Lesson**: Intercept state transitions with serial event hooks so multiple independent verifiers can block completion without tight coupling.
