## Summary

Implements the serial verification interceptor registered on the `kanban/pre-complete` Cordis event hook. Awaited before committing status transitions to `done` for both subtask cards and originating parent tasks. It enforces that subtask execution cannot be marked `done` without passing implementation tests and checking off `tasks.md` checklist items. For parent tasks, it validates that 100% of child subtasks are verified and `done` before parent completion commits.

### Human Decision Point: Option A vs Option B
- **Option A (Active)**: Register an asynchronous serial hook on `kanban/pre-complete` that enforces test verification and checklist completion before committing any card or parent task to `done`, aborting the database transaction on failure.
- **Option B (Alternative)**: Hardcode verification logic into storage mutation methods or permit unverified status transitions, coupling database operations to test runners and risking unproven completions.

## Behaviour

- **Given** a subtask card with failing unit tests **When** `completeSubtask` triggers `kanban/pre-complete` **Then** the hook throws `VerificationGateError` and the card remains in `pending`.
- **Given** a subtask card with passing tests and completed checklist **When** `kanban/pre-complete` evaluates **Then** the hook resolves cleanly allowing status commit to `done`.
- **Given** a parent task roll-up evaluation **When** `kanban/pre-complete` evaluates the parent **Then** it confirms all subtask cards are in `done` before allowing the parent to transition to `done`.
- **Given** an unhandled hook rejection **When** caught by the lifecycle controller **Then** transaction rolls back and no database state is corrupted.

export class VerificationGateError extends Error {
  constructor(readonly entityId: string, readonly reason: string) {
    super(`Verification failed for ${entityId}: ${reason}`)
    this.name = 'VerificationGateError'
  }
}

export function registerVerificationGates(ctx: Context): () => void {
  return ctx.on('kanban/pre-complete', async (entity: TaskRecord | SubtaskCardRecord) => {
    // Verifies subtask tests and tasks.md checklist, or 100% subtask completion for tasks
  })
}

- **What it does**: Intercepts `done` state transitions via the `kanban/pre-complete` serial event hook, executing test verification and checklist validation before allowing status commits.
- **Background**: A serial hook (`ctx.serial()`) executes registered async listeners sequentially. If any listener throws an error, the operation halts immediately, preventing state machine divergence.
- **How it works here**: When an agent attempts to complete a card or task, the lifecycle manager triggers `ctx.serial('kanban/pre-complete', entity)`. The gate listener checks test execution evidence and `tasks.md` checklist completion. If unverified, it throws `VerificationGateError`, rolling back the database transaction.
- **Why this approach**: A decoupled serial hook ensures verification rules stay isolated from core SQLite storage and transaction logic.
- **Approaches considered**: Synchronous hardcoded checks inside storage repository methods (rejected: couples database transactions directly to test runner subprocesses) vs Post-commit rollback triggers (rejected: allows transient unverified states to leak into database projections) vs Pre-commit serial hook intercepting the transition before database commit (chosen).
- **Prior art inspected**: Steins;Gate Divergence Meter and Git pre-commit hook architecture.
- **What we get for free**: Cordis event bus lifecycle handling, serial execution ordering, and automatic transaction rollback on thrown errors.
- **What to notice**: Notice that parent tasks enforce 100% child subtask completion roll-up, ensuring no task transitions to `done` while children remain pending.
- **Concepts to own**: Fail-closed gate verification: operations default to rejection unless explicit, verifiable proof of correctness is presented before the commit point.
- **Interview angle**: How do you prevent premature or unverified task completion in an autonomous multi-agent pipeline? Answer: Intercept state transitions with an asynchronous pre-complete serial hook that validates independent test evidence and aborts the enclosing transaction if checks fail.
- **Decisions you can now make alone**: You can attach additional verification gates (such as linting or security scans) to `kanban/pre-complete` without modifying the state machine.
