## Summary

Registers the model-facing tool suite on `ctx.tools` for Brain and Worker presets. Provides 5 focused tools: `kanban_stage_subtasks` (Brain stages eligible subtasks), `kanban_get_card` (reads card metadata, prompt slice, and `tasks.md`), `kanban_update_tasks_md` (updates checklist items or notes), `kanban_complete_subtask` (worker requests subtask completion), and `kanban_override_task` (moves superseded tasks to trash). Enforces invariant `INV-04` ensuring orchestrator sessions never claim cards for direct execution.
Where this supersedes earlier plans: Replaces the 13-tool catalog from Plan 02 (§5.2) with a focused 5-tool set aligned to `tasks.md`, 3 states, staging, and trash semantics.

## Behaviour

- **Given** an orchestrator Brain session **When** calling `kanban_stage_subtasks` with card IDs **Then** the cards are marked `staged: true` in `todo` status awaiting user accept.
- **Given** a worker session **When** calling `kanban_get_card` **Then** it receives the subtask prompt slice, verification criteria, and `tasks.md` AST.
- **Given** a worker finishing implementation **When** calling `kanban_complete_subtask` **Then** the `kanban/pre-complete` verification hook runs and the card transitions to `done`.
- **Given** a user requirement change **When** the Brain calls `kanban_override_task` **Then** the task and its cards are moved to trash and purged from working context.
- **Given** an orchestrator root session **When** attempting to execute a worker claim **Then** the `INV-04` monotonic tool guard denies execution synchronously.

## Teach me while you build

- **Background**: Model-facing tools are functions exposed to the LLM via its function-calling API. Each tool defines a JSON Schema describing its arguments and return type so the model knows how to invoke it.
- **How it works here**: Tools are defined using `defineTool` and registered into `ctx.tools`. When the Brain calls `kanban_stage_subtasks`, it delegates to `ctx.kanbanStaging`. When a worker calls `kanban_complete_subtask`, it invokes `kanban/pre-complete` and marks the card `done`. Monotonic guard `INV-04` prevents orchestrator sessions from claiming cards. Open `packages/kanban/tools/src/index.ts`.
- **Why this approach**: 5 focused tools. The simplest alternative was exposing 13 fine-grained CRUD tools, but too many tools confuse model tool selection and waste prompt tokens on unused schemas.
- **What we get for free**: Harness `defineTool` validates tool call parameter schemas and handles error serialization back to the model.
- **What to notice**: Look at the `INV-04` guard: orchestrator presets are blocked from calling execution tools, preserving role boundaries.
- **Lesson**: Expose only domain-level verbs to the model, and guard against cross-role tool usage with static role policies.
