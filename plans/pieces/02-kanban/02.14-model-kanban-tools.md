## Summary

Nya~ (=^･ω･^=)🐾 Inspector Cat is laying down the law for model tools so nobody gets their claws tangled! Registers the model-facing tool suite on `ctx.tools` for Brain and Worker presets. Provides 5 focused tools: `kanban_stage_subtasks` (Brain stages eligible subtasks), `kanban_get_card` (reads card metadata, prompt slice, and `tasks.md`), `kanban_update_tasks_md` (updates checklist items or notes), `kanban_complete_subtask` (worker requests subtask completion), and `kanban_override_task` (moves superseded tasks to trash). Enforces invariant `INV-04` ensuring orchestrator sessions never claim cards for direct execution.

### Human Decision Point: Option A vs Option B
- **Option A (Active)**: Expose 5 focused domain-level model tools (`kanban_stage_subtasks`, `kanban_get_card`, `kanban_update_tasks_md`, `kanban_complete_subtask`, `kanban_override_task`) with strict Schemastery schema validation and an `INV-04` orchestrator guard.
- **Option B (Alternative)**: Expose a sprawling 13-tool low-level CRUD catalog for boards, cards, and subtasks, which wastes prompt tokens on unused schemas and confuses model tool selection.

## Behaviour

- **Given** an orchestrator Brain session **When** calling `kanban_stage_subtasks` with card IDs **Then** the cards are marked `staged: true` in `todo` status awaiting user accept.
- **Given** a worker session **When** calling `kanban_get_card` **Then** it receives the subtask prompt slice, verification criteria, and `tasks.md` AST.
- **Given** a worker finishing implementation **When** calling `kanban_complete_subtask` **Then** the `kanban/pre-complete` verification hook runs and the card transitions to `done`.
- **Given** an orchestrator root session **When** attempting to execute a worker claim **Then** the `INV-04` monotonic tool guard denies execution synchronously.

## Teach me while you build

Nya~ Let Inspector Cat teach you how to build clean, purr-fect model tools without confusing the AI!

- **What it does**: Registers 5 model-facing tools (`kanban_stage_subtasks`, `kanban_get_card`, `kanban_update_tasks_md`, `kanban_complete_subtask`, `kanban_override_task`) with strict argument validation and monotonic guard `INV-04`.
- **Background**: Model tools bridge LLM function calling to backend services. `defineTool` pairs parameter schemas with strongly typed handlers so the model knows what to call.
- **How it works here**: In `packages/core/tools/src/schema.ts:545-560`, `defineTool` constructs tool definitions with typed parameter schemas. Tools register on `ctx.tools` (`packages/core/tools/src/index.ts:1100-1106`), where `INV-04` attaches a monotonic `ToolGuard` that rejects card execution attempts from orchestrator sessions.
- **Why this approach**: Exposing 5 domain-specific verbs minimizes token overhead and eliminates hallucinated tool calls compared to a 13-tool low-level CRUD catalog.
- **Approaches considered**: 13-tool raw CRUD catalog (rejected: bloats system prompt with dozens of unused schemas) vs Single mega-tool with action sub-commands (rejected: poor type discrimination and weak tool calling guidance) vs 5 focused domain-level tools with schema validation (chosen).
- **Prior art inspected**: Model Context Protocol (MCP) tool declaration patterns and OpenAI function calling standards.
- **What we get for free**: Schemastery automatic validation of input parameters, JSON Schema generation, and structured error reporting.
- **What to notice**: Notice how `INV-04` uses `ctx.tools.guard()` to enforce role separation without coupling tool logic to preset definitions.
- **Concepts to own**: Monotonic security guards: once any guard layer returns a denial string, downstream execution is unconditionally aborted.
- **Interview angle**: Why separate orchestrator tools from worker tools instead of giving all agents the same tools? Answer: Asymmetric tool exposure preserves organizational boundaries, prevents orchestrator drift into direct execution, and cuts token costs.
- **Decisions you can now make alone**: You can safely add new inspection tools without risking accidental card state mutations.
- **Lesson**: Keep model tool sets tiny, sharply scoped, and guarded by monotonic invariants.
