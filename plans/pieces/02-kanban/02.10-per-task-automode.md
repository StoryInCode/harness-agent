## Summary

Fwahahaha! Heed my warning, lab members! Unchecked global automode is an insidious trap laid by the Organization to plunge our repository into chaos! This controller enforces strictly scoped, opt-in per-task automode. Automode applies exclusively to a single designated task hierarchy; wholesale or workspace-wide automode is strictly forbidden. When active, staged cards auto-advance to `pending`, but the moment automode is revoked, the divergence stops instantly!

### Human Decision Point: Option A vs Option B
- **Option A (Active)**: Opt-in per-task automode scoped strictly to one parent task hierarchy, rejecting global or workspace-wide automation fail-closed with `WHOLESALE_AUTOMODE_FORBIDDEN`.
- **Option B (Alternative)**: Global or workspace-wide automode toggles that auto-advance all tasks indiscriminately, risking runaway loops and unmonitored code churn.

## Behaviour

- **Given** an active task with automode disabled (default) **When** subtask cards are staged **Then** they remain in `todo` awaiting explicit user acceptance.
- **Given** an attempt to enable global or workspace-wide automode **When** invoked **Then** the request is rejected with `WHOLESALE_AUTOMODE_FORBIDDEN`.
- **Given** Task T with automode active **When** a child subtask is staged **Then** it automatically transitions to `pending` and is enqueued for execution without user prompting.
- **Given** active automode on Task T **When** the user calls `disableAutomode(T)` **Then** automode is immediately revoked and any remaining staged subtasks require manual acceptance.

## Harness fit

This component is a `Service Provider` mounted on the host plane (`ctx.kanbanAutomode`) extending `@deepseek-ai/cordis.Service`. It subscribes to `kanban/card-staged` events to conditionally trigger auto-acceptance for opted-in tasks.

  handleStagedCard(card: SubtaskCardRecord): Promise<boolean>

declare module '@deepseek-ai/cordis' {
  interface Context {
    kanbanAutomode: KanbanAutomodeService
  }
}

## Teach me while you build

Beware the perils of runaway feedback loops! Controlled divergence requires an airtight perimeter, or the worldline collapses into chaos!

- **What it does**: Enables selective auto-advance for staged subtasks under one opted-in parent task while strictly prohibiting global automode.
- **Background**: Unbounded autonomous loops easily diverge into destructive cascade failures if not confined to a strict topological boundary.
- **How it works here**: An operator enables automode for a single task via `enableAutomode(taskId)`. When `kanbanStaging` emits `kanban/card-staged`, `kanbanAutomode` checks `isAutomodeEnabled(card.taskId)`. If true, it calls `ctx.kanbanAccept.acceptCard(card.id)`. Any attempt to enable global automode throws `WHOLESALE_AUTOMODE_FORBIDDEN`.
- **Why this approach**: Strictly scoped per-task opt-in. Confining autonomous progression to a single task subtree guarantees that adjacent work is never executed unattended.
- **Approaches considered**: Global harness automode flag (rejected: catastrophic risk of unattended mutations across multiple projects) vs Polling daemon (rejected: high CPU and database churn compared to event subscription) vs Reactive event-driven task decorator (chosen: subscribes to `kanban/card-staged` and acts conditionally).
- **Prior art inspected**: Temporal workflow cancellation scopes and GitHub Actions concurrency group scopes.
- **What we get for free**: Event-driven architecture on Cordis allows automode to decouple from `kanbanStaging` without polling or tight coupling.
- **What to notice**: Revoking automode via `disableAutomode` is instant: future staged subtasks freeze in `todo` immediately without disrupting already executing workers.
- **Concepts to own**: Scoped autonomy: restricting self-advancing state machines to isolated subgraphs rather than system-wide ambient execution.
- **Interview angle**: Why is global automode dangerous in agent systems, and how do you prevent runaway execution? Answer: Global automode lacks clear blast radius boundaries; restricting autonomy to explicit parent task trees and providing instant revocation ensures catastrophic divergence is prevented.
- **Decisions you can now make alone**: You can add telemetry counters (such as tracking auto-advanced cards per task) without altering staging or accept contracts.
- **Lesson**: Autonomy must always be bounded by an explicit scope; wholesale ambient automation is an anti-pattern.
