# 02.10 — Per-Task Automode Opt-In Controller

**Set:** 02-kanban · **Queue:** 10 · **Depends on:** 02.01, 02.08, 02.09
**Status:** todo
**Harness primitive:** Service Provider · **Package:** `@deepseek-ai/dsh-kanban-automode`

## Summary

Enforces opt-in, strictly scoped per-task automode. Automode applies exclusively to one specified parent task and its immediate subtask cards; board-wide or workspace-wide automode is strictly forbidden. When automode is enabled on a task, staged subtasks automatically advance to `pending` upon prerequisite completion without requiring manual acceptance prompts. The user can revoke automode at any time, immediately halting auto-advance for all remaining subtasks.
Where this supersedes earlier plans: Replaces global auto-dispatch and wholesale unattended execution from Plan 01 (§1, §4.3) with strictly scoped per-task opt-in automode.

## Behaviour

- **Given** an active task with automode disabled (default) **When** subtask cards are staged **Then** they remain in `todo` awaiting explicit user acceptance.
- **Given** a user enabling automode on Task T **When** `enableAutomode(T)` runs **Then** automode is enabled exclusively for T, leaving all other tasks in manual mode.
- **Given** an attempt to enable global or workspace-wide automode **When** invoked **Then** the request is rejected with `WHOLESALE_AUTOMODE_FORBIDDEN`.
- **Given** Task T with automode active **When** a child subtask is staged **Then** it automatically transitions to `pending` and is enqueued for execution without user prompting.
- **Given** active automode on Task T **When** the user calls `disableAutomode(T)` **Then** automode is immediately revoked and any remaining staged subtasks require manual acceptance.

## Harness fit

This component is a `Service Provider` mounted on the host plane (`ctx.kanbanAutomode`) extending `@deepseek-ai/cordis.Service`. It subscribes to `kanban/card-staged` events to conditionally trigger auto-acceptance for opted-in tasks.

## Teach me while you build

- **Background**: Automode allows an agent to automatically progress through a series of subtasks without prompting the user at each step.
- **How it works here**: An operator enables automode on a specific task via `enableAutomode(taskId)`. When `kanbanStaging` emits `kanban/card-staged`, `kanbanAutomode` checks `isAutomodeEnabled(card.taskId)`. If true, it automatically calls `ctx.kanbanAccept.acceptCard(card.id)`. Sibling tasks without automode remain paused in `todo`. Open `packages/kanban/automode/src/index.ts`.
- **Why this approach**: Strictly scoped per-task opt-in. The simplest alternative is a global "automode on" switch, but global automode risks unintended runaway execution across multiple projects or unreviewed tasks.
- **What we get for free**: Subscribing to `kanban/card-staged` allows automode to act as a reactive decorator without altering the core staging service.
- **What to notice**: Calling `disableAutomode(taskId)` takes effect immediately, halting further auto-advances without killing currently executing workers.
- **Lesson**: Automation should be an opt-in property scoped to individual task hierarchies, never a blanket global mode.
