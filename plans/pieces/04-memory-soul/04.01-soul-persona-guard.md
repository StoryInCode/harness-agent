## Summary

Tut-turii~ 🌸 Mayuri is here to protect our agent's heart and gentle soul! Injects the founder's immutable `SOUL.md` persona into Identity Slot #1 (`deployment:persona-prefix` at order 0) across all agent sessions and enforces strict human-only write sovereignty (`INV-09`). It loads the identity text from `~/.dsh/SOUL.md` (or `HERMES_SOUL_PATH`), shadows the deployment persona prefix via `@deepseek-ai/dsh-persona`, and installs a synchronous tool execution guard via `ctx.tools.guard()` that rejects any attempt by autonomous file or shell tools to edit or delete `SOUL.md`.

### Human Decision Point: Option A vs Option B
- **Option A (Active)**: Install a synchronous tool execution guard via `ctx.tools.guard()` to intercept tool calls before dispatch and reject writes to `SOUL.md` with `UnauthorizedSoulMutationError`.
- **Option B (Alternative)**: Rely purely on system prompt admonitions instructing the model not to edit its soul file, which fails under adversarial prompt injection.

## Behaviour

- **Given** an agent session mounting `dev-loop-brain` or `dev-loop-worker` **When** prompt assembly runs **Then** `SOUL.md` is rendered in Identity Slot #1 at order `DEPLOYMENT_PERSONA_PREFIX` (0).
- **Given** an autonomous tool invocation targeting `SOUL.md` **When** executed **Then** `ctx.tools.guard` intercepts the call and aborts execution with `UnauthorizedSoulMutationError`.
- **Given** a shell tool invocation with commands modifying or deleting `SOUL.md` **When** evaluated by the tool guard **Then** execution is rejected before process spawn.
- **Given** an environment where `HERMES_SOUL_PATH` is defined **When** persona loads **Then** it reads identity content from the overridden path.

## Teach me while you build

Tut-turii~ 🌸 Mayuri wants to make sure our agent's soul stays safe and warm!

- **What it does**: Injects the founder's persona into the initial system prompt and blocks all autonomous mutations to `SOUL.md`.
- **Background**: In agent architectures, identity defines personality, tone, and core values. If an agent can overwrite its own soul file, a jailbreak or drift can permanently alter its character.
- **How it works here**: At startup, `resolveSoulContent` reads `~/.dsh/SOUL.md` and registers it with `@deepseek-ai/dsh-persona` at order 0 (`DEPLOYMENT_PERSONA_PREFIX`). Meanwhile, `apply()` registers a synchronous guard with `ctx.tools.guard()` that checks input arguments of filesystem and shell tools against `isSoulPath`.
- **Why this approach**: Option A provides kernel-level interception in the harness, making soul protection structural rather than behavioral.
- **Approaches considered**: Advisory prompt instructions (rejected: easily bypassed by prompt injection) vs OS-level file permissions (rejected: requires root or separate user accounts) vs Synchronous tool interceptor in Cordis (chosen).
- **Prior art inspected**: no prior art inspected
- **What we get for free**: `ctx.tools.guard()` already provides lifecycle interception for tool calls before dispatch.
- **What to notice**: Look at how `isSoulPath` resolves symlinks and canonical path strings to prevent directory traversal bypasses like `../SOUL.md`.
- **Concepts to own**: Fail-closed guards, identity immutability, synchronous tool pre-execution interception.
- **Interview angle**: How do you prevent an autonomous agent with shell access from modifying its own core persona? Answer: Intercept tool dispatch at the harness layer before subprocess spawning and block writes synchronously.
- **Decisions you can now make alone**: You can safely add other protected files (like safety guidelines) to the tool guard list.
- **Lesson**: Never rely on an LLM to police its own file writes; enforce critical boundaries deterministically in harness middleware!
