## Summary

An unyielding watchdog to preserve operator primacy across divergent world lines! The Turn Preemption Controller provides low-latency preemption of background review forks upon human intervention. It subscribes to incoming user turn signals (`agent/inbox/inserted` and `agent/pre-step`) on the parent agent. When a user input message arrives while a background review subagent is executing, it immediately triggers the child's `AbortController`, calls `run.dispose()`, and enforces a strict 2.0-second cancellation watchdog deadline (`preemptionTimeoutMs: 2000`). It records the preemption event in the curator ledger and releases system resources without delaying the human turn.

### Human Decision Point: Option A vs Option B
- **Option A (Active)**: Asynchronously abort background review runs with a 2.0-second watchdog deadline upon user message arrival, prioritizing zero user-perceived input latency.
- **Option B (Alternative)**: Block the incoming human turn until the background review finishes its current step or iteration, which stalls user interaction by seconds.

## Behaviour

- **Given** an active background review subagent **When** a user message arrives in the parent agent's inbox **Then** it immediately signals preemption abort without delaying the user turn.
- **Given** preemption is signaled **When** the child subagent settles within 2.0 seconds **Then** it cleanly disposes child resources and logs preemption to the ledger.
- **Given** preemption is signaled **When** the child fails to exit within 2,000ms **Then** the watchdog unmounts the child context forcibly to prevent zombie processes.
- **Given** a parent agent with no active review subagent **When** a user message arrives **Then** the preemption hook is a no-op and user processing proceeds immediately.

## Teach me while you build

Mwahahaha! Step forward, lab members, and gaze upon the watchdog of temporal priority!

- **What it does**: Intercepts foreground operator input and triggers an asynchronous, deadline-bounded abortion of any background review subagents to protect turn latency.
- **Background**: In an agent system with background cognition, human interaction must always maintain absolute priority. Background workers cannot be allowed to monopolize execution threads or delay the human operator.
- **How it works here**: The plugin hooks `agent/inbox/inserted` (`packages/core/agent/src/runtime-types.ts:285`) and `agent/pre-step` (`packages/core/agent/src/runtime-types.ts:330`). When a message arrives for `parentSessionId`, `preemptIfRunning` calls `abortController.abort()`. It arms a 2,000ms watchdog timer via `setTimeout`. If the child run resolves within the window, resources are disposed cleanly; otherwise, it forcibly terminates the child run.
- **Why this approach**: Asynchronous preemption prevents the foreground driver from blocking on child teardown while guaranteeing background runs do not linger as zombie tasks.
- **Approaches considered**: Synchronous turn blocking (rejected: pauses human experience until review finishes) vs fire-and-forget cancellation without watchdog (rejected: risks unkillable child runs consuming API tokens) vs bounded asynchronous watchdog preemption (chosen).
- **Prior art inspected**: `archive/plans/06-curator-and-self-learning.md:428-452` (preemption handshake and 2.0s watchdog deadline).
- **What we get for free**: Native JavaScript `AbortController` and Cordis event listeners provide standard cancellation signals across asynchronous boundaries.
- **What to notice**: Notice that `preemptIfRunning` returns immediately rather than awaiting the child's teardown, keeping the foreground turn unblocked!
- **Concepts to own**: Asynchronous cancellation watchdogs: ensuring cooperative aborts have a hard bounded fallback for uncooperative workers.
- **Interview angle**: How do you design background worker preemption when a high-priority user request arrives? Answer: Signal cooperative abort via AbortSignal immediately, detach foreground execution, and schedule a bounded watchdog to force-kill stuck background workers.
- **Decisions you can now make alone**: You can adjust `preemptionTimeoutMs` based on environment latency without changing foreground turn logic.
- **Lesson**: Human sovereignty is absolute; never allow background machinery to delay the operator's will! El Psy Kongroo.
