## Summary

Daru here. We are implementing `LocalMemoryStore` to persist curated memory files (`USER.md` and `MEMORY.md`) on disk without destroying prompt prefix cache hits. It coordinates atomic disk commits with POSIX file locks while freezing the prompt snapshot (`memory:curated-notes` at order 10) across each LLM turn, keeping prompt tokens invariant during mid-turn tool execution.

### Human Decision Point: Option A vs Option B
- **Option A (Active)**: Capture a frozen prompt snapshot of curated notes at turn start while committing tool mutations to disk immediately, preserving LLM prompt prefix cache stability (`INV-08`) across the turn.
- **Option B (Alternative)**: Re-render system prompt memory sections dynamically after every tool mutation, causing cache misses and latency spikes on subsequent turns.

## Behaviour

- **Given** host boot **When** `LocalMemoryStore` loads **Then** it registers `memory:curated-notes` on `ctx.systemPrompt` at order 10.
- **Given** an active agent turn with a mid-turn memory mutation **When** committed to disk **Then** disk updates immediately while the active turn's prompt snapshot remains byte-identical.
- **Given** a batch mutation **When** `mutate()` executes **Then** operations apply sequentially under POSIX lock and validate character limits against the final state, throwing on budget overflow.

## Harness fit

This component is a host-plane `Service Provider` registering `LocalMemoryStore` on `ctx.memory` and contributing prompt section `memory:curated-notes` at order 10 in `packages/core/system-prompt/src/index.ts:121-178`.

```typescript
import { Context } from '@deepseek-ai/cordis'
import z from '@deepseek-ai/schemastery'
import { MemoryStore, MEMORY_CHAR_LIMIT, USER_CHAR_LIMIT } from '@deepseek-ai/dsh-memory'
import type { MemoryBatchResult, MemoryBudget, MemoryNote, MemoryOperation, MemoryTarget } from '@deepseek-ai/dsh-memory'

export interface Config {
  memoriesDir?: string
  memoryCharLimit?: number
  userCharLimit?: number
  lockTimeoutMs?: number
}

export const Config: z<Config> = z.object({
  memoriesDir: z.string().default('~/.dsh/memories'),
  memoryCharLimit: z.number().default(MEMORY_CHAR_LIMIT),
  userCharLimit: z.number().default(USER_CHAR_LIMIT),
  lockTimeoutMs: z.number().default(5000),
})

export class LocalMemoryStore extends MemoryStore {
  static inject = ['fs', 'systemPrompt']
  constructor(ctx: Context, config?: Config)
  getNotes(target: MemoryTarget): Promise<readonly MemoryNote[]>
  getRawContent(target: MemoryTarget): Promise<string>
  getBudget(target: MemoryTarget): Promise<MemoryBudget>
  mutate(target: MemoryTarget, operations: readonly MemoryOperation[]): Promise<MemoryBatchResult>
  getTurnPromptSnapshot(): string
  captureTurnPromptSnapshot(): void
}
```

## Teach me while you build

Yo, hacker! Let's talk about why disk writes and prompt tokens need air-gapped isolation.

- **What it does**: Persists user and agent memory files under a local directory with atomic write semantics and serves frozen prompt snapshots per turn.
- **Background**: Modern LLMs rely on prompt prefix caching. If the early tokens in a system prompt shift mid-turn, the cache invalidates and inference costs shoot up.
- **How it works here**: When a turn starts, `captureTurnPromptSnapshot()` freezes the current curated notes string. Tool operations call `mutate()`, acquiring a POSIX lock, validating budget, and using atomic rename, but the turn's prompt snapshot stays immutable.
- **Why this approach**: Separating disk state from active turn prompt state ensures durability without forfeiting KV cache performance.
- **Approaches considered**: In-memory caching without disk durability (rejected: loss of state across crashes), direct file re-reading on every prompt assembly (rejected: busts KV prefix cache), and write-through with frozen turn snapshots (chosen).
- **Prior art inspected**: SQLite WAL mode and Linux page cache dirty page writeback architectures.
- **What we get for free**: Cordis context lifecycle handles automatic service unregistration on teardown via `ctx.effect()`.
- **What to notice**: Character budget validation occurs against the final post-mutation state rather than incrementally, allowing atomic note swaps without false overflow.
- **Concepts to own**: Prefix cache stability, POSIX file locking, atomic rename publishing (`rename` over target), and turn-scoped snapshots.
- **Interview angle**: Why shouldn't memory mutations immediately update the active prompt buffer? Because mid-turn prompt changes thrash the KV cache across multi-turn reasoning steps.
- **Decisions you can now make alone**: You can add new memory targets (like workspace scratchpads) while keeping the same locking and snapshot guarantees.
- **Lesson**: Separate your storage write path from your LLM prompt evaluation snapshot to keep system performance high and tokens cheap.
