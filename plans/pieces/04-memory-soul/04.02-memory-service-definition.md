## Summary

Defines the core `MemoryStore` abstract Service class, domain entity models (`MemoryNote`, `MemoryOperation`, `MemoryBudget`, `MemoryBatchResult`), operational errors, and typed Cordis host events for semantic note management. It establishes the host capability seam `ctx.memory` providing synchronous prompt snapshots, character budget calculations, and atomic batch mutations. It enforces strict separation between user preferences (`USER.md`, 1,375 chars) and agent notes (`MEMORY.md`, 2,200 chars), while excluding `SOUL.md` from the mutable domain.

### Human Decision Point: Option A vs Option B
- **Option A (Active)**: Define an abstract `MemoryStore` Cordis service providing atomic batch mutations, strict character budgets (2,200 for MEMORY.md, 1,375 for USER.md), and event-driven drift notification.
- **Option B (Alternative)**: Access raw files directly via filesystem tools in every agent turn, bypassing central character budgeting, atomic locks, and drift detection.

## Behaviour

- **Given** a Cordis context **When** `ctx.memory` is resolved on the host plane **Then** it returns the singleton `MemoryStore` service instance.
- **Given** a query for `memory` budget **When** `getBudget('memory')` is called **Then** it returns remaining characters against the 2,200 character ceiling.
- **Given** a query for `user` budget **When** `getBudget('user')` is called **Then** it returns remaining characters against the 1,375 character ceiling.
- **Given** a successful memory mutation committed to disk **When** mutation resolves **Then** `memory/changed` is emitted on the Cordis event bus with updated character count.

## Contracts

```typescript
import { Context, Service } from '@deepseek-ai/cordis'

export type MemoryTarget = 'memory' | 'user'
export type MemoryAction = 'add' | 'replace' | 'remove'

export interface MemoryNote {
  readonly id: string
  readonly content: string
  readonly sanitizedContent: string
  readonly isBlocked: boolean
}

export interface MemoryOperation {
  readonly action: MemoryAction
  readonly content?: string
  readonly oldText?: string
  readonly newText?: string
}

export interface MemoryBudget {
  readonly target: MemoryTarget
  readonly charLimit: number
  readonly currentChars: number
  readonly remainingChars: number
}

export interface MemoryBatchResult {
  readonly target: MemoryTarget
  readonly operationsApplied: number
  readonly notesCount: number
  readonly charCount: number
  readonly charLimit: number
  readonly notes: readonly MemoryNote[]
}

export const ENTRY_DELIMITER = '\n§\n'
export const MEMORY_CHAR_LIMIT = 2200
export const USER_CHAR_LIMIT = 1375

export class MemoryError extends Error {
  constructor(message: string, readonly code: string) {
    super(message)
    this.name = 'MemoryError'
  }
}
export class MemoryBudgetExceededError extends MemoryError {
  constructor(target: MemoryTarget, attempted: number, limit: number) {
    super(`Memory budget exceeded for ${target}: ${attempted} exceeds limit of ${limit}`, 'MEMORY_BUDGET_EXCEEDED')
  }
}

declare module '@deepseek-ai/cordis' {
  interface Context {
    memory: MemoryStore
  }
  interface Events {
    'memory/changed': (payload: { target: MemoryTarget; charCount: number }) => void
    'memory/drift-detected': (payload: { target: MemoryTarget; backupPath: string }) => void
  }
}

export abstract class MemoryStore extends Service {
  static inject = ['fs']
  constructor(ctx: Context, name = 'memory') {
    super(ctx, name, true)
  }
  abstract getNotes(target: MemoryTarget): Promise<readonly MemoryNote[]>
  abstract getRawContent(target: MemoryTarget): Promise<string>
  abstract getBudget(target: MemoryTarget): Promise<MemoryBudget>
  abstract mutate(target: MemoryTarget, operations: readonly MemoryOperation[]): Promise<MemoryBatchResult>
  abstract getTurnPromptSnapshot(): string
}
```

## Teach me while you build

Yo! Daru here. Time to build the memory store without any bloated junk.

- **What it does**: Defines the abstract `MemoryStore` service contract, character budgets, and event hooks for agent memory files.
- **Background**: Long-running agents accumulate notes over time. Without hard character ceilings and structured batch mutations, files explode in size and blow context windows.
- **How it works here**: Plugins implement `MemoryStore` extending Cordis `Service`. Consumers use `ctx.memory` to read notes, check budgets, and submit atomic mutations.
- **Why this approach**: Option A gives an abstract boundary with strict character limits and atomic operations, keeping callers decoupled from disk serialization.
- **Approaches considered**: Raw disk writes in tools (rejected: no central budgeting or concurrency control) vs SQLite relational storage (rejected: overkill for plain markdown notes) vs Abstract MemoryStore with delimited markdown files (chosen).
- **Prior art inspected**: no prior art inspected
- **What we get for free**: Cordis service lifecycle injection and typed event bus broadcasting.
- **What to notice**: Notice the strict character limits: `MEMORY_CHAR_LIMIT = 2200` and `USER_CHAR_LIMIT = 1375`. Budget checks happen before any disk mutation.
- **Concepts to own**: Capability seams, character-bounded storage domains, ambient TypeScript declarations.
- **Interview angle**: Why declare `MemoryStore` as an abstract class rather than an interface? Answer: Extending `Service` gives runtime Cordis integration and lifecycle injection while enforcing contracts.
- **Decisions you can now make alone**: You can implement different backend storage providers (e.g. SQLite or in-memory) matching `MemoryStore`.
- **Lesson**: Establish domain contracts and budget constraints at the service layer before writing storage engines.
