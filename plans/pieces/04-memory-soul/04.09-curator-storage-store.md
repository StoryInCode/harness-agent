# 04.09 — Curator Storage Domain and Audit Ledger Store

**Set:** 04-memory-soul · **Queue:** 9 · **Depends on:** none
**Status:** todo
**Harness primitive:** Service Provider · **Package:** `@deepseek-ai/dsh-memory-curator-store`

## Summary

Implements the durable persistence layer for the skill curator and self-learning engine using `ctx.storageDomain` (`curator` domain, version 1), completely replacing legacy plain `.curator_ledger.jsonl` and `.usage.json` files per REVIEW-storage findings. It defines the schema for `ledger` (audit log of state transitions, consolidations, and candidate promotions) and `usage` (skill invocation metrics and timestamps). It also generates content-addressed pre-consolidation backup tarballs under `~/.hermes/.curator_backups/blobs/<sha256>`.

## Behaviour

- **Given** host boot **When** the curator storage domain opens **Then** it registers schema-validated `ledger` and `usage` tables with synchronous in-memory read caching.
- **Given** a skill invocation **When** recorded **Then** the `usage` table updates `lastUsedAt`, `lastSessionId`, and increments `useCount` via the domain write chain.
- **Given** a skill state transition **When** recorded **Then** an immutable `CuratorLedgerEntry` is appended to the `ledger` table.
- **Given** a pre-consolidation backup snapshot **When** taken **Then** it generates a tarball, computes its SHA-256 digest, and stores the blob under `~/.hermes/.curator_backups/blobs/<sha256>`.
- **Given** a host restart **When** the domain reopens **Then** all usage records and ledger entries restore accurately without data loss.

## Harness fit

This component is a host-plane `Service Provider` opening `ctx.storageDomain` per Harness storage conventions (`packages/storage/storage-domain/README.md:152`), eliminating bespoke file lockfiles and manual JSONL recovery logic.

## Contracts

```typescript
import { z } from 'zod'
import { defineDomain, domainTable } from '@deepseek-ai/dsh-storage-domain'

export type SkillLifecycleState = 'active' | 'stale' | 'archived'

export interface SkillUsageRecord {
  readonly name: string
  readonly state: SkillLifecycleState
  readonly useCount: number
  readonly lastUsedAt: string
  readonly lastSessionId: string
  readonly updatedAt: string
}

export type CuratorLedgerAction =
  | 'state-transition'
  | 'skill-archived'
  | 'skill-reactivated'
  | 'consolidation-pass'
  | 'candidate-axiom-promoted'
  | 'memory-deletion-staged'

export interface CuratorLedgerEntry {
  readonly id: string
  readonly timestamp: string
  readonly action: CuratorLedgerAction
  readonly skillName?: string
  readonly fromState?: SkillLifecycleState
  readonly toState?: SkillLifecycleState
  readonly details: Readonly<Record<string, unknown>>
  readonly snapshotBlobSha256?: string
}

export const CURATOR_DOMAIN_VERSION = 1

export const curatorDomainSpec = defineDomain({
  name: 'curator',
  version: CURATOR_DOMAIN_VERSION,
  tables: {
    ledger: domainTable<string, CuratorLedgerEntry>(z.any()),
    usage: domainTable<string, SkillUsageRecord>(z.any()),
  },
})
```
