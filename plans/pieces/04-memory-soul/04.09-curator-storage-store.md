## Summary

Daru here. We are implementing the durable persistence layer for the skill curator and self-learning engine using `ctx.storageDomain` (`curator` domain, version 1), completely replacing legacy plain `.curator_ledger.jsonl` and `.usage.json` files per REVIEW-storage findings. It defines the schema for `ledger` (audit log of state transitions, consolidations, and candidate promotions) and `usage` (skill invocation metrics and timestamps). It also generates content-addressed pre-consolidation backup tarballs under `~/.dsh/.curator_backups/blobs/<sha256>`.

### Human Decision Point: Option A vs Option B
- **Option A (Active)**: Persist curator audit ledgers and skill usage via `ctx.storageDomain` with synchronous in-memory read caching and content-addressed SHA-256 backup tarballs, ensuring ACID write safety and crash recovery.
- **Option B (Alternative)**: Persist state via ad-hoc plain JSONL and JSON files on disk (`.curator_ledger.jsonl` and `.usage.json`), risking race conditions, partial writes, and lockfile contention during concurrent turns.

## Behaviour

- **Given** host boot **When** the curator storage domain opens **Then** it registers schema-validated `ledger` and `usage` tables with synchronous in-memory read caching.
- **Given** a skill invocation or state transition **When** recorded **Then** `usage` metrics update and an immutable `CuratorLedgerEntry` appends to `ledger` via the domain write chain.
- **Given** a pre-consolidation backup snapshot **When** taken **Then** it generates a content-addressed tarball stored by its SHA-256 digest under `.curator_backups/blobs/`.

## Harness fit

This component is a host-plane `Service Provider` opening `ctx.storageDomain` per Harness storage conventions (`packages/storage/storage-domain/src/index.ts:1-120`), eliminating bespoke file lockfiles and manual JSONL recovery logic.

## Contracts

```typescript
import { z } from 'zod'
import { defineDomain, domainTable } from '@deepseek-ai/dsh-storage-domain'

export type SkillLifecycleState = 'active' | 'stale' | 'archived'

export interface SkillUsageRecord {
  readonly name: string
  readonly state: SkillLifecycleState
  readonly useCount: number
  readonly lastUsedAt: string
  readonly lastSessionId: string
  readonly updatedAt: string
}

export type CuratorLedgerAction =
  | 'state-transition'
  | 'skill-archived'
  | 'skill-reactivated'
  | 'consolidation-pass'
  | 'candidate-axiom-promoted'
  | 'memory-deletion-staged'

export interface CuratorLedgerEntry {
  readonly id: string
  readonly timestamp: string
  readonly action: CuratorLedgerAction
  readonly skillName?: string
  readonly fromState?: SkillLifecycleState
  readonly toState?: SkillLifecycleState
  readonly details: Readonly<Record<string, unknown>>
  readonly snapshotBlobSha256?: string
}

export const CURATOR_DOMAIN_VERSION = 1

export const curatorDomainSpec = defineDomain({
  name: 'curator',
  version: CURATOR_DOMAIN_VERSION,
  tables: {
    ledger: domainTable<string, CuratorLedgerEntry>(z.any()),
    usage: domainTable<string, SkillUsageRecord>(z.any()),
  },
})
```

## Teach me while you build

Yo, hacker! Let's build rock-solid storage so we never lose telemetry when the process drops.

- **What it does**: Provides crash-resilient structured storage for skill usage metrics, lifecycle state audit logs, and content-addressed backup tarballs.
- **Background**: Unstructured JSONL files are vulnerable to torn writes during ungraceful process terminations. A storage domain provides atomic write serialization and schema enforcement.
- **How it works here**: Calls `ctx.storageDomain.open(curatorDomainSpec)` to create `ledger` and `usage` tables. Reads hit in-memory caches synchronously, while mutations append asynchronously to SQLite WAL storage. Pre-consolidation snapshots write SHA-256 content-addressed tarballs.
- **Why this approach**: Centralized storage domains eliminate bespoke lockfiles, torn writes, and fragile custom deserializers across the codebase.
- **Approaches considered**: Raw JSON files with advisory locks (rejected: fragile and prone to stale locks on SIGKILL), monolithic SQLite databases per package (rejected: schema fragmentation), and Cordis storage domains (chosen).
- **Prior art inspected**: Git object storage (content-addressed SHA-256 blob stores) and Git reflog architectures.
- **What we get for free**: Synchronous read caching, write-queue serialization, and crash-safe WAL persistence from `@deepseek-ai/dsh-storage-domain`.
- **What to notice**: Content-addressed blob paths (`~/.dsh/.curator_backups/blobs/<sha256>`) guarantee immutable rollback points before destructive consolidation passes.
- **Concepts to own**: Domain-driven storage, WAL-backed crash durability, synchronous cache layers, and content-addressable storage (CAS).
- **Interview angle**: How do you guarantee zero data corruption when multiple asynchronous tasks record telemetry? Use a write-ahead logging storage domain that serializes commits while serving synchronous in-memory read snapshots.
- **Decisions you can now make alone**: You can add new telemetry tables to `curatorDomainSpec` by incrementing the domain version number.
- **Lesson**: Don't roll your own JSON file persistence when the framework already provides bulletproof storage domains.
