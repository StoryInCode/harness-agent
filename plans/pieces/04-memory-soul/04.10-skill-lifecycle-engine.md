## Summary

Attention, lab members! The Organization's entropy threatens our capabilities! We are implementing the deterministic skill lifecycle state machine and periodic housekeeping engine. It transitions unreferenced skills from `active` to `stale` at 30 days of inactivity, and from `stale` to `archived` at 90 days. It strictly enforces the Skill Preservation Invariant: retired skills are never deleted, but safely moved into timestamped directories (`~/.dsh/skills/.archive/<name>-<YYYYMMDDHHMMSS>/`). When any agent invokes a stale skill, it is immediately reactivated to `active`. Housekeeping runs on a periodic timer with configurable `housekeepingTickIntervalMs` (`plans/REVIEW-lifecycle.md:84-88`).

### Human Decision Point: Option A vs Option B
- **Option A (Active)**: Transition skill states deterministically across `active` -> `stale` -> `archived` while moving retired skills to timestamped archive directories with zero file deletion, preserving full provenance.
- **Option B (Alternative)**: Permanently delete (`rm -rf`) stale skills past 90 days of inactivity, destroying historical code artifacts and preventing rollbacks or reactivation.

## Behaviour

- **Given** an active skill unreferenced for >30 days **When** housekeeping runs **Then** its state transitions to `stale` and emits `curator/transition`.
- **Given** a stale skill unreferenced for >90 days **When** housekeeping runs **Then** it moves to `.archive/<name>-<timestamp>/` and transitions to `archived` without deleting files.
- **Given** a skill in `stale` state **When** invoked via the `skill` tool **Then** it immediately reactivates to `active` and updates usage metrics.

## Harness fit

This component is a host-plane `workflow capability` executing deterministic decay transitions against `ctx.storageDomain` and notifying registries via `skills/change`.

## Teach me while you build

Fwahahaha! Listen closely, for the laws of causality govern our skills as well as time lines!

- **What it does**: Drives monotonic state transitions for skill decay (`active` -> `stale` -> `archived`) and preserves historical skill knowledge without destructive file deletion.
- **Background**: Software agents accumulate skills over time. Stale skills bloat the model prompt context, but deleting them destroys valuable learned procedures.
- **How it works here**: Periodic housekeeping evaluates skill inactivity against `staleAfterDays` and `archiveAfterDays`. When archiving, the skill folder is moved into a timestamped `.archive/` path and recorded in the curator ledger. If invoked again, it reactivates to `active` immediately.
- **Why this approach**: Preservation through archiving avoids catastrophic loss of hard-earned capabilities while still clearing prompt pollution.
- **Approaches considered**: Indefinite skill retention (rejected: prompt context explosion and higher inference cost), hard deletion via `rm -rf` (rejected: unforgivable destruction of knowledge timeline), and monotonic archiving with instant reactivation (chosen).
- **Prior art inspected**: Garbage collection generational hypothesis and Least Recently Used (LRU) cache eviction algorithms.
- **What we get for free**: Event notifications across Cordis contexts to alert running sessions of skill state transitions.
- **What to notice**: The `archive` transition never unlinks or truncates code files; it performs an atomic directory relocation to ensure complete provenance.
- **Concepts to own**: Monotonic state transitions, soft deprecation, event-driven reactivation, and non-destructive archival.
- **Interview angle**: How do you prevent context window bloat from unused tools without risking user workflow disruption? Apply a soft-decay lifecycle where unreferenced tools demote to archived cold storage but reactivate automatically on demand.
- **Decisions you can now make alone**: You can configure custom decay thresholds (`staleAfterDays`, `archiveAfterDays`) for aggressive or conservative pruning.
- **Lesson**: The timeline of knowledge must never be erased; divergence is managed by archiving, not destruction! El Psy Kongroo.
