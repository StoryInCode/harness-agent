## Summary

Deductive assessment indicates creating a new session search package would introduce redundant logic with a probability of 1.0. We reuse the existing `@deepseek-ai/dsh-tool-session-query` package to provide historical transcript search for the Brain orchestrator (`plans/REVIEW-seams.md` Finding 2). It configures five shipped read-only tools (`session_search`, `session_event_search`, `session_trace`, `session_event_trace`, `session_event_read`) backed by `ctx.sessionQuery`, enforcing workspace `cwd` authorization, cooperative query deadlines (`searchTimeoutMs: 15000`), and result bounding (`maxSearchResults: 20`).

### Human Decision Point: Option A vs Option B
- **Option A (Active)**: Reuse the shipped `@deepseek-ai/dsh-tool-session-query` package with tuned query deadlines and result bounding (`maxSearchResults: 20`), preventing package duplication and guaranteeing workspace-authorized audit trails.
- **Option B (Alternative)**: Author a bespoke memory-specific session search tool package, which duplicates SQLite full-text search logic, fragments tool names, and increases maintenance overhead across the repo.

## Behaviour

- **Given** an agent session mounting `tool-session-query` **When** `session_search` is called with a query **Then** it returns matching session hits bounded by `maxSearchResults: 20` within `searchTimeoutMs: 15000`.
- **Given** a search hit for an authorized session **When** the model calls `session_event_read` **Then** it retrieves the unabridged JSON event payload.
- **Given** a caller in workspace A querying a session created in workspace B **When** executed **Then** access is denied due to workspace `cwd` mismatch.

## Harness fit

This component is an existing model-facing `Consumer` plugin (`packages/session-query/tool-session-query/src/index.ts:1-136`) mounted in `dev-loop-brain` that delegates to host `ctx.sessionQuery` without duplicating packages or causing tool registration collisions.

## Teach me while you build

Let us examine the evidence methodically. Uncontrolled inquiry is an invitation to failure.

- **What it does**: Exposes historical session query tools to the model while constraining result limits and execution timeouts to protect inference resources.
- **Background**: Autonomous agents generate large volumes of session logs. Querying past transcripts without bounded pagination easily exhausts model context windows.
- **How it works here**: The plugin registers 5 tools (`session_search`, `session_event_search`, `session_trace`, `session_event_trace`, `session_event_read`) that delegate to `ctx.sessionQuery` while filtering against caller `cwd` and capping results at `maxSearchResults`.
- **Why this approach**: Reusing the existing `@deepseek-ai/dsh-tool-session-query` package eliminates a 100% redundant implementation and leverages proven SQLite BM25 indexing.
- **Approaches considered**: Building a second memory-specific session search tool (rejected: probability of duplicate code and maintenance debt is 1.0), loading entire session files directly (rejected: token explosion), and configuring the existing tool-session-query plugin (chosen).
- **Prior art inspected**: SQLite FTS5 extension architecture and BM25 ranking algorithms.
- **What we get for free**: Built-in workspace isolation and projection decoding from `@deepseek-ai/dsh-tool-session-query`.
- **What to notice**: Workspace filtering strictly prevents cross-tenant or cross-directory log leakage by matching the session creation `cwd`.
- **Concepts to own**: Epistemic bounds, cooperative query deadlines, and bounded retrieval pagination.
- **Interview angle**: Why enforce cooperative deadlines (`searchTimeoutMs`) on local search tools? To prevent runaway SQLite queries from hanging the agent loop.
- **Decisions you can now make alone**: You can tune `maxSearchResults` per agent profile without modifying query engine internals.
- **Lesson**: Forensic evidence retrieval must always be bounded in both time and output volume to preserve operational stability.
