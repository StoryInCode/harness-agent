## Summary

An isolated observation provides only 50% confidence; however, recurrence across two independent sessions establishes a statistically significant pattern. Implements Invariant `M-013`: promoting recurring lessons and defects discovered across multiple independent sessions into candidate axioms. When a procedural constraint or environment failure recurs across >= 2 independent sessions, it stages a candidate proposal document to `~/.dsh/candidate-axioms/<id>.json` and emits `'curator/candidate-axiom-promoted'`. It maintains a strict dependency edge to the Colocated Axioms subsystem (`03.01`, `03.08`), enabling canonical promotion to target `AGENTS.md` files without duplicating axiom evaluation logic.

### Human Decision Point: Option A vs Option B
- **Option A (Active)**: Require empirical recurrence across at least two independent sessions before staging candidate axioms, preventing single-session noise from polluting repository rules.
- **Option B (Alternative)**: Immediately promote any single-session failure or ad-hoc lesson to repository-wide axioms, leading to rule proliferation and over-constraining the agent.

## Behaviour

- **Given** a lesson recorded in a single session **When** evaluated **Then** it is retained in review notes without triggering candidate axiom promotion.
- **Given** the same lesson recurs in a second independent session **When** evaluated **Then** it stages a proposal at `~/.dsh/candidate-axioms/<id>.json` and emits `'curator/candidate-axiom-promoted'`.
- **Given** a staged candidate proposal **When** approved for canonical promotion **Then** it delegates to `ctx.axiomPromoter.promoteToColocatedAxiom()` (`03.08`) to append the rule to `AGENTS.md`.
- **Given** a proposed candidate payload lacking required occurrence metadata **When** validation runs **Then** it rejects the proposal before writing to disk.

## Contracts

```typescript
import { Context } from '@deepseek-ai/cordis'
import type { SessionId } from '@deepseek-ai/dsh-session'
import type { AxiomId } from '@deepseek-ai/dsh-axiom'

export interface CandidateAxiomOccurrence {
  readonly sessionId: SessionId
  readonly taskId?: string
  readonly timestamp: string
  readonly contextSnippet: string
}

export interface CandidateAxiomProposal {
  readonly id: string                  // "cand_ax_" + 8 hex chars
  readonly statement: string
  readonly reason: string
  readonly occurrences: readonly CandidateAxiomOccurrence[]
  readonly proposedTargetAgentsMd?: string
  readonly createdAt: string
}

declare module '@deepseek-ai/cordis' {
  interface Events {
    'curator/candidate-axiom-promoted': (proposal: CandidateAxiomProposal) => void
  }
}

export class CandidateAxiomPromoter {
  constructor(ctx: Context, candidateAxiomsDir?: string)
  recordLessonOccurrence(
    key: string,
    occurrence: CandidateAxiomOccurrence,
    statement: string,
    reason: string,
    proposedTarget?: string,
  ): Promise<CandidateAxiomProposal | null>
  listCandidateProposals(): Promise<readonly CandidateAxiomProposal[]>
}
```

## Teach me while you build

We observe the recurrence of system behaviors across isolated environments. Data without replication is merely noise.

- **What it does**: Detects recurring defect patterns across independent sessions, promoting lessons that recur across two or more sessions into staged candidate axiom proposals.
- **Background**: Epistemic hygiene requires that rules written into `AGENTS.md` reflect verified empirical constraints rather than transient single-session hallucinations or user idiosyncrasies.
- **How it works here**: When `recordLessonOccurrence` is called with a deduplication `key`, the promoter checks past occurrences in memory or storage. If fewer than 2 independent sessions are recorded, it stores the occurrence and returns `null`. On the second independent session occurrence, it generates a `CandidateAxiomProposal` with an 8-character hex ID, writes JSON to `~/.dsh/candidate-axioms/<id>.json`, and emits `'curator/candidate-axiom-promoted'`.
- **Why this approach**: Gating promotion on independent session recurrence filters out 90%+ of one-off flukes and transient environment quirks.
- **Approaches considered**: Immediate single-session promotion (rejected: rule explosion and over-fitting to flukes) vs manual user tagging only (rejected: misses autonomous discovery of recurring system defects) vs multi-session recurrence staging with human-in-the-loop promotion (chosen).
- **Prior art inspected**: `archive/plans/06-curator-and-self-learning.md:515-538` (recurrence evaluation and candidate axiom staging).
- **What we get for free**: Colocated axiom formatting and AST file updates are delegated entirely to the existing `03.08` promoter (`plans/pieces/03-axioms/03.08-task-axiom-promoter.md`).
- **What to notice**: Notice that occurrence matching requires distinct `sessionId` values; multiple failures within the same session count as one occurrence!
- **Concepts to own**: Evidence correlation across independent runs: distinguishing systematic defects from transient stochastic variance.
- **Interview angle**: How do you prevent an autonomous self-improving system from poisoning its own prompt instructions? Answer: Require multi-session corroboration, stage proposed modifications as inspectable artifacts, and require human approval before landing them into governing instructions.
- **Decisions you can now make alone**: You can tune the recurrence threshold or customize proposal metadata fields without touching the file-writing engine.
- **Lesson**: One observation is an anomaly; two independent observations form a hypothesis; verified evidence justifies a law.
