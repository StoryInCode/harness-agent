## Summary

Mwahahaha! Listen well, lab members! To prevent the cognitive decay of our autonomous system without interrupting active foreground turns, the Review Fork Dispatcher triggers background review forks every 10 foreground turns (`nudgeInterval: 10`) via a serial listener on `agent/turn-stopping`. It invokes `ctx.subagents.start('spawn', ...)` with sandboxed prompt templates and a strictly restricted tool allowlist (`skill`, `read_file`, `fs_search`, `skill_manage`, `memory`). Crucially, it enforces an unyielding anti-recursion lineage check (`isReviewAgent`) to prevent infinite review loops, and severs in-flight review subagents when the parent session is disposed (`plans/REVIEW-lifecycle.md`). El Psy Kongroo!

### Human Decision Point: Option A vs Option B
- **Option A (Active)**: Dispatch background review as an isolated child subagent via `ctx.subagents.start('spawn')` with parent lifecycle abortion linkage, preserving foreground responsiveness while bounding token waste.
- **Option B (Alternative)**: Execute synchronous in-band memory consolidation inside the foreground turn loop, which stalls operator interactions and introduces turn latency spikes.

## Behaviour

- **Given** a foreground agent completing turns 1 through 9 **When** `agent/turn-stopping` fires **Then** the turn counter increments without spawning a subagent.
- **Given** turn 10 completes on a foreground agent **When** `agent/turn-stopping` fires **Then** it resets the counter and launches a review subagent via `ctx.subagents.start()`.
- **Given** an active review subagent **When** `agent/turn-stopping` fires for that child **Then** `isReviewAgent` returns true and exits immediately without incrementing counters or recursing.
- **Given** an in-flight review subagent **When** the parent session is disposed **Then** the child review run is aborted immediately, preventing orphaned background executions.

## Harness fit

This component is a `subagent consumer` hooking `agent/turn-stopping` (`packages/core/agent/src/runtime-types.ts:391`) and delegating child execution to `ctx.subagents.start()` (`packages/subagent/subagent/src/index.ts:560-580`). It bridges session lifecycle cleanup through Cordis context events.

## Teach me while you build

Mwahahaha! Let us observe the intricate fabric of spacetime and subagent concurrency!

- **What it does**: Dispatches a background review subagent every 10 foreground turns while safeguarding world-line stability against recursive self-invocation and orphaned subagent execution.
- **Background**: Autonomous agents accumulate operational observations across turns. Periodic memory synthesis must occur without interrupting user flow or triggering runaway review cascades.
- **How it works here**: On `agent/turn-stopping` in `packages/core/agent/src/runtime-types.ts:391`, the dispatcher increments a session-keyed turn counter. At turn 10, it verifies `!isReviewAgent(agent)`, resets the counter, and calls `ctx.subagents.start('spawn')` from `packages/subagent/subagent/src/index.ts:560`. It records the child `SubagentRun` in an active review map. When the parent session emits disposal, `abortReviewForSession` aborts the child run immediately.
- **Why this approach**: Out-of-band asynchronous review preserves operator turn latency, while strict lineage checking prevents the subagent from reviewing its own review turns.
- **Approaches considered**: In-band synchronous review (rejected: blocks foreground user turns by 5-15 seconds) vs detached daemon process (rejected: loses Cordis context boundaries and session credential sharing) vs isolated child subagent with parent lifecycle coupling (chosen).
- **Prior art inspected**: `plans/REVIEW-lifecycle.md:60-69` (Finding 4 on orphaned review subagent lifecycle coupling).
- **What we get for free**: `ctx.subagents.start` provides complete sandbox encapsulation, token accounting, and cancellation propagation without manual process management.
- **What to notice**: Notice how `isReviewAgent` halts evaluation before incrementing counters, preventing child review turns from ever triggering grandson reviews!
- **Concepts to own**: Lineage guards and supervisor lifecycle binding: child task lifecycles must remain strictly bounded by parent lifespans.
- **Interview angle**: How do you prevent background maintenance tasks from starving foreground request threads or creating infinite task cascades? Answer: Enforce modular interval counters, lineage metadata tags, and hard cancellation linkages to parent lifespans.
- **Decisions you can now make alone**: You can adjust `nudgeInterval` or customize the child tool allowlist without risking recursive fork loops.
- **Lesson**: Unchecked autonomy leads to madness and resource exhaustion; bind child task lifespans unconditionally to parent scopes! El Psy Kongroo.
