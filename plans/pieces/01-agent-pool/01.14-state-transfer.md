## Summary

Projects route switches, quota exhaustion events, and takeover records into durable session state. Registers the `agentPoolState` session projection to track active model assignments, handover lineages, tool call idempotency keys, and remaining token/step budgets across model handovers. Ensures clean state handoff across transitions without transcript loss or history corruption.

### Human Decision Point: Option A vs Option B
- **Option A (Active)**: Maintain model handover lineages and tool idempotency keys in an in-memory session projection derived monotonically from durable session events (`session.append`).
- **Option B (Alternative)**: Store handover state in mutable plugin-private memory or separate sidecar SQLite databases, risking desynchronization and transcript replay drift.

## Behaviour

- **Given** an automatic takeover event `agent-pool/takeover` appended to the session **When** the projection reduces the event **Then** `activeRoute` updates to the replacement model and the handover is recorded in the lineage list.
- **Given** a takeover occurring after tool calls completed **When** the replacement model begins execution **Then** tool execution state is preserved as idempotent, preventing re-execution of committed tool calls.
- **Given** a session replay or reload from disk **When** projection state rebuilds from the transcript **Then** the exact model lineage, turn intervals, and takeover points are faithfully reconstructed.

## Harness fit

This component is a `session projection` registered on `ctx.sessionProjections` (`packages/llm/llm-retry/src/index.ts:125-138`). It maintains an in-memory projection derived strictly from durable session events (`session.append`).

## Teach me while you build

Yo, Daru here! You think passing state between AI models is just copying a dictionary? Hell no! If you don't anchor every handover in append-only event logs, your session replay turns into a corrupted glitch fest!

- **What it does**: Reduces model takeover events into an in-memory session projection tracking active routes, handover history, tool call idempotency keys, and remaining step budgets.
- **Background**: Cordis session projections are pure state reducers that process immutable events appended to `agent.session`. They allow plugins to inspect session history without re-scanning raw JSONL logs.
- **How it works here**: The plugin registers `agentPoolState` via `ctx.sessionProjections.register`. When `agent-pool/takeover` or `agent-pool/route-exhausted` events fire, the `apply` reducer computes the next immutable state, updating the active model and appending to the lineage array.
- **Why this approach**: Deriving state strictly from the session event stream guarantees that transcript replay from disk produces the exact same runtime state as live execution.
- **Approaches considered**: In-memory module singleton (rejected: state is wiped on crash or reload) vs Dedicated SQLite sidecar table (rejected: creates dual sources of truth outside the session log) vs Event-sourced session projection (chosen).
- **Prior art inspected**: `packages/llm/llm-retry/src/index.ts:125-138`, inspecting `ctx.sessionProjections.register` schema, key, and reducer pattern.
- **What we get for free**: Built-in serialization, snapshot caching, and event replay from `@deepseek-ai/dsh-session-projection`.
- **What to notice**: Notice that tool call idempotency keys are retained across handovers so the new model doesn't re-run tools executed before exhaustion struck.
- **Concepts to own**: Event Sourcing and Projections: treating the event stream as the single source of truth and modeling current state as a deterministic fold over events.
- **Interview angle**: How do you avoid state divergence when an agent session is rehydrated from disk? Answer: Projections are pure functions `(State, Event) -> State`; replaying identical events guarantees identical state.
- **Decisions you can now make alone**: You can safely add custom metrics to `AgentPoolSessionState` as long as their values derive purely from session events.
- **Lesson**: If it isn't logged in the session stream, it didn't happen. Never store cross-turn state in volatile variables.
