## Summary

Reconciles DeepSeek Harness's provider and model inventory against permitted access declarations without hardcoding model identifiers or guessing endpoints. Queries `ctx.llm.listProviders()`, `ctx.llm.listConfigurableProviders()`, `ctx.llm.listModels()`, and `ctx.credentials.describe()` to discover live routes and endpoints from the running environment. Categorizes every candidate route into four strictly distinguishable states: `discovered`, `configured`, `access-unverified`, and `currently-usable`. Dynamically updates candidate availability upon observing `llm/adapters-updated` events.

### Human Decision Point: Option A vs Option B
- **Option A (Active)**: Multi-state monotonic reconciliation pipeline (`discovered` -> `configured` -> `access-unverified` -> `currently-usable`) driven by dynamic `llm/adapters-updated` event observation.
- **Option B (Alternative)**: Static one-time boot discovery that assumes fixed provider endpoints and fails to reflect hotplugged adapter extensions or credential changes.

## Behaviour

- **Given** an adapter advertising a provider endpoint **When** discovery inspects the route **Then** it records the model in state `discovered` with endpoint metadata and input modalities.
- **Given** a discovered model with configured credentials **When** non-destructive verification passes access policies from 01.01 **Then** its readiness state advances to `currently-usable`.
- **Given** a live topology change event `llm/adapters-updated` **When** the event fires **Then** the discovery service re-evaluates provider routes, reconciling newly added or removed adapters without restarting the host.
- **Given** a discovered model that violates access policies **When** discovery filters models **Then** the model is omitted from candidate sets with an explicit exclusion reason.

## Harness fit

This is a `Service Provider` mounted on the host plane (`ctx.agentPoolDiscovery`) extending `@deepseek-ai/cordis.Service`. It consumes `ctx.llm` discovery endpoints (`packages/llm/llm/src/index.ts:468-520`) and `ctx.credentials.describe` (`packages/credentials/credentials/src/index.ts:187-192`), subscribing to `llm/adapters-updated` via `ctx.on()`.

## Contracts

```typescript
export type RouteReadinessState =
  | 'discovered'
  | 'configured'
  | 'access-unverified'
  | 'currently-usable'

export interface DiscoveredRoute {
  providerId: string
  modelId: string
  displayName: string
  state: RouteReadinessState
  contextWindow?: number
  maxTokens?: number
  isSubscription?: boolean
  exclusionReason?: string
  lastDiscoveredAt: number
}

export interface AgentPoolDiscoveryService {
  discoverAll(): Promise<readonly DiscoveredRoute[]>
  reconcileRoute(providerId: string, modelId: string): Promise<DiscoveredRoute>
  listUsableRoutes(): Promise<readonly DiscoveredRoute[]>
}
```

## Teach me while you build

Observe the divergence of routes! Every endpoint in this multidimensional model space must be tracked through an exact causal chain.

- **What it does**: Dynamically discovers model routes across adapters and transitions their availability through a verified 4-state lifecycle.
- **Background**: Modern agent harnesses host diverse LLM adapters. Routes can appear, mutate credentials, or fail auth dynamically without a full process reboot.
- **How it works here**: The discovery service queries `ctx.llm.listModels()` and `ctx.credentials.describe()`, filters against `ctx.agentPoolAccess`, and tracks route readiness transitions.
- **Why this approach**: Monotonic progression prevents unverified or malformed routes from receiving agent traffic while allowing hot-plug updates.
- **Approaches considered**: Periodic polling (rejected: wastes CPU and delays topology sync) vs Static YAML manifest (rejected: cannot adapt to dynamic runtime providers) vs Event-driven reactive reconciliation (chosen: immediate reaction to `llm/adapters-updated`).
- **Prior art inspected**: Envoy service discovery and endpoint health state machines.
- **What we get for free**: Cordis event emitter (`ctx.on('llm/adapters-updated', ...)`) provides clean pub/sub mechanics across decoupled plugins.
- **What to notice**: Notice the explicit state distinction between `configured` (credentials present) and `currently-usable` (credential check verified and admitted by policy).
- **Concepts to own**: Monotonic state progression: state only advances forward to usable upon meeting rigorous verification predicates.
- **Interview angle**: How do you avoid race conditions when external API keys or models are dynamically reconfigured? Answer: Transition routes through unverified staging states before committing to active routing tables.
- **Decisions you can now make alone**: You can add new adapter telemetry attributes to `DiscoveredRoute` without invalidating existing routing states.
- **Lesson**: The world line of a route must be proven through strict verification before it can influence reality. El Psy Kongroo!
