# 01.02 — Catalog Discovery and Route Reconciliation

**Set:** 01-agent-pool · **Queue:** 2 · **Depends on:** 01.01
**Status:** todo
**Harness primitive:** Service Provider · **Package:** `@deepseek-ai/dsh-agent-pool-discovery`

## Summary

Reconciles DeepSeek Harness's provider and model inventory against permitted access declarations without hardcoding model identifiers or guessing endpoints. Queries `ctx.llm.listProviders()`, `ctx.llm.listConfigurableProviders()`, `ctx.llm.listModels()`, and `ctx.credentials.describe()` to discover live routes and endpoints from the running environment. Categorizes every candidate route into four strictly distinguishable states: `discovered`, `configured`, `access-unverified`, and `currently-usable`. Dynamically updates candidate availability upon observing `llm/adapters-updated` events.

## Behaviour

- **Given** an adapter advertising a provider endpoint **When** discovery inspects the route **Then** it records the model in state `discovered` with endpoint metadata and input modalities.
- **Given** a discovered model with a corresponding settings profile **When** discovery resolves settings **Then** its status advances to `configured`.
- **Given** a configured route whose credential reference exists but whose live auth check has not run **When** state reconciliation evaluates it **Then** it is marked `access-unverified`.
- **Given** an access-unverified route that passes access policy and successfully completes a non-destructive credential check **When** verification succeeds **Then** it is marked `currently-usable`.
- **Given** a live topology change event `llm/adapters-updated` **When** the event fires **Then** the discovery service re-evaluates provider routes, reconciling newly added or removed adapters without restarting the host.
- **Given** a discovered model that violates access policies from `01.01` **When** discovery filters models **Then** the model is omitted from candidate sets with an explicit exclusion reason.

## Harness fit

This is a `Service Provider` mounted on the host plane (`ctx.agentPoolDiscovery`) extending `@deepseek-ai/cordis.Service`. It consumes `ctx.llm` discovery endpoints (`packages/llm/llm/src/index.ts:468-520`) and `ctx.credentials.describe` (`packages/credentials/credentials/src/index.ts:187-192`), subscribing to `llm/adapters-updated` via `ctx.on()`.

## Contracts

```typescript
export type RouteReadinessState =
  | 'discovered'
  | 'configured'
  | 'access-unverified'
  | 'currently-usable'

export interface DiscoveredRoute {
  providerId: string
  modelId: string
  displayName: string
  state: RouteReadinessState
  contextWindow?: number
  maxTokens?: number
  isSubscription?: boolean
  exclusionReason?: string
  lastDiscoveredAt: number
}

export interface AgentPoolDiscoveryService {
  discoverAll(): Promise<readonly DiscoveredRoute[]>
  reconcileRoute(providerId: string, modelId: string): Promise<DiscoveredRoute>
  listUsableRoutes(): Promise<readonly DiscoveredRoute[]>
}
```
