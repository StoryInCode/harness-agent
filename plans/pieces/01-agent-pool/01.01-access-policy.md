## Summary

Enforces declarative provider and model boundary constraints across permitted access channels without hardcoding endpoint capabilities. It restricts OpenRouter to genuinely free-tier routes while strictly forbidding silent paid siblings or fallbacks, confines OpenCode Go access to Muse and DeepSeek V4.1 while permanently excluding all other Go models, verifies GLM subscription as an independent route isolated from Go restrictions, ensures OpenAI, Gemini, and Claude use supported subscription paths without paid API or Vertex substitution, and isolates OpenCode Zen free-tier models from Go.

### Human Decision Point: Option A vs Option B
- **Option A (Active)**: Declarative fail-closed policy enforcement evaluating route rules (free-tier constraints, permanent exclusions, subscription channel isolation) before catalog admission.
- **Option B (Alternative)**: Permissive dynamic runtime filtering that defers authorization to downstream request dispatchers and risks leaky fallback billing.

## Behaviour

- **Given** an OpenRouter route configuration **When** access verification checks the route **Then** only models declaring a free pricing tier are admitted, and any route falling back to a paid sibling is rejected with `PAID_ROUTE_FORBIDDEN`.
- **Given** an OpenCode Go route reporting multiple available models **When** filtering applies **Then** only discovered models matching Muse or DeepSeek V4.1 are admitted, and all other Go models are permanently excluded with `MODEL_PERMANENTLY_EXCLUDED`.
- **Given** subscription declarations for OpenAI, Gemini, or Claude **When** routes are configured **Then** only supported subscription credential channels are accepted, and requests attempting paid API key or Vertex substitution fail with `UNSUPPORTED_ACCESS_CHANNEL`.
- **Given** a GLM subscription or OpenCode Zen route **When** access boundaries are evaluated **Then** they are admitted via their isolated namespaces independently of OpenCode Go restrictions.

## Harness fit

This component is a `Service Provider` mounted on the host plane (`ctx.agentPoolAccess`) extending `@deepseek-ai/cordis.Service`. It validates declared access boundaries against the settings and credential abstractions (`packages/credentials/credentials/src/index.ts:154-185`) before catalog discovery or execution commences.

## Contracts

```typescript
export type AccessCategory =
  | 'openrouter-free'
  | 'opencode-go-restricted'
  | 'glm-subscription'
  | 'subscription-oauth'
  | 'opencode-zen-free'

export interface AccessDeclaration {
  category: AccessCategory
  providerId: string
  modelPattern?: string
  allowedModelIds?: readonly string[]
  forbiddenFallbacks?: readonly string[]
}

export interface AccessPolicyViolation {
  providerId: string
  modelId: string
  category: AccessCategory
  reason: 'PAID_ROUTE_FORBIDDEN' | 'MODEL_PERMANENTLY_EXCLUDED' | 'UNSUPPORTED_ACCESS_CHANNEL'
}

export interface AgentPoolAccessService {
  isAdmissible(providerId: string, modelId: string): boolean
  validateRoute(providerId: string, modelId: string, category: AccessCategory): AccessPolicyViolation | undefined
  listDeclarations(): readonly AccessDeclaration[]
}
```

## Teach me while you build

Observe the access vectors closely. In forensic security, any ambiguity in route authorization represents a critical vulnerability.

- **What it does**: Enforces boundary rules on external LLM access routes, rejecting unauthorized paid fallbacks and untrusted endpoints.
- **Background**: Multi-provider harnesses risk accidental token spend or credential leakage if model routes silently fall back to commercial endpoints.
- **How it works here**: Declarations in `dsh-agent-pool-access` match incoming provider and model IDs against `AccessDeclaration` rules before any outbound query reaches `packages/llm/llm-pi-ai/src/config.ts:90-140`.
- **Why this approach**: Fail-closed gate evaluation guarantees that unexpected provider configurations fail at admission rather than mid-execution.
- **Approaches considered**: Dynamic runtime tagging (rejected: allows unauthorized requests to reach provider networks before failing) vs Pure compile-time types (rejected: provider model rosters are dynamic) vs Declarative admission policy (chosen: verified before dispatch).
- **Prior art inspected**: Kubernetes Admission Controllers (validating webhook pattern for workload access).
- **What we get for free**: Cordis service isolation ensures policy state in `ctx.agentPoolAccess` is accessible across any consumer plugin.
- **What to notice**: Notice that OpenCode Go and OpenCode Zen share underlying transport protocols but are strictly partitioned at the policy boundary.
- **Concepts to own**: Principle of Least Privilege: ensuring agents only access explicitly declared and approved computational routes.
- **Interview angle**: How do you prevent unexpected cloud billing spikes in autonomous agent loops? Answer: Fail-closed declarative routing policies checked before network egress.
- **Decisions you can now make alone**: You can add new restricted provider categories by registering a new `AccessDeclaration` rule without changing provider drivers.
- **Lesson**: If an access route is not explicitly proven free or permitted, the only safe default probability is zero.
