## Summary

Tracks real-time route availability separately from quality scores across three distinct quota scopes: account-level (limits affecting all routes under a provider account), model-level (rate limits unique to a specific model), and shared-bucket level (collective limits, such as OpenCode Go allocations). Manages status transitions across `available`, `exhausted`, `probing`, `degraded`, and `disabled`. When a shared bucket exhausts, all associated routes immediately transition to `exhausted` without requiring independent failures.

### Human Decision Point: Option A vs Option B
- **Option A (Active)**: Track quota availability across discrete scopes (account, model, shared-bucket) with synchronous in-memory state and persistent domain storage.
- **Option B (Alternative)**: Rely on lazy per-request error interception without scope aggregation, causing repeated redundant failures across sibling models in shared buckets.

## Behaviour

- **Given** an exhaustion event on a route with scope `shared-bucket` **When** exhaustion is recorded **Then** all models mapped to that shared bucket transition to `exhausted` simultaneously.
- **Given** a route reporting rate-limit exhaustion under scope `model` **When** exhaustion is recorded **Then** only that specific model transitions to `exhausted` while sibling models remain `available`.
- **Given** an exhausted route whose reset timer expires or probe succeeds **When** availability is updated **Then** the route transitions from `probing` back to `available`.

## Harness fit

This is a `Service Provider` mounted on the host plane (`ctx.agentPoolQuota`) extending `@deepseek-ai/cordis.Service`. It persists availability state into `ctx.storageDomain` while providing synchronous memory reads for low-latency routing decisions.

## Contracts

```typescript
export type QuotaScope = 'account' | 'model' | 'shared-bucket'
export type AvailabilityState = 'available' | 'exhausted' | 'probing' | 'degraded' | 'disabled'

export interface RouteAvailability {
  routeKey: string
  state: AvailabilityState
  scope: QuotaScope
  bucketKey?: string
  exhaustedAt?: number
  resetAt?: number
  lastProbeAt?: number
  failureReason?: string
}

export interface AgentPoolQuotaService {
  getAvailability(routeKey: string): RouteAvailability
  markExhausted(routeKey: string, scope: QuotaScope, bucketKey?: string, resetAt?: number, reason?: string): Promise<void>
  markProbing(routeKey: string): Promise<void>
  markAvailable(routeKey: string): Promise<void>
  listUnavailableRoutes(): readonly RouteAvailability[]
}
```

## Teach me while you build

A route's availability state in the world line is not a mere binary toggle! It transitions through strict states—available, exhausted, probing, degraded, disabled—governed by quota scopes.

- **What it does**: Maintains real-time availability states across account, model, and shared-bucket quota scopes, cascading exhaustion across shared resources instantly.
- **Background**: Modern LLM providers bundle multiple distinct models under a single account or token bucket (such as OpenCode Go sharing a single quota between models). Tracking limits at the wrong scope leads to cascading retry failures.
- **How it works here**: `AgentPoolQuotaService` manages route availability state maps. When an exhaustion event fires with scope `shared-bucket`, all routes sharing `bucketKey` transition to `exhausted` simultaneously.
- **Why this approach**: Multi-scope tracking prevents "thundering herd" probe loops where an agent tries sibling models that are guaranteed to fail due to shared bucket exhaustion.
- **Approaches considered**: Flat per-model tracking (rejected: wastes requests trying siblings under an exhausted shared quota) vs Account-level global locks (rejected: overly aggressive, taking down unrelated independent routes) vs Hierarchical multi-scope tracker (chosen).
- **Prior art inspected**: AWS Token Bucket rate limiting and Envoy cluster circuit breakers with layered priority tiers.
- **What we get for free**: Memory-efficient projection mapping and structured error extraction from `packages/llm/llm/src/types.ts:40-51`.
- **What to notice**: Notice how `RouteAvailability` records `bucketKey` alongside `scope`, ensuring that shared allocations transition monotonically in a single pass.
- **Concepts to own**: Circuit breaker pattern with hierarchical scope: isolating failure domains to the minimum set of affected resources.
- **Interview angle**: How do you prevent cascade failures when multiple model endpoints share an underlying quota pool? Answer: Track availability by shared bucket scope so exhausting the pool marks all associated routes unavailable in O(1) without requiring individual downstream request errors.
- **Decisions you can now make alone**: You can introduce provider-specific quota resets by populating `resetAt` from provider headers without touching the core routing state machine.
- **Lesson**: The timeline remains stable only when failure boundaries mirror the exact topology of the provider's resource allocation! El Psy Kongroo!
