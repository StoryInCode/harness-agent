# 01.07 — Manual Pinning and Strict Pin Failure Guard

**Harness primitive:** Service Provider · **Package:** `@deepseek-ai/dsh-agent-pool-pinning`

## Summary

Manages user-defined and operator-defined model pins per role or session, enforcing strict fail-stop semantics when a pinned model becomes unavailable. When a pinned route experiences quota exhaustion, authentication failure, or endpoint outage, the system strictly halts execution and raises an explicit operator alert, refusing silent overrides or unapproved fallbacks. Persists manual pins across catalog refresh cycles and runtime restarts.

### Human Decision Point: Option A vs Option B
- **Option A (Active)**: Fail-stop upon pinned route exhaustion, pausing the session and raising an explicit `PINNED_ROUTE_EXHAUSTED` operator alert with zero automatic fallback.
- **Option B (Alternative)**: Automatically failover to the next available model in the role's fallback chain, violating the operator's explicit pinning constraint.

## Behaviour

- **Given** an operator pin command for role `Brain` specifying an exact preset **When** `setPin('Brain', presetId)` is called **Then** that preset is locked as the mandatory model for the Brain, bypassing automated fallback chains.
- **Given** an active strict pin on a preset that suffers quota exhaustion **When** model execution fails **Then** automatic takeover is suspended, execution pauses, and an alert is emitted with `PINNED_ROUTE_EXHAUSTED`.
- **Given** a paused session due to a failed pin **When** an operator unpins the role or clears the exhaustion state **Then** execution resumes from the exact boundary without state corruption.

## Harness fit

This is a `Service Provider` mounted on the host plane (`ctx.agentPoolPinning`) extending `@deepseek-ai/cordis.Service`. It persists pinning records via `ctx.storageDomain` under the `agent-pool` domain and guards selection in `@deepseek-ai/dsh-agent-pool-selector`.

## Contracts

```typescript
import type { AgentPoolRole } from '@deepseek-ai/dsh-agent-pool-roles'

export interface RolePin {
  role: AgentPoolRole
  presetId: string
  sessionId?: string
  isStrict: boolean
  pinnedAt: number
  pinnedBy: string
}

export interface PinFailureAlert {
  role: AgentPoolRole
  presetId: string
  error: string
  pausedAt: number
}

export interface AgentPoolPinningService {
  setPin(pin: RolePin): Promise<void>
  getPin(role: AgentPoolRole, sessionId?: string): Promise<RolePin | undefined>
  removePin(role: AgentPoolRole, sessionId?: string): Promise<boolean>
  handlePinFailure(role: AgentPoolRole, error: string): Promise<PinFailureAlert>
  listPins(): Promise<readonly RolePin[]>
}
```

## Teach me while you build

There is no room for ambiguity when an investigator verifies an invariant. An explicit pin is an absolute bound.

- **What it does**: Locks a role or session to an exact model preset and halts execution fail-stop if that model fails, preventing unauthorized fallback.
- **Background**: Automated routing uses fallback chains when a model fails; manual pinning overrides this by asserting that only the specified model is acceptable.
- **How it works here**: `AgentPoolPinningService` stores pin records in `ctx.storageDomain`. When the selector runs, it checks `getPin()`. If a pin exists, it returns only that preset. If execution fails, `handlePinFailure()` emits `PINNED_ROUTE_EXHAUSTED` and pauses the agent loop.
- **Why this approach**: Explicit pins express intentional operator constraints. Silently falling back to an unapproved model violates the operator's explicit invariant.
- **Approaches considered**: Silent automated fallback to secondary models (rejected: violates explicit operator intent) vs Advisory warning with fallback (rejected: allows unverified model execution) vs Fail-stop execution with pause and explicit alert (chosen).
- **Prior art inspected**: HashiCorp Consul service pinning and Kubernetes node pinning (`nodeSelector`), which fail-stop rather than scheduling pods to unpinned nodes.
- **What we get for free**: Cordis service lifecycle and storage domain persistence via `packages/storage/storage-domain/src/index.ts:21-65`.
- **What to notice**: Notice that `handlePinFailure` records `pausedAt` and returns `PinFailureAlert` without mutating session state or advancing the turn.
- **Concepts to own**: Fail-stop invariant: a design principle where a subsystem immediately halts upon detecting a constraint violation instead of continuing in an uncertain state.
- **Interview angle**: Why is fail-stop behavior preferable to automated fallback for pinned resources? Answer: Automated fallback masks underlying outages and can violate security, cost, or consistency bounds.
- **Decisions you can now make alone**: You can safely introduce session-scoped pin overrides that take precedence over role-wide pins without altering the fail-stop error path.
- **Lesson**: Never substitute an automated fallback when the operator has established an explicit pin constraint.
