## Summary

Renders the interactive agent pool dashboard and management panels in the browser client. Allows users to inspect role pools, read preset explanations and curator rationales, observe active model selections, view fallback chains, manage manual pins, trigger catalog refreshes, and understand why specific routes are excluded or unavailable. Strictly displays "unknown" for unobserved or unverified metrics rather than invented values, showing role, stage, model, next fallback, confidence, quota status, reset countdown, and next heartbeat.

### Human Decision Point: Option A vs Option B
- **Option A (Active)**: Mount an interactive client UI extension into the settings slot system using observable snapshot stores and strictly rendering "unknown" for unobserved metrics.
- **Option B (Alternative)**: Poll the backend server on arbitrary timers and interpolate placeholder default values for unverified metrics, obscuring real telemetry state.

## Behaviour

- **Given** the user navigating to the Agent Pool view **When** the component renders **Then** it displays a card for each role pool indicating active model, next fallback, confidence rating, quota state, reset time, and next heartbeat.
- **Given** an unverified metric or absent reset timer **When** rendered in the UI **Then** the field displays "unknown" instead of an invented or guessed placeholder.
- **Given** a user clicking "Pin Model" on a candidate card **When** submitted **Then** the action dispatches the pin request to `@deepseek-ai/dsh-agent-pool-pinning` and updates the UI state immediately.

## Harness fit

## Teach me while you build

Tut-turii~ Mayuri is designing the dashboard! A warm and clear interface helps operators feel calm and confident while watching their model fleet!

- **What it does**: Provides a reactive browser UI extension mounted in the settings view, allowing users to inspect role pools, pin models, force catalog refreshes, and inspect exclusion reasons.
- **Background**: DeepSeek Harness web interfaces use declarative slot extensions. Plugins contribute UI cards and settings panels that mount into predefined extension points via Typert RPC remotes.
- **How it works here**: The extension registers a slot component rendered at `/settings/agent-pool`. It subscribes to snapshot store changes, rendering `RoleCardViewModel` components. Actions like pin/unpin call RPC remote methods, updating the store immediately.
- **Why this approach**: Integrating into the existing client slot contract preserves consistent design language, styling tokens, and accessible button primitives across all settings panels.
- **Approaches considered**: Standalone bespoke web app (rejected: fractures navigation and requires separate authentication) vs Raw iframe embed (rejected: poor performance, styling mismatches, and broken keyboard navigation) vs Declarative client UI slot extension (chosen).
- **Prior art inspected**: `packages/client/ui-settings-models/src/client/ModelsSection.tsx:1-60`, inspecting provider editor cards, action buttons, and modal dialogs.
- **What we get for free**: Primitive components (buttons, modals, typography, icons) provided by `@deepseek-ai/dsh-client-ui-primitives`.
- **What to notice**: Notice that any unverified quota or heartbeat metric strictly renders as the literal string "unknown", honoring the harness epistemic integrity axioms.
- **Concepts to own**: Epistemic Truth in UI Design: never let the interface invent or hallucinate default numbers when backend measurements are absent.
- **Interview angle**: How do you maintain UX integrity when real-time backend telemetry is incomplete? Answer: Explicitly render an "unknown" status rather than fallback zeros or dummy estimates, preventing operators from acting on false data.
- **Decisions you can now make alone**: You can add new action buttons or filter tabs to the agent pool dashboard while maintaining slot compatibility.
- **Lesson**: A trustworthy UI shows what is known with clarity, and shows what is unknown with complete honesty. Tut-turii~
