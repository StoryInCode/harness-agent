## Summary

Coordinates weekly periodic catalog refresh cycles, processes on-demand manual refresh triggers, and dynamically reconciles catalog state in response to live provider topology notifications (`llm/adapters-updated`). Executes atomic catalog updates that preserve the last-known-good catalog snapshot, manual exclusions, and pins, while strictly preventing newly discovered but unscored models from being auto-adopted into critical roles.

### Human Decision Point: Option A vs Option B
- **Option A (Active)**: Perform atomic catalog updates that retain the last-known-good snapshot on failure and isolate unscored models until curator evaluation completes.
- **Option B (Alternative)**: Overwrite the active catalog in-place during discovery, exposing running sessions to transient provider failures and unvalidated models.

## Behaviour

- **Given** a scheduled weekly timer tick or manual trigger **When** a refresh cycle runs **Then** discovery and curator evaluation execute in the background without blocking active agent sessions.
- **Given** an adapter topology update via `llm/adapters-updated` **When** the event fires **Then** the reconciler checks for added or removed routes, marking disappeared routes unavailable without dropping historical metadata.
- **Given** a refresh cycle encountering network or provider failure **When** the update aborts **Then** the previous last-known-good catalog snapshot is retained with zero disruption.

## Harness fit

This component is an `event/hook plugin` mounted on the host plane subscribing to `llm/adapters-updated` (`packages/llm/llm/src/index.ts:345-378`) and managing recurring timer intervals using `ctx.setInterval()`.

## Teach me while you build

Fwahaha! The topology of world lines is ever shifting! If a provider adapter changes or the weekly cron triggers, we must reconcile the catalog atomically without disturbing active sessions.

- **What it does**: Automates background catalog refreshes on a weekly schedule and on live topology changes, reconciling routes without interrupting active sessions.
- **Background**: Language model providers continually update available models and rates. A reactive scheduler keeps the catalog fresh while isolating in-flight tasks.
- **How it works here**: An event/hook plugin registers a listener on `llm/adapters-updated` via `ctx.on()`, and schedules periodic ticks via `ctx.setInterval()`. When invoked, `triggerRefresh` runs discovery, computes diffs, and writes to `ctx.storageDomain`.
- **Why this approach**: Out-of-band background reconciliation prevents catalog discovery from introducing latency spikes or mid-turn model swaps into user sessions.
- **Approaches considered**: In-band lazy discovery per request (rejected: introduces unpredictable multi-second latency to user turns) vs Synchronous blocking updates (rejected: stalls running agents) vs Non-blocking event-driven background reconciliation (chosen).
- **Prior art inspected**: Envoy dynamic endpoint discovery (EDS) and Kubernetes CoreDNS periodic reconciliation loops.
- **What we get for free**: Cordis timer isolation via `ctx.setInterval` and non-vetoing event dispatch in `packages/llm/llm/src/index.ts:345-378`.
- **What to notice**: Notice that unscored models discovered during refresh remain sequestered until curator research scores them, preventing unverified route adoption.
- **Concepts to own**: Eventual consistency with last-known-good fallback: maintaining an immutable snapshot that remains valid until the next generation cleanly commits.
- **Interview angle**: How do you refresh dynamic service catalogs in zero-downtime environments? Answer: Use out-of-band reconciliation that commits new state atomically and falls back to last-known-good snapshots on network failure.
- **Decisions you can now make alone**: You can add jitter to the weekly cron interval to prevent thundering herds across clustered nodes.
- **Lesson**: The Organization's chaos cannot penetrate our defenses if we commit state atomically and preserve our last-known-good timeline! El Psy Kongroo!
