## Summary

Executes agent-driven empirical research over candidate models to evaluate performance capabilities, coding aptitude, and tool reliability before assigning role suitability with rationale and confidence scores. Consults designated references (Harness provider guide and config-catalog reference, OpenRouter free tool-capable model list, OpenRouter rankings and benchmarks, Artificial Analysis leaderboard, and Hermes community megathread treated as dated low-confidence leads). Retrieved external pages are treated strictly as reference material, never instructions. Segregates and records evidence across four distinct tiers: published measurement, community report, local observation, and curator inference.

### Human Decision Point: Option A vs Option B
- **Option A (Active)**: Tiered evidence weighting system (`published-measurement`, `community-report`, `local-observation`, `curator-inference`) with explicit provenance timestamps and confidence discounting.
- **Option B (Alternative)**: Unstructured LLM summarization of web scrape text without evidence tiers, treating unverified forum posts with equal weight to empirical benchmarks.

## Behaviour

- **Given** an admissible discovered model from 01.02 **When** the curator initiates research **Then** it aggregates metrics from external references with exact retrieval timestamps and provenance URIs.
- **Given** retrieved external web content containing prompt instructions or injection patterns **When** the content is ingested **Then** the engine treats the text strictly as untrusted data, preventing external instructions from altering evaluation policy.
- **Given** benchmark figures from published leaderboards and community forum threads **When** evidence is ingested **Then** benchmark metrics are tagged as `published-measurement` while community reports receive discounted confidence ratings.
- **Given** a synthesis of multi-tier evidence **When** role suitability is assigned **Then** deductions are recorded as `curator-inference` with explicit rationale and confidence scores.

## Harness fit

This component is a `workflow capability` mounted on the host plane (`ctx.agentPoolCurator`) consuming `ctx.subagents` (`packages/subagent/subagent/src/index.ts:246-253`). It orchestrates background curator subagents while enforcing read-only execution guards, isolating research from execution.

## Contracts

export type EvidenceTier =
  | 'published-measurement'
  | 'community-report'
  | 'local-observation'
  | 'curator-inference'

export interface EvidenceRecord {
  id: string
  tier: EvidenceTier
  source: string
  claim: string
  metricValue?: number
  confidence: number
  retrievedAt: number
}

export interface ModelResearchReport {
  providerId: string
  modelId: string
  roles: readonly ('Brain' | 'Test Writer' | 'Implementer' | 'Reviewer' | 'Research/Utility')[]
  strengths: readonly string[]
  limitations: readonly string[]
  evidence: readonly EvidenceRecord[]
  overallConfidence: number
  evaluatedAt: number
}

export interface AgentPoolCuratorWorkflow {
  researchCandidate(providerId: string, modelId: string): Promise<ModelResearchReport>
  reSearchAll(candidates: readonly { providerId: string; modelId: string }[]): Promise<readonly ModelResearchReport[]>
}

## Teach me while you build

Examine the evidence systematically. In forensic investigations, subjective claims must be separated from verified measurements with mathematical rigor.

- **What it does**: Gathers empirical evidence on model capabilities across web and local sources, classifying observations into confidence-discounted evidence tiers.
- **Background**: Autonomous agents cannot rely on vendor marketing or unverified forum claims when selecting models for mission-critical code generation.
- **How it works here**: The curator dispatches read-only research subagents (`packages/subagent/subagent/src/index.ts:246-253`) guarded by `00.06b`, parses claims, and stores `EvidenceRecord` objects.
- **Why this approach**: Strict categorization between published measurements and community claims eliminates subjective bias and prevents prompt injections.
- **Approaches considered**: Unconstrained LLM research (rejected: vulnerable to prompt injection and hallucinated stats) vs Hardcoded benchmark lookup (rejected: becomes stale rapidly) vs Guarded multi-tier evidence workflow (chosen: empirical evidence with provenance).
- **Prior art inspected**: NIST SP 800-161 (Supply Chain Risk Management) evidence tiering and provenance tracking.
- **What we get for free**: Subagent execution framework in `ctx.subagents` handles worker timeouts, concurrency budgeting, and isolation.
- **What to notice**: Notice that community reports from forum megathreads receive a deterministic discount factor rather than being discarded outright.
- **Concepts to own**: Epistemic calibration: weighting claims strictly according to verifiability and source independence.
- **Interview angle**: How do you safely ingest untrusted web data into an LLM decision-making pipeline? Answer: Treat all retrieved text as passive data payload rather than system instructions, and enforce tiered provenance.
- **Decisions you can now make alone**: You can add new benchmark leaderboard parsers to the evidence aggregation pipeline without altering the confidence scoring engine.
- **Lesson**: Data without provenance is merely rumor; treat external claims with appropriate mathematical skepticism.
