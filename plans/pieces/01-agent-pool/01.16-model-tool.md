## Summary

Exposes the `agent_pool_inspect` tool to the Brain orchestrator and subagents. Enables models to programmatically query role pools, review eligible candidate presets, read curator rationales and model limitations, and inspect real-time quota and availability conditions. Empowers the Brain to make informed task delegation decisions aligned with empirical strengths and current operational constraints.

### Human Decision Point: Option A vs Option B
- **Option A (Active)**: Expose a dedicated, schema-validated model tool (`agent_pool_inspect`) returning compact JSON views of role candidate presets, empirical strengths, and quota states.
- **Option B (Alternative)**: Inject the complete model catalog and quota state into the system prompt on every turn, causing massive context token bloat and cache churn.

## Behaviour

- **Given** the Brain calling `agent_pool_inspect({ role: 'Implementer' })` **When** the tool executes **Then** it returns the list of candidate presets for Implementer, including primary and fallback models, strengths, limitations, and current availability.
- **Given** an inspection call without parameters **When** executed **Then** it returns a summary overview of all five role pools and their currently selected models.
- **Given** a query for an exhausted route **When** returned **Then** the output clearly reports the route as exhausted along with its expected reset time if known.
- **Given** an invalid or unknown role argument **When** executed **Then** the tool returns a schema validation error listing the five permitted roles.

## Harness fit

This is a `model-facing tool` registered on `ctx.tools` (`packages/subagent/tool-subagent/src/index.ts:1-45`). It adheres strictly to the model-visible contract rules: outputs are concise, structured JSON without internal implementation leakage.

## Contracts

```typescript
import type { ToolSchema } from '@deepseek-ai/dsh-llm'
import type { AgentPoolRole } from '@deepseek-ai/dsh-agent-pool-roles'

export interface AgentPoolInspectParams {
  role?: AgentPoolRole
  includeExhausted?: boolean
}

export interface CandidatePresetView {
  presetId: string
  provider: string
  model: string
  confidence: number
  strengths: readonly string[]
  limitations: readonly string[]
  availability: string
  resetAt?: number
}

export interface AgentPoolInspectResult {
  role?: AgentPoolRole
  candidates: readonly CandidatePresetView[]
  totalCandidates: number
  availableCandidates: number
}

export const agentPoolInspectSchema: ToolSchema = {
  name: 'agent_pool_inspect',
  description: 'Inspect available model presets, strengths, limitations, and quota status across agent role pools',
  parameters: {
    type: 'object',
    properties: {
      role: {
        type: 'string',
        enum: ['Brain', 'Test Writer', 'Implementer', 'Reviewer', 'Research/Utility'],
        description: 'Optional role pool to inspect. Omit to view summary across all pools.',
      },
      includeExhausted: {
        type: 'boolean',
        description: 'Whether to include currently exhausted or probing models in the output.',
      },
    },
  },
}
```

## Teach me while you build

Nya~ (=^･ω･^=)🐾 Inspector Cat is here to inspect the entire model litter! How can the Brain pick the best cat for the job without sniffing out their skills and nap schedules?

- **What it does**: Registers the `agent_pool_inspect` tool on `ctx.tools`, allowing orchestrator models to query role pools, candidate rankings, strengths, limitations, and real-time quota status.
- **Background**: In multi-model agent systems, orchestrators need visibility into available worker capabilities and quota constraints without polluting turn prompt tokens when inspection is unnecessary.
- **How it works here**: The plugin defines `agent_pool_inspect` using `defineTool`. When invoked with an optional `role`, it queries `ctx.agentPoolRosters` and `ctx.agentPoolSelector`, returning a lightweight JSON payload with candidate preset IDs and availability flags.
- **Why this approach**: On-demand tool invocation provides dynamic, schema-checked model discovery without paying perpetual prompt context costs on turns where no delegation occurs.
- **Approaches considered**: Static prompt injection of all model metadata (rejected: bloats prompt context by thousands of tokens per turn) vs Unchecked freeform shell script query (rejected: breaks structured tool calling and hallucination guards) vs Schema-validated model-facing tool (chosen).
- **Prior art inspected**: `packages/subagent/tool-subagent/src/index.ts:1-45`, inspecting tool definition patterns and runtime schema binding on `ctx.tools`.
- **What we get for free**: Parameter validation, JSON Schema translation, and error formatting handled automatically by `@deepseek-ai/dsh-tools`.
- **What to notice**: Notice how omitting the `role` parameter yields a lightweight summary across all five pools, while supplying a role gives deep candidate views with strengths and limitations.
- **Concepts to own**: Just-In-Time Context Retrieval: exposing environment capabilities via tools rather than eager prompt stuffing to minimize token expenditure.
- **Interview angle**: Why prefer a model tool over static prompt documentation for dynamic runtime registries? Answer: Tools keep the baseline prompt small, load dynamic operational state only when needed, and enforce structured type contracts.
- **Decisions you can now make alone**: You can add new filter parameters (e.g. `minConfidence`) to the tool schema without changing provider routing mechanics.
- **Lesson**: Don't stuff the prompt with facts the model might not need this turn; give it a magnifying glass instead! Purr~
