## Summary

Implements the `/agent-pool` slash command family for operator inspection and control. Provides subcommands to list pool rosters (`/agent-pool pools`), inspect active selections and fallback chains (`/agent-pool status`), manage manual pins (`/agent-pool pin <role> <model>` / `/agent-pool unpin <role>`), trigger on-demand catalog refreshes (`/agent-pool refresh`), and manage manual model exclusions (`/agent-pool exclude <model> <reason>`). Formats output clearly with tabular summaries and transparent rationales.

### Human Decision Point: Option A vs Option B
- **Option A (Active)**: Implement a unified `/agent-pool` slash command family with dedicated subcommands (`status`, `pools`, `pin`, `unpin`, `refresh`, `exclude`) returning structured plain-text CLI tables.
- **Option B (Alternative)**: Create scattered individual top-level slash commands (`/pin-model`, `/pool-status`, `/refresh-catalog`) that crowd the command namespace and complicate discovery.

## Behaviour

- **Given** an operator running `/agent-pool status` **When** executed **Then** it prints a formatted status table displaying role, active model, next fallback, confidence rating, quota state, reset time, and next heartbeat.
- **Given** an operator running `/agent-pool pin Brain claude-3-7-sonnet` **When** executed **Then** the pin is locked via `@deepseek-ai/dsh-agent-pool-pinning` and a confirmation message is displayed.
- **Given** an operator running `/agent-pool refresh` **When** executed **Then** an immediate catalog refresh is dispatched via `@deepseek-ai/dsh-agent-pool-refresh` and the completion summary is printed.

## Teach me while you build

Yo! Super Hacker Daru here. When you're managing a fleet of AI models, you need a crisp command line that doesn't waste model tokens or make you click through five different browser menus!

- **What it does**: Registers the `/agent-pool` slash command with subcommands for checking status, listing rosters, pinning models to roles, forcing catalog refreshes, and recording exclusions.
- **Background**: Slash commands execute directly on the host plane against `ctx.commands` without invoking an LLM generation. They give operators zero-latency, zero-cost control over agent runtime state.
- **How it works here**: The plugin registers `/agent-pool` via `ctx.commands.register`. When dispatched, the handler parses the subcommand token and delegates to `ctx.agentPoolSelector`, `ctx.agentPoolPinning`, or `ctx.agentPoolRefresh`, formatting tabular output.
- **Why this approach**: A unified namespace (`/agent-pool <subcommand>`) keeps the root slash command catalog tidy while offering full administrative control over model allocations.
- **Approaches considered**: Separate top-level commands like `/pool-status` and `/model-pin` (rejected: clutters slash command discovery) vs Raw JSON RPC calls from the frontend (rejected: unavailable in headless terminal sessions) vs Unified hierarchical slash command (chosen).
- **Prior art inspected**: `packages/interaction/commands/src/index.ts:30-65`, inspecting `CommandDescriptor`, `CommandInvocation`, and handler registration contracts.
- **What we get for free**: Command autocomplete, argument parsing hooks, and terminal/Web execution routing provided by `@deepseek-ai/dsh-commands`.
- **What to notice**: Notice that pinning overrides automatic model selection until explicitly unpinned, and the status table highlights pinned models with an explicit indicator.
- **Concepts to own**: Host-Level Control Inversion: providing deterministic human control surfaces that operate out-of-band from the stochastic model generation loop.
- **Interview angle**: Why implement administrative features as slash commands rather than model tools? Answer: Slash commands bypass LLM inference entirely, guaranteeing immediate, deterministic execution without prompt overhead or cost.
- **Decisions you can now make alone**: You can easily add a new subcommand (like `/agent-pool test-route`) by extending the subcommand switch branch.
- **Lesson**: Keep administrative commands deterministic and cheap; never spend LLM tokens on operations the host can execute directly.
