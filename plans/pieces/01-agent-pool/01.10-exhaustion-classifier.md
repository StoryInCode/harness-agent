## Summary

Classifies model execution failures at the adapter boundary, strictly distinguishing genuine quota exhaustion from authentication errors, context length overflow, user cancellations, output token limits, and task budget exhaustion. Inspects `LlmFailure` machine codes, HTTP status codes (429 vs 401/403 vs 400), provider rate-limit headers (`retry-after`, `x-ratelimit-reset`), and error payloads to classify the failure, extracting exact reset timestamps when available. Prevents non-quota errors from triggering false-positive route failovers.

### Human Decision Point: Option A vs Option B
- **Option A (Active)**: Distinguish error causes forensically via structured status codes and headers, restricting automatic route failover exclusively to genuine quota exhaustion.
- **Option B (Alternative)**: Treat all non-200 provider errors uniformly as failover triggers, erroneously marking routes unavailable on bad credentials or oversized context prompts.

## Behaviour

- **Given** an HTTP 429 response or `RATE_LIMIT` code with quota exhausted messaging **When** the classifier evaluates the failure **Then** it classifies it as `quota-exhaustion` with `isQuotaExhausted: true` and extracts the reset timestamp if present.
- **Given** an HTTP 401 or 403 response or `AUTH` error code **When** evaluated **Then** it classifies the failure as `auth-failure` with `isQuotaExhausted: false`, barring false-positive route failover.
- **Given** a context length exceeded error code **When** evaluated **Then** it classifies the failure as `context-overflow`, directing recovery to compaction rather than route switching.

## Contracts

```typescript
import type { LlmFailure } from '@deepseek-ai/dsh-llm'

export type FailureClassification =
  | 'quota-exhaustion'
  | 'auth-failure'
  | 'context-overflow'
  | 'cancellation'
  | 'output-limit'
  | 'task-budget-exhausted'
  | 'transient-network'
  | 'unknown'

export interface ClassifiedFailure {
  classification: FailureClassification
  isQuotaExhausted: boolean
  isRecoverableByTakeover: boolean
  resetAt?: number
  providerRetryAfterMs?: number
  rawCode: string
  rawStatus?: number
  rawMessage: string
}

export interface AgentPoolExhaustionClassifierService {
  classify(failure: LlmFailure, signal?: AbortSignal): ClassifiedFailure
}
```

## Teach me while you build

Conflating an authentication failure or context overflow with a quota exhaustion event is a critical investigative defect. We deduce the exact failure classification by inspecting HTTP codes, provider machine codes, and header timestamps.

- **What it does**: Inspects model errors and normalizes them into an unambiguous classification taxonomy, preventing non-quota errors from triggering route failovers.
- **Background**: When a language model request fails, the failure could stem from quota exhaustion (429), expired API keys (401), context length overflow, client abort, or network resets. Treating all errors identically leads to false route disqualifications.
- **How it works here**: `AgentPoolExhaustionClassifierService` inspects the incoming `LlmFailure`. It evaluates HTTP status codes, matches known regex patterns via `isQuotaExceededError()` and `isContextWindowExceededError()`, and parses `providerRetryAfterMs`. It returns a structured `ClassifiedFailure`.
- **Why this approach**: Forensic classification ensures that failover logic only activates for recoverable capacity issues. Routing around an authentication failure or context overflow does not solve the root cause.
- **Approaches considered**: Monolithic catch-all error handling (rejected: masks credential misconfiguration and loops infinitely) vs String-only message matching (rejected: fragile across provider API changes) vs Structured multi-signal inspection of code, status, and headers (chosen).
- **Prior art inspected**: RFC 6585 (Additional HTTP Status Codes, Section 4: 429 Too Many Requests) and OpenAI API error reference documentation.
- **What we get for free**: Repository regex patterns `isQuotaExceededError` and `isContextWindowExceededError` from `packages/llm/llm/src/error.ts:80-100`.
- **What to notice**: Notice that `ClassifiedFailure` explicitly separates `isQuotaExhausted` from `isRecoverableByTakeover`, ensuring that cancellations and context overflows never mutate route availability.
- **Concepts to own**: Fault discrimination: categorizing faults by recovery domain (e.g. retryable, terminal, or redirectable) rather than transport error representations.
- **Interview angle**: Why is it critical to separate 429 quota exhaustion from 401 authentication errors in multi-provider routers? Answer: 429 indicates temporary capacity limits where switching routes can succeed; 401 indicates invalid credentials where switching routes masks security configuration defects.
- **Decisions you can now make alone**: You can add support for new provider-specific rate-limit headers (like `x-ratelimit-reset-requests`) by mapping them into `resetAt` during classification.
- **Lesson**: Forensic precision at the error boundary prevents superficial symptoms from triggering destructive failover cascades.
