# 01.10 — Quota Exhaustion Classifier and Error Taxonomy

**Set:** 01-agent-pool · **Queue:** 10 · **Depends on:** 01.09
**Status:** todo
**Harness primitive:** Service Provider · **Package:** `@deepseek-ai/dsh-agent-pool-exhaustion`

## Summary

Classifies model execution failures at the adapter boundary, strictly distinguishing genuine quota exhaustion from authentication errors, context length overflow, user cancellations, output token limits, and task budget exhaustion. Inspects `LlmFailure` machine codes, HTTP status codes (429 vs 401/403 vs 400), provider rate-limit headers (`retry-after`, `x-ratelimit-reset`), and error payloads to classify the failure, extracting exact reset timestamps when available. Prevents non-quota errors from triggering false-positive route failovers.

## Behaviour

- **Given** an HTTP 429 response or `RATE_LIMIT` code with quota exhausted messaging **When** the classifier evaluates the failure **Then** it classifies it as `quota-exhaustion` and extracts the reset timestamp if present.
- **Given** an HTTP 401 or 403 or code `AUTH` / `INVALID_CREDENTIAL` **When** evaluated **Then** it classifies the failure as `auth-failure`, barring the route from quota failover to avoid masking bad credentials.
- **Given** a context length exceeded error code **When** evaluated **Then** it classifies the failure as `context-overflow`, directing recovery to compaction rather than route switching.
- **Given** an aborted signal or user cancellation **When** evaluated **Then** it classifies the failure as `cancellation` without marking the route unavailable.
- **Given** a response terminating with finish reason `max-tokens` **When** evaluated **Then** it classifies the event as `output-limit` without affecting route availability.
- **Given** an agent exceeding its maximum step or dollar budget **When** evaluated **Then** it classifies the event as `task-budget-exhausted`.

## Harness fit

This is a `Service Provider` mounted on the host plane (`ctx.agentPoolExhaustion`) extending `@deepseek-ai/cordis.Service`. It normalizes failures emitted through `agent/request-error` (`packages/core/agent/src/runtime-types.ts:363`) and `LlmFailure` (`packages/llm/llm/src/types.ts:40-51`).

## Contracts

```typescript
import type { LlmFailure } from '@deepseek-ai/dsh-llm'

export type FailureClassification =
  | 'quota-exhaustion'
  | 'auth-failure'
  | 'context-overflow'
  | 'cancellation'
  | 'output-limit'
  | 'task-budget-exhausted'
  | 'transient-network'
  | 'unknown'

export interface ClassifiedFailure {
  classification: FailureClassification
  isQuotaExhausted: boolean
  isRecoverableByTakeover: boolean
  resetAt?: number
  providerRetryAfterMs?: number
  rawCode: string
  rawStatus?: number
  rawMessage: string
}

export interface AgentPoolExhaustionClassifierService {
  classify(failure: LlmFailure, signal?: AbortSignal): ClassifiedFailure
}
```
