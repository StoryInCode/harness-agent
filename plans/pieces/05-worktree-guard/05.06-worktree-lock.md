# 05.06 — Administrative Worktree Lock and PID Liveness Manager

## Summary

Manages administrative Git worktree locks using `git worktree lock --reason` tagged with the host process ID and task purpose. It prevents external Git routines (`git worktree prune`) or concurrent tasks from dismantling active checkouts. It features dead-lock detection using POSIX process probing (`process.kill(pid, 0)` catching `ESRCH`), safely unlinking stale locks abandoned by crashed workers while protecting live processes from accidental interference.

## Behaviour

- **Given** an allocated worktree **When** `lockWorktree` executes **Then** `git worktree lock` is applied with structured reason containing host PID and timestamp.
- **Given** a locked worktree **When** `getLockInfo` runs **Then** it extracts owning PID, reason string, and lock liveness status.
- **Given** a lock held by a live process **When** liveness probe runs **Then** `isLockLive` returns `true` and prevents unforced unlocking.
- **Given** a lock held by a deceased process (`ESRCH`) **When** liveness probe runs **Then** `isLockLive` returns `false`, classifying the lock as dead and reclaimable.
- **Given** a valid unlock request **When** `unlockWorktree` runs **Then** `git worktree unlock` is executed and lock files are cleared.

## Harness fit

This is a `workflow capability` primitive owned by `@deepseek-ai/dsh-worktree-lock`. It wraps Git's native worktree locking mechanism and augments it with process liveness probing. Centralizing lock management ensures that orphaned lock files from SIGKILL or power events are safely cleared without risking corruption of running tasks.

## Contracts

```typescript
export interface WorktreeLockInfo {
  readonly isLocked: boolean
  readonly pid?: number | undefined
  readonly reason?: string | undefined
  readonly isLive: boolean
}

export class WorktreeLockedError extends Error {
  constructor(readonly worktreePath: string, readonly lockInfo: WorktreeLockInfo) {
    super(`Worktree "${worktreePath}" is locked by PID ${lockInfo.pid ?? 'unknown'}: ${lockInfo.reason ?? 'no reason'}`)
    this.name = 'WorktreeLockedError'
  }
}

export interface WorktreeLockManager {
  lock(worktreePath: string, reason: string): Promise<void>
  unlock(worktreePath: string, forceIfDead?: boolean): Promise<void>
  getLockInfo(worktreePath: string): Promise<WorktreeLockInfo>
  isProcessLive(pid: number): boolean
}
```
