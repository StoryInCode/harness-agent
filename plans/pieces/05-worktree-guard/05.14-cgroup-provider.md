## Summary

Yo, Daru here. We're cutting through user-space bloat and inspecting systemd cgroup v2 metrics directly for the worker subagent slice (`hermes-work.slice`) under `/sys/fs/cgroup/`. It parses `memory.current`, `memory.max`, `memory.swap.current`, `memory.swap.max`, and `memory.oom.group`, evaluating RAM and swap consumption against configured aggregate slice ceilings (default 6 GiB RAM, 512 MiB swap). On non-Linux platforms, container environments without cgroup v2 delegation, or systems lacking systemd, it cleanly marks `cgroupAvailable: false` without crashing the rig.

### Human Decision Point: Option A vs Option B
- **Option A (Active)**: Directly read and parse `/sys/fs/cgroup/` cgroup v2 pseudo-files (`memory.current`, `memory.max`, `memory.swap.current`, `memory.oom.group`) with graceful fallback to `undefined` and `cgroupAvailable: false` on non-Linux or un-delegated hosts.
- **Option B (Alternative)**: Execute external CLI subprocesses such as `systemd-cgtop` or `systemctl show` on every admission tick, adding severe process spawn latency and failing completely inside unprivileged containers.

## Behaviour

- **Given** a Linux host with cgroups v2 mounted **When** `readSliceMetrics()` runs **Then** it parses current and maximum memory and swap usage for `hermes-work.slice`.
- **Given** a platform without cgroups v2 (macOS, Windows) or missing slice delegation **When** `readSliceMetrics()` runs **Then** it returns `undefined` and marks `cgroupAvailable: false` without throwing.
- **Given** `memory.oom.group` exists in the slice directory **When** read **Then** it notes whether atomic group OOM termination is enabled.

## Harness fit

This is a `Service Provider` primitive owned by `@deepseek-ai/dsh-guard-cgroup-provider`. It isolates low-level Linux cgroup v2 filesystem parsing from general resource admission. Isolating cgroup logic ensures that host degradation on non-Linux or containerized systems operates seamlessly.

## Teach me while you build

Listen up! When subagents run wild, they eat RAM like cheap ramen! Here's how we keep the rig from freezing without burning cycles on heavyweight daemons.

- **What it does**: Reads kernel memory counters directly from systemd cgroup v2 sysfs pseudo-files for the subagent worker slice.
- **Background**: Linux cgroup v2 organizes processes into a unified hierarchy where slices bound resource consumption through sysfs files.
- **How it works here**: Checks for `/sys/fs/cgroup/hermes-work.slice`. Reads `memory.current`, `memory.max`, `memory.swap.current`, `memory.swap.max`, and `memory.oom.group`. If missing or on macOS/Windows, returns `undefined` and sets `cgroupAvailable: false`.
- **Why this approach**: Direct sysfs file reads avoid process spawning overhead, keeping resource inspection fast and non-blocking during high-frequency admission checks.
- **Approaches considered**: Spawning `systemd-cgtop` via subprocess (rejected: massive spawn overhead and IPC latency) vs Parsing `/proc/meminfo` alone (rejected: lacks per-slice process isolation) vs Direct `/sys/fs/cgroup/` reading (chosen: zero-spawn, microsecond latency).
- **Prior art inspected**: Linux kernel cgroup v2 documentation (`Documentation/admin-guide/cgroup-v2.rst`) and systemd resource control specifications.
- **What we get for free**: Standard Node.js `node:fs/promises` provides asynchronous, non-blocking file reads across sysfs mount points.
- **What to notice**: If `memory.max` contains the string `max`, the slice is unbounded; the parser must normalize this to `Infinity` or configured ceiling instead of `NaN`.
- **Concepts to own**: Control groups (cgroups v2): kernel-level resource metering and containment boundaries.
- **Interview angle**: How do you monitor containerized worker resource usage in Node.js without shelling out? Answer: Read cgroup v2 sysfs control files directly and handle platform/delegation absences gracefully.
- **Decisions you can now make alone**: You can tune slice memory ceilings in configuration without altering kernel slice configurations.
- **Lesson**: Don't spawn CLI subprocesses to inspect kernel telemetry when sysfs exposes pseudo-files directly. Keep the plumbing direct and fast.
