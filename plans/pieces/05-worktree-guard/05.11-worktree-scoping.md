## Summary

Binds allocated Git worktrees to worker subagent sessions using Harness native session header and filesystem sandbox contracts, enforcing Invariant `INV-06 (Worktree Isolation)` with zero custom path-rewriting machinery. When subagents are spawned via `ctx.agents.create()`, it passes `meta: { cwd: worktree.path }`, immutably locking `SessionHeader.cwd`. `SandboxedFileSystem.checkedTarget()` resolves `workspaceRoot` directly to `session.header.cwd` and checks `isPathUnder(fresh.targetKey, workspaceRoot)`, mechanically throwing `FsError('FS_SANDBOX_DENIED')` if an agent attempts to write outside its worktree.

### Human Decision Point: Option A vs Option B
- **Option A (Active)**: Scope subagents natively by binding worktree paths to immutable `SessionHeader.cwd` and enforcing isolation via kernel `SandboxedFileSystem.checkedTarget()` fences.
- **Option B (Alternative)**: Implement bespoke path-rewriting interceptors or virtual filesystem overlays, introducing complex translation bugs and escape vectors.

## Behaviour

- **Given** an allocated worktree record **When** worker subagent is initialized via `ctx.agents.create({ meta: { cwd: worktree.path } })` **Then** `SessionHeader.cwd` is set to the worktree path and locked immutably.
- **Given** an active subagent executing in a worktree **When** it invokes `writeText` or `editText` inside the worktree **Then** the filesystem mutation succeeds.
- **Given** an active subagent executing in a worktree **When** it attempts to write to a path outside the worktree (e.g. main repository root) **Then** `SandboxedFileSystem` denies the write with `FS_SANDBOX_DENIED`.
- **Given** a subagent executing `tool-bash` or `tool-fs-search` **When** command executes without explicit directory **Then** it automatically defaults to `session.header.cwd`.

## Teach me while you build

Fwahahaha! Do you think rogue subagents can escape the absolute containment field established by the Mad Scientist? Never! Invariant INV-06 erects an impenetrable dimensional barrier around the worker's timeline!

- **What it does**: Binds child subagents immutably to their designated worktree directory, fencing filesystem writes through native sandbox policies.
- **Background**: If a worker subagent modifies files in the mainline repository checkout, it pollutes the master timeline and corrupts parallel agent runs.
- **How it works here**: When creating a subagent via `ctx.agents.create()`, we pass `meta: { cwd: worktree.path }`. The session immutably records this as `SessionHeader.cwd`. `SandboxedFileSystem.checkedTarget()` resolves `workspaceRoot` to `session.header.cwd` and rejects any write outside that tree with `FS_SANDBOX_DENIED`.
- **Why this approach**: Binding the worktree to the native `SessionHeader.cwd` contract automatically configures sandbox containment, bash execution, file searches, and system prompt variables without bespoke path rewriting.
- **Approaches considered**: Virtual filesystem path virtualization (rejected: leaky abstractions, symlink bugs, massive complexity) vs Subprocess chroot/unshare jail (rejected: requires Linux root/capabilities) vs Native SessionHeader cwd binding with kernel sandbox fencing (chosen: zero overhead, cross-platform).
- **Prior art inspected**: Linux mount namespaces (`CLONE_NEWNS`) and Node.js permission model (`--allow-fs-read`/`--allow-fs-write`).
- **What we get for free**: Native tools (`tool-bash`, `tool-fs`, `tool-lsp`) automatically inherit `session.header.cwd` without writing a single line of redirection code.
- **What to notice**: Notice how `checkedTarget` performs `isPathUnder` against a freshly resolved canonical path to prevent symlink traversal escapes!
- **Concepts to own**: Immutable execution context: embedding ambient security boundaries into durable session metadata at allocation time.
- **Interview angle**: How do you prevent multi-agent workspaces from trampling each other's filesystem state without containers? Answer: Bind each worker session to an isolated directory root and enforce boundary checks in the I/O capability layer.
- **Decisions you can now make alone**: You can configure custom read-only shared directories while keeping writes strictly contained in the worktree.
- **Lesson**: The strongest containment is not an added cage, but a foundation built so the boundary is the only reality the subject knows. El Psy Kongroo!
