# 05.11 — Subagent Worktree Scoping and Sandbox Fencing (INV-06)

**Set:** 05-worktree-guard · **Queue:** 11 · **Depends on:** 05.01, 05.04
**Status:** todo
**Harness primitive:** Consumer · **Package:** `@deepseek-ai/dsh-worktree-scoping`

## Summary

Binds allocated Git worktrees to worker subagent sessions using Harness native session header and filesystem sandbox contracts, enforcing Invariant `INV-06 (Worktree Isolation)` with zero custom path-rewriting machinery. When subagents are spawned via `ctx.agents.create()`, it passes `meta: { cwd: worktree.path }`, immutably locking `SessionHeader.cwd`. `SandboxedFileSystem.checkedTarget()` resolves `workspaceRoot` directly to `session.header.cwd` and checks `isPathUnder(fresh.targetKey, workspaceRoot)`, mechanically throwing `FsError('FS_SANDBOX_DENIED')` if an agent attempts to write outside its worktree.

## Behaviour

- **Given** an allocated worktree record **When** worker subagent is initialized via `ctx.agents.create({ meta: { cwd: worktree.path } })` **Then** `SessionHeader.cwd` is set to the worktree path and locked immutably.
- **Given** an active subagent executing in a worktree **When** it invokes `writeText` or `editText` inside the worktree **Then** the filesystem mutation succeeds.
- **Given** an active subagent executing in a worktree **When** it attempts to write to a path outside the worktree (e.g. main repository root) **Then** `SandboxedFileSystem` denies the write with `FS_SANDBOX_DENIED`.
- **Given** a subagent executing `tool-bash` or `tool-fs-search` **When** command executes without explicit directory **Then** it automatically defaults to `session.header.cwd`.
- **Given** prompt assembly **When** turn starts **Then** system prompt variable `cwd` reflects the exact isolated worktree path.
