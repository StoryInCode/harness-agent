## Summary

Inspects existing Git worktrees and branch references to detect collisions before creating directories or checking out branches. It parses `git worktree list --porcelain` into structured metadata and evaluates local branch registrations. When a conflict is detected—such as when parallel subagents execute sibling tasks or when a prior task crashed leaving disk residue—it computes deterministic, collision-safe fallback directory paths and branch names with unique suffixes.

### Human Decision Point: Option A vs Option B
- **Option A (Active)**: Parse `git worktree list --porcelain` to detect collisions proactively and allocate deterministic suffixed fallback paths and branch names when collisions occur.
- **Option B (Alternative)**: Blindly attempt `git worktree add` and rely on parsing arbitrary subprocess stderr strings when Git fails, leading to unhandled edge cases and race conditions.

## Behaviour

- **Given** an unallocated task ID and clean repository **When** `resolveCollisionFreePath` runs **Then** it returns standard path `.worktrees/<taskId>` and branch `kanban/<taskId>`.
- **Given** an occupied directory or registered worktree path **When** `resolveCollisionFreePath` runs **Then** it detects the collision and appends a 4-hex random suffix (`.worktrees/<taskId>-<hex4>`).
- **Given** a branch name already checked out in another worktree **When** `resolveCollisionFreeBranch` runs **Then** it allocates an isolated fallback branch `kanban/<taskId>-<hex4>`.
- **Given** output from `git worktree list --porcelain` **When** parsed **Then** it returns structured records containing worktree path, HEAD SHA, branch ref, and lock state.

## Harness fit

This is a `workflow capability` primitive owned by `@deepseek-ai/dsh-worktree-collision`. It encapsulates porcelain parsing and deterministic collision resolution algorithms invoked during worktree provisioning. Isolating collision logic avoids race conditions between concurrent subagents without burdening the core `WorktreeManager` service class.

```typescript
export interface PorcelainWorktreeEntry {
  readonly path: string
  readonly headSha: string
  readonly branch?: string | undefined
  readonly isLocked: boolean
  readonly lockReason?: string | undefined
  readonly isBare: boolean
}

export interface CollisionFreeResolution {
  readonly directoryPath: string
  readonly branchName: string
  readonly isFallback: boolean
  readonly originalTaskId: string
}

export interface CollisionResolver {
  parsePorcelainList(porcelainOutput: string): readonly PorcelainWorktreeEntry[]
  resolveCollisionFreePath(
    repoRoot: string,
    taskId: string,
    worktreesDirName?: string,
  ): Promise<CollisionFreeResolution>
  slugifyTaskId(taskId: string): string
}
```

## Teach me while you build

Yo, Daru here. Trying to allocate a worktree without checking if the folder already exists is like running into a raid boss without checking your inventory! You're gonna wipe!

- **What it does**: Parses `git worktree list --porcelain` and generates collision-free paths and branch names when parallel workers clash.
- **Background**: When multiple agents run concurrently or prior crashed sessions leave dirty directories behind, blind `git worktree add` fails and crashes the worker loop.
- **How it works here**: In `packages/dev-loop/worktree/src/git.ts:135-170`, `inventory()` parses porcelain entries to see registered trees. In `packages/dev-loop/worktree/src/index.ts:113-128`, `allocate()` verifies whether `attempted` path exists or collides before invoking Git.
- **Why this approach**: Option A parses porcelain data and safely suffixes fallback paths, whereas Option B tries blindly and crashes on filesystem collisions or branch name reuse.
- **Approaches considered**: Unchecked git worktree add (rejected: crashes on existing paths) vs Subprocess error string scraping (rejected: fragile and localization-dependent) vs Proactive porcelain inspection with fallback suffixing (chosen).
- **Prior art inspected**: Git worktree porcelain output specification (`git worktree list --porcelain -z`).
- **What we get for free**: Native Git porcelain NUL-delimited records prevent filename whitespace corruption without custom delimiters.
- **What to notice**: Look at how `inventory()` checks both filesystem path existence and Git internal registration, since an unlinked disk path is different from an active Git worktree.
- **Concepts to own**: Proactive conflict detection and deterministic disambiguation with unique suffixes.
- **Interview angle**: Why is parsing Git's `--porcelain` format preferred over standard CLI output? Answer: Porcelain guarantees machine-readable stability and avoids formatting breaks across Git versions and user locales.
- **Decisions you can now make alone**: You can configure custom worktree naming conventions without risking path collisions between sibling tasks.
- **Lesson**: Don't guess filesystem state from stderr; parse porcelain records up front and generate collision-safe fallback paths!
