## Summary

Synchronizes essential uncommitted or gitignored developer assets (e.g. `.env`, local configs) from the repository root into freshly allocated worktrees according to `.worktreeinclude` rules. It parses line-delimited path patterns, resolves target relative paths, and applies strict path containment checks using Harness `isPathUnder` to prevent directory traversal attacks (`../`, `/etc/shadow`) from escaping repository root boundaries. It creates symlinks with automatic physical copy fallback for directories or on Windows.

### Human Decision Point: Option A vs Option B
- **Option A (Active)**: Parse `.worktreeinclude` rules with strict canonical path containment (`isPathUnder`) and symlink creation with automatic physical copy fallback.
- **Option B (Alternative)**: Naively copy all untracked files or resolve arbitrary relative paths without containment checks, risking directory traversal exploits and duplicating multi-gigabyte build caches.

## Behaviour

- **Given** a repository with a `.worktreeinclude` listing `.env` **When** `syncIncludes` runs **Then** `.env` is materialized in the target worktree.
- **Given** an entry containing directory traversal elements (`../../etc/passwd` or `/etc/shadow`) **When** `syncIncludes` runs **Then** path containment validation rejects the path, logs a warning, and skips the item without throwing.
- **Given** a repository with no `.worktreeinclude` file **When** `syncIncludes` runs **Then** it completes as a clean no-op.
- **Given** execution on Windows or a filesystem lacking symlink rights **When** symlink creation fails **Then** it falls back to atomic file copying.

## Teach me while you build

Yo, Daru here. Leaving path resolution unvetted in a workspace sync script is how script kiddies end up dumping `/etc/passwd` right into your public worktree!

- **What it does**: Copies or symlinks uncommitted files (like `.env`) into new worktrees while blocking path traversal attacks (`../../etc/passwd`).
- **Background**: Git worktrees only check out tracked files. Local secrets and config files like `.env` don't exist in the worktree unless synchronized. But trusting arbitrary paths from a config file without canonicalization is an open invitation for directory traversal exploits!
- **How it works here**: In `packages/dev-loop/worktree/src/index.ts:114-122`, the filesystem service verifies containment using `fs.contains()`. `syncIncludes` resolves each target relative to the repo root and verifies that the canonical path stays strictly within the repository boundaries before symlinking or copying.
- **Why this approach**: Option A verifies canonical containment and prefers lightweight symlinks with copy fallback, whereas Option B blindly executes file operations that can overwrite arbitrary host files outside the repo.
- **Approaches considered**: Unrestricted file copying (rejected: traversal vulnerability) vs Mandatory symlinking (rejected: fails on Windows without developer mode) vs Contained symlinking with copy fallback (chosen).
- **Prior art inspected**: POSIX symlink specifications and Node fs.realpath traversal protection patterns.
- **What we get for free**: `ctx.fs.contains` provides robust path containment checks that resolve symlinks without manual regex or split logic.
- **What to notice**: Notice how symlink failure triggers a fallback to file copying, ensuring compatibility across Windows and restricted container environments.
- **Concepts to own**: Directory traversal mitigation via canonical path containment (`fs.contains`).
- **Interview angle**: How do you safely synchronize files referenced in user-defined config files? Answer: Canonicalize all paths with realpath and assert strict ancestor containment against the trusted root before performing filesystem mutations.
- **Decisions you can now make alone**: You can add support for directory recursion or globbing in include configs while maintaining strict containment.
- **Lesson**: Never trust relative paths in configuration files without canonical containment checks, or an attacker will read your secret keys!
