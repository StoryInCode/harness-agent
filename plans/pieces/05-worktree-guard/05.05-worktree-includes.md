# 05.05 — Worktree Include Synchronizer and Path Traversal Guard

**Set:** 05-worktree-guard · **Queue:** 5 · **Depends on:** 05.01
**Status:** todo
**Harness primitive:** workflow capability · **Package:** `@deepseek-ai/dsh-worktree-includes`

## Summary

Synchronizes essential uncommitted or gitignored developer assets (e.g. `.env`, local configs) from the repository root into freshly allocated worktrees according to `.worktreeinclude` rules. It parses line-delimited path patterns, resolves target relative paths, and applies strict path containment checks using Harness `isPathUnder` to prevent directory traversal attacks (`../`, `/etc/shadow`) from escaping repository root boundaries. It creates symlinks with automatic physical copy fallback for directories or on Windows.

## Behaviour

- **Given** a repository with a `.worktreeinclude` listing `.env` **When** `syncIncludes` runs **Then** `.env` is materialized in the target worktree.
- **Given** an include entry pointing to a subdirectory **When** `syncIncludes` runs **Then** parent directories are created and target entries linked or copied.
- **Given** an entry containing directory traversal elements (`../../etc/passwd` or `/etc/shadow`) **When** `syncIncludes` runs **Then** `isPathUnder` containment validation rejects the path, logs a warning, and skips the item without throwing.
- **Given** a repository with no `.worktreeinclude` file **When** `syncIncludes` runs **Then** it completes as a clean no-op.
- **Given** execution on Windows or a filesystem lacking symlink rights **When** symlink creation fails **Then** it falls back to atomic file copying.

## Harness fit

This is a `workflow capability` primitive owned by `@deepseek-ai/dsh-worktree-includes`. It encapsulates line-delimited config parsing and path containment verification. Isolating include synchronization prevents file sync logic from cluttering core worktree allocation while ensuring security containment guarantees.
