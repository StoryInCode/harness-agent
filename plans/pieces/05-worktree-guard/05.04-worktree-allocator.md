# 05.04 — Base Commit Pinning and Atomic Worktree Allocator

**Set:** 05-worktree-guard · **Queue:** 4 · **Depends on:** 05.01, 05.02, 05.03
**Status:** todo
**Harness primitive:** workflow capability · **Package:** `@deepseek-ai/dsh-worktree-allocator`

## Summary

Allocates an isolated Git worktree for an autonomous task from a recorded base commit. It resolves the freshest upstream ref or HEAD (`git rev-parse HEAD^{commit}`), pins the immutable 40-character base commit SHA in `WorktreeRecord`, provisions `.worktrees/<taskId>/` on dedicated branch `kanban/<taskId>`, and verifies `.worktrees/` is present in the root `.gitignore`. If worktree creation fails or is aborted, it executes an atomic rollback protocol to purge partial checkout directories, delete half-born branch refs, and prune Git admin records.

## Behaviour

- **Given** a task ID and repository root **When** `allocateWorktree` runs **Then** it queries `git rev-parse HEAD^{commit}`, pins the resulting SHA in `WorktreeRecord.baseCommit`, and creates the worktree directory.
- **Given** an allocation request with `syncBase: true` **When** remote tracking is available **Then** it checks remote upstream freshness before branching.
- **Given** a repository root whose `.gitignore` does not list worktrees **When** allocation executes **Then** it appends `.worktrees/` to `.gitignore`.
- **Given** an execution failure or abort signal during `git worktree add` **When** rollback triggers **Then** it removes partial files, deletes the newly created branch (`git branch -D`), runs `git worktree prune`, and throws structured `WorktreeAllocationError`.
- **Given** an allocated worktree **When** inspected **Then** `WorktreeRecord` contains the exact pinned base commit, branch name, path, and creation timestamp.

## Harness fit

This is a `workflow capability` primitive owned by `@deepseek-ai/dsh-worktree-allocator`. It encapsulates the transactional multi-step creation and rollback sequence. Separating allocation from high-level coordination guarantees atomicity and ensures that checkout errors or cancellation signals never leave orphaned branches or dirty filesystem residue.

## Contracts

```typescript
export interface WorktreeAllocator {
  allocate(options: WorktreeAllocateOptions): Promise<WorktreeRecord>
  resolveBaseCommit(repoRoot: string, baseRef?: string, signal?: AbortSignal): Promise<{ sha: CommitSha; label: string }>
  ensureGitignored(repoRoot: string, entry?: string): Promise<void>
  rollbackFailedAllocation(params: {
    repoRoot: string
    worktreePath: string
    branchName?: string | undefined
  }): Promise<void>
}

export class WorktreeAllocationError extends Error {
  constructor(
    readonly taskId: string,
    readonly worktreePath: string,
    readonly gitStderr: string,
  ) {
    super(`Failed to allocate worktree for task "${taskId}" at "${worktreePath}":\n${gitStderr.trim()}`)
    this.name = 'WorktreeAllocationError'
  }
}
```
