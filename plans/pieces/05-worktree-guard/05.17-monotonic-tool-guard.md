## Summary

Mwahaha! Let it be known that once a gate of Steins Gate closes, no power in the universe may pry it open! We register an owner-level monotonic tool execution guard via `ctx.tools.guard()` that evaluates synchronously inside `ToolRuntime.stagePreExecuteAndGuards` after `tools/pre-execute` and approval resolution. When a tool call arrives, it checks for `SOUL.md` mutations; if detected, it immediately vetoes execution (`INV-09`). If a heavy command or tool is detected and host memory is below absolute floor (1536 MiB) or headroom floor (3072 MiB), it immediately vetoes execution (`INV-12`). Because `ToolGuard` returns `string | undefined`, returning a denial string guarantees immediate, irreversible denial with `isError: true` that no downstream waterfall listener or approval prompt can ever subvert!

### Human Decision Point: Option A vs Option B
- **Option A (Active)**: Install a synchronous monotonic `ctx.tools.guard()` layer returning `string | undefined`, guaranteeing fail-closed vetoes that cannot be bypassed or overridden by downstream extensible listeners.
- **Option B (Alternative)**: Rely on standard `tools/pre-execute` waterfall events, where any subsequent listener could return `{ kind: 'allow' }` and negate a critical safety veto.

## Behaviour

- **Given** an active tool guard **When** any tool executes **Then** it evaluates synchronously inside `stagePreExecuteAndGuards` before `tool.execute()`.
- **Given** a tool call attempting to mutate or delete `SOUL.md` **When** evaluated **Then** it returns an explicit `INV-09` denial string and emits `resource/soul-violation`.
- **Given** a heavy command or tool when host memory is below 1536 MiB or headroom is below 3072 MiB **When** evaluated **Then** it returns an explicit `INV-12` denial string and emits `resource/admission-denied`.

## Teach me while you build

The Organization believes they can bypass our security perimeter with clever event interception. Futile! A true mad scientist designs absorbing states.

- **What it does**: Intercepts all tool execution requests immediately before dispatch to enforce monotonic physical memory limits (`INV-12`) and identity protection (`INV-09`).
- **Background**: In extensible event architectures, waterfall chains allow listeners to transform or override decisions. But safety invariants must be monotonic: once denied, no subsequent listener may permit execution.
- **How it works here**: Registers via `ctx.tools.guard()`. Inside `stagePreExecuteAndGuards`, checks `isSoulMutation`; if true, returns `INV-09` violation string. If `isHeavy`, queries `AdmissionGovernor`; if denied, returns `INV-12` violation string.
- **Why this approach**: `ctx.tools.guard()` runs after all approvals and waterfalls. Returning a string bypasses `tool.execute()` and returns an error result directly to the model.
- **Approaches considered**: Pre-execute waterfall listeners (rejected: mutable, downstream listeners could override denial) vs In-tool validation wrappers (rejected: distributed across dozens of individual tools) vs Monotonic `ctx.tools.guard()` (chosen: centralized, immutable veto).
- **Prior art inspected**: Capability-based security monotonic attenuation models and POSIX capability bounding sets.
- **What we get for free**: Cordis `ctx.tools.guard()` returns an `effect()` disposer, ensuring automated teardown on plugin unload.
- **What to notice**: The guard returns synchronously (`string | undefined`), relying on cached or fast synchronous snapshots to avoid blocking the event loop.
- **Concepts to own**: Monotonic security guards: denial is absorbing; no subsequent operation can escalate privilege or reverse a veto.
- **Interview angle**: Why use a monotonic guard layer instead of middleware filters for security and resource constraints? Answer: Middleware pipelines allow subsequent handlers to catch or override errors; monotonic guards guarantee fail-closed absorption where any denial terminates dispatch.
- **Decisions you can now make alone**: You can attach additional invariant guards without fearing that downstream plugins will suppress your vetoes.
- **Lesson**: Security and physical constraints are not negotiable. Invariants must be absorbing and monotonic! El Psy Kongroo.
