# 05.02 — Typed Git Subprocess Runner and Environment Scrubber

**Set:** 05-worktree-guard · **Queue:** 2 · **Depends on:** 05.01
**Status:** todo
**Harness primitive:** Service Provider · **Package:** `@deepseek-ai/dsh-worktree-git`

## Summary

Provides a typed, security-hardened Git CLI invocation runner wrapping `ctx.subprocess.spawn` (`SubprocessRuntime`) for all worktree operations. It enforces discrete `argv` execution with zero shell interpretation, strips sensitive credentials via `scrubbedParentEnv()`, and forces non-interactive flags (`GIT_TERMINAL_PROMPT=0`). On Linux and Windows, it bounds Git processes inside systemd transient scopes or Job Objects to prevent orphaned lockfiles, and includes shallow repository recovery (`git fetch --unshallow`) to guarantee reachability calculations succeed.

## Behaviour

- **Given** an array of Git arguments **When** `git.run(argv, options)` is executed **Then** `ctx.subprocess.spawn` executes Git directly without `/bin/bash` or shell concatenation.
- **Given** an ambient environment containing API keys (`DEEPSEEK_API_KEY`, etc.) **When** Git commands run **Then** credentials are scrubbed case-insensitively while preserving proxies, `PATH`, and non-interactive flags.
- **Given** an aborted `signal` during Git checkout **When** abort fires **Then** the process group is cleanly terminated, avoiding stale `.git/index.lock` locks.
- **Given** a shallow clone repository (`--depth=1`) **When** reachability analysis runs **Then** `deepenShallowRepo()` fetches missing upstream history (`--unshallow`) before issuing reachability verdicts.
- **Given** a Git process exiting with non-zero code **When** command fails **Then** `GitSubprocessError` is thrown containing exact exit code, stdout, and trimmed stderr.

## Harness fit

This is a `Service Provider` primitive owned by `@deepseek-ai/dsh-worktree-git` injecting `['subprocess']`. It reuses `ctx.subprocess` (`packages/subprocess/subprocess/src/index.ts:86-154`) and rejects `ctx.shell` to eliminate shell injection vulnerabilities and quoting hazards. It leverages platform scopes (`linux-scope.ts:404-450`) for clean process group signal termination.

## Contracts

```typescript
export interface GitRunOptions {
  readonly cwd: string
  readonly timeoutMs?: number | undefined
  readonly signal?: AbortSignal | undefined
  readonly env?: Record<string, string> | undefined
  readonly allowNonZeroExit?: boolean | undefined
}

export interface GitRunResult {
  readonly exitCode: number
  readonly stdout: string
  readonly stderr: string
  readonly durationMs: number
}

export class GitSubprocessError extends Error {
  constructor(
    readonly command: string,
    readonly exitCode: number,
    readonly stdout: string,
    readonly stderr: string,
  ) {
    super(`Git command failed (${exitCode}): git ${command}\n${stderr.trim()}`)
    this.name = 'GitSubprocessError'
  }
}

export interface GitRunner {
  run(argv: readonly string[], options: GitRunOptions): Promise<GitRunResult>
  runLines(argv: readonly string[], options: GitRunOptions): Promise<readonly string[]>
  isShallow(cwd: string, signal?: AbortSignal): Promise<boolean>
  deepenShallowRepo(cwd: string, signal?: AbortSignal): Promise<void>
}
```
