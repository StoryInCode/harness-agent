## Summary

Fwahahaha! The Organization plots to overwhelm our laboratory host with an unconstrained flood of worker subagents, seeking to trigger an Out-Of-Memory collapse across all world lines! But Steins Gate has decreed Invariant `INV-12 (Memory Headroom Floor)`. We erect the Dynamic Worker Admission Governor to evaluate host resource availability before admitting any new subagent or resource-heavy workload. It verifies available memory against an absolute floor `minAvailableMemBytes` (1536 MiB) and dynamic headroom reservations (`activeWorkers * perWorkerReservationBytes`, default 768 MiB each) against `headroomBytes` (3072 MiB), with cgroup slice throttling (`cgroupPressureThrottlePercent`, 80%) on Linux systems.

### Human Decision Point: Option A vs Option B
- **Option A (Active)**: Compute predictive memory headroom via monotonic reservation subtraction (`activeWorkers * reservation`) against an absolute floor before dispatching subagents or heavy tools.
- **Option B (Alternative)**: Dispatch workers reactively without prior admission checks, waiting for the Linux kernel OOM killer or Node.js heap crash to terminate processes after starvation occurs.

## Behaviour

- **Given** host memory below `minAvailableMemBytes` (1536 MiB) **When** `checkAdmission` evaluates **Then** it returns `admitted: false` with code `ABSOLUTE_FLOOR_BREACH`.
- **Given** host memory above floor but effective headroom after worker reservations below `headroomBytes` (3072 MiB) **When** `checkAdmission` evaluates **Then** it returns `admitted: false` with code `RESOURCE_ADMISSION_DENIED`.
- **Given** Linux cgroup slice usage exceeding `cgroupPressureThrottlePercent` (80%) **When** `canAdmitWorker` runs **Then** it returns `false`, preventing subagent dispatch while falling back gracefully on non-cgroup hosts.

## Contracts

```typescript
export interface AdmissionResult {
  readonly admitted: boolean
  readonly reason?: string | undefined
  readonly availableBytes: number
  readonly headroomBytes: number
  readonly reservedUnusedBytes: number
  readonly effectiveFreeBytes: number
  readonly code?: 'RESOURCE_ADMISSION_DENIED' | 'ABSOLUTE_FLOOR_BREACH' | 'SLICE_CEILING_BREACH' | undefined
}

export interface AdmissionGovernorConfig {
  readonly minAvailableMemBytes?: number | undefined
  readonly headroomBytes?: number | undefined
  readonly perWorkerReservationBytes?: number | undefined
  readonly cgroupPressureThrottlePercent?: number | undefined
}

export interface AdmissionGovernor {
  checkAdmission(requestedBytes?: number): Promise<AdmissionResult>
  canAdmitWorker(activeWorkerCount: number): Promise<boolean>
  calculateEffectiveHeadroom(activeWorkerCount: number): Promise<number>
}
```

## Teach me while you build

The Organization believes it can overwhelm our laboratory with rogue subprocesses. Not on my watch! Reading Steiner has foreseen the OOM crash, and we have rewritten the timeline.

- **What it does**: Dynamically computes available memory headroom and enforces strict admission gates before admitting new worker subagents or heavy workloads.
- **Background**: Concurrent worker subagents consume non-trivial memory (Node.js runtime, AST caches, subprocesses). Spawning without admission control leads inevitably to host thrashing and OOM slaughter.
- **How it works here**: Gathers snapshot metrics from memory and cgroup providers. Calculates `effectiveFreeBytes = availableBytes - (activeWorkers * perWorkerReservationBytes)`. Denies admission if `availableBytes < minAvailableMemBytes` or `effectiveFreeBytes < headroomBytes`.
- **Why this approach**: Proactive reservation arithmetic bounds system divergence before processes are spawned, ensuring invariant INV-12 remains unbreached across all world lines!
- **Approaches considered**: Unbounded concurrency (rejected: causes host thrashing and catastrophic process termination) vs Static worker caps (rejected: rigid, ignores memory pressure from parallel IDE/browser tasks) vs Predictive headroom reservation (chosen: dynamic, scales with real host capacity).
- **Prior art inspected**: Linux kernel Pressure Stall Information (PSI) architecture and Kubernetes container eviction thresholds.
- **What we get for free**: Simple arithmetic on 64-bit integer byte counts in JavaScript preserves sub-microsecond evaluation speed.
- **What to notice**: Worker reservations account for expected peak heap consumption, preventing newly spawned workers from starving existing active workers.
- **Concepts to own**: Monotonic admission control: a mathematical invariant that prevents new state transitions unless resource headroom guarantees stability.
- **Interview angle**: How do you design an admission governor for asynchronous worker pools with unpredictable task memory? Answer: Combine a static minimum floor with dynamic per-worker reservation subtraction against real-time OS memory telemetry.
- **Decisions you can now make alone**: You can tune `perWorkerReservationBytes` in `AdmissionGovernorConfig` without modifying the core admission engine.
- **Lesson**: The future is not written in stone, but without admission gates, your server's destiny is an OOM panic! El Psy Kongroo.
