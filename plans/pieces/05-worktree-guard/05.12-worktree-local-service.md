## Summary

Implements the concrete `LocalWorktreeManager` service extending `WorktreeManager` on the Host Plane, injecting `['subprocess', 'fs']`. It orchestrates allocation, collision fallback, inclusion syncing, preservation classification, locking, and pruning, maintaining the active worktree inventory. It exposes a runtime Schemastery `LocalWorktreeConfig` schema (resolving the review lifecycle gap), emits typed lifecycle events, and registers a container disposal effect to cleanly release administrative locks without deleting dirty worktrees on shutdown.

### Human Decision Point: Option A vs Option B
- **Option A (Active)**: Deploy `LocalWorktreeManager` as a singleton provider on the Host Plane with Schemastery schema validation and container disposal hooks.
- **Option B (Alternative)**: Instantiate ephemeral worktree managers inside each agent session, leading to uncoordinated locks and resource leaks.

## Behaviour

- **Given** valid allocation options **When** `ctx.worktrees.allocate(options)` is called **Then** it orchestrates collision detection, base commit pinning, git worktree add, include syncing, administrative locking, and emits `worktree/allocated`.
- **Given** an existing worktree **When** `ctx.worktrees.classify(path)` is queried **Then** it evaluates the 5-tier ladder and returns `WorktreeClassification` without disk mutations.
- **Given** a worktree prune request **When** `ctx.worktrees.prune(path)` is called **Then** it refuses dirty/unpushed checkouts (emitting `worktree/preserved`), or cleanly unlinks clean checkouts (emitting `worktree/cleaned`).
- **Given** host shutdown or container disposal **When** the service unmounts **Then** held administrative locks are released without modifying or deleting worktree checkouts.

## Harness fit

This is a `Service Provider` primitive owned by `@deepseek-ai/dsh-worktree-local` mounted on the Host Plane (`base.cordis.patch.yml`). It subclasses `WorktreeManager` and registers under `ctx.worktrees`. It aggregates individual worktree capabilities into an authoritative service, satisfying Cordis lifecycle, injection, and disposal contracts.

## Contracts

```typescript
import z from '@deepseek-ai/schemastery'

export interface LocalWorktreeConfig {
  worktreesDirName?: string | undefined
  syncBase?: boolean | undefined
  allocationTimeoutMs?: number | undefined
  classificationTimeoutMs?: number | undefined
  maxOrphanAgeHours?: number | undefined
  packSprawlThreshold?: number | undefined
  mergeCachePath?: string | undefined
}

export const LocalWorktreeConfig: z<LocalWorktreeConfig> = z.object({
  worktreesDirName: z.string().default('.worktrees'),
  syncBase: z.boolean().default(true),
  allocationTimeoutMs: z.number().default(120_000),
  classificationTimeoutMs: z.number().default(15_000),
  maxOrphanAgeHours: z.number().default(72),
  packSprawlThreshold: z.number().default(15),
  mergeCachePath: z.string().default('~/.dsh/cache/worktree_merge_verdicts.json'),
})

export class LocalWorktreeManager extends WorktreeManager {
  static readonly inject = ['subprocess', 'fs']
  static readonly Config = LocalWorktreeConfig
}
```

## Teach me while you build

A collection of isolated git functions is useless until you wire them into an authoritative host service. Daru built `LocalWorktreeManager` to assemble all the pieces—allocation, locking, collision resolution, and preservation—into a single Cordis provider.

- **What it does**: Assembles all worktree capabilities into a singleton host service extending `WorktreeManager` with runtime Schemastery validation and lifecycle cleanup.
- **Background**: In Cordis architecture, services extending `Service` register on `Context` and inject dependencies like `subprocess` and `fs` to execute host-level mutations.
- **How it works here**: Mounted on the Host Plane (`base.cordis.patch.yml`), `LocalWorktreeManager` exposes `allocate`, `classify`, and `prune`. It registers a disposal effect on container teardown to safely release administrative locks without deleting dirty trees.
- **Why this approach**: Centralizing coordination into one provider guarantees that subagents cannot bypass safety gates or trigger uncoordinated git mutations.
- **Approaches considered**: Direct ad-hoc tool execution of git CLI (rejected: no lifecycle tracking or lock management) vs Ephemeral service per session (rejected: violates PRESET-RULE 6 and duplicates worktree registries) vs Singleton Host Plane provider with Cordis disposal hooks (chosen: authoritative inventory and clean shutdown).
- **Prior art inspected**: Cordis Service lifecycle contracts and Schemastery object schemas.
- **What we get for free**: Cordis context injection automatically resolves `subprocess` and `fs` runtimes and handles lifecycle disposal registration.
- **What to notice**: Notice the runtime Schemastery schema `LocalWorktreeConfig`: it validates timeouts and directories at boot so bad configs fail fast.
- **Concepts to own**: Host Plane Service Provider: a long-lived singleton service coordinating host resources across short-lived agent sessions.
- **Interview angle**: How do you structure a service managing host-level resources accessed by multiple transient agent sessions? Answer: Mount a singleton service provider on the host container with validated config and container disposal effects.
- **Decisions you can now make alone**: You can add new service methods to `WorktreeManager` and implement them here without modifying agent-plane presets.
- **Lesson**: Coordinate shared physical resources at the host layer; let agents consume them through typed boundaries.
