## Summary

Safely unlinks and tears down clean, fully-merged worktrees after task integration. It validates preservation state through the 5-tier guard, releases administrative locks, and executes `git worktree remove` strictly without `--force` (ensuring Git's native dirty guard blocks TOCTOU races where files were created after pre-check). It deletes auto-generated task branches (`kanban/<taskId>`) while strictly preserving custom user branches, running `git worktree prune` to purge stale Git metadata.

### Human Decision Point: Option A vs Option B
- **Option A (Active)**: Tear down worktrees strictly without `--force`, relying on Git's native dirty guard to catch TOCTOU write races and preserving custom branches.
- **Option B (Alternative)**: Force-remove worktrees with `--force` and delete branches unconditionally, risking clobbered local edits and user branch destruction.

## Behaviour

- **Given** a clean, merged worktree **When** `pruneWorktree` executes **Then** administrative locks are released, `git worktree remove` runs without `--force`, the task branch is deleted, and `true` is returned.
- **Given** a worktree containing uncommitted or unpushed work **When** `pruneWorktree` is called **Then** deletion is refused, disk state is untouched, and `false` is returned.
- **Given** a worktree checked out on a custom feature branch (`feature/*`) **When** prune executes **Then** the worktree directory is unlinked but the custom Git branch ref is preserved.
- **Given** completed pruning **When** teardown finishes **Then** `git worktree prune` purges stale `.git/worktrees/` entries and `worktree/cleaned` is emitted.

## Teach me while you build

Listen up. Running `rm -rf` or throwing `--force` at git is how amateur scripts burn down weeks of hard coding. Here is how real hackers cleanly dismantle an ephemeral worktree.

- **What it does**: Tears down clean, completed worktrees, purges stale `.git/worktrees/` entries, and safely deletes temporary task branches.
- **Background**: Git worktrees leave metadata under `.git/worktrees/<name>/`. If directories are deleted without running `git worktree remove` or `git worktree prune`, Git's internal inventory stays corrupted with ghost trees.
- **How it works here**: After 05.08 confirms the tree is clean, we unlock any administrative lock, invoke `git worktree remove` without `--force`, delete generated branches matching `kanban/*` or `wt/*`, and run `git worktree prune`.
- **Why this approach**: Running `git worktree remove` without `--force` lets Git perform its own final kernel check, shutting down TOCTOU (time-of-check to time-of-use) write races.
- **Approaches considered**: `rm -rf` followed by `git worktree prune` (rejected: bypasses git safety locks and corrupts active refs) vs `git worktree remove --force` (rejected: clobbers late writes) vs Unforced `git worktree remove` with branch filter (chosen: zero TOCTOU risk).
- **Prior art inspected**: Git documentation on `git worktree remove` and `git worktree prune`.
- **What we get for free**: Git's built-in dirty tree detection automatically aborts `git worktree remove` if any file was modified after our pre-check.
- **What to notice**: Generated task branches are deleted with `git branch -d` (safe delete), but custom user branches (`feature/*`) are untouched so humans don't lose branch pointers.
- **Concepts to own**: TOCTOU race mitigation: never assume state observed in step 1 remains unchanged in step 2; let the lower-level system call enforce atomic preconditions.
- **Interview angle**: Why is `git worktree remove` preferred over filesystem directory deletion (`fs.rm`)? Answer: It cleans up linked admin records in `.git/worktrees/` and verifies working-tree cleanliness before unlinking.
- **Decisions you can now make alone**: You can add branch name patterns to the temporary branch cleanup list without touching the unforced removal sequence.
- **Lesson**: The safest command is the one that refuses to run when reality deviates from your assumptions.
