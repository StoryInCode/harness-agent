# 05.07 — Upstream Patch Equivalence Cache

**Status:** todo

## Summary

Provides disk-backed, atomic memoization for expensive `git cherry` patch-equivalence evaluations at `~/.hermes/cache/worktree_merge_verdicts.json`. When task branches are squash-merged or rebased into main branches, re-evaluating patch equivalence across large commit graphs incurs significant subprocess overhead. The cache indexes commit SHA pairs and upstream equivalence verdicts, persisting mutations atomically via temporary files and POSIX renames to prevent corruption across concurrent processes.

## Behaviour

- **Given** an upstream ref and commit SHA **When** `getVerdict` is invoked and entry exists within TTL **Then** it returns the cached boolean verdict immediately without spawning Git.
- **Given** an evaluated `git cherry` result **When** `setVerdict` is invoked **Then** it updates internal memory and writes the record atomically to disk.
- **Given** concurrent writes across processes **When** disk writes occur **Then** writing to a temporary file followed by atomic rename prevents torn JSON records.
- **Given** a missing or malformed cache file on disk **When** cache initializes **Then** it logs a diagnostic warning and recovers with a fresh empty store.
- **Given** cache entries exceeding maximum age **When** garbage collection runs **Then** expired entries are purged to bound disk usage.

## Harness fit

This is a `workflow capability` primitive owned by `@deepseek-ai/dsh-worktree-cherry-cache`. It encapsulates JSON serialization, atomic filesystem writes, and TTL eviction for Git patch analysis. Decoupling disk memoization from Git execution enables preservation evaluators to check merge status with sub-millisecond latency.
