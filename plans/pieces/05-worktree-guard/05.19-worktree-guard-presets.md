# 05.19 — Worktree and Resource Guard Host Patch Layer Composition

**Set:** 05-worktree-guard · **Queue:** 19 · **Depends on:** 05.12, 05.18
**Status:** todo
**Harness primitive:** patch layer · **Package:** `@deepseek-ai/dsh-worktree-guard-presets`

## Summary

Composes `@deepseek-ai/dsh-worktree-local` and `@deepseek-ai/dsh-guard-resource` into the host bundle patch layer (`packages/bundle/base/cordis.patch.yml`). It enforces PRESET-RULES (Rules 2, 4, 6) by mounting both services strictly on the Host Plane (root container) before any session exists. It ensures agent presets (`hermes-brain`, `hermes-worker`) add ZERO rows for these host services, eliminating the invalid preset-wide `$isolate` realm flagged in review findings while ensuring worker tools inherit `SessionHeader.cwd` and benefit from host monotonic tool guards.

## Behaviour

- **Given** root container startup **When** `packages/bundle/base/cordis.patch.yml` loads **Then** `ctx.worktrees` and `ctx.resourceGuard` initialize on the Host Plane.
- **Given** agent presets (`hermes-brain`, `hermes-worker`) **When** audited **Then** neither preset declares rows for `dsh-worktree-local` or `dsh-guard-resource`.
- **Given** tools mounted in `hermes-worker` **When** executed **Then** they automatically inherit `SessionHeader.cwd` and are guarded by the global `ctx.tools.guard()`.
- **Given** worker preset configuration **When** inspected **Then** it contains standard Cordis entries without invalid `$isolate` or `$path` directives.
- **Given** container disposal **When** shutting down **Then** both services execute cleanup effects without leaving orphaned locks.

## Harness fit

This is a `patch layer` primitive owned by `@deepseek-ai/dsh-worktree-guard-presets`. It configures the host-level composition patch (`cordis.patch.yml`). Adhering to PRESET-RULES ensures that host-level infrastructure is never mistakenly mounted inside per-agent session presets.
