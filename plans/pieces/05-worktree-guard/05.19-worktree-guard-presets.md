## Summary

Tut-turii~ Mayuri is here to sew all the pieces together so everyone has a cozy and safe workshop! We compose `@deepseek-ai/dsh-worktree-local` and `@deepseek-ai/dsh-guard-resource` into the host bundle patch layer (`packages/bundle/base/cordis.patch.yml`). Following PRESET-RULES, we mount both infrastructure services strictly on the Host Plane before any session is created. This ensures agent presets (`dev-loop-brain`, `dev-loop-worker`) have zero duplicate service rows and no confusing `$isolate` realms, letting our worker friends inherit `SessionHeader.cwd` smoothly while staying protected by host resource guards.

### Human Decision Point: Option A vs Option B
- **Option A (Active)**: Mount worktree management and resource guard singletons strictly on the Host Plane in `cordis.patch.yml`, keeping worker presets completely free of host infrastructure service definitions.
- **Option B (Alternative)**: Declare worktree and resource services inside individual agent presets or wrap them in preset-wide `$isolate` realms, which breaks PRESET-RULES and isolates subagents from resolving host services.

## Behaviour

- **Given** root container initialization **When** `packages/bundle/base/cordis.patch.yml` loads **Then** `ctx.worktrees` and `ctx.resourceGuard` initialize as singletons on the Host Plane.
- **Given** agent presets (`dev-loop-brain`, `dev-loop-worker`) **When** audited **Then** neither preset declares rows for `dsh-worktree-local` or `dsh-guard-resource`, adhering to PRESET-RULES.
- **Given** worker subagents executing tools **When** dispatched **Then** they inherit `SessionHeader.cwd` and execute under global `ctx.tools.guard()` protection without invalid `$isolate` boundaries.

## Teach me while you build

Mayuri is stitching together everyone's wonderful contributions into a lovely costume! Let's make sure all the seams line up so nothing tears.

- **What it does**: Stitches the worktree manager and resource guard into the host bundle patch layer so they wrap the entire harness safely.
- **Background**: Cordis uses a layered container architecture. Host Plane services sit on the root container, while Agent Presets configure per-session environments.
- **How it works here**: In `cordis.patch.yml`, declares `@deepseek-ai/dsh-worktree-local` and `@deepseek-ai/dsh-guard-resource`. Leaves agent presets clean so workers can access host tools without artificial `$isolate` boundaries.
- **Why this approach**: Keeps host infrastructure separate from agent tools, preventing duplicate service initializations and memory leaks across sessions.
- **Approaches considered**: Embedding services in agent presets (rejected: breaks PRESET-RULE 1 and causes fatal audit crashes) vs Custom per-agent wrapper scripts (rejected: messy and hard to maintain) vs Host patch layer composition (chosen: clean Cordis standard).
- **Prior art inspected**: Cordis patch layer and profile configuration system.
- **What we get for free**: Cordis automatically merges `cordis.patch.yml` entries into the root container during boot.
- **What to notice**: Notice how leaving out `$isolate` lets subagents freely communicate with host services like `ctx.kanban` and `ctx.worktrees`.
- **Concepts to own**: Host Plane vs Agent Plane: keeping hardware/system singleton services outside ephemeral agent session lifecycles.
- **Interview angle**: Why shouldn't singleton hardware services be loaded inside per-session presets in an agent framework? Answer: Loading host services inside session presets creates duplicate listeners, exhausts system resources, and violates container boundaries.
- **Decisions you can now make alone**: You can adjust bundle patch parameters in `cordis.patch.yml` without touching worker preset YAML files.
- **Lesson**: Keep the foundation on the host and let workers roam free in their worktrees. Tut-turii~!
