## Summary

Yo! Here's the dirtiest trick in programming: an implementer can't get a hard test to pass, so they just delete the test or weaken the assertion! Not happening here. Once the Test Writer establishes the RED baseline, Daru calculates a SHA-256 hash of every single test file and freezes it in `SHA256SUMS` and `RED.md`. If the Implementer touches the test files, the gate explodes! Pure anti-cheat protection!

### Human Decision Point: Option A vs Option B
- **Option A (Active)**: Freeze test files with cryptographic SHA-256 hashes recorded in worktree metadata before implementer handoff.
- **Option B (Alternative)**: Allow implementers to edit test files during implementation, permitting tests to be weakened to pass.

## Behaviour

- **Given** a verified RED test suite **When** freezeTests(worktree, testFiles) is called **Then** it writes SHA256SUMS and RED.md into the test directory.
- **Given** an implementer attempting to complete work after modifying a frozen test file **When** verifyFrozenTests runs **Then** it detects hash mismatch and rejects completion.
- **Given** an implementer who modified only production code without touching test files **When** verifyFrozenTests runs **Then** it verifies matching hashes and permits completion.

## Teach me while you build

Anti-cheat 101: Never let the student grade their own test paper. Freeze the exam before giving them the pencil.

- **What it does**: Hashes test files using SHA-256 and locks them so implementers cannot tamper with test expectations.
- **Background**: The No Unproven Done invariant requires tests to be independent of the implementation.
- **How it works here**: Reads test files, hashes each with `crypto.createHash('sha256')`, and commits the manifest to `SHA256SUMS`.
- **Why this approach**: Cryptographic guarantees prevent subagent self-dealing or prompt-drift shortcuts.
- **Approaches considered**: Git file permissions (unreliable in user space) vs Read-only filesystem mount (complex) vs SHA-256 manifest verification (chosen: simple and foolproof).
- **Prior art inspected**: Debian package checksums (`md5sums`) and Git commit tree integrity.
- **What we get for free**: Node's crypto module calculates hashes in microseconds.
- **From the docs**: AGENTS.md: 'Tests describe behavior, not correctness... Production review, coverage, documentation ownership... still required.'
- **What to notice**: Notice that `RED.md` also logs the failing test output as human-readable evidence!
- **Concepts to own**: Integrity manifest: a signed list of cryptographic fingerprints protecting files from unauthorized alteration.
- **Interview angle**: How do you enforce TDD invariants in multi-agent systems? Answer: Cryptographically freeze test files after red baseline before dispatching implementer.
- **Decisions you can now make alone**: You can add extra metadata fields (e.g. author agent ID) to `RED.md` without invalidating the checksums.
- **What you should learn from this**: Lock your tests before writing code. A test you can edit to make green is not a test.
