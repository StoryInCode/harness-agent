# 00.09 — BDD Scenario Extractor and Test Handoff

**Set:** 00-dev-loop · **Queue:** 9 · **Depends on:** 00.01, 00.06, 00.13
**Status:** todo
**Harness primitive:** Service Provider · **Package:** `@deepseek-ai/dsh-dev-loop-test-handoff`

## Summary

Give Test Writer a revision-bound specification, independently establish behavioral RED, and retain the exact tests for Implementer. This proposed Host orchestration calls Roles and subprocess directly. A failing process is not necessarily a failing behavior test. Unresolved load-bearing claims stop authoring; no automatic retry or read-only test-command guarantee is provided.

## Behaviour

- **Given** a current approved piece and resolved claims **When** handoff starts **Then** Test Writer receives its 3–8 scenarios, citations, permitted test paths and runner policy in the retained assignment.
- **Given** unresolved, contradicted or stale claims **When** handoff starts **Then** it rejects with `CLAIM_VERIFICATION_OUTSTANDING` before Test Writer dispatch.
- **Given** malformed or out-of-range scenarios **When** extraction runs **Then** it rejects with `MALFORMED_BDD_SCENARIO` or `INVALID_SCENARIO_COUNT`.
- **Given** authored tests **When** the independent baseline run reports the expected assertion failures **Then** the owner freezes exact test identities, content and baseline Git state with the evidence.
- **Given** syntax, import, infrastructure, no-tests, timeout, killed or truncated-result failure **When** RED is assessed **Then** it cannot authorize implementation.
- **Given** a frozen baseline **When** Implementer is delegated **Then** the same retained assignment and unchanged tests are supplied; a necessary test correction returns to Test Writer for a new baseline.
- **Given** cancellation or a restart residue **When** handoff stops **Then** owned workers/processes are joined and files retained; no automatic authoring retry or rollback is claimed.

## Harness fit

The **Service Provider** publishes `ctx.devLoopTestHandoff`, injecting `agents`, `devLoopDirectory`, `devLoopRoles`, `devLoopClaims`, `fs`, `subprocess`, and `storageDomain`. Its scoped `./tool` Consumer registers `dev_loop_test_handoff` with `{pieceId}` and pure JSON rendering. It requires the exact live `exec.agent`, enters `agents.withInitiator`, and propagates cancellation. Configuration and runner commands are not model inputs.

The current workflow worker's `startChild` calls `subagents.start` directly; it does not call Roles, Queue or Worktree. Its script globals are agent, parallel, pipeline, phase, log and args, not a Host-service bridge. Using that script would bypass the required role policy and assignment path. No workflow engine, worker protocol amendment or Agent-loop change belongs here.

Roles owns Queue admission, actual caller/cwd, child cleanup and durable delegation history under [00.06](00.06-role-delegation.md). Handoff owns sequencing and independently executed test evidence. Test processes use `subprocess.spawn` with fully specified argv/cwd/stdio/grace/signal, await `done`, and terminate/join with `waitForExit` even on failure. Deadlines and reporter interpretation belong to this consumer.

## Contracts

All operations below are proposed, not existing exports. Test Writer freezes concrete branded DTOs and rejection cases before production changes.

- `extractScenarios(pieceId, signal): Promise<TestBrief>` reads `Directory.getPiece`, then the actual file through fs, revalidates its observed content, and returns piece SHA-256, package, scenarios and the current Claims report id. Directory supplies scenarios but no AST; this owner parses the Behaviour section to detect malformed list items the extracted scenario array cannot explain.
- `executeHandoff(pieceId, signal): Promise<HandoffRecord>` captures the real initiator before awaits, verifies current approval/Claims identity, delegates Test Writer through `Roles.delegate`, checks its actual retained assignment, runs the configured baseline command, freezes evidence and durably returns it.
- `getHandoff(pieceId): Promise<HandoffRecord | undefined>` returns the latest detached observation, including incomplete/failed attempts, never a caller-written pass boolean.

`TestBrief` includes exact piece digest, Claims report id, package, scenarios, allowed test paths, configured argv/reporter, baseline commit and expected behavioral assertions. Test Writer reports proposed test paths and assertion identities; Handoff validates them against the actual runner discovery and files. The role's self-reported success is not RED evidence.

`HandoffRecord` includes branded handoff id, piece id/digest, Claims report id, delegation id, WorktreeAssignment, baseline Git commit, relevant tracked/index/untracked content manifest, exact command and cwd, runner/config/lockfile versions and digests, discovered test identifiers, selected expected failure identifiers, test path/content SHA-256 manifest, timestamps, exitCode/signal/timeout/cancellation/cleanup facts, full bounded reporter evidence and limitations. Record command environment policy without secrets. HEAD alone cannot identify a dirty baseline; reject unexplained production changes or preserve their exact manifest as an explicitly accepted baseline.

### RED classification and freeze

The initial supported adapter is the repository-installed Vitest JSON reporter, with its exact resolved installed version and lockfile identity frozen by Test Writer before implementation; no generic stderr heuristic or unspecified reporter is accepted. Configuration explicitly selects that pinned adapter/version. The adapter must distinguish discovery/collection errors from executed test assertion failures. RED requires a nonempty exact selected test set, no unexpected failures, successful collection, expected behavior assertions actually executed and failed for the specified missing behavior, and expected controls passing. Missing symbols/imports, syntax errors, zero tests and process failure do not satisfy this requirement. If a prerequisite API prevents loading tests, freeze and verify that prerequisite independently rather than labeling import failure behavioral RED.

Freeze the test manifest only after successful classification and compare it before and after the run. Include imported test helpers, fixtures, runner configuration, discovery filters and skip/todo counts so changing test selection cannot bypass pinning. Each later run must discover the same selected identities and execute the required assertions. Production revision changes are expected at GREEN; test/config identity changes require a new Test Writer baseline. A digest identifies bytes, not whether assertions are good.

Commands may write caches, snapshots, coverage files or arbitrary files permitted by their execution environment. Inspect before/after manifests, reject changes to frozen inputs, report other effects and never call a test run read-only. Retain test files through Implementer, transfer and post-transfer checks; only the explicit orchestration owner may retire the assignment under 00.05. A restart leaves an incomplete attempt requiring explicit reconciliation, not safe replay.

### Storage and configuration

Own `dev_loop_handoff`, version 1, single layout, schema-validated attempts. Persist intent before delegation; persist the owner-produced classified evidence before successful return. Failed final write leaves unresolved intent; never recreate a pass from a report string. Join admitted operations before domain.close. 00.12 consumes this owner and does not reopen it.

Require repositoryRoot, test-path policy, executable/argv, reporter identifier/version, commandTimeoutMs, terminationGraceMs, maxOutputBytes, maxRecordBytes and maxTestFiles. Validate referents at the earliest resolvable point. Complete UTF-8 records, reporter output and error envelopes obey limits; overflow is explicit and cannot pass. One active handoff per piece rejects overlap. No token/tool-call enforcement is inferred from a role brief.

## Teach me while you build

- **What it does:** Gives one specialist the test-writing job and gives the next specialist exactly those tests.
- **Background:** Behavioral RED is an executed assertion that fails for the missing behavior. Content addressing identifies exact bytes by digest. A lease is a resource whose cleanup must be joined.
- **How it works here:** Read workflow startChild to see the bypass risk, then Roles for the correct child path and lifecycle.run for subprocess ownership. Handoff adds the runner adapter, freeze and durable observation.
- **Why this approach:** Direct Host service calls can reach Roles without inventing a worker RPC bridge. A workflow script wins for independent generic agents whose policy does not require these services.
- **Approaches considered:** Host sequencing is chosen; the existing workflow worker suits generic fan-out; Temporal is an external durable-orchestration alternative when a separately operated execution system is warranted. The reported SDK files establish promise/cancellation separation only, not replay safety here.
- **Prior art inspected:** Research reported Temporal sdk-typescript v1.11.8 workflow.ts and workflow-handle.ts source inspection. Utility did not open external source; no external code reused.
- **What we get for free:** Roles handles child policy/history and Queue cleanup; subprocess provides managed handles; storageDomain serializes writes. Application code owns runner semantics and restart decisions.
- **From the docs:** Domain.close says “reject new writes immediately, drain already-queued writes”; record terminal evidence before closing storage.
- **What to notice:** Nonzero exit and expected assertion failure are different fields. Preserve the manifest before handing production work to Implementer.
- **Concepts to own:** Reproducibility binds evidence to inputs in HandoffRecord; resource ownership joins process cleanup; fail-closed admission rejects ambiguous RED.
- **Interview angle:** “Does a failing test command prove RED?” No: require discovery and the selected behavioral assertion failures. Follow-up: pin helpers/configuration and detect skipped tests.
- **Decisions you can now make alone:** Add reporter classifications with rejection fixtures. Escalate a new runner, test correction, unresolved claim exception or recovery policy to its owner.
- **What you should learn from this:** Evidence must identify both the inputs and the reason an operation failed.
