# 00.06 — Role Delegation Dispatcher and Record

**Set:** 00-dev-loop · **Queue:** 6 · **Depends on:** 00.04, 00.05
**Status:** todo
**Harness primitive:** subagent consumer · **Package:** `@deepseek-ai/dsh-dev-loop-roles`

## Summary

Coordinates role-based subagent delegation for the Brain orchestrator across four roles: Research, Test Writer, Implementer, and Utility. For each delegation, it generates a structured brief, applies role-specific tool restrictions and persona sections onto the child agent context, and persists a durable delegation record capturing assignment, preset, rationale, outcome, and limitations. For the Research role, briefs support pre-implementation claim verification assignments (claim, dependent decision, permitted sources, budget, and required citations). Summarising and orchestrating agents receiving research reports are strictly barred from implying or stating that they directly inspected the underlying source; findings must be explicitly attributed as reported by the delegated role and preset.

## Behaviour

- **Given** a piece requiring implementation **When** the Brain delegates to role `Implementer` **Then** the dispatcher configures the subagent session with editing tools, role instructions, and launches it in the assigned worktree.
- **Given** a delegation request for role `Research` **When** dispatched **Then** the child session is restricted to read-only tools and instructed to return evidence with file citations.
- **Given** a Research role delegation for spec claim verification **When** the Research subagent returns findings **Then** the delegation record and piece updates record provenance as `reported by <role, preset>` rather than `direct inspection`, preventing false claims of direct orchestrator inspection.
- **Given** a completed subagent execution **When** results return to the dispatcher **Then** a `DelegationRecord` is persisted containing assignment, selected preset, rationale, outcome, and limitations.
- **Given** an invalid or undeclared role string **When** delegation is attempted **Then** dispatch fails with `UNKNOWN_DELEGATION_ROLE`.
- **Given** an orchestrator query for a piece's history **When** `getDelegations(pieceId)` is called **Then** all historical role delegation records for that piece are returned in chronological order.

## Harness fit

This is a `subagent consumer` consuming `ctx.subagents` (`packages/subagent/subagent/src/index.ts:246-253`). It configures child sessions dynamically via `childCtx.tools.restrict()` and persona overrides (`plans/00-architecture-mapping.md:12, 181`), avoiding multiplication of static preset files.

## Contracts

```typescript
export type DevLoopRole = 'Research' | 'Test Writer' | 'Implementer' | 'Utility'

export interface VerificationAssignment {
  claim: string
  decisionRestingOnClaim: string
  permittedSources: readonly string[]
  requiredEvidence: readonly string[]
}

export interface DelegationBrief {
  pieceId: string
  role: DevLoopRole
  preset: string
  assignment: string
  rationale: string
  verification?: VerificationAssignment
}

export interface DelegationRecord extends DelegationBrief {
  delegationId: string
  subagentSessionId: string
  outcome: string
  limitations: string[]
  completedAt: number
  provenance: 'direct inspection' | `reported by ${string}`
}

export interface DevLoopRoles {
  delegate(brief: DelegationBrief): Promise<DelegationRecord>
  getDelegations(pieceId: string): Promise<DelegationRecord[]>
}
```

## Teach me while you build

- **Background**: Role delegation decomposes engineering tasks across specialized agent personas (Research, Test Writer, Implementer, Utility) rather than relying on an unguided generalist agent for the entire lifecycle.
- **How it works here**: When the Brain orchestrator delegates work, it calls `delegate(brief)`. The dispatcher maps the requested `DevLoopRole` to tool constraints (e.g. `Research` gets read-only exploration tools; `Implementer` gets write and shell tools). For the `Research` role, briefs can carry a structured `verification` assignment detailing the claim, the decision resting on it, permitted sources, budget, and required citations. It initializes a child session via `ctx.subagents`, binds `cwd` to the allocated worktree, injects role instructions, awaits execution, and records an auditable `DelegationRecord` capturing outcome and limitations. Open `packages/dev-loop/roles/src/index.ts`.
- **Why this approach**: Dynamic session tool restriction via `childCtx.tools.restrict()`. The simplest alternative is maintaining separate static preset YAML files for every role variation, but dynamic restriction prevents preset explosion while guaranteeing strict tool enforcement.
- **What we get for free**: Harness `ctx.subagents` provides child agent lifecycle, streaming output events, and session disposal. It does **not** provide process isolation with the in-process backends: `subagent-spawn-in-process` runs each child "as a fresh child Agent on the same cordis context", and `subagent-fork-in-process` likewise, so the boundary is scope-level. Genuine process separation exists only for out-of-process providers. 00.07's read-only guard rests on scope being the real boundary; do not read more into it than that.
- **What to notice**: Every completed delegation record preserves explicit limitations, rationale, and provenance attribution. A summarising agent receiving research output must never imply it directly opened the cited files; it must record `reported by <role, preset>`.
- **Lesson**: Specialize agent capabilities dynamically at session dispatch time rather than proliferating sprawling static configurations, and never claim direct inspection for delegated research.
