# 00.08 — References Provenance Store and Verification

**Set:** 00-dev-loop · **Queue:** 8 · **Depends on:** 00.01, 00.06
**Status:** todo
**Harness primitive:** Service Provider · **Package:** `@deepseek-ai/dsh-dev-loop-references`

## Summary

Parses and mechanically verifies the `## References` markdown table of each piece file. It enforces the axiom that no document may claim a source was inspected or an agent was invoked unless verified: it verifies that referenced repository files exist, validates that the inspecting role matches recorded delegation history, and records verified provenance records in durable storage.

## Behaviour

- **Given** a piece with a References table citing local repository files **When** verification runs **Then** every file path and line range is verified for physical existence on disk via `ctx.fs`.
- **Given** a piece citing a nonexistent file or directory **When** verification runs **Then** verification fails with `UNRESOLVED_REFERENCE_SOURCE` specifying the missing path.
- **Given** a reference entry claiming a role or preset inspected a source **When** checked against delegation records **Then** verification asserts that a corresponding delegation was executed or that direct inspection occurred.
- **Given** an unverified citation claim **When** verification runs **Then** the check fails with `FABRICATED_AGENT_EVIDENCE`.
- **Given** a piece with no references that explicitly declares so **When** verified **Then** the check passes and records an explicit empty reference set.

## Harness fit

This is a `Service Provider` mounted on the host plane (`ctx.devLoopReferences`) extending `@deepseek-ai/cordis.Service`. It enforces the "No invented delegation or evidence" axiom (`plans/AGENTS.md:67-72`) using `ctx.fs` and delegation histories, persisting verified provenance records to durable storage.

## Teach me while you build

- **Background**: Provenance is the documented chain of origin and custody for factual claims. In autonomous development, language models frequently hallucinate non-existent files or claim an agent ran research when it did not.
- **How it works here**: Mounted as `ctx.devLoopReferences`, the service parses the 5-column markdown table in `## References`. For every cited file, it calls `ctx.fs.exists()` to assert physical presence on disk. For rows claiming `Reported` inspection by a role, it checks `ctx.devLoopRoles.getDelegations(pieceId)` to verify the subagent was actually executed. If valid, it records a `ProvenanceValidationResult`. If a path is missing or role unverified, it throws `UNRESOLVED_REFERENCE_SOURCE` or `FABRICATED_AGENT_EVIDENCE`. Open `packages/dev-loop/references/src/index.ts`.
- **Why this approach**: Mechanical verification of references against disk and delegation records. The simplest alternative is trusting agent-written text, but models routinely invent convincing citations; mechanical validation enforces ground truth.
- **What we get for free**: Harness `ctx.fs` handles asynchronous path resolution without shelling out to filesystem tools.
- **What to notice**: Pieces with no references must explicitly state "none" to pass, distinguishing intentional absence of references from omitted tables.
- **Lesson**: Mechanically verify every citation and delegation claim against ground truth to eliminate hallucinations from system specifications.
