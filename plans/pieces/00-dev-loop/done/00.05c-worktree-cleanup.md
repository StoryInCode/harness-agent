## Summary

Tutturu~ 🌸 After a worker finishes sewing their piece, we have to tidy up the sewing room! But be very careful! If a test failed, or if changes are unmerged, dirty, or borrowed, we must NEVER delete the worktree! We keep it safe for inspection. We only clean up when the tree is owned, clean, and unchanged! No lost work!

### Human Decision Point: Option A vs Option B
- **Option A (Active)**: Explicit nonforce retirement: remove only owned, clean, unchanged worktrees via `git worktree remove` without `--force`; preserve dirty or borrowed trees.
- **Option B (Alternative)**: Force-remove worktrees with `--force`, destroying diagnostic evidence and untransferred commits.

## Behaviour

- **Given** a clean, unchanged, and owned worktree assignment **When** `retireWorktree` is called **Then** it removes the worktree via nonforce `git worktree remove` and returns `{ kind: 'removed' }`.
- **Given** a worktree with modified, staged, untracked, or ignored files, or a changed HEAD commit **When** `retireWorktree` is called **Then** it preserves the tree on disk, retains the assignment, and returns `{ kind: 'preserved', reason: 'dirty' | 'head-changed' }`.
- **Given** a borrowed worktree or a service disposal lifecycle event **When** `retireWorktree` or service shutdown executes **Then** it preserves physical trees on disk without deleting worker files.

## Harness fit

Retirement and teardown methods on `DevLoopWorktree` inside `@deepseek-ai/dsh-dev-loop-worktree/src/index.ts`. Integrates with Cordis lifecycle disposal to preserve physical trees on shutdown.

## Teach me while you build

Never throw away scrap fabric until the dress is completely finished! Tutturu~ 🌸

- **What it does**: Conservatively retires worktrees, preserving directories whenever a task leaves modified files, uncommitted work, or needs human review.
- **Background**: Diagnostic triage requires inspecting the exact disk state where a test failed. Deleting too early destroys evidence.
- **How it works here**: `retireWorktree()` verifies ownership is not borrowed, checks git identity consistency, verifies HEAD commit equality, and inspects untracked/ignored files with `git status --porcelain=v1 -z`. Only clean, unchanged, owned trees run `git worktree remove` without `--force`.
- **Why this approach**: Safety first: disk space is cheap, lost developer debugging time is expensive.
- **Approaches considered**: Aggressive removal with `--force` (destroys debugging evidence) vs Never delete (leaks disk) vs Conservative deletion only on clean unchanged trees (chosen).
- **Prior art inspected**: Docker test containers `--rm` vs `--rm=false` on failure, and transaction rollback protocols.
- **What we get for free**: Git's `worktree remove` automatically cleans up administrative metadata in `.git/worktrees/`.
- **From the docs**: AGENTS.md: 'Merge work back to the mainline, then remove the worktree. A worktree is a scratch space with a lifetime, not a place work accumulates.'
- **What to notice**: Notice that the assignment is deleted from memory only AFTER Git removal succeeds!
- **Concepts to own**: Conservative cleanup: prioritizing evidence preservation and data safety over aggressive resource reclamation upon error.
- **Interview angle**: How do you design sandbox cleanup for automated testing pipelines? Answer: Clean up conservatively; preserve sandbox files on failure or uncommitted changes for forensic analysis.
- **Decisions you can now make alone**: You can safely inspect preserved worktree paths when `retireWorktree` returns `{ kind: 'preserved' }`.
- **What you should learn from this**: Preserve evidence when things go wrong so you can learn and fix them without frustration! Tutturu~ 🌸
