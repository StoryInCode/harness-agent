# 00.06 — Role Delegation Dispatcher and Record

**Set:** 00-dev-loop · **Queue:** 6 · **Depends on:** 00.04, 00.05
**Status:** done
**Harness primitive:** subagent consumer · **Package:** `@deepseek-ai/dsh-dev-loop-roles`

## Summary

Delegate bounded assignments to Research, Test Writer, Implementer, or Utility, run each child in its piece's retained worktree, and retrieve durable delegation history. The Brain calls registered model tools; a persona cannot invoke Host services merely by naming them. Reports preserve assignment, rationale, actual child identity and composition, outcome, limitations, and explicitly attributed evidence.

The [Roles package](../../../../packages/dev-loop/roles/README.md) implements the Host service and scoped `./tool` consumer. The separately frozen child-cwd prerequisite and Roles/Research baselines have implementation and post-transfer evidence below. Completion covers these package-owned behaviors, not final opt-in assembly or independent verification of report truth.

## Behaviour

- **Given** an admitted piece **When** the Brain calls `dev_loop_delegate` **Then** persist its request before enqueueing, allocate or reuse its assignment after admission, and start one child with the real caller and assigned cwd.
- **Given** Research **When** its child executes **Then** inherited write-capable tools are excluded from both model schemas and execution, while its brief requests citations and limitations.
- **Given** Test Writer followed by Implementer **When** each role finishes **Then** the same assignment and Test Writer files remain; role cleanup never retires the tree.
- **Given** a settled run **When** Queue finishes cleanup **Then** persist the terminal observation before returning a successful delegation receipt.
- **Given** cancellation, startup failure, or uncertain cleanup **When** delegation settles **Then** record the observed failure and limitations without claiming completion, quiescence, or deletion.
- **Given** an unknown role, including `Reviewer` **When** the service receives it **Then** reject with `UNKNOWN_DELEGATION_ROLE`; the model tool's enum parser may reject earlier with `INVALID_ARGS`. No fifth role or alias is introduced.
- **Given** a restarted service **When** history is queried **Then** return durable records in deterministic chronological order; an unfinished request remains unresolved rather than being declared running or completed.
- **Given** a delegated research report **When** another agent summarizes it **Then** attribute it to the recorded role and actual composition, never to the summarizer's direct inspection.

## Harness fit

The Host service publishes `ctx.devLoopRoles`, injecting `agents`, `subagents`, `devLoopQueue`, `devLoopWorktree`, and `storageDomain`. Its `./tool` function plugin injects `tools`, `agents`, and `devLoopRoles`, and registers effect-owned tools only in the Brain's scoped composition. Do not mount one Host service or storage domain per role. The service is a consumer of `SubagentRuntime.start(providerName, request)`, not an alternative subagent provider.

Use `ctx.subagents.start`, which owns capability checks, descriptor resolution, catalog publication, and lifecycle observation. Do not call a provider's raw `start` to bypass those checks. Provider registry names are configuration, not LLM model-route identifiers. The consumer supplies `persona` and `toolFilter`; the provider applies them during child creation. No consumer callback receives a `childCtx`.

### Frozen prerequisite: explicit child cwd

This prerequisite is part of 00.06, not a new piece. Its Test Writer freezes behavioral RED independently before implementation. Changes to its scope or expectations require an explicit new baseline; role implementation must not silently expand it.

**Desired behavior:** create the actual child with the assigned absolute workspace in immutable `SessionHeader.cwd`, before setup, publication, and the first model request. Preserve the exact parent's identity, cwd, header, and sibling metadata. Never mutate a parent header, manufacture a caller, or call `process.chdir`.

**Smallest public amendment:** add optional `readonly cwd?: string` to `SubagentStartRequest`. `ResolvedSubagentStartRequest` inherits it alongside its existing descriptor; “resolved” does not imply that the service resolves provider-owned directory defaults. At each existing request-to-creation/run-spec step, select explicit request cwd, then the provider's configured cwd where supported, then the real parent cwd. Invalid explicit input rejects without fallback. Omission preserves existing behavior, including undefined in-process cwd and remote providers' required usable directory. Validate paths in the provider's execution world, not by adding generic Host filesystem probes.

Pass the selected cwd into `childSessionMeta`; do not leave that helper to reread the parent workspace. All current providers must honor cwd as a baseline request field, so no capability bit is added. Existing Agent creation already accepts `meta.cwd` and snapshots metadata before setup; no Agent-loop change, generic `meta`/`setup` request escape, or Session format bump is needed.

### Configuration, tools, and actual composition

The Host service owns `Config` (role policies and brief/outcome retention limits). The scoped `./tool` consumer owns its separate validated `ToolConfig` (complete rendered-output bytes and history record count); it must not read the service's private configuration. Require all four role configurations and positive safe-integer limits, validated at their owning mounts with no invented deployment defaults. Validate nonempty provider/persona and nonempty tool-filter configuration; resolve missing providers and unsupported capabilities at the earliest resolvable point and again through the service at start. Research permits only configured read-only capabilities; general execution and further-delegation tools must be excluded unless another real enforcement owner bounds their effects. Bounds cover UTF-8 bytes of complete owned JSON/rendered results, including metadata, provenance, and wrappers, not just assistant text.

Register `dev_loop_delegate` with the JSON fields of DelegationBrief and `dev_loop_delegations` with `{pieceId}` through `ctx.tools.register(defineTool(...))`, declaring parameters, output schema, and a pure renderer. Neither accepts provider, cwd, preset, parent, signal, persona, or toolFilter from the model. Use existing generic tool cards unless a separate pure presenter is justified; model-visible output is logged by the tool runtime. No new SessionEventMap member is needed for this tool-owned result path.

Reject oversized briefs before any request record or enqueue. If provider output exceeds maxOutcomeBytes or cannot be represented as text, record a bounded failed observation with an explicit limitation; never present a clipped report as complete. Tool output exceeding maxToolOutputBytes returns an explicit bounded error naming the durable delegation id instead of silently truncating its record. History tool output returns the complete ordered array only when both maxHistoryRecords and maxToolOutputBytes permit it; otherwise report overflow without a partial array. The service retains and returns full history. Validate configured output budgets can represent the fixed error envelopes; test tiny, exact, and multibyte boundaries. These limits do not promise bounded provider buffering or automatic history deletion.

There is no arbitrary brief.preset. The child optionally inherits the parent's live standing composition through `agentPresets.composeFrom`; a rosterless parent is supported. Capture actual `run.localAgent.session.header.agentPreset` while the run is live, or omit it when unavailable. Do not substitute a requested label or stale parent header. Provenance renders as reported by the role and actual preset, or explicitly states that no preset was recorded.

`ToolRuntime.restrict` removes inherited host/preset capabilities from schemas and real executor dispatch, including nested PTC calls. Filters intersect; unknown and reserved transport names reject. Tools registered in the child's own scope remain visible, including structured-result capture. This is not a security fence against trusted plugins, service calls, or filesystem effects of an allowed shell. Persona text is instructions, not enforcement. Allocation alone is not confinement: sandbox policy consumes the real cwd, workspace-write retains temp allowances, danger-full-access bypasses containment, and direct subprocess calls do not imply sandbox enforcement.

### Caller, Queue, and assignment ownership

At tool entry, require `exec.agent` and exact live registry equality, then invoke the service under `ctx.agents.withInitiator(exec.agent, ...)` with `exec.signal`. At service entry, capture `callerAgent = ctx.agents.requireInitiator()` before awaiting and require `ctx.agents.get(callerAgent.id) === callerAgent`. Derive its Session once. Restore that exact initiator around enqueue after persistence; never reconstruct a replacement Agent by id.

Call `queue.enqueue({pieceId, signal, dispatch})`. Its callback receives the exact captured Agent and combined cancellation. Inside admitted dispatch, require parent cwd, call `assignWorktree({pieceId,cwd,signal})`, construct the role brief, and call `subagents.start(configuredProvider,{parent:agent,signal,cwd:assignment.worktreePath,prompt,persona,toolFilter,...})`. Capture only needed run id/composition leaves and return the actual SubagentRun immediately. Do not await its result, dispose it, write a post-start storage record before handing it to Queue, or return a continuable receipt.

Queue owns result observation, disposal, and late-start cleanup through quiescence. The service awaits ticket.result; it does not claim cleanup succeeded when Queue rejects for uncertain cleanup. Cancellation after startup must cancel/join the ticket. Service disposal stops admission and joins all owned operations before closing storage. Worktree assignment survives every role result, cancellation, failure, and plugin disposal. Only the orchestration owner may retire it after all users stop and transfer/post-transfer verification finish; borrowed/dirty/changed-HEAD preservation remains 00.05's authority.

### Durable history before 00.12

The Roles service owns one `defineDomain({name:'dev_loop_roles',version:1,layout:'single',tables:{delegations:domainTable(...)}})` using a Zod discriminated record schema. Open it in Service initialization through `ctx.storageDomain.open`, retain `domain.table('delegations')`, and close it through an owned disposer after role operations settle. Domain names use storage's lowercase SQL-safe identifier grammar; the underscore spelling is required, unlike the hyphenated npm package name. DomainFacility enforces single-open ownership. Authoritative invalid records reject opening; do not use backup-and-skip.

The Host composition supplies existing storage, a durable backend, and storage-domain routing. For the JSON backend, storage-json Config.root is explicit and storage-domain Config.backend names `json`; Roles neither invents a storage file nor accesses that backend directly. `KvTable.put/update` await backend durability before memory publication and domain/changed. That event is a runtime notification, not a Session event or a second persistence mechanism.

Persist a requested row before enqueue; storage failure prevents startup. After ticket result/cleanup, persist a settled observation before returning it. Expected startup, cancellation, and child failures produce truthful terminal records where persistence succeeds; inability to prove quiescence sets cleanup to unproven. Preserve the failure exposed by Queue or startup independently of a terminal-write failure. A rejected ticket alone proves no cleanup outcome. After Queue acquires a returned lease, successful awaited `ticket.cancel()` establishes its cleanup; a rejecting cancel records `unproven`. An attempted start that rejects without returning a lease remains `unproven`, because runtime startup can swallow a disposal failure. Do not claim access to an earlier child failure replaced by a disposal failure. Recording uses the domain write lifetime, not an already-aborted caller signal; domain writes accept no AbortSignal. Close storage only after final recording attempts, because close rejects new writes while draining already-queued writes.

Record only actual acquired assignment, child id, preset, and stop reason. A pre-start failure has no child id. Storage and child startup are not one transaction: a crash can leave a requested row with no recorded child id, and a failed terminal write leaves that prior row intact. Reopening displays unresolved requested records without fabricating activity, completion, or automatic retry. 00.12 owns later recovery/reconciliation and consumes this service rather than becoming its dependency or reopening its domain.

`getDelegations` filters table.entries by canonical piece id, orders by requestedAt then delegationId, and returns detached owned DTOs. Records include repository/worktree metadata because a piece id alone does not identify a directory; the service uses the one-repository scope of its configured allocator. Do not expose another repository's history through an unscoped global model tool. The chosen Host composition owns that repository association; cross-repository routing and automatic history retention are outside this piece.

## Teach me while you build

- **What it does:** The Brain gives a specialist a bounded job, keeps its work directory for the next specialist, and saves what actually happened.
- **Background:** A provider starts a child; a consumer chooses how to use it. An immutable Session header records creation facts. A durable domain stores application records independently of whether a model turn is open.
- **How it works here:** A registered tool supplies real caller/cancellation, Roles saves intent, Queue admits creation, Worktree supplies the retained path, and subagents starts the child. Queue cleans the run before Roles persists its terminal observation. Failures remain distinguishable from completion.
- **Why this approach:** Workspace metadata belongs at creation, execution cleanup belongs to Queue, and assignment retirement belongs to the piece owner. Sharing one lifetime would either delete handoff files or publish success before cleanup.
- **Approaches considered:** Dynamic role options over existing spawn/fork reuse proven lifecycle machinery. Separate static presets win when entire plugin composition differs, but cannot be selected through the existing request. A new provider could own metadata but duplicates unrelated lifecycle work. An event-sourced history is an alternative when the Session log owns all queries; this piece instead needs a piece-wide durable store before 00.12. Temporal's TypeScript SDK is an external alternative when durable workflow orchestration is needed; Research inspected separate child-start/completion promises and cancellation commands, not the server's recovery behavior. This piece reuses Harness ownership instead of adding that runtime.
- **Prior art inspected:** In-repository AgentPresets composition inheritance, WorkspaceRegistry's storageDomain initialization, and tool-present's defineTool registration. Research, preset not recorded, opened [Temporal SDK v1.11.8 workflow.ts](https://github.com/temporalio/sdk-typescript/blob/v1.11.8/packages/workflow/src/workflow.ts), `startChildWorkflowExecutionNextHandler`, and sibling `workflow-handle.ts`: start and completion are separate promises, cancellation is a command, and an execution id differs from a logical workflow id. No external code reused or server replay guarantee inferred.
- **What we get for free:** The tool runtime logs model-facing results; providers create children and apply supported options; Queue joins leases; storageDomain serializes durable writes and validates reopened records. Roles owns role policy, truthful records, bounds, and caller-to-piece coordination, not process isolation or crash recovery.
- **From the source documentation:** Domain.close promises to “reject new writes immediately, drain already-queued writes”; close storage after terminal recording, not before cancelling workers. See the domain interface cited below.
- **What to notice:** In [Roles perform](../../../../packages/dev-loop/roles/src/index.ts), `startup.attempted` without a returned child id records cleanup as unproven: promise rejection does not prove resource disposal. In the [scoped tool](../../../../packages/dev-loop/roles/src/tool.ts), complete rendered content is byte-counted, not just report text. The [Roles README](../../../../packages/dev-loop/roles/README.md#understand-the-implementation) explains these ownership choices. No external source was newly inspected by this Utility pass; prior-art reports below retain their original attribution.
- **Concepts to own:** Resource ownership separates run, assignment, and storage lifetimes; commit-point publication reports a record only after durable write; nominal typing prevents confusing child and delegation ids; non-atomic side effects explain unresolved crash residue.
- **Interview angle:** “How do you avoid losing delegated work on cancellation?” Join the run, retain its workspace, and independently persist the observed result. Follow-up: a crash between independent systems requires reconciliation rather than an invented transaction.
- **Decisions you can now make alone:** Adjust validated role policy and byte budgets with focused tests. Escalate arbitrary preset selection, repository routing, child-local security enforcement, transfer/deletion, or recovery changes to their owners.
- **What you should learn from this:** Tool visibility, directory allocation, durable identity, cleanup, and evidence attribution are separate guarantees; one does not prove another.
