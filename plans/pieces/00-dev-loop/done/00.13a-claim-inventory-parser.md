## Summary

Nya~ (=^･ω･^=)🐾 Inspector Cat is checking the claims table! Every piece has a `## Resources and proof` section with a shiny 4-column proof table: Claim, Citation, How established, and Checked against! We parse each row to find what promises the piece is making! If a claim is marked unverified, our detective friends must verify it before anyone writes code! No unverified claims allowed!

### Human Decision Point: Option A vs Option B
- **Option A (Active)**: Extract structured `InventoryClaim` rows from `## Resources and proof` tables, validating 4-column structure (`Claim`, `Citation`, `How established`, `Checked against`).
- **Option B (Alternative)**: Treat claims as unparsed text, preventing programmatic verification of load-bearing assertions.

## Behaviour

- **Given** a `## Resources and proof` section with valid claim rows **When** `parseInventory` is called **Then** it returns `InventoryClaim` records with `claimId`, `row`, `claim`, `citation`, `howEstablished`, and `checkedAgainst`.
- **Given** a proof table with missing columns or unescaped pipes **When** `parseInventory` runs **Then** it throws an error requiring four nonempty cells or matching columns.
- **Given** a proof section with `No load-bearing claims.` **When** `parseInventory` executes **Then** it returns an empty array without throwing.

## Teach me while you build

Before you believe a story, make a list of every claim! Let's inventory the facts! Nya~

- **What it does**: Parses the proof table rows into strongly typed `InventoryClaim` objects for verification.
- **Background**: The R-claims-verified axiom requires every load-bearing claim to have an explicit citation and verification method.
- **How it works here**: Locates `## Resources and proof`. Extracts lines between it and the next `##` heading. Parses markdown table cells using GFM AST.
- **Why this approach**: Enables programmatic checking of whether claims were verified, measured, or remain unverified.
- **Approaches considered**: Unstructured prose claims (impossible to verify automatically) vs Structured 4-column table (chosen: machine-checkable).
- **Prior art inspected**: Scientific paper assertion indexing and formal verification claim registries.
- **What we get for free**: Reuses `mdast-util-from-markdown` and `mdast-util-gfm` for robust AST parsing.
- **From the docs**: `plans/AGENTS.md`: "A proof table — one row per load-bearing claim: the claim, the citation... how it was established... and the date."
- **What to notice**: Notice how column 3 enforces the closed vocabulary: `direct inspection`, `measured`, `reported by`, `readme only`, `unverified`!
- **Concepts to own**: Claim inventory: extracting testable assertions from technical prose into structured data.
- **Interview angle**: How do you automate architectural claim verification in engineering proposals? Answer: Parse structured assertion tables mapping claims to locators and verification methods.
- **Decisions you can now make alone**: You can add custom claim category tags in the citation column without breaking table extraction.
- **What you should learn from this**: Every engineering decision rests on claims. Inventory them explicitly so you can verify each one! Purr~
