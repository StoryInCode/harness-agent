## Summary

Every investigation requires a forensic ledger. When a subagent settles, its reported findings, limitations, exit status, and execution duration must be recorded permanently in the storage domain. If a system crashes, the ledger preserves the exact provenance of all delegated labor. Unrecorded work does not exist in the eyes of the law.

### Human Decision Point: Option A vs Option B
- **Option A (Active)**: Store complete settled delegation records in durable storage domain with schema validation.
- **Option B (Alternative)**: Keep delegation results in volatile memory only, losing audit trails upon host restart.

## Behaviour

- **Given** a delegation request **When** `delegate` starts execution **Then** it persists a `RequestedDelegation` record into `ctx.storageDomain` before queue admission.
- **Given** a settled delegation with outcome text and limitations **When** child execution completes or aborts **Then** it replaces the row with a `SettledDelegation` record documenting terminal status and reported provenance.
- **Given** a host restart occurring after delegation completion **When** `getDelegations(pieceId)` is called on a fresh instance **Then** it hydrates and returns the full delegation history from the durable storage domain.
- **Given** a query for delegations on an unworked piece **When** `getDelegations('99.99')` runs **Then** it validates the piece ID schema and returns an empty array without errors.

## Harness fit

Durable storage domain table in `packages/dev-loop/roles/src/records.ts` and history queries via `DevLoopRoles` in `packages/dev-loop/roles/src/index.ts` using `ctx.storageDomain`.

## Contracts

export type DelegationRecord = RequestedDelegation | SettledDelegation

export interface SettledDelegation extends Omit<RequestedDelegation, 'state'> {
  readonly state: 'settled'
  readonly finishedAt: number
  readonly subagentSessionId?: SessionId
  readonly effectivePreset?: string
  readonly worktreeAssignment?: WorktreeAssignment
  readonly stopReason?: SubagentStopReason
  readonly status: 'completed' | 'aborted' | 'failed'
  readonly cleanup: 'quiescent' | 'unproven'
  readonly outcome: string
  readonly limitations: readonly string[]
  readonly provenance: {
    readonly kind: 'reported'
    readonly role: DevLoopRole
    readonly preset?: string
  }
}

export declare class DevLoopRoles extends Service {
  getDelegations(pieceId: string): Promise<readonly DelegationRecord[]>
}

## Teach me while you build

Evidence without provenance is inadmissible. The chain of custody must be unbroken.

- **What it does**: Persists every delegation attempt, outcome, and limitation into durable storage.
- **Background**: DSH uses `ctx.storageDomain` to partition structured JSON records with schema validation.
- **How it works here**: When a delegation is initiated, `perform` writes a `RequestedDelegation` before dispatch. When the subagent settles, it replaces the entry with a `SettledDelegation`. `getDelegations` queries the storage domain by piece ID.
- **Why this approach**: Survives process restarts and provides an incontrovertible audit log for claim verification.
- **Approaches considered**: Volatile memory (lost on crash) vs Append-only log file (harder to query) vs Schema-validated storage domain (chosen).
- **Prior art inspected**: W3C PROV-DM provenance data model and double-entry bookkeeping ledgers.
- **What we get for free**: DSH storage domain handles atomic writes, serialization, and directory management.
- **From the docs**: AGENTS.md: 'Durable state uses the session/event/projection conventions or ctx.storageDomain; it does not invent private persistence.'
- **What to notice**: Notice how `provenance.kind === 'reported'` explicitly flags subagent claims as reported testimony rather than verified fact!
- **Concepts to own**: Provenance tracking: maintaining an auditable record of who produced an artifact, when, and under what constraints.
- **Interview angle**: How do you track attribution and provenance in autonomous multi-agent systems? Answer: Immutable outcome ledgers distinguishing observed evidence from reported claims.
- **Decisions you can now make alone**: You can configure retention policies for historical delegation logs in `cordis.yml`.
- **What you should learn from this**: Document every finding permanently. Truth must survive system restarts.
