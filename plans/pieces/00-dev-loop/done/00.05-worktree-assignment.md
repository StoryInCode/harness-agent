# 00.05 — Per-Piece Detached Git Worktree Allocation

**Set:** 00-dev-loop · **Queue:** 5 · **Depends on:** 00.04
**Status:** done
**Harness primitive:** Service Provider · **Package:** `@deepseek-ai/dsh-dev-loop-worktree`

## Summary

Give each piece a detached Git worktree. A worktree is a second working directory that shares the repository's history. Keep its assignment alive across Test Writer and Implementer runs until transfer and post-transfer verification finish. Reuse existing linked-worktree isolation rather than nesting another checkout. Allocation never creates branches, commits, transfers changes, pushes, or deletes work automatically.

This is the dev-loop-owned `ctx.devLoopWorktree` service, not a consumer of `ctx.worktrees`: no such upstream allocator existed in the inspected source. The broader [worktree-management plan](../../../07-worktree-management.md) is not an implementation dependency. Its branch, remote, automatic-ignore-maintenance, and kernel-confinement assumptions do not govern this piece.

## Behaviour

- **Given** a valid mainline checkout and an ignored worktree root **When** a piece is assigned **Then** create one detached worktree at the resolved mainline commit, verify Git registration, and publish its immutable assignment.
- **Given** an existing linked worktree outside a submodule **When** assignment starts from it **Then** borrow its top-level directory without creating another tree, and record that this service does not own removal.
- **Given** an unignored root, occupied target, or escaping symlink **When** allocation is requested **Then** refuse without overwriting files or changing ignore configuration.
- **Given** repeated or concurrent compatible requests for one piece **When** assignment runs **Then** return the same retained assignment instead of allocating twice or changing its base.
- **Given** a Test Writer run leaving tests in its tree **When** the Implementer role starts later **Then** the assignment and files remain at the same path. Role completion is not retirement.
- **Given** failure, cancellation, or plugin disposal **When** an owned command is active **Then** terminate and await managed-range quiescence. Preserve and disclose physical residue rather than recursively deleting it.
- **Given** explicit retirement of an owned, unused, clean tree whose HEAD equals its base **When** Git removal succeeds **Then** retire its mapping. Borrowed, dirty, or changed-HEAD trees remain.

## Harness fit

**Service Provider** in `@deepseek-ai/dsh-dev-loop-worktree`: a host-plane Cordis Service publishing `ctx.devLoopWorktree` and injecting `['fs', 'subprocess']`. Keep its definition and concrete provider together while only the dev-loop needs this API. Do not mount one service per role. `workspaceRegistry` records existing directories and session membership, not Git allocation.

Consume filesystem target resolution, metadata, and containment, plus argv-based subprocess execution. Git owns creation, registration, and explicit removal. `FileSystem` has no `mkdir`, `rename`, or `rm` method. Do not invent filesystem interception or a replacement process runner.

Assignments are process-lifetime host state shared across roles, not child-session effects. Disposal stops admission, cancels commands, and awaits settlement, but never removes trees. [00.12](00.12-loop-persistence.md) owns durable association and recovery through Harness persistence conventions. This piece writes no private mapping JSON. After restart, report an occupied unrecorded path for recovery instead of adopting it with a guessed base.

The following API is **proposed**, not shipped:

```typescript
import type { Branded } from '@deepseek-ai/dsh-brand'

export interface Config {
  mainlinePath: string
  worktreeRoot?: string

  outputMaxBytes: number
  terminationGraceMs: number
}

export interface WorktreeAssignment {
  readonly id: WorktreeAssignmentId
  readonly pieceId: string
  readonly mainlinePath: string
  readonly worktreePath: string
  readonly baseCommit: GitCommit
  readonly ownership: 'created' | 'borrowed'
}

  readonly pieceId: string
  readonly cwd: string
  readonly signal: AbortSignal
}

export type WorktreeRetirement =
  | { readonly kind: 'removed' }
  | { readonly kind: 'preserved'; readonly reason: 'borrowed' | 'dirty' | 'head-changed' }

export interface DevLoopWorktree {
  assignWorktree(request: AssignWorktreeRequest): Promise<WorktreeAssignment>
  getAssignment(pieceId: string): WorktreeAssignment | undefined

```

### Configuration and identity

`mainlinePath` is required. It must resolve to an existing non-bare main checkout with a valid commit. `worktreeRoot` defaults through validated Config to `.worktrees` beneath that checkout. Require canonical containment and reject symlink escape. Command timeout and termination grace are required positive safe integers within the Node timer limit. Output cap is a required positive safe integer. Resolve defaults once into complete internal configuration, not inside command execution.

One service instance owns one repository, so its piece-id mapping is unambiguous. Piece IDs follow the corpus's dotted syntax and cannot be arbitrary path fragments. Validate Git output before branding commit IDs, and do not assume only SHA-1 repositories. Unknown retirement IDs, incompatible repeated requests, occupied targets, and different pieces claiming one borrowed tree reject explicitly. Serialize assignment and retirement mutations. A same-piece call waits for the existing attempt. Cancellation of that attempt rejects its waiters, who may explicitly retry after settlement. A waiting caller's own cancellation must not cancel another caller's command.

### Allocation protocol

1. Resolve request paths with `ctx.fs.resolve`, obtain subprocess-world paths through `processPath`, and inspect entries through `lstat`/`stat`. Filesystem and subprocess providers must share an execution world.
2. Probe top-level, bare status, absolute Git directory, common Git directory, and superproject working tree. Canonicalize directory results before comparison. Differing Git/common directories without a superproject identify linked isolation, and you may borrow its top-level only within the configured repository. Reject submodules rather than treating a `.git` file as sufficient evidence.
3. For a new tree, resolve the configured mainline's `HEAD^{commit}` once. Check the proposed root with `git check-ignore` before creating anything beneath it. Nonignored means refusal, not automatic `.gitignore` editing. Check path occupancy and Git inventory, and refuse collisions instead of unbounded suffix searching.
4. Execute `git worktree add --detach <absolute-path> <resolved-commit>` with discrete arguments. Never rely on Git's implicit branch defaults.
5. Read `git worktree list --porcelain -z`, and verify repository membership, path, detached status, and base before publication. A borrowed tree records its observed HEAD without rewriting it. Existing attached linked isolation may be borrowed, but this service never creates or moves its branch.

Git checkout copies committed content only. It does not copy mainline staged, unstaged, untracked, or ignored files. Do not copy `.env`, dependencies, or other ignored assets. Ignore rules keep the worktree root out of ordinary parent tracking. They do not prove child files are disposable, and they do not untrack explicitly tracked files.

### Subprocess lifetime and failures

Use `ctx.subprocess.resolveExecutable` and `spawn(SubprocessSpawnSpec)`, not shell strings. Every spawn sets `cwd`, `argv`, `stdin: 'ignore'`, bounded collected stdout/stderr, `graceMs`, and a signal combining caller cancellation, service disposal, and command deadline. Explicitly disable interactive Git prompts and remove ambient Git repository/index redirection variables so `cwd` identifies the repository. Credential scrubbing alone does not remove those variables.

`graceMs` is termination and drain grace, not a command timeout. A deadline initiates cancellation but does not prove a process stopped. Request termination and await `waitForExit()` without a wait deadline before claiming quiescence, including after `done` rejects. A provider fault can hold teardown or make observation fail. Report failure, and never substitute an elapsed timer for cleanup. Preserve independent abort, exit-code, and signal facts. Zero exit after cancellation is not success.

Reject lossy or truncated stdout before parsing inventory or status. Report bounded diagnostics, the attempted path, and whether residue remains or could not be determined. Publish no successful assignment after failure. Never delete residue, force-unlock Git state, or run broad prune/reset/clean recovery.

### Retention and explicit retirement

The orchestration owner must stop all users of an assignment before retirement, and must retain it through RED, GREEN, transfer, and post-transfer tests. Service disposal and subagent termination never invoke retirement. There is no `force` parameter.

A borrowed tree always returns `preserved`. For a created tree, revalidate Git identity, HEAD, and staged/unstaged/untracked files. A changed HEAD is preserved even with clean status, because clean detached commits may be untransferred. Git's ordinary clean status excludes ignored files. So retirement additionally checks ignored files and conservatively returns `dirty` when any exist. They may contain evidence or secrets. Build-looking names are not deletion authority.

Only a clean, unchanged, owned tree may be removed with `git worktree remove` without force. Retain its mapping on removal failure, and remove the mapping only after success. Require exclusive caller ownership and revalidate immediately before removal. This service cannot make Git checks transactional against arbitrary external writers.

Dirty post-transfer deletion is deferred to an explicit later transfer/retirement protocol. Allocation does not compare patches, merge branches, infer transfer from tests, or certify master contents. Actual transfer must preserve unrelated master staged/unstaged/untracked work, surface overlapping conflicts, and never reset or clean master.

### Child sessions and confinement

[00.06](00.06-role-delegation.md) consumes retained assignments. Current `SubagentStartRequest` has no `cwd`/`meta` override, and `childSessionMeta` inherits parent cwd. Child-cwd selection requires an explicit real-consumer/provider API amendment there. Do not invent `start({ meta: { cwd } })`, mutate a parent header, or claim this allocator records a child header.

Allocation is not a sandbox fence. Once a child actually holds the assigned `SessionHeader.cwd`, sandbox policy derives its workspace root from that value. File writes are confined only through the sandboxing backend under `workspace-write`, with `/tmp` and OS temp also writable. `danger-full-access` bypasses containment. Direct subprocess execution is not automatically filesystem-policy enforcement, and shell confinement belongs to its sandbox composition.

## Teach me while you build

- **What it does:** A piece gets a second directory, and later roles receive that directory without losing the Test Writer's files.
- **Background:** A Git worktree has its own files, index (staging area), and HEAD (current commit reference), while sharing repository objects. Detached HEAD points to a commit without a named branch. Clean status does not prove work reached master.
- **How it works here:** The host service receives a piece and cwd, probes Git through `ctx.subprocess`, checks paths through `ctx.fs`, and publishes only after Git confirms allocation. Failures retain files and disclose residue. The role dispatcher consumes the path but does not own deletion.
- **Why this approach:** Assignment lifetime follows the piece, not one agent run. A host service supplies one owner across roles without implementing a general worktree subsystem.
- **Approaches considered:** (1) Detached linked worktrees, documented by Git and chosen here, share objects while separating files and index. (2) Independent clones separate repository metadata at greater setup and disk cost. Consider them for independent repositories or machines, not this local allocator. No external clone implementation was inspected. (3) Serial main-checkout editing avoids allocation but cannot isolate concurrent edits and fails this piece's requirement.
- **Prior art inspected:** Delegated research opened the official Git manual's DESCRIPTION, COMMANDS add/remove/prune, OPTIONS detach/porcelain/z, DETAILS, and LIST OUTPUT FORMAT/Porcelain Format. It adopted command semantics, not external code, and no code-license reuse applies. No quotation is claimed.
- **What we get for free:** Git owns checkout and registration, filesystem owns canonical target identity, and subprocess owns managed termination. We own mapping, deadlines, publication, and conservative retirement. Git does not certify transfer of uncommitted files.
- **What to notice:** `done` reports command outcome, while `waitForExit` observes managed-range emptiness. A timeout initiates termination but cannot certify emptiness. Ignored files are absent from ordinary status and still deserve preservation.
- **Concepts to own:** Resource ownership decides who may delete a tree. Idempotency returns one resource on repeat calls. Commit-point publication excludes failed allocations. Nominal typing distinguishes assignment IDs from commit IDs.
- **Interview angle:** “How do sequential agent roles stay isolated without losing handoff files?” Give the piece one retained tree, pass its path to each role, and separate retirement from teardown. Follow-up: crash recovery needs durable association and reconciliation, not a guessed base from leftover files.
- **Decisions you can now make alone:** Add allocation refusal cases and diagnostics without adding transfer behavior. Escalate dirty-tree deletion, remote equivalence, and child-provider changes to their owning pieces. Never weaken preservation because tests succeeded.
- **What you should learn from this:** Workspace allocation, execution lifetime, transfer correctness, and deletion authority are separate obligations, and none proves the others.

## Reuse capture

- **Reuse candidate:** Piece-owned detached worktree assignment, retaining one host mapping across sequential roles, potentially useful for other local multi-agent handoffs. Generic configuration and durable recovery need separate current consumers before extraction. Evidence: implemented service, real Git/Loader tests, and parent post-transfer strict coverage. Confidence: medium for this local retained-assignment use, not generic cross-process recovery.
- **Anti-pattern:** Treating clean status, an expired timeout, or a finished child as deletion authority. Each omits a separate fact: transfer, quiescence, or piece lifetime.
- **Known limitations:** Local non-bare repositories, and submodules rejected. No ignored-asset copying, cross-process assignment lock, durable reattachment, child-cwd override, transfer engine, or dirty-tree retirement. Ignored assets block retirement. External writers can race checks. Disposal preserves disk but not an in-memory association.
