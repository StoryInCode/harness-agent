### Human Decision Point: Option A vs Option B

## Behaviour

- **Given** a Brain orchestrator session **When** inspecting available tools **Then** approval presentation, candidate inspection, and role delegation tools are present, but worker execution and proof tools are excluded.
- **Given** a micro-gate transition request to `done` **When** pre-complete gates execute **Then** a failure in any of the Four Gates (Format, Red, Green, Transfer) halts the transition immediately with a fail-closed error.
- **Given** an admitted micro-gate task **When** dispatched to a worker subagent **Then** an isolated detached Git worktree under `.worktrees/<piece-id>` is allocated from current mainline HEAD.

## Teach me while you build

Mwahahaha! Let me unveil the secret structure of our lab's grandest invention!

- **Background**: In multi-agent autonomous engineering, giving an orchestrator direct access to file editing or test execution causes fatal execution drift. The orchestrator gets bogged down in minor syntax bugs instead of governing the overall architecture.
- **How it works here**: The host plane runs durable TypeScript services (`ctx.devLoopLifecycle`, `ctx.devLoopQueue`, `ctx.devLoopWorktree`). The agent plane boots the `dev-loop-brain` preset, exposing model-facing tools (`kanban_stage_subtasks`, `role_dispatch`) while strictly forbidding self-execution via monotonic tool guards.
- **Why this approach**: Asymmetric capability distribution guarantees organizational integrity. The orchestrator directs; specialized subagents execute; verification gates audit.
- **Approaches considered**: Monolithic agent (rejected: hallucinations cascade into broken code) vs Shell script wrappers (rejected: lacks typed Cordis lifecycle and recovery) vs Dual-plane Cordis composition (chosen: clean separation, type-safe event hooks).
- **Prior art inspected**: DeepSeek Harness Cordis architecture and multi-agent presets.
- **What we get for free**: Native Cordis dependency injection, lifecycle disposal, and event broadcasting.
- **What to notice**: Notice that the orchestrator never touches production files directly. It creates a detached worktree for the subagent, ensuring zero timeline contamination!
- **Concepts to own**: Asymmetric capability boundaries: separating planning authority from execution privilege in autonomous systems.
- **Interview angle**: Why should an orchestrator agent not have tools to edit code directly? Answer: To prevent cognitive collapse, maintain architectural boundaries, and enforce objective external verification.
- **Decisions you can now make alone**: You can safely add new specialized worker roles without altering the orchestrator's decision loop.
- **What you should learn from this**: The Organization trembles when our architecture is provably deterministic and strictly segregated! El Psy Kongroo.
