## Summary

Nya~ (=^･ω･^=)🐾 Inspector Cat is on the case! Before we can read any piece file, we have to sniff out all the headings and make sure sneaky code blocks don't trick us! We scan raw text line-by-line to find ATX `##` headers while skipping fenced code blocks (` ``` ` or `~~~`). It's like sorting delicious fish treats from empty wrappers!

### Human Decision Point: Option A vs Option B
- **Option A (Active)**: Scan line-by-line with a pure zero-dependency stateful scanner that tracks fence opening and closing delimiters.
- **Option B (Alternative)**: Use an external heavyweight CommonMark AST parser like unified/remark which adds 15MB of node_modules and slows down intake.

## Behaviour

- **Given** lines of markdown with valid `##` headings outside fences **When** `splitSections` is called **Then** it returns the header lines and section spans with exact start and end line indices.
- **Given** lines of markdown with a `##` line inside a fenced code block **When** `splitSections` processes the lines **Then** the heading inside the fence is treated as content rather than a section boundary.
- **Given** lines of markdown with tilde fences `~~~` **When** `splitSections` processes the lines **Then** it ignores headings inside tilde fences and does not let backticks close them.

## Teach me while you build

Purr~ Let's learn how to look at markdown without getting confused by cat toys! (=^･ω･^=)

- **What it does**: Separates the header metadata lines and body sections (`## Heading`) while ignoring fake headings inside code fences.
- **Background**: In CommonMark, code fences start with 3 or more backticks or tildes. Anything inside them is raw text, not markdown structure.
- **How it works here**: We loop through each line in `splitSections`. `fenceMarkerAt` checks if the line opens or closes a fence. If we are not inside a fence and see `## `, we start a new section.
- **Why this approach**: A single linear pass O(N) requires zero regex backtracking and no external dependencies.
- **Approaches considered**: Remark AST parser (rejected: huge dependency tree and slower) vs Regex matching (rejected: catastrophic backtracking on unclosed fences) vs Pure state scanner (chosen).
- **Prior art inspected**: CommonMark specification Section 4.5 (Fenced Code Blocks).
- **What we get for free**: Node.js string methods like `startsWith` and `slice` make array processing fast and pure.
- **From the docs**: CommonMark spec: 'A code fence is a sequence of at least three consecutive backtick characters or tildes.'
- **What to notice**: Notice how `fence.char` ensures backticks don't close a tilde block!
- **Concepts to own**: State machine parsing: maintaining parser mode (inside/outside fence) across sequential tokens.
- **Interview angle**: How would you parse markdown structure without a full compiler pipeline? Answer: A streaming single-pass scanner tracking fence depth.
- **Decisions you can now make alone**: You can safely add support for 4-space indentation fences without changing section logic.
- **What you should learn from this**: Never parse document structure with naive regular expressions when code fences can embed false positives! Purr~
