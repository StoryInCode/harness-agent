## Summary

Nya~ (=^･ω･^=)🐾 Inspector Cat is listening at the command desk! Human operators type commands like `/dev-loop status` or `/dev-loop show 00.01a`! We parse raw input strings into typed `Request` operations (`help`, `status`, `list`, `queue`, `show`, `approve`, `reject`), validating piece IDs and SHA256 digests while keeping rejection reasons as clean unquoted remainders. If input is malformed, we return complete usage guidance with a friendly purr instead of crashing! Everything is strictly typed and cozy!

### Human Decision Point: Option A vs Option B
- **Option A (Active)**: Parse whitespace-delimited tokens with strict grammar, dedicated subcommands (`help`, `status`, `list`, `queue`, `show`, `approve`, `reject`), and literal remainder handling for rejection reasons without quote complexity.
- **Option B (Alternative)**: Implement full shell-like quoting and flags parser that complicates command input and introduces quoting edge cases.

## Behaviour

- **Given** an empty input, whitespace, or 'help' **When** `parse` is invoked **Then** it returns `{ verb: 'help' }` without throwing.
- **Given** an operation with missing required ID or invalid ID syntax **When** `parse` runs **Then** it throws a `Refusal` explaining the expected `NN.MM` or `NN.MMx` format.
- **Given** a rejection command `/dev-loop reject 00.01a needs more tests` **When** `parse` executes **Then** it preserves the multi-word reason remainder literally as `{ verb: 'reject', id: '00.01a', reason: 'needs more tests' }`.
- **Given** an unknown operation or unexpected extra arguments **When** `parse` executes **Then** it throws a `Refusal` describing the malformed input.

## Teach me while you build

How does the computer understand human whispers? We turn words into tidy command tokens! Purr~

- **What it does**: Parses `/dev-loop` CLI inputs and maps raw strings to typed `Request` operations.
- **Background**: Human operators interact through chat and CLI interfaces where commands must fail safely with actionable diagnostics.
- **How it works here**: `parse` trims input and splits tokens by whitespace. Subcommands like `help`, `status`, `list`, `queue` forbid extra arguments. `show`, `approve`, and `reject` require validated piece IDs. `reject` slices the rest of the string directly to preserve reason text without requiring shell quotes.
- **Why this approach**: Whitespace tokenization with slice-based remainder avoids complex quoting state machines while cleanly supporting multi-word human reasons.
- **Approaches considered**: Shell quote tokenizer (rejected: unnecessary complexity and fragile quoting rules) vs Structured JSON arguments (rejected: clumsy human ergonomics) vs Positional grammar with literal remainder (chosen: simple, robust, and operator-friendly).
- **Prior art inspected**: Git subcommand parsing and IRC slash command dispatchers.
- **What we get for free**: Cordis command registration handles invocation signal cancellation and UI dispatch.
- **From the docs**: AGENTS.md: 'Public APIs are pre-stable... Switch on discriminant tags.'
- **What to notice**: Notice that the piece ID regex `/^\d{2}\.\d{2}[a-z]?$/u` supports both macro pieces and micro-gate sequential letters!
- **Concepts to own**: Domain-specific input parsing: converting unstructured operator text into fail-closed tagged unions.
- **Interview angle**: Why prefer literal remainder slicing over quoting for trailing free-text arguments? Answer: It eliminates quote escaping bugs and simplifies input syntax for human operators.
- **Decisions you can now make alone**: You can add new non-mutating verbs to the `Request` tagged union and command switch statement.
- **Lesson**: Keep command grammars simple and fail-closed: explicit error diagnostics prevent operator mistakes. Purr~
