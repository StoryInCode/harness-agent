## Summary

Nya~ (=^･ω･^=)🐾 Inspector Cat is checking the citation footnotes! Every piece has a `## References` section with a neat markdown table listing sources, roles, and questions. We parse the GFM tables and AST locators into clean `ReferenceEntry` records so our detective friends can verify them. No messy scratched-up tables allowed!

### Human Decision Point: Option A vs Option B
- **Option A (Active)**: Parse markdown table rows into an AST via GFM extensions, handling escaped pipes, link definitions, and inline code locators cleanly.
- **Option B (Alternative)**: Parse table rows with naive regex or string splits that break whenever inline code contains an escaped pipe `\|` or link reference definitions.

## Behaviour

- **Given** a `## References` section with a canonical five-column table **When** `parseReferences` parses the text **Then** it returns structured `ReferenceEntry` records preserving question, inspection, and usage fields.
- **Given** a table row containing multiple links and escaped pipes inside inline code **When** `parseReferences` parses the row **Then** it expands the locators while preserving escaped pipes without splitting columns.
- **Given** a piece with no `## References` heading **When** `parseReferences` is called **Then** it records a `MISSING_REFERENCES` error with an empty entries array.

## Harness fit

Pure Markdown and GFM AST parser in `packages/dev-loop/references/src/parser.ts`. Used by `DevLoopReferences` (`ctx.devLoopReferences`) to extract detached source locators and column metadata.

## Contracts

```typescript
import type { ReferenceEntry, ReferenceError } from './types.ts'

export type LocatorKind = 'code' | 'link' | 'invalid'

export function parseReferences(text: string, maxReferences: number): {
  entries: ReferenceEntry[]
  errors: ReferenceError[]
  explicitEmpty: boolean
  kinds: LocatorKind[]
}

export interface ReferenceEntry {
  row: number
  source: string
  sourceText: string
  attribution: string
  rolePreset?: string
  question?: string
  inspection?: string
  usage?: string
  explanatoryColumns: Readonly<Record<string, string>>
  sourceStatus: 'resolved' | 'missing' | 'invalid' | 'not-checked'
  attributionStatus: 'linked-report' | 'unverified' | 'contradicted'
  inspectionStatus: 'unverified'
  contentSha256?: string
  lineRange?: { start: number; end: number }
  fragment?: string
  limitations: readonly string[]
}
```

## Teach me while you build

Time to organize our cat-alog! Let's see how markdown tables turn into neat data rows! Purr~

- **What it does**: Extracts source locators, line ranges, and metadata columns from markdown tables in the References section.
- **Background**: Markdown tables use `|` delimiters. Parsing them naively with `line.split('|')` breaks on escaped pipes (`\|`) and nested link references.
- **How it works here**: `parseReferences` parses text with `mdast-util-from-markdown` and GFM extensions, extracting table rows and resolving link references from collected definition nodes.
- **Why this approach**: AST-based parsing ensures code citations containing escaped pipes (`\|`) or multiple link elements parse accurately without column splitting.
- **Approaches considered**: Naive string split (breaks on escaped pipes) vs manual regex (brittle) vs CommonMark GFM AST (chosen: fully standards-compliant).
- **Prior art inspected**: GitHub Flavored Markdown (GFM) table specification §4.10 and `mdast-util-gfm`.
- **What we get for free**: `mdast-util-from-markdown` tokenizes GFM tables and link definition nodes across the document tree automatically.
- **From the docs**: scripts/check-pieces.ts: 'Only an unescaped pipe delimits a cell... interior empty cells are preserved.'
- **What to notice**: Column profiles (e.g. 5-column canonical vs authored layouts) are validated against known schemas before mapping cells to record fields!
- **Concepts to own**: AST-based table extraction: parsing structured tabular Markdown into abstract syntax trees rather than brittle string splitting.
- **Interview angle**: How do you parse GFM markdown tables when cells contain inline code with pipes or markdown links? Answer: Use an AST parser with GFM table support so token boundaries follow markdown syntax rules rather than raw delimiter splits.
- **Decisions you can now make alone**: You can add supported column profiles and extract custom explanatory columns without risking regex breakage.
- **What you should learn from this**: Always respect escape characters and use ASTs when parsing structured content from human-authored Markdown! Purr~ (=^･ω･^=)
