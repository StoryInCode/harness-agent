## Summary

When the Research subagent returns with an evidentiary finding, we do not take its word at face value. We verify the cryptographic SHA-256 digest of cited local evidence against physical disk contents through `checkEvidence`. Did the agent actually inspect the file? Does the SHA-256 hash match the physical bytes on disk? If the recorded hash differs from disk by even one bit, or if external citations lack immutable versions, the evidence is disqualified and downgraded to unverified. The detective trusts only physical mathematics.

### Human Decision Point: Option A vs Option B
- **Option A (Active)**: Compute streaming SHA-256 digests over byte-faithful disk reads with `checkEvidence`, downgrading reported evidence to unverified on any drift or missing identity.
- **Option B (Alternative)**: Accept reported agent assertions without verifying local file digests or immutable citations, allowing hallucinated citations and silent drift to pass.

## Behaviour

- **Given** an attributed `ClaimFinding` citing a local repository file with matching SHA-256 digest **When** `checkEvidence` is called **Then** it returns an empty issue list, confirming required recorded identities.
- **Given** a finding citing a file whose bytes on disk have changed or whose digest does not match **When** `checkEvidence` runs **Then** it returns an issue reporting `Evidence identity changed: <locator>`.
- **Given** external evidence lacking an immutable version/digest or citing mutable paths like `/latest` **When** `checkEvidence` executes **Then** it flags that external evidence requires an immutable version and digest.

## Teach me while you build

The suspect presented a photograph. We check the digital negative's cryptographic hash. Reality cannot be forged.

- **What it does**: Inspects reported evidence in research findings and computes streaming SHA-256 digests across disk files to detect drift or fabrication.
- **Background**: Autonomous agents can hallucinate convincing file paths and citations. Requiring exact SHA-256 content digests binds findings to immutable physical state.
- **How it works here**: Iterates over finding evidence. For local files, streams chunks via `fs.streamText`, verifies decoded byte length equals `fs.stat` size, and hashes with `node:crypto`.
- **Why this approach**: Prevents silent drift or hallucinated assertions from compromising development decisions.
- **Approaches considered**: Timestamp comparison (insufficient: modtime changes without content edits) vs Word matching (fragile) vs SHA-256 byte-faithful digest (chosen: cryptographic certainty).
- **Prior art inspected**: Git blob object hashing and content-addressable storage (CAS) mechanisms.
- **What we get for free**: Node's native `createHash('sha256')` and `FileSystem` streaming abstractions.
- **From the docs**: `packages/dev-loop/claims/README.md`: "Piece and local-evidence digests require byte-faithful UTF-8: the filesystem must report a known size equal to the complete decoded text's re-encoded byte length."
- **What to notice**: Notice that evidence qualifications downgrade reported `supported` findings to `unverified` without discarding the agent's observation!
- **Concepts to own**: Epistemic corroboration: requiring independent physical verification of model-reported artifacts.
- **Interview angle**: How do you prevent hallucinated file citations in an agentic coding harness? Answer: Enforce cryptographic CAS verification — require subagents to supply SHA-256 digests and independently hash physical disk bytes at admission.
- **Decisions you can now make alone**: You can enforce lockfile and export entry-point checks for dependency evidence.
- **What you should learn from this**: Do not trust reported findings without checking physical digests on disk. Mathematics does not lie.
