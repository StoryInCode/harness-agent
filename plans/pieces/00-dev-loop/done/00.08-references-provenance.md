# 00.08 — References Provenance Store and Verification

**Set:** 00-dev-loop · **Queue:** 8 · **Depends on:** 00.01, 00.06
**Status:** done
**Harness primitive:** Service Provider · **Package:** `@deepseek-ai/dsh-dev-loop-references`

## Summary

This piece checks the source links in a piece's References section. It also preserves provenance. Provenance means the record of who reported a finding and from where.

A file that resolves proves the file exists. It does not prove that anyone read it or that its content is true. A linked delegation proves who produced a report. It does not prove that the author used every cited source. Missing evidence stays unverified. Evidence that contradicts a claimed identity is reported as contradicted.

## Behaviour

- **Given** local references **When** verification runs **Then** the service resolves them in the configured repository, checks containment, regular-file existence and optional line ranges, and keeps content fingerprints.
- **Given** a missing source, an invalid range or an escaping symlink **When** checked **Then** the service returns a specific source error. It never silently admits the source.
- **Given** an explicit delegation id **When** its settled record matches this piece and names an actual child identity **Then** the service keeps the actual role, optional preset, terminal status and limitations as linked-report provenance.
- **Given** requested-only or unavailable delegation evidence **When** checked **Then** the service reports unverified attribution, never verified inspection. A visible record that contradicts an asserted role or preset reports contradicted attribution.
- **Given** a direct-inspection assertion without independent observation evidence **When** checked **Then** the service keeps it as an unverified assertion. It is not proven inspection and not automatically fabrication.
- **Given** an explicit empty References declaration **When** parsed **Then** the service saves an empty observation. An absent section or malformed table rejects validation.
- **Given** a restart **When** queried **Then** the service returns the durable observation with its checked piece fingerprint. Later edits to the piece require fresh verification.

## Harness fit

A Host Service publishes `ctx.devLoopReferences`. It injects `devLoopDirectory`, `devLoopRoles`, `fs`, and `storageDomain`. Directory supplies a piece path and parsed metadata. It does not supply a Markdown AST. An AST is the parsed tree of a document. This owner reads the file through `fs.resolve` and bounded `streamText`. It parses the References section with maintained Markdown/GFM dependencies. Runtime code must not import the repository-only `scripts/markdown.ts`.

The service opens its own `dev_loop_references` single-layout domain. It validates records with Zod. It owns serialized verification/write operations and waits for them before closing. Later persistence consumes this owner. It does not reopen or duplicate the domain. References do not inject unlogged model context. Claims and Gates consume its detached observations. Any model-visible consumer logs its rendered result through the existing tool runtime.

## Contracts

The Test Writer's [baseline](../../../../packages/dev-loop/references/tests/RED.md) freezes the exported DTOs before implementation. A DTO is a data transfer object, the fixed record shape passed across boundaries. The baseline's initial fingerprint stays historical. Comment-only amendments are recorded separately beside it. The implemented operations are `verifyReferences(pieceId, signal)` (read, verify, durably store, return) and `getProvenance(pieceId)` (detached latest observation or undefined). Do not expose a method that accepts arbitrary caller-supplied `valid: true` records as verified evidence.

Each observation records the piece id, the piece content SHA-256, the checked time, the explicit-empty state, entries, validation errors and limitations. Each entry keeps the original source locator and attribution text, a source status (`resolved`, `missing`, `invalid`, `not-checked`), an attribution status (`linked-report`, `unverified`, `contradicted`), and an optional observed local content fingerprint or linked delegation metadata. Structural validity and epistemic confidence stay separate fields. Epistemic confidence means how sure we are that a claim is knowledge. No field promises verified inspection or claim truth.

### Parsing and source policy

Support the five named columns in the piece-format template: Source, Role/preset that inspected it, Question it answered, Direct inspection or reported, How it was used. Also support the authored profiles `Source | Role/preset and provenance | Decision informed`, `Source | Question answered | Provenance`, `Source | Provenance | Decision informed`, and `Source | Role/preset | Provenance | Decision informed`. Normalize inline Markdown and whitespace in headings, but reject unsupported or reordered profiles. Keep absent fields as absent. Do not guess them. Missing Source or attribution columns, duplicate required columns and malformed rows fail explicitly. A table with no recognized rows is not accepted as empty. An explicit plain `None.` or `No references.` declaration is the empty grammar. Markdown links and inline-code locators are parsed from the AST, not split on raw pipes inside code.

Local inline-code paths resolve from explicit `Config.repositoryRoot`. Relative Markdown links resolve from the piece's directory. Canonical `fs.contains` confines resolved targets to the configured root, including intermediate symlinks. A symlink is a file that points at another file. Absolute local paths and directory references reject. Optional `:N` or `:N-M` line suffixes require positive ordered integers within the decoded line count. A symbol/fragment is kept as a locator but is not claimed as semantically verified. HTTP(S) locators are kept as `not-checked`. This service neither fetches URLs nor claims their contents were inspected. Unsupported locator syntax produces an explicit error, never a guessed path.

Directory may reject a missing References section before returning a PieceRecord. Keep its real parse rejection instead of inventing an observation. Directory lookup currently reads whole files, so this owner's limits do not bound that dependency's buffering. This owner's streaming reads bound the UTF-8 encoding of filesystem-decoded text. SHA-256 covers that complete decoded text without newline normalization. It does not unconditionally cover the original raw bytes. Source fingerprints cover the whole file, not just selected lines. Reject an oversized piece before publishing any observation or digest. Source overflow is an invalid entry without a content fingerprint. Complete observation overflow rejects persistence. Never silently clip evidence or publish a partial-read fingerprint as complete. Config requires repositoryRoot, maxPieceBytes, maxSourceBytes, maxObservationBytes, and maxReferences as positive safe integers where numeric. There are no invented deployment defaults. Validate minimum representable error envelopes. Cancellation prevents new checks. Already-admitted domain writes settle under the domain lifetime.

### Attribution policy

Attribution means naming who made a claim. Optional machine-readable attribution uses `delegation:<id>` in the attribution cell. The parser validates exact ids before branding. A linked record must belong to this piece, be settled, and name an actual child session. Keep its actual role/preset. Never fill a missing preset from a requested label. Explicit `role:<canonical role>` and `preset:<id>` tokens assert identity. An entire role cell equal to a canonical role also asserts that role. Mismatches against visible linked records are contradicted. Other prose is kept without heuristic identity extraction. A preset assertion when the record has no preset stays unverified, not a proven mismatch. Human prose without an exact id stays unverified, including historical Research reports in this set.

A failed or aborted delegation can carry a partial report. Keep its status and limitations. Do not upgrade it to success. A requested-only record cannot establish an executed report. Roles exposes piece-scoped history only. An id absent from that history is unavailable and unverified, whether unknown or owned by another piece. Do not enumerate other pieces or add a cross-piece lookup just to tell those cases apart. No linked report proves source usage. No direct assertion becomes an independent observation just because the verifier can read the file now. A source missing now does not prove it never existed. Claims owns the decision whether these limits permit further work.

## Teach me while you build

- **What it does:** Checks where references point. It keeps a record of who claims to have inspected them. It never turns claims into facts.
- **Background:** Provenance records origin. Attribution names an author. Source usage means an activity actually consumed a source. These are different relationships.
- **How it works here:** Directory identifies the piece. The filesystem supplies its current text. Markdown parsing extracts references. Roles supplies exact delegation records. A storage domain keeps the detached observations. Missing or conflicting evidence is visible data, not inferred success.
- **Why this approach:** The available runtime records delegation but does not record trusted source usage. Claiming inspection verification would exceed the evidence. Instrumented source-access logging would win if independent observation becomes a required product guarantee.
- **Approaches considered:** Plain text trust is simple for informal notes but insufficient for automation. Exact report linkage plus structural checks fits the existing services. W3C PROV-DM offers richer relationships for cross-system provenance. Its distinctions inform this model without importing a general graph framework. Trusted source-access instrumentation could provide stronger evidence but needs a separate owned event path and tests.
- **Prior art inspected:** Research opened the dated W3C recommendation's overview and provenance-of-provenance example, not an implementation and not the full normative section. No external code was reused.
- **What we get for free:** Markdown dependencies parse tables and links. Filesystem providers resolve paths and enforce canonical containment checks. Storage domains validate and serialize durable writes. Our application logic owns attribution and uncertainty. It is not a universal truth detector.
- **From the docs:** Research reported that W3C PROV-DM separates usage, attribution and delegation. The opened overview sections informed this distinction. No uninspected normative guarantee is claimed.
- **What to notice:** In [sources.ts](../../../../packages/dev-loop/references/src/sources.ts), `fingerprint` hashes complete decoded text and `boundedText` refuses partial evidence. In [index.ts](../../../../packages/dev-loop/references/src/index.ts), publication follows the durable write, while `inspectionStatus` stays unverified. A valid file plus a real child id still does not show source usage. A stale piece fingerprint requires rechecking.
- **What the tests prove:** The Test Writer records 84 behavioral failures against the mounted inert service, not missing-import failures. The integration Utility reports those cases plus 21 supplemental cases and the separately frozen nested-definition regression passing. The regression catches valid global link definitions inside blockquotes. Recursive maintained-AST traversal, rather than a root-only scan, preserves that Markdown behavior.
- **Concepts to own:** Epistemic uncertainty separates what is known from what is asserted. Referential integrity links exact records. Content addressing identifies the exact checked text. Canonical containment handles symlink escapes.
- **Interview angle:** “How do you prevent fabricated research evidence?” Validate exact report identity and source locators. Keep unresolved claims visible. Do not equate authorship with source usage. Follow-up: trusted usage evidence requires instrumentation beyond report prose.
- **Decisions you can now make alone:** Add supported locator syntax with rejection tests. Escalate stronger inspection guarantees, external fetching and alternate repository routing to their owners.
- **What you should learn from this:** Verification must state exactly which relationship it checked.
