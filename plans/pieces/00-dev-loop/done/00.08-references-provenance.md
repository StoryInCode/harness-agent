# 00.08 — References Provenance Store and Verification

**Set:** 00-dev-loop · **Queue:** 8 · **Depends on:** 00.01, 00.06
**Status:** done
**Harness primitive:** Service Provider · **Package:** `@deepseek-ai/dsh-dev-loop-references`

## Summary

Check source locators in a piece's References section and preserve the attribution of inspection claims. A resolvable file proves existence, not inspection or truth. A linked delegation proves who produced a report, not that its author used every cited source. Missing evidence remains unverified; contradictory identity evidence is reported separately.

## Behaviour

- **Given** local references **When** verification runs **Then** resolve them in the configured repository, check containment, regular-file existence and optional line ranges, and retain content fingerprints.
- **Given** a missing source, invalid range or escaping symlink **When** checked **Then** return a specific source error, never silently admit it.
- **Given** an explicit delegation id **When** its settled record matches this piece and has an actual child identity **Then** retain the actual role, optional preset, terminal status and limitations as linked-report provenance.
- **Given** requested-only or unavailable delegation evidence **When** checked **Then** report unverified attribution, never verified inspection; a visible record contradicting an asserted role or preset reports contradicted attribution.
- **Given** a direct-inspection assertion without independent observation evidence **When** checked **Then** retain it as an unverified assertion, not proven inspection and not automatically fabrication.
- **Given** an explicit empty References declaration **When** parsed **Then** save an empty observation; an absent section or malformed table rejects validation.
- **Given** a restart **When** queried **Then** return the durable observation with its checked piece fingerprint; subsequent edits require fresh verification.

## Harness fit

A Host Service publishes `ctx.devLoopReferences` and injects `devLoopDirectory`, `devLoopRoles`, `fs`, and `storageDomain`. Directory supplies a piece path and parsed metadata, not a Markdown AST. This owner reads the file through `fs.resolve` and bounded `streamText` and parses its References section using maintained Markdown/GFM dependencies. Runtime code must not import repository-only `scripts/markdown.ts`.

The service opens its own `dev_loop_references` single-layout domain, validates records with Zod, owns serialized verification/write operations and awaits them before closing. Later persistence consumes this owner instead of reopening or duplicating its domain. References do not inject unlogged model context; Claims and Gates consume its detached observations. Any model-visible consumer logs its rendered result through the existing tool runtime.

## Contracts

The Test Writer's [baseline](../../../../packages/dev-loop/references/tests/RED.md) freezes the exported DTOs before implementation; its initial fingerprint remains historical, with comment-only amendments recorded separately beside it. The implemented operations are `verifyReferences(pieceId, signal)` (read, verify, durably store, return) and `getProvenance(pieceId)` (detached latest observation or undefined). Do not expose a method that accepts arbitrary caller-supplied `valid: true` records as verified evidence.

Each observation records piece id, piece content SHA-256, checked time, explicit-empty state, entries, validation errors and limitations. Each entry preserves the original source locator and attribution text, source status (`resolved`, `missing`, `invalid`, `not-checked`), attribution status (`linked-report`, `unverified`, `contradicted`), and optional observed local content fingerprint or linked delegation metadata. Structural validity and epistemic confidence are distinct fields. No field promises verified inspection or claim truth.

### Parsing and source policy

Support the five named columns in the piece-format template: Source, Role/preset that inspected it, Question it answered, Direct inspection or reported, How it was used. Also support the authored profiles `Source | Role/preset and provenance | Decision informed`, `Source | Question answered | Provenance`, `Source | Provenance | Decision informed`, and `Source | Role/preset | Provenance | Decision informed`. Normalize inline Markdown and whitespace in headings, but reject unsupported or reordered profiles; preserve rather than guess absent fields. Missing Source or attribution columns, duplicate required columns and malformed rows fail explicitly. No table is accepted as empty merely because no row was recognized. An explicit plain `None.` or `No references.` declaration is the empty grammar. Markdown links and inline-code locators are parsed from the AST, not split on raw pipes inside code.

Local inline-code paths resolve from explicit `Config.repositoryRoot`; relative Markdown links resolve from the piece's directory. Canonical `fs.contains` confines resolved targets to the configured root, including intermediate symlinks. Absolute local paths and directory references reject. Optional `:N` or `:N-M` line suffixes require positive ordered integers within decoded line count. A symbol/fragment is retained as a locator but is not claimed semantically verified. HTTP(S) locators are retained as `not-checked`; this service neither fetches URLs nor claims their contents were inspected. Unsupported locator syntax produces an explicit error rather than a guessed path.

Directory may reject a missing References section before returning a PieceRecord; preserve its real parse rejection instead of fabricating an observation. Directory lookup currently reads whole files, so this owner's limits do not bound that dependency's buffering. This owner's streaming reads bound the UTF-8 encoding of filesystem-decoded text. SHA-256 covers that complete decoded text without newline normalization, not unconditionally the original raw bytes; source fingerprints cover the whole file, not just selected lines. Reject an oversized piece before publishing any observation or digest. Source overflow is an invalid entry without a content fingerprint; complete observation overflow rejects persistence. Never silently clip evidence or publish a partial-read fingerprint as complete. Config requires repositoryRoot, maxPieceBytes, maxSourceBytes, maxObservationBytes, and maxReferences as positive safe integers where numeric; no invented deployment defaults. Validate minimum representable error envelopes. Cancellation prevents new checks; already-admitted domain writes settle under the domain lifetime.

### Attribution policy

Optional machine-readable attribution uses `delegation:<id>` in the attribution cell. Exact ids are validated at the parser before branding. A linked record must belong to this piece, be settled, and name an actual child session. Preserve its actual role/preset; never fill a missing preset from a requested label. Explicit `role:<canonical role>` and `preset:<id>` tokens assert identity; an entire role cell equal to a canonical role also asserts that role. Mismatches against visible linked records are contradicted. Other prose is preserved without heuristic identity extraction; a preset assertion when the record has no preset remains unverified, not a proven mismatch. Human prose without an exact id stays unverified, including historical Research reports in this set.

A failed or aborted delegation can carry a partial report; retain its status and limitations without upgrading it to success. A requested-only record cannot establish an executed report. Roles exposes piece-scoped history only: an id absent from that history is unavailable and unverified, whether unknown or owned by another piece. Do not enumerate other pieces or add a cross-piece lookup solely to distinguish those cases. No linked report proves source usage, and no direct assertion becomes an independent observation merely because the verifier can read the file now. A source missing now does not prove it never existed. Claims owns the decision whether these limits permit further work.

## Teach me while you build

- **What it does:** Checks where references point and preserves who claims to have inspected them without turning claims into facts.
- **Background:** Provenance records origin. Attribution names an author; source usage means an activity actually consumed a source. These are different relationships.
- **How it works here:** Directory identifies the piece, the filesystem supplies its current text, Markdown parsing extracts references, Roles supplies exact delegation records, and a storage domain retains the detached observations. Missing or conflicting evidence is visible data, not inferred success.
- **Why this approach:** The available runtime records delegation but does not record trusted source usage. Claiming inspection verification would exceed the evidence. Instrumented source-access logging would win if independent observation becomes a required product guarantee.
- **Approaches considered:** Plain text trust is simple for informal notes but insufficient for automation. Exact report linkage plus structural checks fits the existing services. W3C PROV-DM offers richer relationships for cross-system provenance; its distinctions inform this model without importing a general graph framework. Trusted source-access instrumentation could provide stronger evidence but needs a separate owned event path and tests.
- **Prior art inspected:** Research opened the dated W3C recommendation's overview and provenance-of-provenance example, not an implementation or the full normative section. No external code reused.
- **What we get for free:** Markdown dependencies parse tables and links; filesystem providers resolve and enforce canonical containment checks; storage domains validate and serialize durable writes. Application logic owns attribution and uncertainty, not a universal truth detector.
- **From the docs:** Research reported that W3C PROV-DM separates usage, attribution and delegation; these opened overview sections informed the distinction. No uninspected normative guarantee is claimed.
- **What to notice:** In [sources.ts](../../../../packages/dev-loop/references/src/sources.ts), `fingerprint` hashes complete decoded text and `boundedText` refuses partial evidence. In [index.ts](../../../../packages/dev-loop/references/src/index.ts), publication follows the durable write, while `inspectionStatus` remains unverified. A valid file plus a real child id still does not show source usage; stale piece fingerprints require rechecking.
- **What the tests prove:** The Test Writer records 84 behavioral failures against the mounted inert service, not missing-import failures. Integration Utility reports those cases plus 21 supplemental cases and the separately frozen nested-definition regression passing. The latter catches valid global link definitions inside blockquotes; recursive maintained-AST traversal, rather than a root-only scan, preserves that Markdown behavior.
- **Concepts to own:** Epistemic uncertainty separates what is known from asserted; referential integrity links exact records; content addressing identifies the exact checked text; canonical containment handles symlink escapes.
- **Interview angle:** “How do you prevent fabricated research evidence?” Validate exact report identity and source locators, retain unresolved claims, and do not equate authorship with source usage. Follow-up: trusted usage evidence requires instrumentation beyond report prose.
- **Decisions you can now make alone:** Add supported locator syntax with rejection tests. Escalate stronger inspection guarantees, external fetching and alternate repository routing to their owners.
- **What you should learn from this:** Verification must state precisely which relationship it checked.
