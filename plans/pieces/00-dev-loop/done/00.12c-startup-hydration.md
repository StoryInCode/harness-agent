## Summary

Mwahahaha! Rise from the ashes of system restart! When the Host Plane boots, the Startup Hydrator inspects the temporal timeline! It scans the filesystem via readLocalPieces, reads the durable transitions and anomalies tables, and reconciles any discrepancies left by unexpected shutdowns! Incomplete intents are resolved into anomalies, committed transitions are hydrated despite unchanged disk headers, and the lab's state is restored to pristine harmony! El Psy Kongroo!

### Human Decision Point: Option A vs Option B
- **Option A (Active)**: Reconcile durable storage state against filesystem at boot, hydrating committed transitions and quarantining discrepancies.
- **Option B (Alternative)**: Assume memory state is empty and ignore disk discrepancies, leading to orphaned worktrees and stale status.

## Behaviour

- **Given** a system booting with committed transitions in durable storage **When** loadLifecycle(signal) is executed **Then** it hydrates pieces with their committed status, sequence, and source observations even if the markdown header remains todo.
- **Given** a system booting after an unexpected shutdown that left an unresolved intent **When** loadLifecycle runs **Then** it records an unresolved-intent anomaly in the anomalies table and marks the piece quarantined.
- **Given** a piece whose local source changed after acceptance or whose done path contradicts durable history **When** loadLifecycle runs **Then** it flags the piece as quarantined with a corresponding anomaly record.

## Teach me while you build

Temporal paradoxes cannot withstand our diagnostic probes! Let me teach you how startup reconciliation repairs the timeline!

- **What it does**: Reconciles durable storage domain records against local filesystem reality upon startup.
- **Background**: After an unexpected process termination, in-flight operations may leave durable transition records and disk files in diverging states.
- **How it works here**: Calls `readLocalPieces` to scan repository directories and inspect file bytes. Merges local files with `transitions` table history. Hydrates committed state, detects unjournaled files, flags unresolved intents, and populates `anomalies`.
- **Why this approach**: Guarantees deterministic state recovery without manual operator database surgery.
- **Approaches considered**: Manual operator intervention on crash (terrible recovery time) vs Automatic silent state rollback (loses audit trail) vs Deterministic startup hydration with discrepancy quarantine (chosen: fail-closed and self-healing).
- **Prior art inspected**: Journaling filesystem replay (ext4 fsck) and event sourcing projection reconstruction.
- **What we get for free**: `@deepseek-ai/dsh-dev-loop-directory` provides AST validation while `ctx.fs` guarantees UTF-8 byte faithfulness.
- **From the docs**: AGENTS.md: 'Restart does not reconstruct live Queue callbacks or children. Unjournaled historical done files remain explicit anomalies.'
- **What to notice**: Notice how committed status is hydrated even when the disk file's markdown header has not yet been edited to done!
- **Concepts to own**: State hydration: reconstructing consistent in-memory lifecycle status from durable records and observed filesystem state.
- **Interview angle**: How do you design crash recovery for stateful services managing local filesystem resources? Answer: Write-ahead intent logs replayed and reconciled against observed filesystem state during startup hydration.
- **Decisions you can now make alone**: You know how to add diagnostic logging during hydration without changing the state reconstruction order.
- **What you should learn from this**: Self-healing systems reconcile reality against memory. Clean up after yesterday's crashes before starting today's world line!
