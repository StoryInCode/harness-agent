Nya~ (=^･ω･^=)🐾 Inspector Cat loves looking into the treat basket! How many treats are waiting? Which kitties are currently snacking? We provide clean inspection APIs (`getQueuedEntries`, `getActiveWorkers`) on `DevLoopQueue` so the human operator and status commands can see every pending piece, its wait duration, and active workers. Transparency is cozy!

### Human Decision Point: Option A vs Option B
- **Option A (Active)**: Return detached scalar snapshot records (`{ ...entry.view }`) containing only primitive strings and numbers, with no internal map or Agent references.
- **Option B (Alternative)**: Expose internal entry objects or live collection references that allow external consumers to mutate internal queue state.

## Behaviour

- **Given** a queue with 1 active worker and 1 waiting piece **When** `getActiveWorkers()` and `getQueuedEntries()` are called **Then** they return detached scalar records with `pieceId`, `queueOrder`, `enqueuedAt`, and `status`.
- **Given** an external consumer mutates the fields of a returned `QueueEntry` object **When** queue inspection methods are called again **Then** the internal queue state remains unchanged and uncorrupted.
- **Given** a query on an empty queue **When** `getActiveWorkers()` or `getQueuedEntries()` is called **Then** each returns an empty array immediately without throwing errors.

## Contracts

```typescript
export interface QueueEntry {
  /** Canonical piece id. */
  pieceId: string
  /** Canonical queue priority; lower values run first. */
  queueOrder: number
  /** Epoch milliseconds at request admission. */
  enqueuedAt: number
  /** Starting includes reserved startup; running retains its reservation during cleanup. */
  status: 'queued' | 'starting' | 'running'
  /** Child session id after startup returns; not a continuable run epoch. */
  subagentId?: SessionId
}

export class DevLoopQueue extends Service {
  getActiveWorkers(): QueueEntry[]
  getQueuedEntries(): QueueEntry[]
}
```

## Teach me while you build

Let's count our shiny toys without dropping any! Purr~ (=^･ω･^=)

- **What it does**: Provides non-destructive snapshots of queue contents for active workers and queued candidates without exposing internal references.
- **Background**: Inspection APIs must return detached copies (defensive copying) so callers cannot accidentally mutate internal queue state.
- **How it works here**: `getActiveWorkers()` filters entries where `status !== 'queued'` and shallow-clones the view object `{ ...entry.view }`. `getQueuedEntries()` does the same for queued entries sorted by priority.
- **Why this approach**: Enables CLI commands and web dashboards to inspect queue telemetry safely without risking concurrency hazards or reference leakage.
- **Approaches considered**: Returning internal maps (dangerous: caller can delete/modify entries) vs Frozen read-only views vs Detached scalar copies (chosen: pure detached objects).
- **Prior art inspected**: Java `ConcurrentLinkedQueue.toArray()` and Linux `ethtool` queue telemetry.
- **What we get for free**: Object spread syntax `{ ...entry.view }` creates clean shallow copies with scalar values.
- **From the docs**: AGENTS.md: 'Trust TypeScript at typed same-process boundaries... Runtime invariants assert owned relationships.'
- **What to notice**: Notice that mutating `pieceId` or `queueOrder` on the returned snapshot has zero effect on subsequent queue queries!
- **Concepts to own**: Defensive copying: protecting internal state by handing callers isolated copies rather than original references.
- **Interview angle**: Why should getter methods on stateful services return defensive copies? Answer: Prevents outside callers from bypassing invariants via reference mutation.
- **Decisions you can now make alone**: You can safely add diagnostic fields to `QueueEntry` as long as they remain pure scalars.
- **What you should learn from this**: Make internal state open for inspection, but closed for outside mutation! Purr~
