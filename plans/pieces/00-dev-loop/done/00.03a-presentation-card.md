## Summary

Tutturu~ 🌸 Mayuri made a lovely presentation card for you! Before we ask our human developer to approve a piece, we don't want to dump a huge scary file on them without guidance. Instead, we present the complete specification text enriched with gentle teaching review warnings, alongside clear decision choices (`Accept`, `Question`, `Change`) and optional feedback! It's as easy as looking at a cafe menu!

### Human Decision Point: Option A vs Option B
- **Option A (Active)**: Present complete specification source accompanied by missing-teaching inspection warnings and structured decision options (`Accept`, `Question`, `Change`).
- **Option B (Alternative)**: Output an unreviewed summary card or raw unvalidated dump directly into chat, overwhelming the human operator or missing critical teaching context.

## Behaviour

- **Given** a valid `todo` piece specification **When** `present_piece_for_approval` is invoked by a live root agent **Then** it presents the complete markdown source as detail in a single-select `decision` question with options `Accept`, `Question`, and `Change`, alongside an optional `feedback` question.
- **Given** a piece missing required teaching subsections (such as `Approaches considered` or `Prior art inspected`) **When** the piece is presented for review **Then** review warnings are appended to the presentation detail without altering the underlying source file.
- **Given** a reviewer selects an approval decision and enters comments **When** the human response settles **Then** it returns a `PresentPieceResult` containing the piece ID, lowercase decision, and trimmed optional feedback.

## Harness fit

Consumer plugin in `packages/dev-loop/approval/src/index.ts` registered via `apply(ctx: Context)`. Mounts the model-facing `present_piece_for_approval` tool into `ctx.tools`, consuming `ctx.userQuestions`, `ctx.devLoopDirectory`, `ctx.devLoopLifecycle`, and `ctx.fs`.

## Teach me while you build

When presenting your work, always package it with kindness and care! Tutturu~

- **What it does**: Presents the complete specification source with teaching audit warnings to the human reviewer for explicit decision-making.
- **Background**: Cognitive overload and missing context cause rubber-stamp approvals. Clear presentations with automated checks ensure genuine oversight.
- **How it works here**: `presentPiece` reads and validates the piece source via `ctx.fs` and `ctx.devLoopDirectory`, calls `reviewDetail` to scan for missing teaching subsections (`Approaches considered`, `Prior art inspected`), and passes the enriched detail to `ctx.userQuestions.ask`.
- **Why this approach**: Formatting cards in pure Markdown with appended warnings ensures full transparency across CLI terminals, web UIs, and chat interfaces.
- **Approaches considered**: Raw JSON dump (unreadable for humans) vs Cached summary only (hides real source changes) vs Complete markdown with teaching warnings (chosen: transparent and structured).
- **Prior art inspected**: GitHub Pull Request summary templates and Slack interactive message cards.
- **What we get for free**: `ctx.userQuestions` handles terminal and web UI interaction, validation of selections, and asynchronous pausing.
- **From the docs**: `packages/dev-loop/approval/README.md`: 'The tool displays the complete current markdown, warns about missing teaching subsections, and queues only an unchanged todo piece explicitly accepted by the human.'
- **What to notice**: Notice how `reviewDetail` checks headings and bold list labels inside `## Teach me while you build`, while strictly ignoring code fences!
- **Concepts to own**: Non-destructive review enrichment: adding advisory diagnostic annotations without modifying the audited artifact.
- **Interview angle**: How do you design human-in-the-loop interfaces to prevent decision fatigue? Answer: Surface complete authoritative source enriched with automated checklist audits and crisp single-select choices.
- **Decisions you can now make alone**: You can add extra advisory checks to `reviewDetail` without breaking the core decision schema.
- **Lesson**: Kindness in UI design means respecting your reviewer's time and attention with honest, structured guidance! 🌸
