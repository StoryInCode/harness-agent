## Summary

When a claim is marked unverified or when a citation requires forensic corroboration, we do not send an agent on an open-ended browsing spree. An unfocused agent burns tokens and hallucinates. We compile a structured Research assignment with full source, explicit inventory rows, and strict JSON output requirements. Research must return exactly one whole JSON object containing inventory coverage, findings, and candidate premises. Fences, prose, or rewritten claims are rejected fail-closed. Precision is our weapon.

### Human Decision Point: Option A vs Option B
- **Option A (Active)**: Validate whole-outcome Research JSON against strict schemas with 1:1 inventory correspondence, rejecting fences, surrounding prose, and rewritten claims fail-closed.
- **Option B (Alternative)**: Dispatch vague prompts and extract JSON from conversational prose with lenient patterns, permitting hallucinated structures and omitted premises.

## Behaviour

- **Given** terminal Research output wrapped in markdown code fences or conversational prose **When** `parseResearchJson` is called **Then** it throws a syntax error, rejecting formatted or partial outputs.
- **Given** valid Research JSON matching inventory rows and limits **When** `parseResearchJson` runs **Then** it returns a typed `ResearchReport` with `inventoryCoverage`, `findings`, and `additionalClaims`.
- **Given** Research output that omits an inventory claim or rewrites a claim string **When** `parseResearchJson` executes **Then** it throws an error requiring exact inventory identification without rewriting.

## Teach me while you build

An investigator given vague instructions returns with gossip. An investigator given an exact address returns with evidence.

- **What it does**: Validates that Research subagent output adheres to strict JSON schemas, covers all inventory claims without modification, and stays within configured limits.
- **Background**: Language models frequently decorate JSON with markdown fences, preamble, or subtly rephrase claims. Epistemic rigor demands fail-closed rejection of modified premises.
- **How it works here**: Parses output via `JSON.parse` and validates through `researchSchema`. Maps each finding back to `inventory` by `claimId`, confirming identical claim strings.
- **Why this approach**: Prevents silent drift or hallucinated assertions from entering the durable ledger.
- **Approaches considered**: Conversational markdown extraction (unreliable, vulnerable to injection) vs Strict root JSON parsing (chosen: deterministic and fail-closed).
- **Prior art inspected**: Zod schema validation and JSON schema strict mode parsing.
- **What we get for free**: Native `zod` object parsing and runtime schema validation.
- **From the docs**: `packages/dev-loop/claims/README.md`: "Research must return one strict JSON object with exactly one unchanged finding per inventory row and an assessment of omitted premises."
- **What to notice**: Notice that fences, leading prose, or trailing commentary cause schema parsing to throw immediately!
- **Concepts to own**: Whole-outcome validation: validating the entire unformatted payload as a single atomic data structure.
- **Interview angle**: How do you enforce structured outputs from autonomous agents without relying on permissive regex parsing? Answer: Require strict JSON at the protocol boundary and reject any payload containing markdown formatting or fences fail-closed.
- **Decisions you can now make alone**: You can configure `maxClaims` and `maxEvidenceBytes` to bound payload sizes.
- **What you should learn from this**: Never let an agent reword the premises it was asked to prove. Exact identity is required.
