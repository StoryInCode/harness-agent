# 00.01 — Piece Directory and Specification Parser

**Set:** 00-dev-loop · **Queue:** 1 · **Depends on:** none
**Status:** done
**Harness primitive:** Service Provider · **Package:** `@deepseek-ai/dsh-dev-loop-directory`

## Summary

Discovers, parses, and validates piece specification markdown files (`plans/pieces/**/*.md`) across the repository. It scans set directories, extracts the metadata header, enforces the configured line ceiling, validates the known sections in their canonical order, and ensures the declared Harness primitive and status belong to their closed vocabularies. This provides an authoritative record and schema validator that prevents oversized or malformed specifications from entering the development loop.

The parser is the executable form of the `axiom` blocks in `plans/AGENTS.md`; their shell checkers delegate through `scripts/check-pieces.ts` to the same parser. It carries their severity: `R-piece-size`, `R-piece-required-sections`, `R-harness-primitive-declared`, `R-piece-visible-result`, and `R-piece-teaches` are blockers that reject the file, while `R-piece-reuse-capture` is a warning recorded on the returned record. The line ceiling, the discovery root, and the primitive vocabulary are validated `Config` fields, so a deployment changes them from `cordis.yml` rather than by editing code.

## Behaviour

- **Given** a valid piece markdown file within the configured ceiling carrying every blocker-required section **When** the directory parses it **Then** it returns a validated `PieceRecord` with status `todo`, extracted metadata, and no warnings.
- **Given** a piece file exceeding the configured `maxLines` **When** validation runs **Then** parsing fails with `PIECE_SIZE_EXCEEDED` reporting the line count and the ceiling.
- **Given** a piece missing a blocker-required section such as `## Behaviour` **When** validation runs **Then** parsing fails with `MISSING_REQUIRED_SECTION` naming the missing section.
- **Given** two sections transposed, so one that belongs later appears earlier than a section that must precede it **When** validation runs **Then** parsing fails with `MISSING_REQUIRED_SECTION` naming the canonically-later section that appeared too early.
- **Given** a piece carrying a `##`-prefixed line inside a fenced code block, opened by either three backticks or three tildes **When** validation runs **Then** that line is content, not a section heading: it neither satisfies a required section nor violates the section order. A fence left unclosed runs to the end of the file, and a closing fence may be longer than its opener, as CommonMark specifies.
- **Given** a piece carrying a `##` heading outside the canonical list **When** validation runs **Then** the unknown heading is ignored rather than reported, because a piece may carry extra sections.
- **Given** a piece carrying every blocker-required section but no `## Reuse capture` **When** validation runs **Then** parsing succeeds and the record carries one `MISSING_RECOMMENDED_SECTION` warning.
- **Given** a piece declaring an unapproved primitive such as `Plugin` **When** validation runs **Then** parsing fails with `INVALID_HARNESS_PRIMITIVE` listing the accepted vocabulary.
- **Given** a piece with an invalid status other than `todo`, `pending`, `done`, or `blocked` **When** validation runs **Then** parsing fails with `INVALID_PIECE_STATUS`.
- **Given** a set directory containing multiple pieces **When** `scanSet('00-dev-loop')` is called **Then** `pieces` is returned ordered by queue position, then by id, and `rejected` is empty.
- **Given** a set in which one piece is malformed **When** the set is scanned **Then** the valid pieces are still returned and the malformed file appears in `rejected` with its code and findings. One bad file never denies a caller the rest of the set: a malformed sibling is data about the corpus, not an exception belonging to an unrelated caller.
- **Given** a malformed piece elsewhere in the corpus **When** `getPiece` or `getQueueCandidates` runs **Then** the failure never names a file the caller did not ask for. `getPiece` raises a parse error only when the requested id's own file is the rejected one, and `getQueueCandidates` selects from the valid pieces of every set it scans.
- **Given** a set whose completed pieces were moved to `<set>/done/` per `R-done-pieces-moved` **When** `scanSet` runs **Then** the set directory and its `done/` subdirectory are merged into one queue-ordered list.
- **Given** a completed piece located in `<set>/done/` **When** dependencies are resolved or queue candidates are queried **Then** it resolves successfully as a dependency but is excluded from `getQueueCandidates`, so completed work is never offered for dispatch.
- **Given** a piece whose status is `blocked` **When** `getQueueCandidates` runs **Then** it is excluded too: a blocked piece waits on a human decision, not on a dispatch slot, so candidates are the `todo` and `pending` pieces only.
- **Given** no set name **When** `getQueueCandidates()` runs across every set **Then** results are ordered by set, then queue, then id, because queue numbers are set-local and interleaving independent sets would offer a later set's first piece before an earlier set finished.
- **Given** a set name that no directory matches **When** `scanSet` or `getQueueCandidates` runs **Then** it rejects with `SET_NOT_FOUND` rather than returning an empty list, so a mistyped set never reads as a finished one. A missing `done/` stays optional, and a set whose pieces have all moved into `done/` scans successfully while yielding no candidates.
- **Given** the same piece id present in both `<set>/` and `<set>/done/`, as a half-finished move leaves it **When** the set is scanned **Then** it rejects with `DUPLICATE_PIECE_ID` naming both paths.
- **Given** a consumer that must enumerate the whole corpus, including `done` and `blocked` pieces **When** `listSets()` is called **Then** it returns every set directory name under the root, sorted by name, because `getQueueCandidates` filters to `todo` and `pending` and would otherwise leave those states unreachable through the public surface.
- **Given** a root holding no set directories **When** `listSets()` is called **Then** it returns an empty list, because nothing was named and so nothing is missing. **Given** a configured root that does not exist **When** it is called **Then** it rejects, because misconfiguration read as "no work" would idle every consumer silently.
- **Given** an unknown piece id **When** `getPiece('99.99')` is called **Then** it rejects with `PIECE_NOT_FOUND`.

## Harness fit

This capability is a `Service Provider` mounted on the host plane (`ctx.devLoopDirectory`) extending `@deepseek-ai/cordis.Service`, following the service-plus-`static Config` shape of `packages/skill/skill/src/index.ts:356-377`. It performs filesystem discovery through the existing filesystem seam `ctx.fs` (`packages/fs/fs/src/index.ts:116-236`) rather than `node:fs`, so a sandboxed or remote backend governs every read. Parsing is a pure function over file text, which keeps the validator testable without a filesystem and reusable by the format gate in 00.10. `Directory` is the role word `docs/cookbook/adding-a-package.md:54` defines for a service that "exposes entries and metadata for discovery or selection"; nothing registers pieces, so `Registry` would be dishonest.

## Contracts

```typescript
export type PieceStatus = 'todo' | 'pending' | 'done' | 'blocked'

export type PieceFindingCode =
  | 'PIECE_SIZE_EXCEEDED'
  | 'MISSING_REQUIRED_SECTION'
  | 'MISSING_RECOMMENDED_SECTION'
  | 'INVALID_HARNESS_PRIMITIVE'
  | 'INVALID_PIECE_STATUS'
  | 'MALFORMED_PIECE_HEADER'

export interface PieceFinding {
  code: PieceFindingCode
  severity: 'blocker' | 'warning'
  message: string
}

export interface PieceMetadata {
  id: string
  title: string
  set: string
  queue: number
  dependsOn: readonly string[]
  status: PieceStatus
  primitive: string
  pkg: string
}

export interface PieceRecord extends PieceMetadata {
  path: string
  lineCount: number
  summary: string
  scenarios: readonly { given: string; when: string; then: string }[]
  warnings: readonly PieceFinding[]
}

/** Every field is optional so a cordis.yml row may set one and inherit the rest. Defaults and meanings are in the package README. */
export interface Config {
  root?: string
  maxLines?: number
  primitives?: string[]
}

/** One file the scan could not parse. A malformed sibling is data, not an exception. */
export interface PieceRejection {
  path: string
  code: PieceFindingCode
  findings: readonly PieceFinding[]
}

/** Valid records and rejected files, reported together so neither hides the other. */
export interface SetScan {
  pieces: readonly PieceRecord[]
  rejected: readonly PieceRejection[]
}

export class DevLoopDirectory extends Service {
  /** Set directory names under the configured root, so a consumer can enumerate the corpus. */
  listSets(signal?: AbortSignal): Promise<string[]>
  getPiece(id: string, signal?: AbortSignal): Promise<PieceRecord>
  scanSet(setName: string, signal?: AbortSignal): Promise<SetScan>
  getQueueCandidates(setName?: string, signal?: AbortSignal): Promise<PieceRecord[]>
  validate(filePath: string, content: string): PieceRecord
}
```

`PieceParseError extends Error` takes `(path, code, findings)` and exposes all three; the explicit code keeps the class total, with no unreachable fallback branch. Scan-level corpus defects are separate errors, because they belong to no single file: `SetNotFoundError` (`code: 'SET_NOT_FOUND'`, carrying `setName`) and `DuplicatePieceError` (`code: 'DUPLICATE_PIECE_ID'`, carrying `pieceId` and both `paths`). `PieceNotFoundError` carries `code: 'PIECE_NOT_FOUND'` and `pieceId`.

## Dependencies

None among pieces. This piece is the root entry point for discovery and validation of all specification pieces. It consumes the already-shipped `fs` service and declares it through `inject`.

## Teach me while you build

- **Background** — A *Cordis Service* is a class whose instance is published on the shared `Context` under one key, reachable as `ctx.<key>`. A *Service Provider* is the package that publishes one. *Dependency injection* here means a plugin lists services it cannot run without in `inject`; Cordis delays starting it until they exist and restarts it if they vanish. A *closed vocabulary* is a fixed set of accepted strings — anything outside it is an error, not a new case.
- **How it works here** — `ctx.devLoopDirectory.scanSet('00-dev-loop')` resolves `<root>/00-dev-loop` through `ctx.fs.resolve()`, lists it and its `done/` subdirectory with `ctx.fs.listDir()`, keeps basenames matching `NN.MM-<kebab-slug>.md`, reads each with `ctx.fs.readText()`, and hands the text to the pure `validate(path, content)`. `validate` splits lines, parses the header region before the first heading, walks `##` headings once against the canonical order while toggling a fenced-code flag, and collects findings. A blocker throws `PieceParseError`; warnings ride on the record. Open `packages/dev-loop/directory/src/parse.ts` and `src/index.ts`.
- **Why this approach** — Parsing is split from I/O because two callers need it: this service after `readText`, and the 00.10 format gate which already holds the text. A pure function also needs no temp directory to test, which is what makes 100% per-file coverage affordable.
- **Approaches considered** — (1) *Fence-aware line scan, chosen.* The idiom in `scripts/verify-agent-note-format.ts:44-70`; zero dependencies, ~3 lines for the fence toggle. Wins because the piece format is ATX-`##`-only by construction. (2) *`mdast-util-from-markdown`,* already a root devDependency and a runtime dependency of `packages/client/ui-primitives`; the Research role recommended it, and it would win the moment the format admits setext or HTML headings — measured at zero occurrences across 117 pieces today. (3) *`remark` + `unified-lint-rule` + `vfile-message`,* used by remark-lint, MDX and Gatsby; a real plugin architecture, correct if third parties must contribute rules, rejected as ~6 packages and an inversion of control nothing here needs. (4) *YAML frontmatter validated by schemastery,* which is already mounted for `Config`; rejected because `PIECE-FORMAT.md:11-13` fixes a `**Bold:** value ·` prose header.
- **Prior art inspected** — `markdownlint`'s `lib/md043.mjs` (source read, MIT) solves exactly this problem with a single monotone cursor over a required-heading array plus `addErrorDetailIf(expected, actual)`; its walk is adopted, its stop-at-first-error is not. `vfile-message`'s readme (API docs only, MIT) models severity as `fatal: true|false|undefined` on one message type — evidence for one `PieceFinding` carrying `severity` rather than Danger JS's four parallel arrays (`source/dsl/DangerResults.ts`, source read, MIT), which force every consumer to know all four names. Cucumber Gherkin's `javascript/src/Errors.ts` (source read) accumulates into `CompositeParserException` instead of throwing first — why `findings` is a list. Conftest encodes severity in rule names (`deny`/`warn`), rejected because a naming convention is invisible to TypeScript. No code was copied from any of them.
- **What we get for free** — Cordis supplies service publication, `inject` gating, and disposal on unload. `@deepseek-ai/schemastery` validates `Config` at load, so a bad `maxLines` in `cordis.yml` fails the mount instead of surfacing as a strange parse result. The `fs` seam supplies path resolution, listing, UTF-8 decoding, and binary rejection. We write the markdown grammar and the severity model, nothing else.
- **From the docs** — `plans/AGENTS.md` `R-piece-size` states the ceiling and narrates its own history: 160 originally, 220 when the visibility, teaching and reuse-capture sections became mandatory, and 280 once `Resources and proof` became required. `Config.maxLines` tracks whatever that axiom currently says, which is why this piece quotes the axiom by name rather than pinning a number in prose — a quoted number goes stale the moment the axiom moves, as this very bullet did twice.
- **What to notice** — The section walk is one forward pass with a monotone cursor, so a missing section and a transposed section fall out of the same loop. And `validate` never reads the filesystem: `path` exists only for messages.
- **Concepts to own** — *Pure function / referential transparency* (`validate`). *Functional core, imperative shell* — computation separated from I/O (`parse.ts` vs `index.ts`). *Total vs partial function* — `validate` returns findings; `getPiece` rejects with `PIECE_NOT_FOUND`. *Tagged union / closed vocabulary* (`PieceStatus`, `PieceFindingCode`). *Single-pass algorithm with a monotone cursor* (the section walk). *Severity-based policy evaluation* — blocker rejects, warning rides along. *Error accumulation versus fail-fast* (`findings` as a list). *Schema validation at a trust boundary* — schemastery over `cordis.yml`, since file text is untrusted input.
- **Interview angle** — *"How would you validate that a document follows a required structure?"* One forward pass with a cursor over the required list; a heading found before the cursor is reported with expected/actual, and required headings never reached are reported at the end — missing and misordered are the same defect in a sequence check. Follow-up: *"How do you report every problem instead of stopping at the first, and why does markdownlint choose to stop?"* Then: *"When do you take a dependency instead of writing forty lines?"* — mdast was already in the lockfile and would delete real edge cases, but measured zero of them in this corpus, and `unified` would add a plugin pipeline while deleting no owned code. Follow-up: *"What is your rollback plan when the dependency changes its AST in a major version?"*
- **Decisions you can now make alone** — Adding, reordering, or re-severity-ing a canonical section: the list and severity map are data, so change the constant and add the rejected/accepted-with-warning tests. Finding message wording, following the `path:line: quoted-text` form the other gates print. Whether the section walk stops after the first ordering violation. **Escalate:** any dependency not already in the lockfile; adding a `PieceFindingCode` member, because 00.04 and 00.10 will branch on it; changing the `maxLines` default, which tracks `R-piece-size` and must move with it; and any use of `node:fs`, which the `ctx.fs` seam forbids. **Still open for your judgment:** whether `validate` should return `{ record, findings }` uniformly instead of throwing for blockers and returning warnings — two channels for one concept, with no repository precedent either way.
- **Lesson** — When a written rule already names a checker, implement the rule where it can return structured, severity-carrying findings; a document citing a script that does not exist enforces nothing.

## Reuse capture

- **Reuse candidate:** ordered-section markdown validator · Walks a fixed heading sequence once, fence-aware, reporting missing versus out-of-order sections with per-section severity · Used by `validate()` in `DevLoopDirectory` · Reusable for Agent Note templates, postmortem templates, and README structure gates, several of which hand-roll their own scan in `scripts/` · Would need the section list and severity map lifted into parameters instead of module constants · Evidence: the ordering and severity cases in `packages/dev-loop/directory/tests/directory.spec.ts` · Confidence: medium
- **Known limitations** — Only ATX `##` headings participate; setext headings are not recognised, which is safe only while the corpus contains none. Line ranges inside a References table are not verified against the cited file; 00.08 owns that. Do NOT reuse this to judge prose quality — it checks structure only.
- **Failure worth keeping** — The first implementation of this piece was written before any test existed, and scanned `##` headings with a regex over every line, silently treating a `##` line inside a fenced code block as a section heading. The Research role found it by comparing against `markdownlint`. The trigger is *not* `PIECE-FORMAT.md`, which `isPieceFilename` rejects so `scanSet` never reads it; it is a piece that embeds a markdown template inside `## Contracts` — this piece already embeds a fenced `typescript` block — and the 00.10 gate calling `validate()` on text it holds directly. The Test Writer role caught that misattribution while writing the case for it. Transferable lesson: a structure check over markdown must know where code fences are, writing the implementation before the tests hides exactly this class of defect, and a justification can be wrong even when the rule it argues for is right.
- **Anti-pattern worth keeping** — This piece twice pinned a ceiling number in prose and twice went stale: it first specified 160 while the axiom said 220, and later quoted the 220 text verbatim after the axiom moved to 280. The Implementer role caught the second instance. A specification's own citation is not evidence until the cited lines are reopened, and a number copied out of an axiom is a fact with a decay rate — name the axiom instead.

## Acceptance

1. Unit tests in `packages/dev-loop/directory/tests/directory.spec.ts` pass, covering valid parsing, metadata extraction, and scenario extraction.
2. Parser rejects files exceeding the configured ceiling with `PIECE_SIZE_EXCEEDED`, and accepts a file of exactly the ceiling.
3. Parser rejects pieces with missing or out-of-order blocker sections with `MISSING_REQUIRED_SECTION`, ignores unknown headings, and ignores `##` lines inside fenced code blocks.
4. Parser rejects primitives outside `Config.primitives` with `INVALID_HARNESS_PRIMITIVE`, and statuses outside the four states with `INVALID_PIECE_STATUS`.
5. A piece lacking only `## Reuse capture` validates successfully and carries exactly one warning.
6. `listSets()` returns the corpus's set directories sorted by name, excluding files and each set's own `done/`, returning `[]` for an empty root and rejecting for a missing one; `getQueueCandidates` enumerates through it, proven by a case asserting candidate set order agrees with the reported order rather than restating the sort.
7. `scanSet('00-dev-loop')` over the real `plans/pieces` corpus returns every piece of the set in queue order, whether it sits in the set directory or in its `done/` subdirectory. The assertion checks the invariants the parser does **not** already guarantee — strictly increasing queue positions, unique ids, each record's declared `**Set:**` agreeing with the directory holding it, and a file under `done/` if and only if it declares `done` — plus one anchor id proving the scan reached the right tree. It never pins an id list, because the set grows. It deliberately does not assert that every piece is within the ceiling or that every primitive is in the vocabulary: `parsePiece` already rejected any file violating those, so such assertions cannot fail and would read as coverage while providing none.
8. `getQueueCandidates` resolves a `done` piece as a dependency through `getPiece` but excludes it from the candidate list.
9. `ctx.devLoopDirectory` disposal removes the service, proven by a fiber-disposal test.
