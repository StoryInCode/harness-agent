# 00.10 — Evidence-Bound Completion Gates

**Set:** 00-dev-loop · **Queue:** 10 · **Depends on:** 00.02, 00.09
**Status:** todo
**Harness primitive:** Service Provider · **Package:** `@deepseek-ai/dsh-dev-loop-gates`

## Summary

Require Format, behavioral RED, GREEN and post-transfer evidence before Lifecycle completes a piece. This proposed Host service runs checks and retains their actual observations. It does not consume an imaginary verification package or accept caller-supplied pass records. Its serial pre-complete listener vetoes by throwing; it cannot transition the already-claimed piece to blocked inside that listener.

## Behaviour

- **Given** current evidence for all four checks **When** Lifecycle requests completion **Then** the listener allows its existing Git completion path.
- **Given** missing or stale evidence **When** completion is requested **Then** it throws and the committed status remains pending after claim release.
- **Given** altered frozen tests/helpers/configuration or selected identities **When** GREEN or post-transfer runs **Then** it rejects test drift rather than accepting weakened coverage.
- **Given** passing worktree tests but failed/missing mainline execution **When** completion is requested **Then** post-transfer refuses completion.
- **Given** non-behavioral baseline failure **When** RED is checked **Then** it rejects syntax/import/infrastructure/no-tests/killed outcomes.
- **Given** a veto **When** the orchestration caller awaits transition rejection and then requests pending-to-blocked **Then** Lifecycle may legally block; the hook itself never makes that nested transition.

## Harness fit

The **Service Provider** publishes `ctx.devLoopGates`, injecting `devLoopDirectory`, `devLoopTestHandoff`, `fs`, `subprocess` and `storageDomain`. It effect-owns `ctx.on('piece/pre-complete', async event => ...)`; Lifecycle already calls this event serially while holding its done claim. No Agent-loop modification or workflow bridge is needed.

The current Lifecycle.claim compares `piece.claim ?? piece.status`; complete releases its claim when a hook rejects. Therefore the hook evaluates/throws only. Explicit orchestration handles any later block after transition settles, rechecking current status and propagating cancellation. No failed gate alone proves the later block succeeded.

## Contracts

Proposed API:

- `runChecks(pieceId, stage, signal): Promise<GateReport>`, where stage is `worktree` or `post-transfer`. It executes owner-configured commands and builds observations itself; caller arguments cannot supply result flags, paths, commands, revisions or evidence.
- `getReport(pieceId): Promise<GateReport | undefined>` returns the latest detached report with failures/staleness.
- The private pre-complete evaluator rereads current source/Git/test identities and consumes exact owner-produced records; it rejects incomplete/stale evidence instead of rerunning arbitrary commands during the completion hook.

`GateReport` contains branded report id, piece id/digest, handoff id, repository/worktree assignment identity, production revision manifest, runner/test/config manifest, observation times and one evaluation per `format | red | green | post-transfer`. Each evaluation has derived status, reason code, exact checked identities and evidence ids. No public `recordPass`, `setGateResult` or arbitrary `passed:true` setter exists.

The required scoped `./tool` Consumer owns dev_loop_check `{pieceId,stage:'worktree'|'post-transfer'}`, dev_loop_gate_report `{pieceId}` and dev_loop_complete `{pieceId}`. It injects tools, agents, devLoopGates and devLoopLifecycle, requires exact live exec.agent registry equality, captures its initiator with agents.withInitiator and propagates exec.signal. Check/report call runChecks/getReport; complete calls Lifecycle.transition(pieceId,'pending','done',undefined,signal), whose actual hook validates evidence. The complete Consumer reports rejection only after transition settles; it never auto-blocks, transfers, retires worktrees or accepts model passed/evidence/revision/command fields. Its own Config.maxToolOutputBytes bounds complete rendered UTF-8 results with a minimum derived from its fixed error envelope; overflow is explicit, not clipped success. Effect-own registrations, use pure rendering and prove model-visible logged results.

| Check | Required observation |
|---|---|
| Format | Read current source and call Directory.validate(path,content); record full findings/digest. Also execute explicitly configured applicable axiom checks, recording argv/version/results. Do not claim Directory validates every prose axiom or supplies AST. |
| RED | Read Handoff’s durable record for this exact piece/claim/test baseline; require its behavioral expected-failure classification and full frozen input identity under 00.09. |
| GREEN | Run exact selected tests in retained assignment against the observed implementation revision; require no collection/runtime/infra errors, all required assertions executed/passed, and unchanged frozen test/config identities before and after. |
| Post-transfer | Run the same pinned selection in configured mainline after explicit transfer; record mainline Git/working content identity, transferred production manifest and unchanged tests. Worktree GREEN is never substituted. |

Production identity includes HEAD plus relevant tracked/index/untracked content digests and configured package/lockfile inputs, not HEAD alone. Capture before and after every command; unexpected input drift invalidates its result. Validate the transferred implementation files against the GREEN manifest; unrelated mainline changes are recorded and tested rather than overwritten. The exact command policy and selected test identities must remain pinned even when working directory changes.

Completion compares all four evaluations against the current piece, test baseline and mainline identity. Historical RED stays tied to its original production baseline; it must not falsely match GREEN’s changed production revision. The shared link is the frozen test/claim/spec identity. Lifecycle’s own later status-header edit and done/ move are expected completion effects, not permission to alter substantive approved source. Record raw source digest and define only the lifecycle-owned status token/path as completion metadata normalization; no arbitrary prose exclusion.

### Runner and ownership

Reuse Handoff’s runner interpretation through an exported owned adapter module or the smallest shared code inside these two consumers once real duplicate use exists; do not invent a general verification service. Its machine-readable protocol distinguishes assertion outcomes, skipped/zero tests, syntax/import/collection errors, timeout/cancel/signal and cleanup failure. No truncated reporter or overflow can pass. A clean exit after timeout is still failure.

Use subprocess.spawn with full argv/cwd/stdio/grace/signal. Owner deadlines trigger cancellation, then terminate and await waitForExit; output capture and cleanup facts are independent. Commands may mutate caches/files and are not promised read-only. Report effects, refuse changes to frozen inputs and retain worktrees. Gates never transfers code, commits, pushes, moves pieces or retires assignments.

Own `dev_loop_gates`, version 1, single layout, schema-validated attempts/reports. Persist intent before execution and terminal evidence before success. Failed final write leaves unresolved intent. Serialize same-piece operations; join active work before domain.close. Config requires repositoryRoot, mainlinePath, format command policy, runner policy, commandTimeoutMs, terminationGraceMs, maxOutputBytes and maxReportBytes. Missing referents and invalid complete UTF-8 budgets fail explicitly. No hidden deployment constants.

## Teach me while you build

- **What it does:** Stops completion unless evidence belongs to the exact work being completed.
- **Background:** A serial policy hook is awaited before the owner continues. A compare-and-set claim reserves a transition. Content addressing identifies bytes, not whether a test is meaningful.
- **How it works here:** Lifecycle.claim reserves done before complete calls the hook. Gates reads exact reports and throws on stale evidence; only the caller can block after that claim releases.
- **Why this approach:** The existing sole-writer hook prevents invalid completion. A post-completion observer can report failure but cannot retroactively veto the move.
- **Approaches considered:** Serial policy plus durable owner evidence is chosen; post-event observation suits dashboards. in-toto Statements provide a real external digest-bound evidence envelope, useful for interchange, but importing its whole attestation machinery would not establish test semantics.
- **Prior art inspected:** Research reported in-toto attestation commit 06eafe3635bf8a425ad52cc82c6c90861e94a471 spec/v1/statement.md inspection. Utility did not inspect external source directly; no external code reused.
- **What we get for free:** Lifecycle owns claim/release and Git move; subprocess owns managed ranges; storageDomain owns durable writes. Gates owns classification, input binding and stale refusal.
- **From the docs:** PiecePreCompleteEvent states “listeners must settle their owned work before returning.” Veto is not permission to leave a process running.
- **What to notice:** RED and GREEN have different production revisions but the same frozen tests. A nested block call conflicts with the held done claim.
- **Concepts to own:** Complete mediation checks the actual completion writer; time-of-check/time-of-use protection rechecks identities; provenance preserves which run produced evidence.
- **Interview angle:** “How do you avoid reusing yesterday’s green result?” Bind it to current piece/tests/revision and reject drift. Follow-up: Git HEAD alone misses dirty working content.
- **Decisions you can now make alone:** Improve diagnostics and invalid-evidence fixtures. Escalate test changes, transfer ownership and lifecycle transitions to their owners.
- **What you should learn from this:** A passing result without exact input identity cannot authorize completion.

## Acceptance

1. Freeze behavioral RED before implementation and exercise actual Lifecycle completion in a Loader composition.
2. Four checks consume owner-produced exact evidence; missing/stale/cross-piece/cross-test/cross-revision records cannot pass.
3. Hook rejection leaves pending and no completion filesystem effects; nested block is never attempted. Explicit caller blocking occurs only after release and recheck.
4. Real runner covers expected RED, pass, syntax/import/no-tests, skips, timeout/killed/truncation and cleanup failure without self-reported pass APIs.
5. Changed tests/helpers/fixtures/config/discovery and before-after input drift fail GREEN/post-transfer; HEAD-only matching cannot pass dirty revisions.
6. Real separate mainline execution after transfer is mandatory; preserve unrelated mainline work and retained assignment files.
7. Prove persistence restart/write failure, cancellation/join/disposal, complete bounds and exact durable report linkage.
8. Record unit, real Loader and relevant keyless visible-output snapshots; update owner docs/Agent Note and post-transfer evidence before completion.
