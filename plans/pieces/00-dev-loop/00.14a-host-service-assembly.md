### Human Decision Point: Option A vs Option B
- **Option A (Active)**: Assemble all Dev Loop services in the Host Plane as a reusable Cordis patch layer.
- **Option B (Alternative)**: Mount services separately inside each agent session, creating fragmented, desynchronized queues.

## Behaviour

- **Given** a deployment loading `cordis.patch.yml` with dev loop enabled **When** host boot executes **Then** all 9 dev loop services register into root Cordis context.
- **Given** a multi-session setup where session A enqueues a piece and session B inspects it **When** query runs across sessions **Then** both sessions observe the exact same shared queue and database state.
- **Given** host shutdown or reload **When** dispose runs **Then** services dispose cleanly in reverse dependency order.

## Teach me while you build

Putting together a sewing kit means making sure the scissors, needles, and threads are all in their proper places! Tutturu~

- **What it does**: Mounts the dev loop's core services into the shared Host Plane container via Cordis patch composition.
- **Background**: In DSH, services shared across sessions (queues, worktree pools, databases) must live in the Host Plane, not in private agent sessions.
- **How it works here**: The patch YAML specifies each plugin package and its validated configuration. Cordis Loader mounts them during boot.
- **Why this approach**: Ensures all sessions share a single queue and single database, preventing split-brain states.
- **Approaches considered**: Session-local mounting (gives every session its own private queue) vs Host patch layer (chosen: shared coordination).
- **Prior art inspected**: Kubernetes DaemonSets and systemd system daemons.
- **What we get for free**: Cordis dependency injection (`ctx.inject`) ensures services load in proper topological order automatically.
- **From the docs**: AGENTS.md: 'Host plane versus agent plane is decided by the rules in PRESET-RULES... Host Plane owns cross-session persistent state.'
- **What to notice**: Notice how each plugin only declares its own dependencies; Cordis wires them without manual glue code!
- **Concepts to own**: Host Plane singleton architecture: colocating shared state services in the application container root.
- **Interview angle**: How do you coordinate state across multiple agent sessions in an extensible micro-kernel? Answer: Mount coordination services as host-level plugins shared by all session scopes.
- **Decisions you can now make alone**: You can adjust plugin configuration parameters in `cordis.patch.yml` without modifying source code.
- **What you should learn from this**: Keep shared resources at the host level so all agents work in perfect harmony! 🌸
