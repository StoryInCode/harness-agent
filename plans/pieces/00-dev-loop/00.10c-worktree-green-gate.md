## Summary

Yo! Daru runs Gate 3. This is the big one: we execute the entire test suite inside the worker's isolated worktree. Every single test must pass with exit code 0! Not 99%, not 'just one minor timeout'—ONE HUNDRED PERCENT GREEN. If a single test fails, the gate slams shut and the implementer is sent back to fix their code. No broken builds allowed!

### Human Decision Point: Option A vs Option B
- **Option A (Active)**: Execute complete test suite in isolated worktree and require exit code 0 and 0 failures.
- **Option B (Alternative)**: Rely on subagent self-reported claims of tests passing without executing an independent verification run.

## Behaviour

- **Given** a worktree where all unit and integration tests pass with exit code 0 **When** evaluateGate3(worktree) is called **Then** it passes Gate 3 with green evidence.
- **Given** a worktree where one test times out or asserts false **When** evaluateGate3 runs **Then** it casts a veto with the exact failing test name and failure output.
- **Given** a worktree that fails typecheck or linting **When** evaluateGate3 executes **Then** it casts a veto with typecheck error details.

## Teach me while you build

Metal doesn't lie. Exit code 0 or GTFO. Let's run the real test rig.

- **What it does**: Runs all tests inside the worktree to guarantee the implementation made the tests green.
- **Background**: Subagents often hallucinate that tests passed. Gate 3 executes an independent, host-mediated run.
- **How it works here**: Spawns `pnpm exec vitest run` inside the worktree directory. Captures process exit code and JSON results.
- **Why this approach**: Independent host execution eliminates all possibility of model deception or false reporting.
- **Approaches considered**: Agent self-report (unreliable: agents lie to exit) vs Host-executed test runner (chosen: absolute truth).
- **Prior art inspected**: Continuous integration test runners (GitHub Actions, Jenkins).
- **What we get for free**: Vitest runs fast in-process with multi-threading.
- **From the docs**: AGENTS.md: 'A task is not done when the code works. It is done when the owner can SEE it working.'
- **What to notice**: Notice how the worktree CWD ensures test artifacts and database files stay isolated!
- **Concepts to own**: Independent host verification: executing verification checks outside the agent's control boundary.
- **Interview angle**: How do you prevent AI coding agents from falsely reporting that tests passed? Answer: Mediate all test execution through an un-bypassable host runner.
- **Decisions you can now make alone**: You can customize the test runner command (e.g. adding coverage flags) via `Config.testCommand`.
- **What you should learn from this**: Never trust an agent's word on test results. Run the test yourself and demand exit code 0!
