## Source and human authorization

Persistence exports the inert pure `observeSource(path: string, content: string, version: FsVersion): SourceObservation` scaffold for Lifecycle, Approval and Command. It owns raw hashing and initial-header-only normalization, not fetching, storage or authorization. The caller supplies a canonical Directory path, complete fatal-decoded validated UTF-8 source, and its actual provider version. A known observed file size must equal the UTF-8 byte length of that content. Missing size or a mismatch is explicitly refused by Consumers and required hydration; neither case establishes byte-faithful source identity. The local provider already rejects invalid UTF-8 but strips an initial BOM, so BOM-prefixed source is currently unsupported and must be refused rather than assigned the digest of stripped text. No filesystem provider change or unbounded raw-byte fallback is authorized.

Actual human authorization is forwarded in both memory and required modes. Memory mode remains nondurable; it does not erase who accepted which source. No public durability accessor or duplicate Consumer mode option is added merely to preserve historical call arity.

`SourceObservation.path` is the exact canonical path returned by Directory; its configured root may be relative to the filesystem provider base or absolute. `rawDigest` is lowercase SHA-256 over complete UTF-8 bytes. `contentDigest` uses the same bytes with only the parsed initial lifecycle Status header value replaced by `todo`. Body examples, whitespace, line endings, title, metadata, and every other byte remain significant. Records retain both source and terminal raw digests. A raw difference is not independently accepted merely because normalized digests match: it must correspond to the recorded lifecycle-owned status edit. Current live approval compares the actual `FsVersion`; remount compares recorded source bytes/digests rather than requiring the old host filesystem token to survive copying or restart.

## Publication, failure and recovery

A held Lifecycle claim precedes the first await. Sequence starts at one and increases for every admitted intent, including failed attempts. Legal-state and stale-CAS rejection create no intent. `beginTransition` succeeds only after the complete intent record is durable, before policy or filesystem side effects. Begin I/O failure is `DEV_LOOP_INTENT_WRITE_FAILED` with header/index/move `none`; record/history bounds retain their specific bound code. Required authorization and stale-source failures precede mutation.

`finishTransition` updates the existing intent row; it never creates an unrelated completion row. A committed terminal follows successful policy and actual filesystem/Git effects. Only after this durable write may Lifecycle publish memory, release the claim, and announce. A terminal I/O failure is `DEV_LOOP_TERMINAL_WRITE_FAILED` and independently discloses header, index, move and cleanup certainty. Post-effect recording failure quarantines the piece and leaves an unresolved intent for remount. Cancellation cannot cancel the obligation to record an admitted terminal attempt. Disposal joins all admitted transitions before domain close, including non-done transitions.

`TransitionEffects.header/index/move` describe whether each forward effect occurred, not whether later cleanup erased it. `cleanup` reports restoration separately. A pre-complete veto records a failed attempt with no effects and keeps committed pending; the released claim allows a subsequent explicit pending-to-blocked call. A notification defect cannot erase a committed terminal. Recovery uncertainty never pretends the Git index was rolled back merely because the header was restored.

Hydration adopts consistent committed state before admission, including pending/blocked with unchanged todo headers. Unknown durable references, missing/duplicated files, changed substantive source, status/path conflict, unjournaled done and unresolved intents remain anomalies. Quarantined `getStatus` and transition calls throw `PIECE_QUARANTINED`, preserving the difference from unknown piece identity and preventing consumers from treating a done location as dependency authorization. No illegal done-to-pending transition repairs hydration.

`getHistory` returns detached sequence-ordered records; `getAnomalies` returns detached deterministic anomalies. `acknowledgeAnomaly` rereads local observations and rejects changed observations with `DEV_LOOP_ANOMALY_STALE`. Its returned record binds the actual root command invocation, complete reason, exact observations and timestamp. It appends awareness only. Acknowledgment survives remount and never clears quarantine or changes lifecycle state.

## Bounds and recovery command

Provider configuration requires explicit `repositoryRoot`, `maxRecordBytes` and `maxHistoryRecords`; budgets are positive safe integers. Record bounds cover UTF-8 JSON for the complete retained row, including terminal and acknowledgment metadata. The history cap counts intent rows per piece, including failed attempts; overflow rejects rather than silently truncating. Retained anomaly/acknowledgment rows obey the same complete-record byte bound. Root relocation or reuse of foreign repository records is unsupported.

Inspection success text is exactly `JSON.stringify({pieceId,history,anomalies})` in that field order, with anomalies filtered to the requested piece. Acknowledgment success text is `JSON.stringify(acknowledgment)`. The separate named-export Consumer registers `dev-loop-recovery` without a slash and injects only commands, agents and persistence. Grammar is exactly `inspect <pieceId>` or `acknowledge <anomalyId> <reason...>`. Missing/extra fixed arguments and repair/promote/done verbs reject. Mutating commands require the exact live root Agent (`agents.get(id) === agent` and membership in `agents.roots()`). The whole remaining nonempty reason is preserved apart from surrounding whitespace. Disposal removes the real registration.

Command configuration requires `maxInputBytes` and `maxOutputBytes`. The complete returned CommandResult JSON, not only its text, obeys the UTF-8 output cap. Minimum valid output is the complete `{kind:'error',text:'Recovery output exceeds maxOutputBytes; increase the configured limit.'}` JSON byte size. Smaller configuration rejects. That exact refusal is returned when an otherwise valid inspection exceeds the configured budget, never clipped history. CommandRuntime owns the actual command/run and command/done log pair and commandId; this suite inspects those events through `Session.snapshotEvents()`.

## Teaching and limitations

Write-ahead intent means recording an operation before its side effect. Compare-and-set means only the caller whose expected state still holds may acquire the transition. Durable-before-visible publication means readers cannot observe success before restart can recover that same success. Look at the all-legal-edge test: Git really moves the file, but an empty history still fails the assertion. File movement and authorized completion are separate observations.

The chosen adjacent Lifecycle integration reaches every direct caller. An announcement listener is simpler for telemetry but cannot intercept a transition before publication or cover blocked-to-todo. A storage-only service cannot hydrate Lifecycle's private state. An external workflow engine could own replay if execution moved into that engine, but no external implementation was inspected or reused in this Test Writer task; no external recovery guarantee is claimed.

The real Loader provides activation ordering, Directory validates source, local providers perform Git/filesystem work, and storage-domain serializes durable writes. Application code must interpret uncertainty and authorization. Barriers place cancellation at an observed edit/stage/move/write checkpoint; they do not use elapsed time as evidence. The transferable lesson is to compare independent observations rather than accepting a component's success string. Reuse candidate: private-root real-provider barrier fixtures for another multi-system operation; confidence is limited until the frozen tests pass a separate implementation.
